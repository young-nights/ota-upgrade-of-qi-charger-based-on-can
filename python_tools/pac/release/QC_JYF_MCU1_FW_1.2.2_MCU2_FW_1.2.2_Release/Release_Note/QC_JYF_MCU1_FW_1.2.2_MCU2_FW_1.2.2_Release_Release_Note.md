## 3. Change Log

### 3.1 相对上一发布（1.2.1 → 1.2.2，2026-10-19）

| # | 问题/需求描述 | 修改细节 | 修改后预期行为 | 受影响 MCU/模块 | issue/ticket |
|---|---------------|----------|----------------|-----------------|--------------|
| 1 | Qi 功率设定与芯片档位不一致，值域难对齐 | DID `0x210D` 改为 **1 字节档位码**：`0x01`=5W / `0x02`=10W / `0x03`=15W（即 `QI_POWER_*`）；写侧主格式 1B，兼容旧 2B 载荷并映射；值域外 NRC `0x31`；`qi_protocol_set_power` 原样转发档位码；NVM 接受新档位码并兼容旧值；上位机/Python 全链路同步 | 读写 `0x210D` 得到/写入档位码；充电功率按 5/10/15W 档执行 | MCU1 / Qi 功率配置 + 产线上位机 + Python 脚本 | — |
| 2 | 旧 NVM / 旧载荷兼容映射单位错误（按 500/1000/1500 而非 mW） | `qi_nvm_load_config` 与写 `0x210D` 兼容路径改为 mW **5000/10000/15000** → `QI_POWER_5W/10W/15W` | 升级后旧配置不被误解释为错误功率档 | MCU1 / NVM 配置 | — |
| 3 | 充电持续 >60s 后充电门禁 stale 超时**误放行 Sleep**（本应保持充电禁止睡眠） | `can_lp_mark_uds()` 每次 UDS 交互重置 `g_charge_gate_since=0`；60s 窗口仅在**真正无 UDS 通信**时到期（判定禁充写入丢失） | 正常充电 + 周期 UDS 保活不会误进 Sleep；禁充写入丢失场景仍可恢复 | MCU1 / 低功耗 + 充电门禁 | — |
| 4 | MCU2 随包版本对齐 | QI IAP 载荷版本字段 `0x302D` `01 02 01`→`01 02 02`（与 `QI_IAP_Ver_1_2_2.BIN` 一致） | Qi 版本查询上报 1.2.2 | MCU2 / IAP 载荷 | — |

> 说明：条目 2 的源码提交（`c5da36c`）曾将 `SW_VERSION_STR` 标为 1.2.3，随后 `72c24b3` 回写为 **1.2.2** 以对齐本交付包；镜像 strings 已核对为 `QC_JYF_MCU1_FW_1.2.2`。
