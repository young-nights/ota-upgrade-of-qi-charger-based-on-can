## 1. 功能总览

| 功能 | 按钮 | UDS 要点 | 会话/解锁 |
|------|------|----------|-----------|
| 扫描串口 | 扫描 | 自动识别 ZQWL（VID `3562`） | — |
| 连接 / 断开 | 连接 / 断开 | 配置 CAN0 250k 扩展帧，长连接 | — |
| 链路自检 | 链路自检 | `3E 00` + `22 F195` | 任意 |
| 读版本 | 读版本 | `F195`+`2133`+`F180`+`F193` 一次读全 | 任意 |

| IAP 升级（Qi 芯片） | IAP 升级 | 目标 `2E 20 10 04`，块 22B | 编程 + 解锁 |
| Qi 状态查询 | Qi 状态查询 | `2132/2102/2104/2105/2108/2109/210B/210C/210D` | 任意 |
| 设置 Qi 功率 | 设置 Qi 功率 | `10 03` → SA → `2E 210D` | 扩展 + 解锁 |
| 开启 / 关闭充电 | 开启充电 / 关闭充电 | `10 03` → SA → `2E 2101` | 扩展 + 解锁 |
| 日志复制 / 导出 | 复制日志 / 导出… | 贴给远程支持 | — |

**界面特性：**
- 窗口等比缩放，缩小不截断
- COM 下拉自动扫描并标 ★ 选中 ZQWL
- 波特率固定 **2000000**（ZQWL USB 私有协议，只读）
- 操作前自动等待 UDS 就绪（防 Boot 窗口误判）
- 失败只提示、不崩溃；操作记录多行块显示

## 2. 硬件与连接

### 2.1 需要什么

| 硬件 | 说明 |
|------|------|
| ZQWL-CANFD USB-CAN | VID:PID `3562:0101`，USB CDC 私有协议 |
| CAN 线 | CANH / CANL / GND，终端电阻 120Ω |
| 待修充电器 | 12V 供电，CAN 250 kbps、29-bit 扩展帧 |
| （可选）写 SN / OTA | `docs/keys/private.pem`（ECDSA 解锁） |

### 2.2 CAN 标识

| ID | 方向 | 含义 |
|----|------|------|
| `0x18DA0D03` | 上位机 → ECU | UDS 请求 |
| `0x18DA030D` | ECU → 上位机 | UDS 应答 |
| `0x18FF260D` | ECU 广播 | 生命周期（BOOTUP / WK / ABT / SB） |
| `0x18FF480D` | ECU 广播 | Boot 诊断 M1–M4 |
| `0x18FF270D` | ECU 广播 | LP 诊断 |

### 2.3 插上就能用

1. ZQWL 插 **Windows**（不要被 WSL `usbipd attach` 占用）
2. 打开 `QiChargerStationTool.exe`
3. 顶部「COM 口」自动扫描，★ 为 ZQWL → 点 **连接**
4. 日志出现 `CAN0 250k ext ready` 即可操作

## 4. 典型维修流程

### 4.1 先诊断

1. **连接** → **链路自检** 或 **读版本**
2. 看是否读到四路版本（MCU1 / MCU2 / Boot / HW）
3. **Qi 状态查询**：IAP 状态、充电状态、故障码、FOD、温度

### 4.2 故障分流

| 现象 | 判断 | 处理 |
|------|------|------|
| 无任何 CAN 回包 | 线 / 供电 / 盒子 | 查 CANH-CANL、终端电阻、12V |
| 只有 `0x18FF480D` Boot 帧 | APP 未运行 | 刷 OTA / 检查镜像 |
| `01 41 42 54` ABT 心跳 | Boot Safe Mode | 刷 `merge_prod_bin` 产线镜像 |
| 读 SN 回 NRC 0x31 | **SN 未写入** | 扫码 → 写入 |
| 读版本 PARTIAL | 部分 DID 失败 | 看 ⚠ 行（如 MCU2 版本缓存空） |
| UDS 超时但有生命周期 | APP 刚启动 | 等 1～2 秒重试（工具会自动等就绪） |

### 4.3 写 SN（返修换板）

1. 读 SN → 显示 `EMPTY`（新板）
2. 扫码或手输 SN → **写入**
3. 自动读回校验，PASS 为准

### 4.4 刷固件

1. **AT32 OTA**：选 `app_image_v*.bin`（XATO 签名包）→ OTA 升级
2. **Qi 芯片 IAP**：选 log bin → IAP 升级
3. 等自复位后 **读版本** 确认

### 4.5 充电验证

1. **设置 Qi 功率**（5W / 10W / 15W）
2. **开启充电** → 放手机 → **Qi 状态查询** 看是否 `充电中`
3. **关闭充电**

## 5. 协议与 DID 对照

### 5.1 版本

| DID | 内容 | 示例 |
|-----|------|------|
| `F195` | MCU1 APP | `QC_JYF_MCU1_FW_1.2.3` |
| `2133` | MCU2 Qi（3B） | `QC_JYF_MCU2_FW_x.y.z` |
| `F180` | Bootloader | `QC_JYF_BL_1.0.0` |
| `F193` | 硬件 | `QC_JYF_HW_1.1.5` |

### 5.2 SN 与配置

| DID | 读写 | 说明 |
|-----|------|------|
| `F18C` | R/W | SN 32B ASCII；读 NRC 0x31 = 未写入 |
| `210D` | R/W | Qi 功率档位码 `0x01`=5W / `0x02`=10W / `0x03`=15W |
| `2101` | W | 充电使能 0/1 |

### 5.3 Qi 状态（只读）

| DID | 内容 |
|-----|------|
| `2132` | IAP：state / progress / Qi版本3B / 已发 / 总长 |
| `2102` | 充电状态机 |
| `2104` | 输出功率 u16 LE mW |
| `2105` | 输入电压/电流 raw |
| `2108` / `2109` / `210B` / `210C` | 温度 / FOD / 故障 / 热降额 |

### 5.4 生命周期帧（`0x18FF260D`）

| 载荷 | 含义 |
|------|------|
| `01 41 00 …` | BOOTUP（上电/复位） |
| `01 41 57 4B …` | BOOTUP-WK（唤醒） |
| `01 41 42 54 …` | ABT Boot 安全模式心跳 |
| `06 41 53 42 …` | SHUTDOWN-SB（待机） |

## 7. 打包发布

### 7.1 VS 界面

1. 配置 **Release** | **Any CPU**
2. 右键 `QiChargerStationTool.App` → **发布** → **文件夹**
3. 设置：`win-x64` + **自包含** + **生成单个文件**
4. **发布** → 得到 `QiChargerStationTool.exe`

### 7.2 脚本（推荐）

```powershell
cd QiChargerStationTool
.\publish.ps1          # 绿色版 + 单文件版
.\publish.ps1 -Zip     # 加 zip
```

自动打包 `keys\private.pem` 与使用说明。安装包：用 Inno Setup 编译 `installer\QiChargerStationTool.iss`。

### 7.3 分发到维修工位

```
QiChargerStationTool.exe
keys\private.pem      ← 写 SN / OTA 时需要
```

目标机无需 VS、无需 .NET（自包含包）。

## 8. 常见问题

| 问题 | 处理 |
|------|------|
| `COMxx Access denied` | 串口被占用：关旧实例/串口助手；`usbipd detach`；拔插 USB |
| 无 `18DA030D` 应答 | 见 §4.2 故障分流；点「链路自检」看 `[CAN-RX]` |
| 读 SN NRC 0x31 | **SN 未写入**（正常新板），先写入 |
| 启动后点按钮无反应 | 已修复；若仍发生请断开后重连 |
| 超时/失败后点不动 | 已修复（`_busy` 释放）；仍异常则重启 exe |
| 缺少私钥 | 拷 `docs\keys\private.pem` 到 exe 旁 `keys\` |
| 心跳 `5A FF` 刷屏 | 盒子状态心跳，已过滤，只显示 CAN 帧 |
| 日志要发远程 | 点「复制日志」或「导出…」 |

## 附录 A. 技术选型结论

**C#（WPF）/ .NET 8**，不用 Qt。

| 考量 | 说明 |
|------|------|
| 平台 | 维修工位 Windows，C# 原生部署干净（单文件自包含） |
| 硬件 | ZQWL USB CDC → `SerialPort` 零驱动对接 |
| UI | 大按钮 / 日志 / PASS-FAIL，WPF 效率高 |
| 生态 | 扫码枪、导出报表、NuGet，工业工装主流 |
| 退出 Qt 的场景 | 需 Linux/Mac GUI 或强 C++ 定制图形 |

详细论证过程见 Git 历史中本文件旧版（产线技术选型）。
