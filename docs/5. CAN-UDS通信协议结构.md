## 1. UDS 概述

UDS（Unified Diagnostic Services，统一诊断服务）是 ISO 14229 标准定义的诊断通信协议。它为 ECU（电子控制单元）提供了一套标准化的诊断服务接口，用于读取故障码、读写数据、刷写固件、执行例程等操作。

UDS 本身是应用层协议，可以运行在多种传输层之上：

- **CAN**（ISO 15765-2）：最常见的车载诊断传输方式
- **LIN**、**DoIP**（Ethernet）、**FlexRay** 等

本文聚焦 **CAN-UDS**，即 UDS over CAN（ISO 15765-2）的协议结构。

## 2. CAN-UDS 协议栈分层架构

CAN-UDS 采用四层协议栈：

```
┌─────────────────────────────────────────────┐
│        应用层 (Application Layer)            │
│   ISO 14229 — UDS 诊断服务                   │
│   SID / DID / NRC / Session / Security       │
├─────────────────────────────────────────────┤
│        传输层 (Transport Layer)              │
│   ISO 15765-2 — ISO-TP                       │
│   单帧(SF) / 首帧(FF) / 连续帧(CF) / 流控(FC) │
├─────────────────────────────────────────────┤
│        数据链路层 (Data Link Layer)          │
│   CAN 2.0B — Classical CAN                   │
│   29-bit 扩展帧 / 仲裁 / 错误检测            │
├─────────────────────────────────────────────┤
│        物理层 (Physical Layer)               │
│   ISO 11898-2 — 高速 CAN 收发器              │
│   250 kbps / 120Ω 终端 / 差分信号            │
└─────────────────────────────────────────────┘
```

各层职责：

| 层级       | 标准                 | 职责                                         |
| ---------- | -------------------- | -------------------------------------------- |
| 应用层     | ISO 14229            | 定义诊断服务语义（读数据、写数据、刷写等）   |
| 传输层     | ISO 15765-2 (ISO-TP) | 将超过 8 字节的 UDS 报文分段传输，或单帧封装 |
| 数据链路层 | CAN 2.0B             | 帧封装、仲裁、CRC 校验、错误处理             |
| 物理层     | ISO 11898-2          | 电气信号、波特率、终端电阻                   |

## 3. CAN ID 寻址方式

### 3.1 标准帧 vs 扩展帧

| 特性        | 标准帧 (11-bit)         | 扩展帧 (29-bit)                   |
| ----------- | ----------------------- | --------------------------------- |
| CAN ID 长度 | 11 bit（0x000 ~ 0x7FF） | 29 bit（0x00000000 ~ 0x1FFFFFFF） |
| 适用场景    | 普通 CAN 通信           | J1939、UDS 诊断                   |
| UDS 使用    | 不推荐                  | **必须使用**（ISO 15765-2） |

### 3.2 29-bit 扩展帧寻址（J1939 PDU1 风格）

CAN-UDS 使用 J1939 PDU1 寻址格式，CAN ID 布局如下：

```
CAN ID = 0x18DA{TA}{SA}
         ──┬── ─┬─ ─┬─ ─┬─
           │    │   │   └── 源地址 (N_SA)：发送方地址
           │    │   └────── 目标地址 (N_TA)：接收方地址
           │    └────────── PF (PDU Format) = 0xDA
           └─────────────── 优先级 (Priority) = 6
```

- **优先级**: 固定为 6（对应 0x18 前缀的高 3 位）
- **PF**: 0xDA（PDU1 格式，表示点对点诊断）
- **PS 字段**: 作为 N_TA（目标地址）
- **SA 字段**: 作为 N_SA（源地址）

### 3.3 物理寻址 vs 功能寻址

| 寻址方式 | PF   | CAN ID 格式        | 用途                         |
| -------- | ---- | ------------------ | ---------------------------- |
| 物理寻址 | 0xDA | `0x18DA{TA}{SA}` | 点对点诊断（请求特定 ECU）   |
| 功能寻址 | 0xDB | `0x18DB33xx`     | 广播诊断（同时请求多个 ECU） |

功能寻址时，PS 字段为功能组地址（0x33），SA 无限制，接收端通过 PS=0x33 识别功能寻址。

### 3.4 实际 CAN ID 示例

假设 CCU 地址为 `0x03`，Qi 充电器地址为 `0x0D`（与 SRS / 文档 3 一致）：

| 方向                | CAN ID         | 计算过程                           |
| ------------------- | -------------- | ---------------------------------- |
| CCU → Qi（请求）   | `0x18DA0D03` | 0x18DA + TA=`0x0D` + SA=`0x03` |
| Qi → CCU（响应）   | `0x18DA030D` | 0x18DA + TA=`0x03` + SA=`0x0D` |
| CCU → 全部（功能） | `0x18DB33xx` | 0x18DB + PS=`0x33` + SA 任意     |

## 4. ISO-TP 传输层详解

ISO-TP（ISO 15765-2）负责将 UDS 报文封装到 CAN 帧中。单个 CAN 帧最大载荷为 8 字节，但 UDS 报文可能远超此限制（如固件传输），因此需要分段传输。

### 4.1 四种帧类型

ISO-TP 定义了四种帧类型，通过 PCI（Protocol Control Information）的高 4 位区分：

| 帧类型                     | PCI 缩写 | N_PCI 高 4 位 | 用途                     |
| -------------------------- | -------- | ------------- | ------------------------ |
| 单帧 (Single Frame)        | SF       | 0x0           | 载荷 ≤ 7 字节，单帧传输 |
| 首帧 (First Frame)         | FF       | 0x1           | 多帧传输的第一帧         |
| 连续帧 (Consecutive Frame) | CF       | 0x2           | 多帧传输的后续帧         |
| 流控制帧 (Flow Control)    | FC       | 0x3           | 接收方控制发送方节奏     |

### 4.2 单帧 (SF) 结构

```
CAN 数据: [PCI | SF_DL | SF_Data ...]
          Byte0  Byte1  Byte2 ~ Byte7
```

- **PCI** (4 bit): 高 4 位 = 0x0，低 4 位 = SF_DL（单帧数据长度）
- **SF_DL**: 单帧数据长度（0 ~ 7 字节）
- **SF_Data**: UDS 报文

示例 — 读取软件版本 `[0x22, 0xF1, 0x89]`（3 字节）：

```
CAN 数据: 03 22 F1 89 00 00 00 00
          ─┬─ ───────┬───────
           │         └── UDS 报文: SID=0x22, DID=0xF195
           └── SF_PCI: SF=0, DL=3
```

### 4.3 首帧 (FF) 结构

```
CAN 数据: [FF_PCI | FF_DL | FF_Data ...]
          Byte0    Byte1-2  Byte3 ~ Byte7
```

- **FF_PCI** (4 bit): 高 4 位 = 0x1，低 4 位 = FF_DL 的高 4 位
- **FF_DL** (12 bit): 多帧数据总长度（8 ~ 4095 字节）
- **FF_Data**: 前 5 字节的 UDS 数据

示例 — 传输 300 字节固件（FF_DL = 0x012C）：

```
CAN 数据: 11 2C [前5字节数据]
          ─┬─ ─┬─
           │   └── FF_DL = 0x12C（300）
           └── FF_PCI: FF=1, DL高4位=0x1
```

### 4.4 连续帧 (CF) 结构

```
CAN 数据: [CF_PCI | CF_Data ...]
          Byte0    Byte1 ~ Byte7
```

- **CF_PCI** (4 bit): 高 4 位 = 0x2，低 4 位 = SN（序号，0 ~ 15 循环）
- **CF_Data**: 后续 UDS 数据（最多 7 字节）

序号 SN 从 1 开始，递增到 15 后回绕到 0。

### 4.5 流控制帧 (FC) 结构

```
CAN 数据: [FC_PCI | FS | BS | STmin]
          Byte0   Byte1 Byte2 Byte3
```

- **FC_PCI** (4 bit): 高 4 位 = 0x3
- **FS** (Flow Status): 流控制状态
  - 0x00 = Continue To Send (CTS)：允许继续发送
  - 0x01 = Wait：要求等待
  - 0x02 = Overflow：溢出，拒绝接收
- **BS** (Block Size): 每次发送的最大连续帧数量（0x00 = 无限制）
- **STmin**: 连续帧之间的最小间隔（0x00 ~ 0x7F ms，0xF1 ~ 0xF9 = 100 ~ 900 μs）

### 4.6 ISO-TP 完整传输示例

假设发送 20 字节 UDS 数据 `[0x2E, 0xF1, 0x89, ... 17字节数据...]`：

```
发送方（CCU）                          接收方（外设）
    │                                      │
    │  ──── 首帧 (FF) ────>                │
    │  [10 14 2E F1 89 ...] (前5字节)       │
    │                                      │
    │  <──── 流控制 (FC) ──                │
    │  [30 00 01 00] (CTS, BS=0, STmin=1ms)│
    │                                      │
    │  ──── 连续帧1 (CF) ─>                │
    │  [21 ... 7字节]  (SN=1)              │
    │                                      │
    │  ──── 连续帧2 (CF) ─>                │
    │  [22 ... 7字节]  (SN=2)              │
    │                                      │
    │  ──── 连续帧3 (CF) ─>                │
    │  [23 ... 1字节]  (SN=3)              │
    │                                      │
```

### 4.7 ISO-TP 定时参数

| 参数 | 含义                    | 默认值  |
| ---- | ----------------------- | ------- |
| N_As | 发送方发送 CAN 帧的超时 | 1000 ms |
| N_Ar | 接收方发送 FC 帧的超时  | 1000 ms |
| N_Bs | 发送方等待 FC 帧的超时  | 1000 ms |
| N_Cr | 接收方等待 CF 帧的超时  | 1000 ms |

## 5. UDS 报文结构

### 5.1 请求报文

```
[SID] [SubFunction] [Data...]
```

- **SID** (1 byte): 服务标识符 (Service ID)
- **SubFunction** (1 byte, 可选): 子功能参数（第 7 位为抑制肯定响应位）
- **Data** (0 ~ N bytes): 服务相关数据

示例 — 读取软件版本：

```
请求: 22 F1 95
      ─┬─ ──┬─
       │    └── DID = 0xF195
       └── SID = 0x22 (ReadDataByIdentifier)
```

### 5.2 肯定响应

```
[SID + 0x40] [SubFunction] [Data...]
```

- 肯定响应的 SID = 请求 SID + 0x40
- 后续数据为响应内容

示例 — 读取版本的肯定响应：

```
响应: 62 F1 89 31 2E 30 2E 30
      ─┬─ ──┬─ ───────────┬────────
       │    │             └── 版本字符串 "1.0.0"
       │    └── DID = 0xF195
       └── 0x22 + 0x40 = 0x62
```

### 5.3 否定响应

```
7F [SID] [NRC]
```

- 固定前缀 0x7F
- 原始 SID
- NRC: 否定响应码 (Negative Response Code)

示例 — 安全访问被拒绝：

```
响应: 7F 27 33
      ─┬─ ─┬─ ─┬─
       │   │   └── NRC = 0x33 (SecurityAccessDenied)
       │   └── SID = 0x27
       └── 否定响应前缀
```

## 6. 常用 UDS 服务说明

### 6.1 0x10 — DiagnosticSessionControl（诊断会话控制）

切换 ECU 的诊断会话模式。

| 项目     | 内容                                               |
| -------- | -------------------------------------------------- |
| 请求格式 | `10 [SubFunction]`                               |
| 子功能   | 0x01=Default, 0x02=Programming, 0x03=Extended      |
| 肯定响应 | `50 [SubFunction] [P2_Hi P2_Lo] [P2*_Hi P2*_Lo]` |
| 安全要求 | 无                                                 |

示例：

```
请求: 10 02                  → 进入编程会话
响应: 50 02 00 32 01 F4      → 确认, P2=50ms, P2*=5000ms
```

### 6.2 0x11 — ECUReset（ECU 复位）

| 项目     | 内容                                                    |
| -------- | ------------------------------------------------------- |
| 请求格式 | `11 [SubFunction]`                                    |
| 子功能   | 0x01=Hard Reset, 0x02=Key Off On Reset, 0x03=Soft Reset |
| 肯定响应 | `51 [SubFunction]`                                    |
| 安全要求 | 无                                                      |

示例：

```
请求: 11 01      → 硬复位
响应: 51 01      → 确认
```

### 6.3 0x22 — ReadDataByIdentifier（按标识符读数据）

| 项目     | 内容                               |
| -------- | ---------------------------------- |
| 请求格式 | `22 [DID_Hi] [DID_Lo]`           |
| 肯定响应 | `62 [DID_Hi] [DID_Lo] [Data...]` |
| 安全要求 | 无（大部分 DID）                   |

示例 — 同时读取软件版本和硬件版本：

```
请求: 22 F1 95 F1 93
响应: 62 F1 95 31 2E 30 2E 30 F1 93 32 2E 30
           ──┬── ───────┬────── ──┬── ─────┬───
              │          │         │        └── HW "2.0"
              │          │         └── DID 0xF193
              │          └── SW "1.0.0"
              └── DID 0xF195
```

### 6.4 0x27 — SecurityAccess（安全访问）

详见 [第 9 章 安全访问机制](#9-安全访问机制)。

| 项目             | 内容                               |
| ---------------- | ---------------------------------- |
| 请求格式（种子） | `27 [Level_odd]`                 |
| 请求格式（密钥） | `27 [Level_even] [Signature...]` |
| 肯定响应（种子） | `67 [Level_odd] [Seed...]`       |
| 肯定响应（密钥） | `67 [Level_even]`                |
| 安全要求         | 无（用于解锁）                     |

### 6.5 0x2E — WriteDataByIdentifier（按标识符写数据）

| 项目     | 内容                               |
| -------- | ---------------------------------- |
| 请求格式 | `2E [DID_Hi] [DID_Lo] [Data...]` |
| 肯定响应 | `6E [DID_Hi] [DID_Lo]`           |
| 安全要求 | 受保护 DID 需 SecurityAccess       |

示例 — 写入固件类型：

```
请求: 2E 20 10 01      → 写 DID 0x2010 = 0x01 (APP 固件)
响应: 6E 20 10         → 确认
```

### 6.6 0x31 — RoutineControl（例程控制）

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 请求格式 | `31 [SubFunction] [RoutineID_Hi] [RoutineID_Lo] [Data...]` |
| 子功能   | 0x01=Start, 0x02=Stop, 0x03=RequestResults                   |
| 肯定响应 | `71 [SubFunction] [RoutineID_Hi] [RoutineID_Lo] [Data...]` |
| 安全要求 | 受保护例程需 SecurityAccess                                  |

示例 — 擦除 Flash：

```
请求: 31 01 FF 00 [地址 4字节] [大小 4字节]
响应: 71 01 FF 00         → 擦除完成
```

### 6.7 0x34 — RequestDownload（请求下载）

| 项目     | 内容                                                                 |
| -------- | -------------------------------------------------------------------- |
| 请求格式 | `34 [DataFormatID] [AddrAndLenFormatID] [MemAddr...] [MemSize...]` |
| 肯定响应 | `74 [LengthFormatID] [MaxNumberOfBlockLength...]`                  |
| 安全要求 | SecurityAccess Level 1                                               |

示例：

```
请求: 34 00 44 08 00 00 00 00 00 10 00
           ─┬─ ─┬─ ───────────── ────────
            │   │   起始地址 0x08000000    大小 0x1000 (4KB)
            │   └── 地址4字节+长度4字节
            └── 无压缩/无加密
响应: 74 20 00 FF
           ─┬─ ─────┬─
            │       └── 最大块长度 255 字节
            └── 长度格式: 2字节, 0字节地址
```

### 6.8 0x36 — TransferData（传输数据）

| 项目     | 内容                                    |
| -------- | --------------------------------------- |
| 请求格式 | `36 [BlockSequenceCounter] [Data...]` |
| 肯定响应 | `76 [BlockSequenceCounter]`           |
| 安全要求 | SecurityAccess Level 1（隐式）          |

- BlockSequenceCounter 从 0x01 开始，每帧递增
- 到 0xFF 后回绕至 0x01
- 0x00 不作为正常序号使用

示例：

```
请求: 36 01 [255字节数据]    → 第 1 块
响应: 76 01                  → 确认
请求: 36 02 [255字节数据]    → 第 2 块
响应: 76 02                  → 确认
```

### 6.9 0x37 — RequestTransferExit（退出传输）

| 项目     | 内容                             |
| -------- | -------------------------------- |
| 请求格式 | `37 [Data...]`（可选校验数据） |
| 肯定响应 | `77 [Data...]`                 |
| 安全要求 | SecurityAccess Level 1（隐式）   |

示例：

```
请求: 37                     → 结束传输
响应: 77                     → 确认，ECU 开始验证
```

### 6.10 0x3E — TesterPresent（测试仪在线）

保持非默认会话活跃，防止超时回退到默认会话。

| 项目     | 内容                             |
| -------- | -------------------------------- |
| 请求格式 | `3E [SubFunction]`             |
| 子功能   | 0x00=正常响应, 0x80=抑制肯定响应 |
| 肯定响应 | `7E [SubFunction]`             |
| 安全要求 | 无                               |

示例：

```
请求: 3E 80      → 抑制肯定响应模式
响应: (无响应)
```

## 7. 否定响应码（NRC）详解

当 ECU 无法执行请求的服务时，返回否定响应 `7F [SID] [NRC]`。

| NRC  | 名称                                      | 含义                   | 典型场景                      |
| ---- | ----------------------------------------- | ---------------------- | ----------------------------- |
| 0x10 | GeneralReject                             | 通用拒绝               | 无法归类的错误                |
| 0x11 | ServiceNotSupported                       | 服务不支持             | ECU 未实现该 SID              |
| 0x12 | SubFunctionNotSupported                   | 子功能不支持           | ECU 未实现该子功能            |
| 0x13 | IncorrectMessageLengthOrInvalidFormat     | 消息长度错误或格式无效 | 请求长度不符合规范            |
| 0x14 | ResponseTooLong                           | 响应过长               | 响应超出 ISO-TP 限制          |
| 0x22 | ConditionsNotCorrect                      | 条件不满足             | 当前会话/状态不允许操作       |
| 0x24 | RequestSequenceError                      | 请求序列错误           | 未按正确顺序执行操作          |
| 0x25 | NoResponseFromSubnetComponent             | 子网组件无响应         | 网关转发失败                  |
| 0x26 | FailurePreventsExecutionOfRequestedAction | 故障阻止执行           | ECU 内部故障                  |
| 0x31 | RequestOutOfRange                         | 请求超出范围           | 不支持的 DID/例程/参数        |
| 0x33 | SecurityAccessDenied                      | 安全访问被拒绝         | 未解锁安全级别                |
| 0x35 | InvalidKey                                | 密钥无效               | 签名验证失败                  |
| 0x36 | ExceededNumberOfAttempts                  | 超过尝试次数           | 连续安全访问失败（通常 3 次） |
| 0x37 | RequiredTimeDelayNotExpired               | 延迟未到期             | 安全锁定冷却期                |
| 0x70 | UploadDownloadNotAccepted                 | 上传/下载不被接受      | 下载前置条件失败              |
| 0x71 | TransferDataSuspended                     | 传输挂起               | 传输中断                      |
| 0x72 | GeneralProgrammingFailure                 | 通用编程失败           | Flash 擦写/CRC/签名失败       |
| 0x73 | WrongBlockSequenceCounter                 | 块序号错误             | TransferData 序号不连续       |
| 0x78 | RequestCorrectlyReceivedResponsePending   | 请求已接收，响应待发   | 长操作（擦除/签名验证）需等待 |
| 0x7E | SubFunctionNotSupportedInActiveSession    | 当前会话不支持该子功能 | 子功能与会话不匹配            |
| 0x7F | ServiceNotSupportedInActiveSession        | 当前会话不支持该服务   | 服务与会话不匹配              |

**特殊说明 — NRC 0x78：**

NRC 0x78 是一个"正面的否定响应"，表示 ECU 已正确接收请求，但需要更多时间处理。收到 NRC 0x78 后：

- ECU 应在 P2*（通常 5000 ms）内发送最终响应
- 客户端将超时从 P2 重置为 P2*
- 如果超时未响应，客户端应重试

## 8. 会话管理与超时机制

### 8.1 会话类型

| 会话                    | 子功能值 | 用途                 | 安全状态   |
| ----------------------- | -------- | -------------------- | ---------- |
| Default（默认会话）     | 0x01     | 正常运行、只读诊断   | 自动清除   |
| Programming（编程会话） | 0x02     | 固件更新、Flash 操作 | 需重新解锁 |
| Extended（扩展会话）    | 0x03     | 受保护配置、扩展诊断 | 需重新解锁 |

### 8.2 会话切换状态机

```
                    0x10 0x02
    ┌────────────┐ ──────────> ┌─────────────┐
    │   Default  │             │ Programming  │
    │   (0x01)   │ <────────── │   (0x02)     │
    └────────────┘   0x10 0x01 └─────────────┘
         ↑                         ↑
         │ 0x10 0x01               │ 0x10 0x02
         │ (或超时)                │
    ┌────────────┐                 │
    │  Extended  │ ────────────────┘
    │   (0x03)   │   0x10 0x02（清除安全状态）
    └────────────┘
```

### 8.3 会话超时

- 非默认会话需要定期收到 `TesterPresent (0x3E)` 保持活跃
- 超时时间：**5 秒**（5000 ms）
- 超时后：ECU 自动回退到默认会话，清除安全解锁状态

### 8.4 会话切换规则

| 场景                            | 行为                               |
| ------------------------------- | ---------------------------------- |
| 非默认 → 非默认                | 清除安全解锁状态，CCU 必须重新认证 |
| 非默认 → 默认（超时）          | 清除安全状态，中止固件传输         |
| 任何会话 → Default (0x10 0x01) | 清除安全状态，中止传输             |
| 进入 Programming                | 之前的安全解锁失效                 |

## 9. 安全访问机制

### 9.1 SecurityAccess 概述

SecurityAccess (0x27) 用于解锁受保护的诊断操作（如固件下载、DID 写入）。采用挑战-响应（Challenge-Response）机制验证客户端身份。

### 9.2 Level 分配

| Level          | 子功能 | 用途             |
| -------------- | ------ | ---------------- |
| Level 1 (种子) | 0x01   | 请求种子         |
| Level 1 (密钥) | 0x02   | 发送签名         |
| Level 3 (种子) | 0x03   | 可选更高安全级别 |
| Level N (种子) | N×2-1 | 依此类推         |
| Level N (密钥) | N×2   | 依此类推         |

### 9.3 ECDSA P-256 挑战-响应流程

```
CCU (客户端)                           外设 (服务器)
    │                                      │
    │  ──── 1. 请求种子 ────>               │
    │       [27 01]                         │
    │                                      │
    │  <─── 2. 返回种子 ────               │
    │       [67 01 seed(4B)]                │
    │                                      │
    │  3. CCU 用私钥对 seed 签名            │
    │     sig = ECDSA_Sign(privKey, seed)   │
    │                                      │
    │  ──── 4. 发送签名 ────>               │
    │       [27 02 sig(64B)]                │
    │                                      │
    │            5. 外设用公钥验证签名       │
    │               result = ECDSA_Verify(  │
    │                 pubKey, seed, sig)     │
    │                                      │
    │  <─── 6. 验证结果 ────               │
    │  成功: [67 02]                        │
    │  失败: [7F 27 35] (InvalidKey)        │
```

### 9.4 安全要求

| 要求       | 说明                              |
| ---------- | --------------------------------- |
| 种子唯一性 | 每次请求必须生成新的随机种子      |
| 种子源     | 硬件 RNG 或经批准的密码学 RNG     |
| 公钥存储   | Device Info 区（`0x0801D000 + 56`），支持后期更换；未配置则回退 Bootloader 内置公钥 |
| 失败计数   | 连续 3 次失败触发锁定             |
| 锁定延迟   | 固定 30 秒                        |
| 锁定解除   | 会话复位到 Default 可清除失败计数 |
| 签名算法   | ECDSA P-256（64 字节签名）        |

## 10. 固件下载流程

### 10.1 UDS OTA 完整步骤

```
CCU                                    外设 (ECU)
 │                                       │
 │  1. 进入编程会话                       │
 │  ── 10 02 ──────────────────────>     │
 │  <── 50 02 00 32 01 F4 ──────────     │
 │                                       │
 │  2. 解锁安全访问                       │
 │  ── 27 01 ──────────────────────>     │
 │  <── 67 01 [seed 4B] ────────────     │
 │  ── 27 02 [signature 64B] ──────>     │
 │  <── 67 02 ──────────────────────     │
 │                                       │
 │  3. 选择固件类型                       │
 │  ── 2E 20 10 01 ────────────────>     │
 │  <── 6E 20 10 ───────────────────     │
 │                                       │
 │  4. 擦除目标区域                       │
 │  ── 31 01 FF 00 [addr] [size] ──>     │
 │  <── 31 01 FF 00 ────────────────     │
 │      (或 NRC 0x78 等待后返回)          │
 │                                       │
 │  5. 请求下载                           │
 │  ── 34 00 44 [addr] [size] ─────>     │
 │  <── 74 [lenFmt] [maxBlockSize] ──     │
 │                                       │
 │  6. 传输固件数据（循环）               │
 │  ── 36 01 [data...] ────────────>     │
 │  <── 76 01 ──────────────────────     │
 │  ── 36 02 [data...] ────────────>     │
 │  <── 76 02 ──────────────────────     │
 │  ... (按 maxBlockSize 分块)            │
 │  ── 36 NN [data...] ────────────>     │
 │  <── 76 NN ──────────────────────     │
 │                                       │
 │  7. 结束传输                           │
 │  ── 37 ─────────────────────────>     │
 │  <── 77 ──────────────────────────     │
 │      (ECU 验证 CRC32 + ECDSA 签名)    │
 │      (可能 NRC 0x78 等待)              │
 │                                       │
 │  8. 复位激活新固件                     │
 │  ── 11 01 ──────────────────────>     │
 │  <── 51 01 ──────────────────────     │
 │      (ECU 重启，加载新固件)            │
 │                                       │
```

### 10.2 验证流程

外设在固件传输完成后执行以下验证：

1. **CRC32 校验**：验证数据完整性
2. **ECDSA P-256 签名验证**：验证固件来源可信
3. **长度检查**：验证实际传输长度与声明一致

### 10.3 块序号计数器规则

| 规则   | 说明                                               |
| ------ | -------------------------------------------------- |
| 初始值 | 首帧传输前为 0x00，递增后首帧使用 0x01             |
| 递增   | 每帧 +1                                            |
| 回绕   | 0xFF → 0x01（跳过 0x00）                          |
| 异常   | 序号不连续 → NRC 0x73 (WrongBlockSequenceCounter) |

### 10.4 异常处理

| 异常场景         | ECU 行为                   |
| ---------------- | -------------------------- |
| 序号错误         | 返回 NRC 0x73，中止传输    |
| CRC 校验失败     | 拒绝镜像，保留之前有效固件 |
| 签名验证失败     | 拒绝镜像，返回 NRC 0x72    |
| 传输中断（掉电） | 重启后加载之前有效固件     |
| Flash 擦除失败   | 返回 NRC 0x72              |

### 10.5 Device Info 保留区保护

OTA 固件下载流程中的 Flash 擦除操作（`0x31 01 FF00`）**不包含** Device Info 保留区 (`0x0801D000` ~ `0x0801DFFF`, 4KB)。

- Device Info 区域存放设备 SN 序列号等标识信息
- 该区域在产线烧录时写入，之后只读不写
- Bootloader 执行擦除时会校验目标地址，拒绝擦除 Device Info 区域
- OTA 升级完成后，SN 序列号仍然保留在 Device Info 保留区中
- SN 可通过 UDS `0x22 F18C` 读取

## 11. Qi 充电模块 DID 速查

本项目 Qi 充电模块（地址 `0x0D`）实现的专用 DID 汇总，详见 [3. 通用CAN协议规范.md](3.%20通用CAN协议规范.md) §8.5。

### 充电控制 DID

| DID    | 名称         | R/W | 说明 |
| ------ | ------------ | --- | ---- |
| 0x2100 | 充电器能力   | R   | 4 字节，byte0=15（15W） |
| 0x2101 | 充电器使能   | W   | 0x00=禁用, 0x01=使能，复位后默认 0x00 |
| 0x2102 | 充电状态     | R   | PB2 电平：高=CHARGING, 低+使能=STANDBY, 低+未使能=DISABLED |
| 0x2103 | 设备在位     | R   | 从 Qi 帧回调更新 |
| 0x2104 | 输出功率     | R   | uint16 mW，从 Qi 帧回调更新 |
| 0x2105 | 输入电压/电流 | R  | 保留，来源 CCU |
| 0x2108 | PCB 温度     | R   | 待定，暂返回 0 |
| 0x2109 | FOD 状态     | R   | 0x00=正常, 0x02=FOD 确认 |
| 0x210B | 故障码       | R   | 0x00=无, 0x04=过压, 0x05=欠压, 0x06=FOD, 0x07=过温, 0x0A=过流 |
| 0x210C | 热降额等级   | R   | 85 度保护，60 度恢复 |
| 0x210D | 功率限值     | W   | 三档 5W/10W/15W，NVM 持久化 |
| 0x2110 | 末次故障详情 | R   | 待定，暂返回全 0 |
| 0x2118 | 夹臂状态     | R   | PA0 低=0x00(有手机), 高=0x01(无手机) |

### Qi IAP DID

| DID    | 名称        | R/W | 说明 |
| ------ | ----------- | --- | ---- |
| 0x2130 | Qi IAP 控制 | W   | 0x01=启动（+大小 BE），0x00/0x02=中止；UART `0xCC 0x01` |
