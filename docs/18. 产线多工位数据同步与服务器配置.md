## 1. 场景约束与总体架构

| 事实 | 影响 |
|------|------|
| 工位机是 Windows + C# 上位机（`QiChargerStationTool.App`，单机测试已跑通） | 客户端用 `HttpClient` 上传即可，无新技术栈 |
| 服务器是另一台 Windows 工控机/PC | 不上 Linux/Docker，控制台进程 + 开机自启即可 |
| 产线 LAN（同一交换机/路由器），不联外网 | 只需局域网固定 IP，纯 HTTP，不折腾证书 |
| 断网、换班、误关机都可能发生 | **数据先落本地队列、后台补传**，绝不因网络丢测试记录 |
| 测试记录字段有限（SN、工位、PASS/FAIL、明细、时间…） | 单条 < 10 KB，日产量千级，SQLite 绰绰有余 |

**总体架构：**

```
┌──────────────┐  POST /api/v1/test-results  ┌───────────────────────┐
│ 工位机 ST-01  │ ──────────────────────────► │  服务器 QI-SERVER      │
│ App + COM7   │                            │  Server 项目 (:5000)  │
└──────────────┘                            │  → SQLite station.db  │
┌──────────────┐                            │                       │
│ 工位机 ST-02  │ ──────────────────────────► │                       │
└──────────────┘                            └───────────┬───────────┘
┌──────────────┐                                        │
│ 工位机 ST-03  │ ──────────────────────────►            ▼
└──────────────┘                            查询 / 导出 Excel / 后续 MES
```

- **传输**：HTTP + JSON（局域网直传，失败进队列重试）
- **存储**：服务器端 SQLite（单文件免运维；产线量级足够）
- **客户端容错**：上传失败 → 落本地队列文件 → 后台定时补传

**与现有工程的对应关系**（解决方案 `QiChargerStationTool/QiChargerStationTool.sln`，现有 Core / App / Tests 三项目）：

| 项目 | 角色 | 本文改动 |
|------|------|----------|
| `QiChargerStationTool.Server`（**新增**） | 服务器端 API | §4 建项目 + Minimal API + EF Core |
| `QiChargerStationTool.Core` | 业务/协议（`net8.0`） | §5 放 DTO `TestResult` + `ResultUploader` |
| `QiChargerStationTool.App` | 工位机 UI | `appsettings.json` 加 `Server`/`StationId` 配置（§5.1） |

## 2. 同步方案选型

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| A. 共享文件夹（SMB） | 各工位往 `\\server\产线数据\` 写 CSV | 零开发 | 并发写冲突、半截文件、无回执、权限麻烦 | ❌ 仅应急 |
| B. HTTP API + SQLite（推荐） | 工位机 POST JSON → 服务器 API 入库 | 有「已收到」回执、断网可补传、易扩展 MES、好查 | 需写一个极简服务（~100 行） | ✅ **采用** |
| C. 直连数据库 | 每台工位机 INSERT | 实时 | 断网即丢/写超时卡 UI、并发锁、每台机配连接串 | ❌ |
| D. 消息队列（MQTT 等） | 发布订阅 | 解耦强 | 产线场景过重，运维成本高 | ❌ |

**选 B 的关键理由**：客户端拿到服务器 200 回执才算成功，失败自动进本地队列补传——正好同时解决「连接」与「断网丢数据」两个问题。

## 3. 服务器机器配置

> 只做一次。假设服务器局域网 IP 定为 `192.168.10.10`（按现场实际改）。

### 3.1 网络

1. **静态 IP**（网卡手配或路由器绑定）：IP `192.168.10.10`，掩码 `255.255.255.0`；工位机示例 `.11`/`.12`/`.13`…（同一网段）。
2. **固定主机名**（可选但推荐）：改成 `QI-SERVER`，工位机也可用 `http://QI-SERVER:5000` 访问。
3. 网络配置文件类别设为「**专用网络**」（公用网络下 Windows 防火墙默认更严）。
4. 工位机 `StationId` 规划：ST-01 / ST-02 / ST-03…，贴在工位机机箱上。

### 3.2 防火墙放行端口（管理员 PowerShell，服务器执行一次）

```powershell
New-NetFirewallRule -DisplayName "QiStationServer 5000" `
  -Direction Inbound -Protocol TCP -LocalPort 5000 -Action Allow
```

### 3.3 电源与系统

| 项 | 设置 |
|----|------|
| 电源计划 | 「高性能」；关闭睡眠/休眠（服务不能被休眠打断） |
| 自动登录 | 允许（重启后能自动拉起服务，配合 §4.5） |
| 时间同步 | 服务器与工位机都开「自动设置时间」；对账以**服务器入库时间**为准 |
| 磁盘 | 数据目录 `D:\QiStationData\`（别放 C 盘桌面）；每周备份 `station.db` |

### 3.4 数据目录

```
D:\QiStationData\
├── station.db          # SQLite 主库（服务自动创建）
├── station.db-wal      # WAL 日志（自动）
└── backup\             # 定期复制的备份
```

## 4. 服务器端搭建（新增 Server 项目）

### 4.1 VS2022 建项目

1. 打开解决方案 `QiChargerStationTool\QiChargerStationTool.sln`。
2. 右键解决方案 → 添加 → 新建项目 → 搜索 **「ASP.NET Core Web API」**（C#、.NET 8，**不是**「.NET Framework」版）。
3. 项目名 `QiChargerStationTool.Server`，位置 `...\QiChargerStationTool\src`。
4. 创建向导：框架 .NET 8.0，认证类型「无」，**勾掉「启用 Docker」「使用 HTTPS」**（局域网纯 HTTP，工位机不用装证书）。
5. NuGet：`Microsoft.EntityFrameworkCore.Sqlite`。
6. 项目引用：Server → Core（共用 §5.2 的 `TestResult` DTO）。

### 4.2 数据模型（放 `QiChargerStationTool.Core`，Server/App 共用）

```csharp
// Core/Reporting/TestResult.cs
public class TestResult
{
    public int Id { get; set; }                 // 服务器自增主键
    public string Sn { get; set; } = "";        // 产品 SN
    public string StationId { get; set; } = ""; // 工位号 ST-01/ST-02…
    public string Result { get; set; } = "";    // PASS / FAIL
    public string FirmwareVersion { get; set; } = ""; // DID 0xF195 版本
    public string ItemsJson { get; set; } = ""; // 测试项明细（JSON 数组）
    public string? FailReason { get; set; }
    public string? Operator { get; set; }       // 操作员（可空）
    public DateTime ClientTime { get; set; }    // 工位机测试时刻（参考）
    public DateTime ServerTime { get; set; }    // 服务器收到时刻（以此为准）
    public string? ClientRecordId { get; set; } // 客户端唯一 id，幂等去重
}
```

> DTO 放 `Core`、Server/App 都引用，字段永不漂移；Server 端不要再定义一份。

### 4.3 `Program.cs`（Minimal API，替换模板生成的 WeatherForecast 样板）

```csharp
// QiChargerStationTool.Server/Program.cs
using Microsoft.EntityFrameworkCore;
using QiChargerStationTool.Core.Reporting;

var builder = WebApplication.CreateBuilder(args);

// 监听局域网所有网卡（默认只听 localhost，工位机连不上——最常见的坑）
builder.WebHost.UseUrls("http://0.0.0.0:5000");

var dbPath = Path.Combine(@"D:\QiStationData", "station.db");
Directory.CreateDirectory(Path.GetDirectoryName(dbPath)!);
builder.Services.AddDbContext<StationDb>(o => o.UseSqlite($"Data Source={dbPath}"));

var app = builder.Build();
using (var scope = app.Services.CreateScope())
    scope.ServiceProvider.GetRequiredService<StationDb>().Database.EnsureCreated();

app.MapPost("/api/v1/test-results", async (TestResult r, StationDb db) =>
{
    r.ServerTime = DateTime.Now;
    // 幂等：同一 ClientRecordId 补传只留一条
    if (r.ClientRecordId != null &&
        await db.Results.AnyAsync(x => x.ClientRecordId == r.ClientRecordId))
        return Results.Ok(new { ok = true, duplicate = true });

    db.Results.Add(r);
    await db.SaveChangesAsync();
    return Results.Ok(new { ok = true, id = r.Id });
});

// 健康检查（连通性自检用）
app.MapGet("/api/v1/ping", () => Results.Ok(new { ok = true, time = DateTime.Now }));

// 查询最近 100 条（管理机浏览器直接看）
app.MapGet("/api/v1/test-results",
    (StationDb db) => db.Results.OrderByDescending(x => x.Id).Take(100));

app.Run();

public class StationDb : DbContext
{
    public StationDb(DbContextOptions<StationDb> o) : base(o) { }
    public DbSet<TestResult> Results => Set<TestResult>();
}
```

### 4.4 运行与验证（服务器本机）

```powershell
dotnet run --project src/QiChargerStationTool.Server/QiChargerStationTool.Server
```

浏览器开 `http://localhost:5000/api/v1/ping` 看到 `{"ok":true,...}` 即服务正常。

> 注：本解决方案的项目实际嵌套一层目录（如 `src/QiChargerStationTool.Server/QiChargerStationTool.Server/`），与现有 App/Core 一致，命令行路径按实际为准。

### 4.5 发布与开机自启

```powershell

  -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true `

```

## 5. 工位机连接配置（客户端上传）

### 5.1 每台工位机的配置（只改两处）

在 `App/appsettings.json`（及 `config/station.appsettings.json` 模板）现有字段基础上**新增** `Server` 段：

```json
{
  "ComPort": "",
  "Baud": 2000000,
  "ExtraComMatch": [],
  "FirmwarePath": "firmware/app_image_v1_1_57.bin",
  "SnCode": "",
  "DoReadVersion": true,
  "DoWriteSn": false,
  "DoOtaUpgrade": true,
  "DoChargeTest": false,
  "TransferBlock": 128,

  "Server": {
    "Url": "http://192.168.10.10:5000",
    "TimeoutSeconds": 5
  },
  "StationId": "ST-01"
}
```

- `Server.Url`：服务器实际 IP（或 `http://QI-SERVER:5000`）
- `StationId`：每台工位机唯一（ST-01/ST-02/…），贴机箱
- 其余字段维持现状，不动

### 5.2 上传客户端 `ResultUploader`（放 `QiChargerStationTool.Core/Reporting`）

设计要点：**上传失败不阻塞测试流程** → 落本地队列 → 后台补传。

```csharp
public class ResultUploader : IDisposable
{
    private readonly HttpClient _http;
    private readonly string _serverUrl;   // http://192.168.10.10:5000
    private readonly string _stationId;
    private readonly string _queuePath;   // 本地补传队列（JSONL，一行一条）

    public ResultUploader(string serverUrl, string stationId, string queuePath)
    {
        _http = new HttpClient { Timeout = TimeSpan.FromSeconds(5) };
        // …
    }

    // 测试完成时调用；永远不抛异常打断测试流程
    public async Task UploadAsync(TestResult result, CancellationToken ct = default)
    {
        result.StationId = _stationId;
        result.ClientRecordId ??= Guid.NewGuid().ToString("N");
        try { await PostAsync(result, ct); }   // 1) 先直传
        catch { AppendToQueue(result); }       // 2) 失败进本地队列
    }

    private async Task PostAsync(TestResult r, CancellationToken ct)
    {
        var resp = await _http.PostAsync(
            $"{_serverUrl}/api/v1/test-results",
            new StringContent(JsonSerializer.Serialize(r), Encoding.UTF8, "application/json"),
            ct);
        resp.EnsureSuccessStatusCode();        // 服务器回 200 才算成功
    }

    private void AppendToQueue(TestResult r) { /* 追加一行 JSON 到 _queuePath */ }

    // 后台补传：每 30s 把队列按序重发；成功即删行
    // ClientRecordId 幂等，重复发服务器也只留一条
    public async Task RetryQueueLoopAsync(CancellationToken ct) { /* … */ }
}
```

App 启动时创建 uploader 并拉起 `RetryQueueLoopAsync`；队列文件建议放程序目录 `upload_queue.jsonl`（或 `D:\QiStationData\queue\`）。

## 6. 连通性自检与联调流程

### 6.1 网络通（每台工位机 PowerShell）

| # | 命令 | 通过标准 |
|---|------|----------|
| 1 | `ping 192.168.10.10` | 有回包，延迟 < 10 ms |
| 2 | `Test-NetConnection 192.168.10.10 -Port 5000` | `TcpTestSucceeded : True` |
| 3 | `curl.exe http://192.168.10.10:5000/api/v1/ping` | 返回 `{"ok":true,...}` |
| 4 | POST 冒烟（下行命令） | 返回 `{"ok":true,"id":...}` |

POST 冒烟（PowerShell 整段粘贴）：

```powershell
$body = '{"sn":"TEST-001","stationId":"ST-01","result":"PASS",
          "firmwareVersion":"1.2.1","itemsJson":"[]","clientTime":"2026-10-18T12:00:00"}'
Invoke-RestMethod -Uri http://192.168.10.10:5000/api/v1/test-results `
  -Method Post -ContentType "application/json" -Body $body
```

服务器 `GET /api/v1/test-results` 能查到该记录 = 链路闭环。

### 6.2 联调验收（一次性）

1. 服务器起服务（§4.5）→ 本机 `ping` 自检通过；
2. 每台工位机按 6.1 四步全绿；
3. 一台工位机跑一次完整测试（真 SN），服务器能查到记录且 `StationId` 正确；
4. **断网演练**：拔网线跑 3 条测试 → 记录进本地队列文件；插回网线 → ≤30 s 内服务器查到 3 条且无重复；
5. 换一台工位机重复 3，确认 `StationId` 各不相同。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| 端口不通 | 防火墙未放行 / 服务没起 | §3.2 规则 + 确认进程在跑 |
| `curl` 通但上位机超时 | `Server.Url` 写成 `https://` 或 IP 错 | 核对 `appsettings.json`，纯 HTTP |
| 时好时坏 | 网线/交换机、IP 冲突 | `arp -a` 查冲突；服务器静态绑定 |
| 工位机显示已传但服务器查不到 | 传到别的机器/旧端口 | 用 `ClientRecordId` 对账 |
| 补传出现重复记录 | 没带 `ClientRecordId` | 用 §5.2 代码，幂等键必带 |
| 时间对不上 | 各机时钟漂移 | 以 `ServerTime` 为准；开自动对时 |
| 5000 被占 | 别的程序占端口 | `netstat -ano \| findstr :5000`，换端口后同步改两处配置 |
| Server 引用不到 `TestResult` | 各自定义了 DTO | 统一放 `Core/Reporting`，两边引用 |

## 8. 关键参数速查

| 项 | 值 |
|----|-----|
| 服务端口 | TCP `5000` |
| 服务器地址示例 | `http://192.168.10.10:5000` |
| 提交测试结果 | `POST /api/v1/test-results`（JSON） |
| 健康检查 | `GET /api/v1/ping` |
| 查询最近记录 | `GET /api/v1/test-results` |
| 幂等键 | `clientRecordId`（客户端生成，重复上传去重） |
| 客户端超时 | 5 s |
| 补传周期 | 30 s |
| 数据库 | SQLite `D:\QiStationData\station.db` |
| 时间基准 | `ServerTime`（服务器入库时刻） |
