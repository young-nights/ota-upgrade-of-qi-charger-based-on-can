# 22. QI-SERVER 服务器搭建手册（从零到跑通）

> **读者**：现场实施 / 产线 IT 人员。本手册是「照着一步步做」的操作教学，每一步给出可直接复制粘贴的命令，做到最后一步即可跑通 QI-SERVER。
> **QI-SERVER 是什么**：产线局域网里的一台 Windows 电脑，跑一个 HTTP 服务（`:5000`）+ SQLite，承担两件事：① 汇总各工位机测试记录（[20. 产线多工位数据同步与服务器配置](./20.%20产线多工位数据同步与服务器配置.md)）；② 工位1 多机并发时联机分配 SN，保证不撞号（[21. 工位1多机并发SN联机分配方案](./21.%20工位1多机并发SN联机分配方案.md)）。
> **设计论证**（为什么这么选型）见 doc 20 / doc 21，本文不重复；只讲怎么做。产品整体背景见 [15. 功能需求文档](./15.%20功能需求文档.md)。

## 1. 硬件与前置准备

### 1.1 服务器选型

**不需要服务器级硬件**。一台普通 Windows 10/11 Pro 工控机或 PC 即可，参考配置：

| 项 | 要求 | 说明 |
|----|------|------|
| 操作系统 | Windows 10/11 **Pro**（或工控机同级） | 需要改主机名、配静态 IP、计划任务；家庭版功能受限不推荐 |
| CPU | Intel i3 级或以上 | 服务为极简 HTTP API + SQLite，负载 ≈ 0.1 QPS |
| 内存 | 8 GB | 绰绰有余 |
| 硬盘 | 128 GB SSD | 数据库是单文件 SQLite，日产量千级记录远用不满 |
| 网口 | 千兆以太网口 ×1 | 接交换机 SW1 |
| 显示/键鼠 | 装机调试用，装完可不接 | 用远程桌面维护亦可 |

### 1.2 物料清单

| # | 物料 | 数量 | 用途 |
|---|------|------|------|
| 1 | 服务器（上述 PC/工控机） | 1 台 | 跑 QI-SERVER |
| 2 | 千兆二层交换机（16 或 24 口，非网管即可） | 1 台 | 产线 LAN 星型汇聚（doc 21 §2 中的 SW1）；**仅 2 台机直连场景可省**（见附录 A） |
| 3 | 网线（Cat5e 及以上） | 每台电脑 1 根 + 备用 | 服务器、各工位机接入 SW1 |
| 4 | U 盘（≥8 GB） | 1 个 | 从开发机搬运发布产物到服务器（现场无源码时用） |

### 1.3 前提条件（开始前逐条确认）

| # | 前提 | 确认 |
|---|------|------|
| 1 | 产线 LAN（交换机 SW1 + 各电脑）**不联外网**，纯局域网 | ☐ |
| 2 | 全网段规划为 `192.168.10.0/24`：服务器固定 `192.168.10.10`，工位机 `.11`/`.12`/`.13`… | ☐ |
| 3 | 服务器已装好 Windows、能进桌面、有管理员账户（可设自动登录） | ☐ |
| 4 | 本手册命令默认在 **管理员 PowerShell** 中执行（右键开始菜单 →「终端(管理员)」/「Windows PowerShell(管理员)」），不再逐一提示 | ☐ |
| 5 | 若走 §5 路径 A：开发机上已有源码仓库与 .NET 8 SDK，能 `dotnet publish` | ☐ |

> 网络拓扑、机位命名与 IP 明细见 [21. 工位1多机并发SN联机分配方案](./21.%20工位1多机并发SN联机分配方案.md) §2（交换机 SW1、QI-SERVER=`192.168.10.10`、每机位 1 个 ZQWL-CANFD 盒子走 USB/CAN，不经交换机）。

## 2. 操作系统设置

> 每项只做一次。**电源与时间**尤其重要：服务不能被休眠打断；SN 取号按**服务器时钟**生成日期段，时间错了会产错日期的 SN。

### 2.1 电源计划设为「高性能」

**图形界面**：`控制面板` → `硬件和声音` → `电源选项` → 选中「**高性能**」（若没有，点左侧「创建电源计划」→ 基于「高性能」创建）。

**命令方式**（可选，管理员 PowerShell；如提示找不到该方案，先执行第二行复制出该方案再激活）：

```powershell
powercfg /setactive 8c5e7fda-e8bf-4a96-9a85-a6e23a8c635c
powercfg -duplicatescheme 8c5e7fda-e8bf-4a96-9a85-a6e23a8c635c
```

### 2.2 关闭睡眠 / 休眠（管理员 PowerShell）

```powershell
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
powercfg /hibernate off
```

**图形界面**：`设置` → `系统` → `电源和睡眠`（Win11 为 `系统` → `电源`）→ 「睡眠」两项均选「**从不**」。

### 2.3 允许自动登录

目的：断电重启后自动进桌面，开机自启（§7）才能把服务拉起来。

1. `Win + R` → 输入 `netplwiz` → 回车。
2. 选中本机日常使用的账户 → **取消勾选**「要使用本计算机，用户必须输入用户名和密码」→ 点「应用」。
3. 在弹窗中输入该账户的密码并确认 → 「确定」。

> 重启一次验证：开机后不输密码直接进桌面。

### 2.4 时区与自动设置时间（重要：SN 按服务器时钟取号）

**图形界面**：`设置` → `时间和语言` → `日期和时间`：

1. 「时区」选 **(UTC+08:00) 北京，重庆，香港特别行政区**（按现场所在地选）；
2. 打开「**自动设置时间**」；
3. 打开「自动设置时区」（若有）。

**命令方式**（管理员 PowerShell，可作核对）：

```powershell
tzutil /s "China Standard Time"
w32tm /resync
w32tm /query /status
```

`w32tm /query /status` 输出的「源」与「上次成功同步时间」正常即 OK。**服务器与所有工位机都要开自动设置时间**；对账、追溯一律以服务器入库时间（`ServerTime`）为准。

### 2.5 网络配置文件设为「专用网络」

「公用网络」下 Windows 防火墙默认策略更严，容易出现 ping 通但端口不通。

**图形界面**：`设置` → `网络和 Internet` → `以太网` → 点击当前连接 → 「网络配置文件类型」选「**专用网络**」。

**命令方式**（管理员 PowerShell，先看网卡名再改）：

```powershell
Get-NetConnectionProfile
Set-NetConnectionProfile -InterfaceAlias "以太网" -NetworkCategory Private
```

> 网卡别名不是「以太网」时（如 `Ethernet`），把命令里的名字换成 `Get-NetConnectionProfile` 显示的实际 `InterfaceAlias`。

## 3. 网络配置

### 3.1 静态 IP：`192.168.10.10/24`

#### 方式一：控制面板（图形界面）

1. `控制面板` → `网络和 Internet` → `网络和共享中心` → 左侧「**更改适配器设置**」。
2. 右键「以太网」→「属性」→ 双击「**Internet 协议版本 4 (TCP/IPv4)**」。
3. 选「使用下面的 IP 地址」：

| 字段 | 值 |
|------|----|
| IP 地址 | `192.168.10.10` |
| 子网掩码 | `255.255.255.0` |
| 默认网关 | **留空**（产线 LAN 不联外网；若现场有统一网关按现场填） |
| 首选 DNS 服务器 | 留空 |

4. 确定 → 关闭。

#### 方式二：netsh（管理员 PowerShell / CMD）

```powershell
netsh interface ip set address name="以太网" source=static addr=192.168.10.10 mask=255.255.255.0
```

#### 方式三：PowerShell（管理员）

```powershell
Get-NetAdapter
New-NetIPAddress -InterfaceAlias "以太网" -IPAddress 192.168.10.10 -PrefixLength 24
```

验证（三条都应符合预期）：

```powershell
ipconfig | findstr IPv4
ping 192.168.10.10
ping 192.168.10.11
```

| 期望 | 说明 |
|------|------|
| `IPv4 地址 . . . : 192.168.10.10` | 服务器自身 |
| `ping 192.168.10.10` 有回包 | 本机协议栈正常 |
| `ping 192.168.10.11` 有回包 | 至少一台工位机已在线（没在线可后补此验证） |

### 3.2 主机名改为 `QI-SERVER`

改名后工位机可用 `http://QI-SERVER:5000` 访问，比记 IP 直观。

**命令方式**（管理员 PowerShell，执行后自动重启）：

```powershell
Rename-Computer -NewName "QI-SERVER" -Restart
```

**图形界面**：`设置` → `系统` → `系统信息` → 「重命名这台电脑」→ 填 `QI-SERVER` → 重启。

重启后核对：

```powershell
hostname
```

期望输出：`QI-SERVER`。

### 3.3 防火墙放行 TCP 5000（管理员 PowerShell，执行一次）

```powershell
New-NetFirewallRule -DisplayName "QiStationServer 5000" `
  -Direction Inbound -Protocol TCP -LocalPort 5000 -Action Allow
```

核对规则已存在：

```powershell
Get-NetFirewallRule -DisplayName "QiStationServer 5000" | Get-NetFirewallPortFilter
```

期望输出中 `LocalPort` 为 `5000`、`Protocol` 为 `TCP`。

## 4. 安装 .NET 8 SDK

### 4.1 下载与安装

1. 浏览器打开（可先在有外网的机器下载后用 U 盘拷来）：`https://dotnet.microsoft.com/download/dotnet/8.0`
2. 在「SDK」一栏点「**Download**」（**选 SDK，不是 Runtime**），下载 **Windows x64** 的安装包（文件名形如 `dotnet-sdk-8.0.xxx-win-x64.exe`）。
3. 双击安装 → 全默认下一步 → 完成。

### 4.2 验证安装

```powershell
dotnet --version
dotnet --list-sdks
```

| 期望 | 说明 |
|------|------|
| `dotnet --version` 输出 `8.0.x` | 主版本 8 即可，小版本不限 |
| `dotnet --list-sdks` 含一行 `8.0.x [C:\Program Files\dotnet\sdk]` | SDK 就绪 |

### 4.3 为什么必须装 SDK（而不是 Runtime）

| 包 | 能干什么 | 本手册用在哪 |
|----|----------|--------------|
| **.NET 8 SDK**（推荐装这个） | 编译、`dotnet publish` 发布、`dotnet run` 运行，**自带运行时** | §5 路径 B 现场编译；§6 运行；日常运维验证 |
| .NET Runtime / ASP.NET Core Runtime | 只能**运行**已发布程序，不能编译 | 若走 §5 路径 A 且服务器只跑 exe 不编译，装 ASP.NET Core Runtime 8.0 x64 也可 |
| 什么都不装 | — | 仅当发布时用了 `--self-contained true`（§5 路径 A），产物自带运行时 |

> 简单原则：**服务器上装 SDK**，一劳永逸；占几百 MB 磁盘，可忽略。

## 5. 部署服务端程序

两条路径二选一：

| 路径 | 适用场景 | 做法 |
|------|----------|------|
| **A（推荐）** | 现场**没有**源码 / 不想现场编译 | 开发机 `dotnet publish` 产出目录 → U 盘拷到服务器 `D:\QiStationServer\` |
| B | 现场**有**源码、需要改代码 | 在服务器上建项目 + 把下文完整 `Program.cs` 写进去 + `dotnet run` |

### 5.1 路径 A：开发机发布 → 拷贝到服务器（推荐）

**在开发机**（已装 .NET 8 SDK、有源码）执行——以 doc 20 规划的 Server 项目为例（项目目录按实际为准）：

```powershell
cd <仓库根目录>\QiChargerStationTool
dotnet publish src\QiChargerStationTool.Server\QiChargerStationTool.Server `
  -c Release -r win-x64 --self-contained false -o publish
```

| 参数 | 含义 |
|------|------|
| `-c Release` | 发布配置 Release |
| `-r win-x64` | 目标平台 Windows x64 |
| `--self-contained false` | **不**自带运行时（产物小；服务器需装 .NET 8 ASP.NET Core Runtime 或 SDK，见 §4） |
| `-o publish` | 输出到 `publish\` 目录 |

若目标服务器**不装任何 .NET**（连 Runtime 也不装），改用自带运行时（产物约 70~90 MB）：

```powershell
dotnet publish src\QiChargerStationTool.Server\QiChargerStationTool.Server `
  -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o publish
```

**拷贝到服务器**：

1. 把 `publish\` 目录下**全部内容**拷入 U 盘；
2. 在服务器上建目录并粘贴（最终形如 `D:\QiStationServer\QiChargerStationTool.Server.exe`）：

```powershell
New-Item -ItemType Directory -Path D:\QiStationServer -Force
# 然后把 U 盘里的 publish\* 全部复制到 D:\QiStationServer\
```

> exe 文件名与项目程序集名一致，形如 `QiChargerStationTool.Server.exe`；同目录的 `.dll`/`.json`/`.pdb` 等**都要一起拷**，缺文件会起不来。

### 5.2 路径 B：现场有源码，建项目并写入代码

#### 5.2.1 建项目（VS2022 或命令行二选一）

**VS2022**（与 doc 20 §4.1 相同）：

1. 打开解决方案 `QiChargerStationTool\QiChargerStationTool.sln`；
2. 右键解决方案 → 添加 → 新建项目 → 搜索「**ASP.NET Core Web API**」（C#、.NET 8，**不是**「.NET Framework」版）；
3. 项目名 `QiChargerStationTool.Server`，位置 `...\QiChargerStationTool\src`；
4. 创建向导：框架 **.NET 8.0**，认证类型「**无**」，**勾掉「启用 Docker」「使用 HTTPS**」（局域网纯 HTTP，工位机不装证书）；
5. NuGet：`Microsoft.EntityFrameworkCore.Sqlite`（工具 → NuGet 包管理器 → 程序包管理器控制台 → `Install-Package Microsoft.EntityFrameworkCore.Sqlite`）。

**命令行**（等价做法，在任意干净目录执行）：

```powershell
dotnet new webapi -n QiChargerStationTool.Server
cd QiChargerStationTool.Server
dotnet add package Microsoft.EntityFrameworkCore.Sqlite
```

> 若 `dotnet new webapi` 模板生成了 `WeatherForecast.cs` / `Controllers\WeatherForecastController.cs` 等样板文件，**全部删掉**——下文 `Program.cs` 会整体替换模板代码，不依赖样板。

#### 5.2.2 写入 `Program.cs`（完整可编译，整文件替换）

本文件已包含 [20. 产线多工位数据同步与服务器配置](./20.%20产线多工位数据同步与服务器配置.md) §4.2 数据模型 + §4.3 Minimal API，以及 [21. 工位1多机并发SN联机分配方案](./21.%20工位1多机并发SN联机分配方案.md) §5.1 三个 SN 接口 + §5.2 两张表，接口清单：

| 接口 | 方法 | 作用 |
|------|------|------|
| `/api/v1/ping` | GET | 健康检查（连通性自检） |
| `/api/v1/test-results` | POST | 提交测试记录（幂等：`ClientRecordId` 去重） |
| `/api/v1/test-results` | GET | 查询最近 100 条记录 |
| `/api/v1/sn/next` | POST | SN 逐号申请（事务内 `MAX(seq)+INSERT`） |
| `/api/v1/sn/reserve` | POST | SN 号段申请（断网兜底，台账入 `sn_block`） |
| `/api/v1/sn/lookup` | GET | SN 追溯查询 |

```csharp
// QiChargerStationTool.Server/Program.cs
// QI-SERVER：测试记录汇总 + SN 联机分配
// 对应 doc 20 §4（记录同步）、doc 21 §5（SN 三接口 + 两表）
// NuGet：Microsoft.EntityFrameworkCore.Sqlite（8.x）
using Microsoft.EntityFrameworkCore;

var builder = WebApplication.CreateBuilder(args);

// ① 监听所有网卡（默认只听 localhost，工位机连不上——最常见的坑）
builder.WebHost.UseUrls("http://0.0.0.0:5000");

// ② SQLite 数据库：程序与数据分离，便于备份；改数据目录时同步改这里
var dbPath = Path.Combine(@"D:\QiStationData", "station.db");
Directory.CreateDirectory(Path.GetDirectoryName(dbPath)!);
builder.Services.AddDbContext<StationDb>(o => o.UseSqlite($"Data Source={dbPath}"));

var app = builder.Build();

// ③ 启动建库建表（幂等：已存在则跳过）
using (var scope = app.Services.CreateScope())
    scope.ServiceProvider.GetRequiredService<StationDb>().Database.EnsureCreated();

// ---------- 健康检查 ----------
app.MapGet("/api/v1/ping", () => Results.Ok(new { ok = true, time = DateTime.Now }));

// ---------- 测试记录：提交 ----------
// 注意：ClientTime 是测试发生时刻，补传时可能是几小时前——它只做参考存档，
// 不参与 5 分钟时钟校验（校验只做在 SN 取号请求上，见 /sn/next、/sn/reserve）。
app.MapPost("/api/v1/test-results", async (TestResult r, StationDb db) =>
{
    r.ServerTime = DateTime.Now;               // 时间基准 = 服务器入库时刻

    // 幂等：同一 ClientRecordId 补传只留一条
    if (!string.IsNullOrEmpty(r.ClientRecordId) &&
        await db.Results.AnyAsync(x => x.ClientRecordId == r.ClientRecordId))
        return Results.Ok(new { ok = true, duplicate = true });

    db.Results.Add(r);
    await db.SaveChangesAsync();
    return Results.Ok(new { ok = true, id = r.Id });
});

// ---------- 测试记录：查询最近 100 条 ----------
app.MapGet("/api/v1/test-results", async (StationDb db) =>
    Results.Ok(await db.Results.OrderByDescending(x => x.Id).Take(100).ToListAsync()));

// ---------- SN：逐号申请（doc 21 §5.1 /api/v1/sn/next） ----------
app.MapPost("/api/v1/sn/next", async (SnRequest req, StationDb db) =>
{
    if (string.IsNullOrWhiteSpace(req.Station))
        return Results.BadRequest(new { ok = false, error = "station 必填" });
    if (!SnHelper.ClockOk(req.ClientTime, out var clockErr))
        return Results.BadRequest(new { ok = false, error = clockErr });

    var count = req.Count is > 0 and <= 100 ? req.Count.Value : 1;
    var today = DateTime.Now.ToString("yyMMdd");   // 日期以服务器时钟为准

    await using var tx = await db.Database.BeginTransactionAsync();
    var maxSeq = await db.SnIssued.Where(x => x.Date == today)
                                  .MaxAsync(x => (int?)x.Seq) ?? 0;
    if (maxSeq + count > 9999)
    {
        await tx.RollbackAsync();
        return Results.BadRequest(new { ok = false, error = "当日序号不足（上限 9999）" });
    }

    var items = new List<object>();
    for (var i = 1; i <= count; i++)
    {
        var seq = maxSeq + i;
        var sn = SnHelper.Build(today, seq);
        db.SnIssued.Add(new SnIssued
        {
            Date = today, Seq = seq, Sn = sn,
            Station = req.Station, Machine = req.Machine, Operator = req.Operator,
            Mode = "next", IssuedAt = DateTime.Now.ToString("yyyy-MM-dd HH:mm:ss")
        });
        items.Add(new { sn, seq });
    }
    await db.SaveChangesAsync();
    await tx.CommitAsync();
    return Results.Ok(new { date = today, items });
});

// ---------- SN：号段申请（doc 21 §5.1 /api/v1/sn/reserve，离线兜底） ----------
app.MapPost("/api/v1/sn/reserve", async (SnRequest req, StationDb db) =>
{
    if (string.IsNullOrWhiteSpace(req.Station))
        return Results.BadRequest(new { ok = false, error = "station 必填" });
    if (!SnHelper.ClockOk(req.ClientTime, out var clockErr))
        return Results.BadRequest(new { ok = false, error = clockErr });

    var count = req.Count is > 0 and <= 500 ? req.Count.Value : 50;
    var today = DateTime.Now.ToString("yyMMdd");

    await using var tx = await db.Database.BeginTransactionAsync();
    var maxSeq = await db.SnIssued.Where(x => x.Date == today)
                                  .MaxAsync(x => (int?)x.Seq) ?? 0;
    if (maxSeq + count > 9999)
    {
        await tx.RollbackAsync();
        return Results.BadRequest(new { ok = false, error = "当日序号不足（上限 9999）" });
    }

    var startSeq = maxSeq + 1;
    var endSeq = maxSeq + count;
    for (var seq = startSeq; seq <= endSeq; seq++)
        db.SnIssued.Add(new SnIssued
        {
            Date = today, Seq = seq, Sn = SnHelper.Build(today, seq),
            Station = req.Station, Machine = req.Machine, Operator = req.Operator,
            Mode = "reserve", IssuedAt = DateTime.Now.ToString("yyyy-MM-dd HH:mm:ss")
        });
    db.SnBlocks.Add(new SnBlock
    {
        Date = today, Station = req.Station, Machine = req.Machine,
        StartSeq = startSeq, EndSeq = endSeq,
        HandedAt = DateTime.Now.ToString("yyyy-MM-dd HH:mm:ss")
    });
    await db.SaveChangesAsync();
    await tx.CommitAsync();
    return Results.Ok(new { date = today, startSeq, endSeq });
});

// ---------- SN：追溯查询（doc 21 §5.1 /api/v1/sn/lookup） ----------
app.MapGet("/api/v1/sn/lookup", async (string sn, StationDb db) =>
{
    var row = await db.SnIssued.AsNoTracking().FirstOrDefaultAsync(x => x.Sn == sn);
    return row is null
        ? Results.NotFound(new { ok = false, error = "SN 不存在" })
        : Results.Ok(new

// SN 组装与客户端时钟校验
public static class SnHelper
{
    // 20 位 SN：LSCH42JY01（LS+CH+42+JY+01） + yymmdd + 4 位流水
    public static string Build(string yymmdd, int seq) => $"LSCH42JY01{yymmdd}{seq:D4}";

    // 客户端时钟偏差 > 5 分钟拒绝（防跨日错位，doc 21 §5.1）
    public static bool ClockOk(string? clientTime, out string error)
    {
        error = "";
        if (string.IsNullOrWhiteSpace(clientTime)) return true; // 未带则不校
        if (!DateTime.TryParse(clientTime, out var t))
        {
            error = "clientTime 格式错误（建议 ISO 8601，如 2026-11-04T10:00:00）";
            return false;
        }
        if (Math.Abs((DateTime.Now - t).TotalMinutes) > 5)
        {
            error = "客户端时钟偏差超过 5 分钟，请校时后重试";
            return false;
        }
        return true;
    }
}
```

| 要点 | 实现位置 | 说明 |

| 监听 `http://0.0.0.0:5000` | `builder.WebHost.UseUrls(...)` | **不能只听 localhost**，否则工位机全连不上 |

### 9.1 每台工位机的两个配置文件

**① `machine.json`**（机位身份，放上位机程序目录）：

```json
{
  "stationNo": 1,
  "machineId": "1"
}
```

- `stationNo` = 工位号（1~4），`machineId` = 机位号（同工位内不重复，推荐 1、2、3… 顺序启用）；
- 上位机界面/台账显示的**机位编码**自动拼成 **`ST-工位号-机位号`**（如 `ST-01-1`、`ST-01-2`、`ST-01-3`），与 [21. 工位1多机并发SN联机分配方案](./21.%20工位1多机并发SN联机分配方案.md) §2 一致；
- 机位数随产量动态增减：加机位=装上位机+命名+重启；减机位=直接撤电脑，代码/服务器零改动。
- **推荐经上位机「设置」页操作**（主窗口顶部菜单「设置」，按类型分页）：**「机位与网络」**页——机位命名（写本文件并记 `machine_change.log` 留痕）、查看本机 IP、服务器连通检测、跳转系统网络设置改 IP；**「检测参数」**页——步骤 5 双线圈电流阈值/窗口/超时（保存后下次测试生效）。也可手工编辑本文件。

**② `appsettings.json`**（服务器地址段，与现有测试字段并存，见 doc 20 §5.1）：

```json
{
  "ComPort": "",
  "Baud": 2000000,
  "FirmwarePath": "firmware/app_image_v1_1_57.bin",
  "Server": {
    "Url": "http://QI-SERVER:5000",
    "TimeoutSeconds": 5
  },
```

| 字段 | 取值 | 说明 |
|------|------|------|
| `Server.Url` | `http://QI-SERVER:5000` 或 `http://192.168.10.10:5000` | **必须 http://**，不能写 https://；IP 形式不依赖主机名解析，最稳 |
| `StationId` | `ST-01-1`…（机位编码） | 与 `machine.json` 拼出的编码一致，贴在机箱上 |

### 9.2 机位数动态增减（1~N 台/工位）

服务器一次搭好后**零改动**，新增一个机位只需三步：

1. **接网线**：新电脑插到交换机 SW1，配同网段 IP（`192.168.10.x` 静态，或路由器 DHCP 保留）；

减机位：直接撤机，服务器台账不受影响。

| 6 | 断网演练 | 拔网线：跑 3 条测试 + 取号（走本地队列/本地号段）→ 插回网线 | 队列记录 ≤30 s 补传到服务器且无重复；号段续用不撞号 | ☐ |
| 7 | 备份文件生成 | `schtasks /Run /TN "QiStationData-Backup"` 后查 `D:\QiStationData\backup\<日期>\` | `station.db`（及 -wal/-shm）存在 | ☐ |

第 5 项参考命令（每台机各跑一次，对比返回的 `sn` 与 `seq` 不重复）：

```powershell
$body = @{ station = "ST-01"; machine = "1"; operator = "A"; count = 1;
           clientTime = (Get-Date).ToString("yyyy-MM-ddTHH:mm:ss") } | ConvertTo-Json
Invoke-RestMethod -Uri http://192.168.10.10:5000/api/v1/sn/next -Method Post `
  -ContentType "application/json" -Body $body
```

## 11. 常见问题

| # | 现象 | 原因 | 处理 |
|---|------|------|------|
| 1 | 启动 exe 报端口占用 / 起不来 | 5000 被别的程序占（或服务起了两份） | `netstat -ano \| findstr :5000` 看占用 PID → `taskkill /PID <pid> /F`；确需换端口则改 `UseUrls`、防火墙规则、工位机 `Server.Url` 三处同步 |
| 2 | 本机 curl 通、工位机 ping 通但端口不通 | 防火墙没放行 5000（或网络配置文件是「公用」） | 重做 §3.3 放行规则；`Set-NetConnectionProfile -InterfaceAlias "以太网" -NetworkCategory Private` |
| 3 | 工位机 `Test-NetConnection` 超时，服务器本机正常 | 服务只听了 localhost | 确认 `Program.cs` 有 `UseUrls("http://0.0.0.0:5000")`；`netstat -ano \| findstr :5000` 应显示 `0.0.0.0:5000 ... LISTENING`（若显示 `127.0.0.1:5000` 就是这个坑） |
| 4 | 上位机超时，浏览器/curl 却正常 | `Server.Url` 误写成 `https://` | 改回 `http://`；本服务纯 HTTP，无证书 |
| 5 | `/api/v1/sn/next` 返回「客户端时钟偏差超过 5 分钟」 | 工位机时钟漂移，会被拒号（防产错日期 SN） | 工位机 `设置 → 时间 → 自动设置时间` 打开；管理员执行 `w32tm /resync`；与服务器时间对齐后重试 |
| 6 | 服务器偶发 `SQLite database is locked` | 并发写锁等待 / 正在拷贝备份 | 稍后重试即恢复（写事务 <1 ms）；确保**只跑一个**服务实例；备份走 §8 的 robocopy 三个文件一起拷；仍频繁出现则重启服务 |
| 7 | ping 通但 curl 超时 | 服务没起来 / 防火墙拦 / 监听错 | 按 §7 自启 + `schtasks /Run` 拉起服务；`netstat` 查监听；重做 §3.3 |
| 8 | 重启后服务没自己起来 | 没配自启 / 没设自动登录 | 重做 §2.3 自动登录 + §7（推荐任务计划程序） |
| 9 | 工位机显示已传，服务器查不到 | 传到旧地址/别的机器，或补传未触发 | 用 `ClientRecordId` 对账（`GET /api/v1/test-results` 里查该 id）；核对 `Server.Url` |
| 10 | SN 取号报「当日序号不足」 | 当日 9999 个流水号用尽，或客户端时钟跨日错位 | 查 `sn_issued` 台账确认产量；核对服务器时钟（§2.4）；次日自动翻日归 1 |
| 11 | `dotnet` 不是内部或外部命令 | .NET 8 SDK 没装 / PATH 没生效 | 重做 §4；重开一个 PowerShell 窗口再试 |

## 附录 A：两台机直连（无交换机）最小配置

> **适用**：只有 **2 台电脑**（1 台服务器 + 1 台工位机）的最小场景——一根网线直连，不接交换机/路由器。服务端**零改动**（照 §5 部署，`http://0.0.0.0:5000` 照听），只是把 §2/§3 的网络部分换成下面 3 步。3 台及以上不要直连（见 A.4）。

### A.1 网线

普通 Cat5e 及以上网线 **1 根即可**。两台机网卡都是 Auto-MDI/MDIX，**不需要交叉线**，也不用动网卡速率/双工设置。插上网口灯亮即物理连通。

### A.2 IP 配置（两端各配一次，静态）

没有路由器/交换机就没有 DHCP，两端手动配同网段静态 IP；**网关、DNS 留空**（本链路不出外网）：

| 电脑 | IPv4 地址 | 子网掩码 | 默认网关 |
|------|-----------|----------|----------|
| 服务器 | `192.168.10.10` | `255.255.255.0` | 留空 |
| 工位机 | `192.168.10.11` | `255.255.255.0` | 留空 |

**图形界面**（两端相同步骤）：`设置` → `网络和 Internet` → `以太网` → 点击当前连接 → 「IP 分配」→「编辑」→「手动」→ 打开 IPv4 → 按上表填 → 保存。

**PowerShell**（管理员，在对应电脑上执行）：

```powershell
# 服务器上执行
New-NetIPAddress -InterfaceAlias "以太网" -IPAddress 192.168.10.10 -PrefixLength 24

# 工位机上执行
New-NetIPAddress -InterfaceAlias "以太网" -IPAddress 192.168.10.11 -PrefixLength 24
```

> 若 `192.168.10.x` 与工位机已有的其他网络（办公室路由器等）冲突，两端换同段他值（如 `10.10.10.10` / `10.10.10.11`）即可，后文地址同步替换。

### A.3 防火墙（直连最大的坑）

直连网卡常被 Windows 判成「未识别网络」→ 归为**公用网络**；§3.3 的放行规则若只对「专用」生效，5000 端口会被拦。二选一：

- **改网络类型**（推荐，两台都执行）：

  ```powershell
  Set-NetConnectionProfile -InterfaceAlias "以太网" -NetworkCategory Private
  ```

- **或放行规则勾「公用」**：重做 §3.3 时把配置文件里的「公用」勾上。

之后照 §6.3 从工位机验证（全绿即通）：

| # | 命令（工位机 PowerShell） | 期望输出 |
|---|------|----------|
| 1 | `ping 192.168.10.10` | 有回包 |
| 2 | `Test-NetConnection 192.168.10.10 -Port 5000` | `TcpTestSucceeded : True` |
| 3 | `curl.exe http://192.168.10.10:5000/api/v1/ping` | `{"ok":true,...}` |

> 访问地址一律用 **IP 形式** `http://192.168.10.10:5000`（上位机 `appsettings.json` 的 `Server.Url` 同此）。直连没有 DNS，`http://QI-SERVER:5000` 主机名形式解析不了。

### A.4 3 台及以上不要直连

一根网线只连 2 台。多台工位机不用交换机只能靠服务器多网卡 + Windows 网桥/ICS 串接——能通但脆弱（中间掉一台牵连整条链路、延迟叠加、故障难定位），产线**不建议**。**8 口非网管千兆交换机百元级**，插上即用，网络部分回到 §2/§3 正文即可。
