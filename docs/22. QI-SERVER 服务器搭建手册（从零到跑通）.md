# 22. QI-SERVER 服务器搭建手册（从零到跑通）

> **读者**：现场实施 / 产线 IT 人员。本手册是「照着一步步做」的操作教学，每一步给出可直接复制粘贴的命令，做到最后一步即可跑通 QI-SERVER。
> **QI-SERVER 是什么**：产线局域网里的一台 Windows 电脑，**以「汇总机」身份运行 ProductionStationTool**（同一套产线上位机，源码：仓库 `ProductionStationTool/`，WSL 路径 `\\wsl.localhost\Ubuntu\home\nights\embedded_item\ota-upgrade-of-qi-charger-based-on-can\ProductionStationTool`）。汇总机身份即服务端：内置 **:5000 工位机接入监听**（心跳自动登记）+ **SQLite 数据库**（`station_records.db`）+ 汇总机管理页（接入管理 / 数据库表格）。工位机身份 = 产线测试上位机（同一 exe，启动登录时选）。设计参照：[20. 产线多工位数据同步与服务器配置](./20.%20产线多工位数据同步与服务器配置.md)、[21. 工位1多机并发SN联机分配方案](./21.%20工位1多机并发SN联机分配方案.md)。
> **设计论证**（为什么这么选型）见 doc 20 / doc 21，本文不重复；只讲怎么做。产品整体背景见 [15. 功能需求文档](./15.%20功能需求文档.md)。
> **产线上位机**：`ProductionStationTool`（工位机/汇总机一体；源码：仓库 `ProductionStationTool/`，
> WSL 路径 `\\wsl.localhost\Ubuntu\home\nights\embedded_item\ota-upgrade-of-qi-charger-based-on-can\ProductionStationTool`）。
> 本手册只讲服务器怎么搭建与验证，不含程序代码细节——服务端程序源码由开发机在仓库内维护。

## 1. 硬件与前置准备

### 1.1 服务器选型

**不需要服务器级硬件**。一台普通 Windows 10/11 Pro 工控机或 PC 即可，参考配置：

| 项 | 要求 | 说明 |
|----|------|------|
| 操作系统 | Windows 10/11 **Pro**（或工控机同级） | 需要改主机名、配静态 IP、计划任务；家庭版功能受限不推荐 |
| CPU | Intel i3 级或以上 | 服务为极简 HTTP API + SQLite，负载 ≈ 0.1 QPS |
| 内存 | 8 GB | 绰绰有余 |
| 硬盘 | 128 GB SSD | 数据库是单文件 SQLite，日产量千级记录远用不满 |
| 网口 | 千兆以太网口 ×1 | 接交换机 SW1 |
| 显示/键鼠 | 装机调试用，装完可不接 | 用远程桌面维护亦可 |

### 1.2 物料清单

| # | 物料 | 数量 | 用途 |
|---|------|------|------|
| 1 | 服务器（上述 PC/工控机） | 1 台 | 跑 QI-SERVER |
| 2 | 千兆二层交换机（16 或 24 口，非网管即可） | 1 台 | 产线 LAN 星型汇聚（doc 21 §2 中的 SW1）；**仅 2 台机直连场景可省**（见附录 A） |
| 3 | 网线（Cat5e 及以上） | 每台电脑 1 根 + 备用 | 服务器、各工位机接入 SW1 |
| 4 | U 盘（≥8 GB） | 1 个 | 从开发机搬运发布产物到服务器（现场无源码时用） |

### 1.3 前提条件（开始前逐条确认）

| # | 前提 | 确认 |
|---|------|------|
| 1 | 产线 LAN（交换机 SW1 + 各电脑）**不联外网**，纯局域网 | ☐ |
| 2 | 全网段规划为 `192.168.10.0/24`：服务器固定 `192.168.10.10`，工位机 `.11`/`.12`/`.13`… | ☐ |
| 3 | 服务器已装好 Windows、能进桌面、有管理员账户（可设自动登录） | ☐ |
| 4 | 本手册命令默认在 **管理员 PowerShell** 中执行（右键开始菜单 →「终端(管理员)」/「Windows PowerShell(管理员)」），不再逐一提示 | ☐ |
| 5 | 若走 §5 路径 A：开发机上已有源码仓库与 .NET 8 SDK，能 `dotnet publish` | ☐ |

> 网络拓扑、机位命名与 IP 明细见 [21. 工位1多机并发SN联机分配方案](./21.%20工位1多机并发SN联机分配方案.md) §2（交换机 SW1、QI-SERVER=`192.168.10.10`、每机位 1 个 ZQWL-CANFD 盒子走 USB/CAN，不经交换机）。

## 2. 操作系统设置

> 每项只做一次。**电源与时间**尤其重要：服务不能被休眠打断；SN 取号按**服务器时钟**生成日期段，时间错了会产错日期的 SN。

### 2.1 电源计划设为「高性能」

**图形界面**：`控制面板` → `硬件和声音` → `电源选项` → 选中「**高性能**」（若没有，点左侧「创建电源计划」→ 基于「高性能」创建）。

**命令方式**（可选，管理员 PowerShell；如提示找不到该方案，先执行第二行复制出该方案再激活）：

```powershell
powercfg /setactive 8c5e7fda-e8bf-4a96-9a85-a6e23a8c635c
powercfg -duplicatescheme 8c5e7fda-e8bf-4a96-9a85-a6e23a8c635c
```

### 2.2 关闭睡眠 / 休眠（管理员 PowerShell）

```powershell
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
powercfg /hibernate off
```

**图形界面**：`设置` → `系统` → `电源和睡眠`（Win11 为 `系统` → `电源`）→ 「睡眠」两项均选「**从不**」。

### 2.3 允许自动登录

目的：断电重启后自动进桌面，开机自启（§7）才能把服务拉起来。

1. `Win + R` → 输入 `netplwiz` → 回车。
2. 选中本机日常使用的账户 → **取消勾选**「要使用本计算机，用户必须输入用户名和密码」→ 点「应用」。
3. 在弹窗中输入该账户的密码并确认 → 「确定」。

> 重启一次验证：开机后不输密码直接进桌面。

### 2.4 时区与自动设置时间（重要：SN 按服务器时钟取号）

**图形界面**：`设置` → `时间和语言` → `日期和时间`：

1. 「时区」选 **(UTC+08:00) 北京，重庆，香港特别行政区**（按现场所在地选）；
2. 打开「**自动设置时间**」；
3. 打开「自动设置时区」（若有）。

**命令方式**（管理员 PowerShell，可作核对）：

```powershell
tzutil /s "China Standard Time"
w32tm /resync
w32tm /query /status
```

`w32tm /query /status` 输出的「源」与「上次成功同步时间」正常即 OK。**服务器与所有工位机都要开自动设置时间**；对账、追溯一律以服务器入库时间（`ServerTime`）为准。

### 2.5 网络配置文件设为「专用网络」

「公用网络」下 Windows 防火墙默认策略更严，容易出现 ping 通但端口不通。

**图形界面**：`设置` → `网络和 Internet` → `以太网` → 点击当前连接 → 「网络配置文件类型」选「**专用网络**」。

**命令方式**（管理员 PowerShell，先看网卡名再改）：

```powershell
Get-NetConnectionProfile
Set-NetConnectionProfile -InterfaceAlias "以太网" -NetworkCategory Private
```

> 网卡别名不是「以太网」时（如 `Ethernet`），把命令里的名字换成 `Get-NetConnectionProfile` 显示的实际 `InterfaceAlias`。

## 3. 网络配置

### 3.1 静态 IP：`192.168.10.10/24`

#### 方式一：控制面板（图形界面）

1. `控制面板` → `网络和 Internet` → `网络和共享中心` → 左侧「**更改适配器设置**」。
2. 右键「以太网」→「属性」→ 双击「**Internet 协议版本 4 (TCP/IPv4)**」。
3. 选「使用下面的 IP 地址」：

| 字段 | 值 |
|------|----|
| IP 地址 | `192.168.10.10` |
| 子网掩码 | `255.255.255.0` |
| 默认网关 | **留空**（产线 LAN 不联外网；若现场有统一网关按现场填） |
| 首选 DNS 服务器 | 留空 |

4. 确定 → 关闭。

#### 方式二：netsh（管理员 PowerShell / CMD）

```powershell
netsh interface ip set address name="以太网" source=static addr=192.168.10.10 mask=255.255.255.0
```

#### 方式三：PowerShell（管理员）

```powershell
Get-NetAdapter
New-NetIPAddress -InterfaceAlias "以太网" -IPAddress 192.168.10.10 -PrefixLength 24
```

验证（三条都应符合预期）：

```powershell
ipconfig | findstr IPv4
ping 192.168.10.10
ping 192.168.10.11
```

| 期望 | 说明 |
|------|------|
| `IPv4 地址 . . . : 192.168.10.10` | 服务器自身 |
| `ping 192.168.10.10` 有回包 | 本机协议栈正常 |
| `ping 192.168.10.11` 有回包 | 至少一台工位机已在线（没在线可后补此验证） |

### 3.2 主机名改为 `QI-SERVER`

改名后工位机可用 `http://QI-SERVER:5000` 访问，比记 IP 直观。

**命令方式**（管理员 PowerShell，执行后自动重启）：

```powershell
Rename-Computer -NewName "QI-SERVER" -Restart
```

**图形界面**：`设置` → `系统` → `系统信息` → 「重命名这台电脑」→ 填 `QI-SERVER` → 重启。

重启后核对：

```powershell
hostname
```

期望输出：`QI-SERVER`。

### 3.3 防火墙放行 TCP 5000（管理员 PowerShell，执行一次）

```powershell
New-NetFirewallRule -DisplayName "QiStationServer 5000" `
  -Direction Inbound -Protocol TCP -LocalPort 5000 -Action Allow
```

核对规则已存在：

```powershell
Get-NetFirewallRule -DisplayName "QiStationServer 5000" | Get-NetFirewallPortFilter
```

期望输出中 `LocalPort` 为 `5000`、`Protocol` 为 `TCP`。

## 4. 安装 .NET 8 桌面运行时

### 4.1 下载与安装

1. 浏览器打开（可先在有外网的机器下载后用 U 盘拷来）：`https://dotnet.microsoft.com/download/dotnet/8.0`
2. 找 **.NET Desktop Runtime 8.0.x** → **Windows x64** → 下载 `windowsdesktop-runtime-8.0.x-win-x64.exe`；
3. 双击安装 → 完成（一路下一步）。

### 4.2 验证安装

```powershell
dotnet --list-runtimes
```

期望输出包含一行（版本号以实际为准）：

```text
Microsoft.WindowsDesktop.App 8.0.x [C:\Program Files\dotnet\shared\Microsoft.WindowsDesktop.App]
```

### 4.3 为什么是 Desktop Runtime

| 包 | 干什么 | 用在哪 |
|----|--------|--------|
| **.NET Desktop Runtime 8.0 x64**（服务器装这个） | 运行 WPF 桌面程序——ProductionStationTool 是 `net8.0-windows` WPF 应用 | 服务器跑汇总机 |
| .NET SDK | 编译、`dotnet publish` 发布 | 只在**开发机**需要（§5.1） |
| 发布时 `--self-contained true` | 产物自带运行时 | 服务器可不装任何运行时 |

> 简单原则：服务器装 **Desktop Runtime** 即可；开发机装 **SDK**。

## 5. 部署 QI-SERVER（ProductionStationTool 汇总机）

> 同一套程序区分身份：启动登录选**「工位机」**= 产线测试上位机（工位机用）；
> 选**「汇总机」**= QI-SERVER 服务端（本手册）。服务端不装任何额外组件——
> :5000 监听、数据库、管理页都在这个 exe 里。

### 5.1 开发机发布 → 拷贝到服务器

**在开发机**（Windows + .NET 8 SDK + 仓库源码）：

```powershell
cd <仓库根目录>\ProductionStationTool
dotnet publish src\ProductionStationTool.App\ProductionStationTool.App `
  -c Release -r win-x64 --self-contained false -o publish
```

| 参数 | 含义 |
|------|------|
| `-c Release` | 发布配置 Release |
| `-r win-x64` | 目标平台 Windows x64 |
| `--self-contained false` | 不自带运行时（服务器装 §4 的 Desktop Runtime）；要免运行时版本则改 `--self-contained true` |
| `-o publish` | 输出到 `publish\` 目录 |

**拷贝到服务器**：

```powershell
New-Item -ItemType Directory -Path D:\QiStationServer -Force
# 然后把 U 盘里 publish\ 的全部内容复制到 D:\QiStationServer\
```

> 产物含 `ProductionStationTool.App.exe` 与同目录 `.dll`/`.json` 等，**都要一起拷**，缺文件会起不来。

### 5.2 服务器首次运行（登录选汇总机）

1. 运行 `D:\QiStationServer\ProductionStationTool.App.exe`；
2. 启动登录窗选 **「汇总机」** → 输入管理密码（默认 `admin123`，登录后在「设置 → 设置汇总机密码…」改掉）→ 登录；
3. 进入汇总机管理页即服务在跑：
   - **:5000 接入监听**已启动——工位机心跳（约 15s 一报）自动登记卡片；
   - **数据库**：程序运行目录 `station_records.db`（SQLite）；
   - **管理页**：「工位机接入管理」（在线/离线卡片、允许/禁止接入）+「数据库表格」（时间/工位/机位/结果筛选）。

> 汇总机身份不发工位心跳、不计入机位；退出 = 关闭窗口（重开再选身份）。

## 6. 运行与验证

### 6.1 启动

| 方式 | 做法 | 适用 |
|------|------|------|
| 手动 | 运行 exe → 登录选「汇总机」 | 调试/临时 |
| 开机自启 | §7（任务计划 + 自动登录） | 产线常态 |

### 6.2 服务器本机冒烟（PowerShell）

```powershell
Test-NetConnection -ComputerName localhost -Port 5000
```

期望输出片段：

```text
TcpTestSucceeded : True
```

接入心跳冒烟（等价一台工位机上报）：

```powershell
$body = '{"code":"ST-01-1","stationNo":1,"machineId":"1"}'
Invoke-RestMethod -Uri http://localhost:5000/hello -Method Post `
  -ContentType "application/json" -Body $body
```

期望输出：

```json
{}
```

**页面预期**：汇总机页「工位机接入管理」立即出现 `ST-01-1` 卡片（IP=本机）——手工冒烟的伪机位，可「移除记录」清掉。

### 6.3 从工位机验证（每台工位机执行，全绿才算通）

| # | 命令（工位机 PowerShell） | 期望输出 |
|---|--------------------------|----------|
| 1 | `ping 192.168.10.10` | 有回包，延迟 < 10 ms |
| 2 | `Test-NetConnection 192.168.10.10 -Port 5000` | `TcpTestSucceeded : True` |
| 3 | 心跳冒烟（下行整段粘贴） | `{}` |

```powershell
$body = '{"code":"ST-01-1","stationNo":1,"machineId":"1"}'
Invoke-RestMethod -Uri http://192.168.10.10:5000/hello -Method Post `
  -ContentType "application/json" -Body $body
```

第 2 步的期望输出样例：

```text
ComputerName     : 192.168.10.10
RemoteAddress    : 192.168.10.10
RemotePort       : 5000
TcpTestSucceeded : True
```

**最终验收（页面口径）**：工位机启动 ProductionStationTool（登录选「工位机」；`machine.json` 的 `serverHost` 填 `192.168.10.10`，可经「设置 → 机位与网络」维护）后约 15s 内，汇总机页「工位机接入管理」自动生成该机位卡片（编码 `ST-工位号-机位号`、●在线绿灯、最近接入、测试概况），无需手动录入；「数据库表格」可按时间/工位/机位/结果筛选测试记录。

> **规划接口备注**（doc 20/21 设计，API 落地后用）：
>
> ```powershell
> curl.exe http://192.168.10.10:5000/api/v1/ping
> ```
> 期望：`{"ok":true,"time":"…"}`
>
> ```powershell
> $body = @{ station = "ST-01"; machine = "1"; operator = "TEST"; count = 1;
>            clientTime = (Get-Date).ToString("yyyy-MM-ddTHH:mm:ss") } | ConvertTo-Json
> Invoke-RestMethod -Uri http://192.168.10.10:5000/api/v1/sn/next -Method Post `
>   -ContentType "application/json" -Body $body
> ```
> 期望：`{ "date": "261104", "items": [ { "sn": "…0001", "seq": 1 } ] }`（再跑一次 seq 递增）
>
> ```powershell
> $body = '{"sn":"TEST-001","stationId":"ST-01-1","result":"PASS","firmwareVersion":"1.2.1","itemsJson":"[]","clientTime":"2026-11-04T12:00:00"}'
> Invoke-RestMethod -Uri http://192.168.10.10:5000/api/v1/test-results -Method Post `
>   -ContentType "application/json" -Body $body
> ```
> 期望：`{"ok":true,"id":…}`；回查 `GET /api/v1/test-results` 能查到即闭环。

## 7. 开机自启（汇总机是图形程序，配自动登录）

> ProductionStationTool 是 **WPF 图形程序**——必须在登录会话里运行（**不能**注册为
> Windows 服务，服务会话里没有界面）。自启 = 自动登录（§2.3）+ 登录后自动拉起 exe。

### 7.1 方式一：启动文件夹放快捷方式（最简）

1. `Win+R` → 输入 `shell:startup` 回车，打开「启动」文件夹；
2. 右键 `D:\QiStationServer\ProductionStationTool.App.exe` → 「创建快捷方式」，把快捷方式**移入**该文件夹；
3. 注销重登（或重启）→ 程序自动启动 → 在登录窗选「汇总机」（管理密码）即可。

> 汇总机身份不持久化——每次启动都要在登录窗选一次「汇总机」。

### 7.2 方式二：任务计划程序（推荐）

命令行（管理员 PowerShell）：

```powershell
schtasks /Create /TN "QI-SERVER" `
  /TR "D:\QiStationServer\ProductionStationTool.App.exe" `
  /SC ONLOGON /RL HIGHEST /F
```

立即验证（不重启）：

```powershell
schtasks /Run /TN "QI-SERVER"
```

图形界面等价：`Win+R` → `taskschd.msc` → 创建任务：常规名称 `QI-SERVER`、
勾「使用最高权限运行」；触发器「登录时」；操作「启动程序」→ 程序
`D:\QiStationServer\ProductionStationTool.App.exe`、起始于 `D:\QiStationServer`；
「设置」可勾「如果任务失败，按以下频率重新启动」做崩溃拉起。

## 8. 数据目录与备份

### 8.1 数据库位置（程序自动创建）

数据库 = **程序运行目录**下的 `station_records.db`（SQLite）：

```text
D:\QiStationServer\
├── ProductionStationTool.App.exe   # 程序
├── station_records.db              # SQLite 主库（测试记录 + 接入登记）
├── station_records.db-wal          # WAL 日志（自动出现，正常现象）
├── station_records.db-shm          # 共享内存文件（自动出现，正常现象）
└── backup\                        # 备份目录（§8.3 自动往里放）
```

- **别放 C 盘桌面/文档**：重装系统、清理磁盘会连数据一起没；程序与库统一放 `D:\QiStationServer\`。
- 备份/拷走时必须把 `station_records.db`、`-wal`、`-shm` **三个文件一起拷**（只拷 db 可能丢最近几条记录）。
- 各工位机的 `station_records.db` 在工位机程序目录；汇总机页「数据库表格」查询**本机**库。

### 8.2 每周备份脚本

新建 `D:\QiStationServer\backup.ps1`（记事本粘贴另存为，编码 UTF-8 或 ANSI 均可）：

```powershell
# D:\QiStationServer\backup.ps1 —— 每周备份 station_records.db（含 WAL/SHM）
$dst = Join-Path "D:\QiStationServer\backup" (Get-Date -Format "yyyyMMdd")
robocopy D:\QiStationServer $dst station_records.db station_records.db-wal station_records.db-shm /R:3 /W:5
# robocopy 退出码 0~7 都算成功
if ($LASTEXITCODE -le 7) { Write-Host "backup OK -> $dst" } else { exit 1 }
```

手动跑一次验证：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\QiStationServer\backup.ps1
dir D:\QiStationServer\backup\
```

### 8.3 每周备份计划任务（管理员 PowerShell）

```powershell
schtasks /Create /TN "QiStationData-Backup" `
  /TR "powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\QiStationServer\backup.ps1" `
  /SC WEEKLY /D SUN /ST 20:00 /RU SYSTEM /RL HIGHEST /F
```

立即试跑一次：

```powershell
schtasks /Run /TN "QiStationData-Backup"
```

> 磁盘空间：单条记录 < 10 KB、日产量千级，每周全量复制一份，一年不到 1 GB；backup 目录可按需手工清理 3 个月前的日期文件夹。

## 9. 工位机侧对照

> 服务器搭完后，每台工位机只改两个小配置文件。工位机软件 = **`ProductionStationTool`** 上位机（源码：仓库 `ProductionStationTool/`，WSL 路径 `\\wsl.localhost\Ubuntu\home\nights\embedded_item\ota-upgrade-of-qi-charger-based-on-can\ProductionStationTool`；工位机/汇总机一体，启动登录选「工位机」）；安装与测试流程不在本手册范围，见 [11. 维修上位机使用与开发说明](./11.%20维修上位机使用与开发说明.md)、[20. 产线多工位数据同步与服务器配置](./20.%20产线多工位数据同步与服务器配置.md) §5。

> **ProductionStationTool 启动登录**：App 启动先选登录身份——「工位机」免密码进测试页；「汇总机」需管理密码（服务器电脑专用，**不计入机位/工位**）。身份仅启动时选定、两页无互切入口，退出 = 关窗重开。

### 9.1 每台工位机的两个配置文件

**① `machine.json`**（机位身份，放上位机程序目录）：

```json
{
  "stationNo": 1,
  "machineId": "1"
}
```

- `stationNo` = 工位号（1~4），`machineId` = 机位号（同工位内不重复，推荐 1、2、3… 顺序启用）；
- 上位机界面/台账显示的**机位编码**自动拼成 **`ST-工位号-机位号`**（如 `ST-01-1`、`ST-01-2`、`ST-01-3`），与 [21. 工位1多机并发SN联机分配方案](./21.%20工位1多机并发SN联机分配方案.md) §2 一致；
- 机位数随产量动态增减：加机位=装上位机+命名+重启；减机位=直接撤电脑，代码/服务器零改动。
- **推荐经上位机「设置」页操作**（主窗口顶部菜单「设置」，按类型分页）：**「机位与网络」**页——机位命名（写本文件并记 `machine_change.log` 留痕）、查看本机 IP、服务器连通检测、跳转系统网络设置改 IP；**「检测参数」**页——步骤 5 双线圈电流阈值/窗口/超时（保存后下次测试生效）。也可手工编辑本文件。

**② `appsettings.json`**（服务器地址段，与现有测试字段并存，见 doc 20 §5.1）：

```json
{
  "ComPort": "",
  "Baud": 2000000,
  "FirmwarePath": "firmware/app_image_v1_1_57.bin",
  "Server": {
    "Url": "http://QI-SERVER:5000",
    "TimeoutSeconds": 5
  },
  "StationId": "ST-01-1"
}
```

| 字段 | 取值 | 说明 |
|------|------|------|
| `Server.Url` | `http://QI-SERVER:5000` 或 `http://192.168.10.10:5000` | **必须 http://**，不能写 https://；IP 形式不依赖主机名解析，最稳 |
| `StationId` | `ST-01-1`…（机位编码） | 与 `machine.json` 拼出的编码一致，贴在机箱上 |

### 9.2 机位数动态增减（1~N 台/工位）

服务器一次搭好后**零改动**，新增一个机位只需三步：

1. **接网线**：新电脑插到交换机 SW1，配同网段 IP（`192.168.10.x` 静态，或路由器 DHCP 保留）；
2. **装上位机**：装 `ProductionStationTool`（源码见上）及 ZQWL-CANFD 驱动（每机位 1 个盒子）；
3. **填配置**：上位机「设置」页命名机位（`stationNo` + `machineId`，写 `machine.json` 并留痕），界面自动显示机位编码 `ST-工位号-机位号`；`appsettings.json` 填 `Server.Url` + `StationId`（= 机位编码）。

减机位：直接撤机，服务器台账不受影响。

## 11. 常见问题

| # | 现象 | 原因 | 处理 |
|---|------|------|------|
| 1 | 双击 exe 一闪而过 / 起不来 | .NET Desktop Runtime 未装 / 产物没拷全 | 装 §4 运行时；publish 目录**整个**拷全 |
| 2 | 启动报「端口占用」/ 监听失败 | 5000 被别的程序占（或起了两份） | `netstat -ano \| findstr :5000` 看占用 PID → `taskkill /PID <pid> /F` |
| 3 | 工位机 ping 通、5000 端口不通 | 防火墙没放行（或网络配置文件是「公用」） | 重做 §3.3；`Set-NetConnectionProfile -InterfaceAlias "以太网" -NetworkCategory Private` |
| 4 | 工位机上线但汇总机页无卡片 | 工位机 `machine.json` 的 `serverHost` 填错 / 服务器没登录「汇总机」身份 | 核对 `serverHost`=汇总机 IP；服务器登录窗选「汇总机」 |
| 5 | 汇总机页「数据库表格」为空 | 各工位记录落各自本机库，汇总机只查本机 `station_records.db` | 跨机汇总按 doc 20/21 规划对接（记录上传 API 落地后生效） |
| 6 | 重启后 exe 没自己起来 | 没配自启 / 没设自动登录 | 重做 §2.3 自动登录 + §7 |
| 7 | 卡片一直「离线」 | 工位机心跳未发出（程序未开/网断）或 45s 无上报 | 复测 `Test-NetConnection`；看工位机日志；汇总机页可「移除记录」让其重登记 |
| 8 | `dotnet --list-runtimes` 没有 WindowsDesktop | 装错运行时（装了纯 Runtime） | 装 **Desktop Runtime**（§4.1） |

## 附录 A：两台机直连（无交换机）最小配置

> **适用**：只有 **2 台电脑**（1 台服务器 + 1 台工位机）的最小场景——一根网线直连，不接交换机/路由器。服务端**零改动**（照 §5 部署，`http://0.0.0.0:5000` 照听），只是把 §2/§3 的网络部分换成下面 3 步。3 台及以上不要直连（见 A.4）。

### A.1 网线

普通 Cat5e 及以上网线 **1 根即可**。两台机网卡都是 Auto-MDI/MDIX，**不需要交叉线**，也不用动网卡速率/双工设置。插上网口灯亮即物理连通。

### A.2 IP 配置（两端各配一次，静态）

没有路由器/交换机就没有 DHCP，两端手动配同网段静态 IP；**网关、DNS 留空**（本链路不出外网）：

| 电脑 | IPv4 地址 | 子网掩码 | 默认网关 |
|------|-----------|----------|----------|
| 服务器 | `192.168.10.10` | `255.255.255.0` | 留空 |
| 工位机 | `192.168.10.11` | `255.255.255.0` | 留空 |

**图形界面**（两端相同步骤）：`设置` → `网络和 Internet` → `以太网` → 点击当前连接 → 「IP 分配」→「编辑」→「手动」→ 打开 IPv4 → 按上表填 → 保存。

**PowerShell**（管理员，在对应电脑上执行）：

```powershell
# 服务器上执行
New-NetIPAddress -InterfaceAlias "以太网" -IPAddress 192.168.10.10 -PrefixLength 24

# 工位机上执行
New-NetIPAddress -InterfaceAlias "以太网" -IPAddress 192.168.10.11 -PrefixLength 24
```

> 若 `192.168.10.x` 与工位机已有的其他网络（办公室路由器等）冲突，两端换同段他值（如 `10.10.10.10` / `10.10.10.11`）即可，后文地址同步替换。

### A.3 防火墙（直连最大的坑）

直连网卡常被 Windows 判成「未识别网络」→ 归为**公用网络**；§3.3 的放行规则若只对「专用」生效，5000 端口会被拦。二选一：

- **改网络类型**（推荐，两台都执行）：

  ```powershell
  Set-NetConnectionProfile -InterfaceAlias "以太网" -NetworkCategory Private
  ```

- **或放行规则勾「公用」**：重做 §3.3 时把配置文件里的「公用」勾上。

之后照 §6.3 从工位机验证（全绿即通）：

| # | 命令（工位机 PowerShell） | 期望输出 |
|---|------|----------|
| 1 | `ping 192.168.10.10` | 有回包 |
| 2 | `Test-NetConnection 192.168.10.10 -Port 5000` | `TcpTestSucceeded : True` |
| 3 | `curl.exe http://192.168.10.10:5000/api/v1/ping` | `{"ok":true,...}` |

> 访问地址一律用 **IP 形式** `http://192.168.10.10:5000`（上位机 `appsettings.json` 的 `Server.Url` 同此）。直连没有 DNS，`http://QI-SERVER:5000` 主机名形式解析不了。

### A.4 3 台及以上不要直连

一根网线只连 2 台。多台工位机不用交换机只能靠服务器多网卡 + Windows 网桥/ICS 串接——能通但脆弱（中间掉一台牵连整条链路、延迟叠加、故障难定位），产线**不建议**。**8 口非网管千兆交换机百元级**，插上即用，网络部分回到 §2/§3 正文即可。
