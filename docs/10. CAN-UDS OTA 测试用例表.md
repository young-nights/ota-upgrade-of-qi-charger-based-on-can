## 1. 基本下载流程

- [X] **TC-0101** (P0) — 完整 Safe Mode 下载流程

  - 前置: 空片或双槽无效，Bootloader Safe Mode，CAN 链路正常
  - 步骤: `10 02`→`27 01`→`27 03`(16帧)→`27 02`→`2E 2010 01`→`31 01 FF 00`→`34`→`36`循环→`37`→`11 01`
  - 预期: 全流程正响应，MCU 复位进入 Trial Boot 窗口
- [X] **TC-0102** (P0) — 双槽有效时 Safe Mode 下载

  - 前置: 双槽有效，Bootloader Safe Mode
  - 步骤: 安全解锁→`2E 2010 01`→擦非活跃槽→`34`→`36`→`37`→`11 01`
  - 预期: 下载成功，Trial Boot 确认后 active_slot 更新
- [X] **TC-0103** (P0) — 不同大小镜像下载

  - 前置: 有效镜像已准备（pack_image.py 打包）
  - 步骤: 分别用最小/正常(~30KB)/最大(接近42KB)镜像执行完整下载
  - 预期: 三种大小均下载成功，Trial Boot 确认后正常运行
- [X] **TC-0104** (P1) — TesterPresent 保活

  - 前置: Bootloader Safe Mode，编程会话已建立
  - 步骤: 执行下载流程，关键步骤间插入 `3E 80`
  - 预期: 全流程无 S3 超时，各服务正常响应
- [X] **TC-0105** (P1) — ResponsePending 时序

  - 前置: Bootloader Safe Mode，CAN 网络正常
  - 步骤: 观察擦槽(`31 01 FF 00`)和验签(`37`)的响应时序
  - 预期: 先收到 `7F xx 78`，等待 2~8s 后收到正响应
- [X] **TC-0106** (P2) — SN 保留验证

  - 前置: 下载完成，MCU 已复位
  - 步骤: 运行 `zcanpro_sn_write.py` 写入 SN（如 `LSCH42JY012606020001`）→ OTA 升级 → 复位后用 UDS 工具读取 DID `F18C`(SN) 和 `F195`(SW 版本)
  - 预期: SN 与 OTA 前一致，SW 版本为新刷入版本
  - 验证方式: `zcanpro_sn_write.py` 脚本写入 + UDS 工具 `22 F18C` / `22 F195` 读回

## 2. Qi 充电 DID

- [ ] **TC-1001** (P0) — 读取充电器能力

  - 前置: APP 正常运行
  - 步骤: `22 21 00`
  - 预期: 返回 4 字节，byte0=0x0F（15W）

- [ ] **TC-1002** (P0) — 写入充电器使能

  - 前置: APP 正常运行
  - 步骤: `2E 21 01 01`（使能）→ `22 21 02`（读充电状态）
  - 预期: 写入成功 `6E 21 01`；若 PA0 检测到手机则 PB2 拉高

- [ ] **TC-1003** (P0) — 读取充电状态

  - 前置: 充电器已使能，手机已放置
  - 步骤: `22 21 02`
  - 预期: 返回 CHARGING 状态（PB2 高电平）

- [ ] **TC-1004** (P0) — 写入功率限值

  - 前置: APP 正常运行
  - 步骤: `2E 21 0D 02`（10W）→ `22 21 0D` 读回
  - 预期: 写入成功，NVM 持久化，Qi 芯片收到功率设置

- [ ] **TC-1005** (P1) — 读取设备在位状态

  - 前置: APP 正常运行
  - 步骤: `22 21 03`
  - 预期: 返回 0x01（在位）或 0x00（不在位），与 Qi 帧回调一致

- [ ] **TC-1006** (P1) — 读取夹臂状态

  - 前置: APP 正常运行
  - 步骤: `22 21 18`
  - 预期: PA0 低电平=0x00（有手机），PA0 高电平=0x01（无手机）

- [ ] **TC-1007** (P1) — 读取故障码

  - 前置: APP 正常运行
  - 步骤: `22 21 0B`
  - 预期: 返回 0x00（无故障）或对应故障码

- [ ] **TC-1008** (P1) — 读取 FOD 状态

  - 前置: APP 正常运行
  - 步骤: `22 21 09`
  - 预期: 返回 0x00（正常）或 0x02（FOD 确认）

- [ ] **TC-1009** (P2) — 功率限值 NVM 持久化

  - 前置: APP 正常运行
  - 步骤: 写入 0x210D=0x03（15W）→ 复位 → 读 0x210D
  - 预期: 复位后仍为 0x03

- [ ] **TC-1010** (P2) — Qi IAP 状态读取

  - 前置: APP 正常运行
  - 步骤: `22 21 32`
  - 预期: 返回 2 字节，state=0x00（空闲），progress=0x00

## 4. 充电控制逻辑

- [ ] **TC-1201** (P0) — 充电双重条件控制

  - 前置: APP 正常运行
  - 步骤: 写`2E 21 01 01`(使能)→确认PA0低(有手机)→读`22 21 02`
  - 预期: PB2高电平，返回CHARGING(0x04)

- [ ] **TC-1202** (P0) — 未使能时霍尔无效

  - 前置: APP 正常运行，未发送使能
  - 步骤: PA0检测到手机(低电平)→读`22 21 02`
  - 预期: PB2保持低，返回DISABLED(0x00)

- [ ] **TC-1203** (P0) — 失能立即断电

  - 前置: 充电器已使能，正在充电
  - 步骤: 写`2E 21 01 00`(失能)
  - 预期: PB2立即拉低，充电停止

- [ ] **TC-1204** (P1) — 功率限值转发到Qi芯片

  - 前置: APP 正常运行，编程会话+安全解锁
  - 步骤: 写`2E 21 0D E8 03`(10W=1000)→读`22 21 0D`
  - 预期: 写入成功，NVM持久化，Qi芯片收到0x02功率设置

- [ ] **TC-1205** (P1) — 功率限值三档校验

  - 前置: 编程会话+安全解锁
  - 步骤: 分别写500(5W)/1000(10W)/1500(15W)→读回
  - 预期: 三档均接受；写600→`7F 2E 31`(RequestOutOfRange)

- [ ] **TC-1206** (P2) — 夹臂状态PA0逻辑

  - 前置: APP 正常运行
  - 步骤: PA0低电平(有磁场)→读`22 21 18`→PA0高电平(无磁场)→读`22 21 18`
  - 预期: 低→0x00(有手机)，高→0x01(无手机)
