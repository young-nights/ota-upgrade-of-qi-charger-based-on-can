## 1. 基本下载流程

- [X] **TC-0101** (P0) — 完整 Safe Mode 下载流程

  - 前置: 空片或双槽无效，Bootloader Safe Mode，CAN 链路正常
  - 步骤: `10 02`→`27 01`→`27 03`(16帧)→`27 02`→`2E 2010 01`→`31 01 FF 00`→`34`→`36`循环→`37`→`11 01`
  - 预期: 全流程正响应，MCU 复位进入 Trial Boot 窗口
- [X] **TC-0102** (P0) — 双槽有效时 Safe Mode 下载

  - 前置: 双槽有效，Bootloader Safe Mode
  - 步骤: 安全解锁→`2E 2010 01`→擦非活跃槽→`34`→`36`→`37`→`11 01`
  - 预期: 下载成功，Trial Boot 确认后 active_slot 更新
- [X] **TC-0103** (P0) — 不同大小镜像下载

  - 前置: 有效镜像已准备（pack_image.py 打包）
  - 步骤: 分别用最小/正常(~30KB)/最大(接近42KB)镜像执行完整下载
  - 预期: 三种大小均下载成功，Trial Boot 确认后正常运行
- [X] **TC-0104** (P1) — TesterPresent 保活

  - 前置: Bootloader Safe Mode，编程会话已建立
  - 步骤: 执行下载流程，关键步骤间插入 `3E 80`
  - 预期: 全流程无 S3 超时，各服务正常响应
- [X] **TC-0105** (P1) — ResponsePending 时序

  - 前置: Bootloader Safe Mode，CAN 网络正常
  - 步骤: 观察擦槽(`31 01 FF 00`)和验签(`37`)的响应时序
  - 预期: 先收到 `7F xx 78`，等待 2~8s 后收到正响应
- [ ] **TC-0106** (P2) — SN 保留验证

  - 前置: 下载完成，MCU 已复位
  - 步骤: 复位后读取 DID `F18C`(SN) 和 `F195`(SW 版本)
  - 预期: SN 与 OTA 前一致，SW 版本为新刷入版本

## 2. APP 触发 OTA

- [X] **TC-0201** (P0) — APP 触发完整 OTA 流程

  - 前置: APP 正常运行，当前在 APP 槽
  - 步骤: `10 02`→APP 写 DOWNLOADING→`11 01` 复位→Bootloader Safe Mode→完整下载
  - 预期: APP→Boot→Safe Mode→下载→Trial→确认，新固件正常运行
- [ ] **TC-0202** (P0) — 现场升级自动化

  - 前置: APP 正常运行
  - 步骤: `10 02`→`11 01`→等 200ms→`10 02`(Boot)→安全解锁→下载→复位
  - 预期: 全程自动化完成，中间掉回 Default 不影响
- [ ] **TC-0203** (P1) — DOWNLOADING 标记写入验证

  - 前置: APP 正常运行
  - 步骤: `10 02`→观察 APP 复位前写入 metadata→复位后 Bootloader 读取
  - 预期: Bootloader 正确识别 DOWNLOADING 标记，进入 Safe Mode
- [ ] **TC-0204** (P1) — 活跃槽切换验证

  - 前置: APP 正常运行，APP 槽为当前活跃槽
  - 步骤: APP 触发 OTA→下载到非活跃槽→`11 01`→Trial 确认
  - 预期: active_slot 切换到新槽，下次重启从新槽启动
- [ ] **TC-0205** (P2) — DOWNLOADING 标记写入失败

  - 前置: APP 正常运行
  - 步骤: `10 02` 后立即断开 CAN→复位后 Bootloader 读取 metadata
  - 预期: 标记未写入时 Bootloader 按默认逻辑启动

- [ ] **TC-0303** (P1) — Trial 窗口内确认

  - 前置: Trial Boot 窗口内
  - 步骤: 发送 `10 02` 确认，测量复位到确认的时间
  - 预期: 10s 窗口内完成确认，新固件激活
- [ ] **TC-0304** (P1) — Trial 边界值测试

  - 前置: Trial Boot 窗口内
  - 步骤: 在 10s 窗口最后一秒发送确认
  - 预期: 仍被接受，新固件激活
- [ ] **TC-0305** (P2) — 回滚后版本验证

  - 前置: Trial 超时回滚完成
  - 步骤: 读取 `F195`、active_slot，尝试再次触发 OTA

- [ ] **TC-0306** (P2) — 重复确认不影响系统

  - 前置: Trial Boot 窗口内
  - 步骤: 反复发送确认消息（多次 `10 02`）
  - 预期: 确认后再次收到不影响系统，active_slot 仅更新一次

## 4. 错误处理 (NRC)

- [ ] **TC-0401** (P0) — 未擦就 34

  - 前置: 编程会话已建立
  - 步骤: 跳过擦槽直接发 `34`
  - 预期: `7F 34 24`（RequestSequenceError）
- [ ] **TC-0402** (P0) — 未解锁就写固件类型

  - 前置: 编程会话已建立
  - 步骤: 未完成 `27 02` 直接发 `2E 2010 01`
  - 预期: `7F 2E 33`（SecurityAccessDenied）
- [ ] **TC-0403** (P0) — blockSeq 跳号

  - 前置: 下载传输进行中
  - 步骤: `36 01`→故意跳 `36 03`
  - 预期: `7F 36 73`（WrongBlockSequenceCounter）
- [ ] **TC-0404** (P0) — 无效固件类型

  - 前置: 编程会话，安全已解锁
  - 步骤: `2E 2010 FF`
  - 预期: `7F 2E 31`（RequestOutOfRange）
- [ ] **TC-0405** (P1) — 默认会话擦槽

  - 前置: 默认会话
  - 步骤: `31 01 FF 00`
  - 预期: `7F 31 7F`（ServiceNotSupportedInActiveSession）
- [ ] **TC-0406** (P1) — 下载大小超限

  - 前置: 编程会话已建立
  - 步骤: `34` size 超过 0xA800
  - 预期: `7F 34 31`（RequestOutOfRange）
- [ ] **TC-0407** (P1) — 传输中断恢复

  - 前置: 下载过程中
  - 步骤: 断开 CAN→重新上电
  - 预期: 从旧固件启动或 Safe Mode，不加载损坏镜像
- [ ] **TC-0408** (P1) — CRC 校验失败

  - 前置: 传输结束
  - 步骤: 镜像 CRC32 篡改后发 `37`
  - 预期: `7F 37 72`，镜像被丢弃
- [ ] **TC-0409** (P2) — 不支持的 SID

  - 前置: 编程会话已建立
  - 步骤: 发送 `0xAB`
  - 预期: `7F AB 11`（ServiceNotSupported）
- [ ] **TC-0410** (P2) — 长度错误

  - 前置: 编程会话已建立
  - 步骤: `10 02 03`（多一字节）
  - 预期: `7F 10 13`（IncorrectMessageLengthOrInvalidFormat）

## 5. 安全访问

- [ ] **TC-0501** (P0) — 正常安全解锁

  - 前置: 编程会话已建立
  - 步骤: `27 01`→SHA256+ECDSA→`27 03`(16帧)→`27 02`
  - 预期: `67 02`，安全解锁成功
- [ ] **TC-0502** (P0) — 错误签名

  - 前置: 编程会话已建立
  - 步骤: `27 01`→篡改签名→`27 02`
  - 预期: `7F 27 35`（InvalidKey）
- [ ] **TC-0503** (P0) — 连续失败锁定

  - 前置: 编程会话已建立
  - 步骤: 连续 3 次发送错误签名
  - 预期: 前2次 `7F 27 35`，第3次 `7F 27 36`，锁定 30s
- [ ] **TC-0504** (P1) — 锁定期间与解除

  - 前置: 安全访问已被锁定
  - 步骤: 锁定期间发 `27 01`→等 30s→正确签名
  - 预期: 锁定期 `7F 27 37`，30s 后可正常解锁
- [ ] **TC-0505** (P1) — 种子随机性

  - 前置: 编程会话已建立
  - 步骤: `27 01` 获取种子 A→取消→重新 `27 01` 获取种子 B→对 A 签名
  - 预期: 种子不同，旧种子签名返回 `7F 27 35`
- [ ] **TC-0506** (P1) — 会话切换清除安全状态

  - 前置: 编程会话已建立
  - 步骤: 解锁→`10 01`→`10 02`→直接 `2E 2010 01`
  - 预期: `7F 2E 33`，需重新解锁
- [ ] **TC-0507** (P2) — S3 超时清除安全状态

  - 前置: 编程会话已建立
  - 步骤: `27 01` 后不发签名，等 5s
  - 预期: S3 超时回退默认会话，安全状态清除

**修复的问题**:

3. **OTA后CAN RX失聪**: Bootloader跳转前SIT1145操作导致收发器状态异常。修复：跳转前不操作SIT1145。
4. **生命周期广播持续发送**: `lifecycle_poll()`每1000ms周期发送。修复：禁用周期广播，只在启动时发一次。

**结论**: V1.1.1 基础功能验证通过，UDS通信正常，Qi IAP流程正常，充电控制逻辑正常。
