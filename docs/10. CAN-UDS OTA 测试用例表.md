## 帧格式速查

公共约定：诊断标记与 UDS 单帧 DLC=8，余量填 `CC`。标记帧发送失败或超过 3ms 即弃帧，启动路径照常走完。

### 启动链

| 场景                 | 线上顺序                                                                        |
| -------------------- | ------------------------------------------------------------------------------- |
| 无 pending、App 完好 | M1 → M2（无 pending）→ M4                                                     |
| OTA 拷贝成功         | M1 → M2（开始）→ M3（Backup 预验）→ 擦写 → M3（App 复验）→ M2（提交）→ M4 |
| 拷贝失败、App 完好   | M1 → M2（开始）→ M3（失败）→ M2（失败）→ M4（旧 App）                       |
| App 无效             | … → Safe mode 心跳                                                            |

M3 只在拷贝链里出现。跳转前的 App 预校验不发标记。

### M1 metadata 快照　`0x18FF480D`

| 字节 | 0      | 1        | 2        | 3      | 4      | 5–7   |
| ---- | ------ | -------- | -------- | ------ | ------ | ------ |
| 含义 | `A1` | meta_src | magic_ok | ver_ok | crc_ok | `CC` |

| 字段              | 取值                                              |
| ----------------- | ------------------------------------------------- |
| meta_src          | `00` 主区生效　`01` 备区恢复　`02` 默认重建 |
| magic / ver / crc | `01` 通过　`00` 失败                          |

主区完好：`A1 00 01 01 01 CC CC CC`

### M2 拷贝决策　`0x18FF480D`

| 字节 | 0      | 1      | 2      | 3–7   |
| ---- | ------ | ------ | ------ | ------ |
| 含义 | `A2` | result | detail | `CC` |

| result | detail | 含义                      |
| ------ | ------ | ------------------------- |
| `00` | `FF` | 无 pending                |
| `00` | `00` | 拷贝开始                  |
| `01` | `00` | 拷贝提交成功              |
| `FF` | step   | 拷贝失败，step 见失败码表 |

### M3 镜像校验（仅拷贝链）　`0x18FF480D`

| 字节 | 0      | 1    | 2         | 3      | 4–7   |
| ---- | ------ | ---- | --------- | ------ | ------ |
| 含义 | `A3` | pass | fail_step | target | `CC` |

| pass   | fail_step | target        | 含义                  |
| ------ | --------- | ------------- | --------------------- |
| `00` | `FF`    | `00`/`01` | 开始校验 Backup / App |
| `01` | `00`    | `00`/`01` | 校验通过              |
| `00` | step      | `00`/`01` | 校验失败              |

### M4 跳转　`0x18FF480D`

入口 `0x08004100` 小端 4 字节：`A4 00 41 00 08 CC CC CC`

### Safe mode

| 帧                 | ID             | 数据                                                    |
| ------------------ | -------------- | ------------------------------------------------------- |
| 探测请求（裸）     | `0x18DA0D03` | `22 21 13`                                            |
| 探测请求（ISO-TP） | `0x18DA0D03` | `03 22 21 13 CC CC CC CC`                             |
| 探测应答           | `0x18DA030D` | `05 62 21 13 FE <fail_step> CC CC`                    |
| TesterPresent      | `0x18DA0D03` | `02 3E 00 CC CC CC CC` → `02 7E 00 CC CC CC CC CC` |
| `3E 80`          | `0x18DA0D03` | 无应答                                                  |
| 其他`22` DID     | `0x18DA030D` | `03 7F 22 11 CC CC CC CC`                             |
| 心跳（每 500ms）   | `0x18FF260D` | `01 41 42 54 <cause> <fail_step> A5 00`               |

两种探测写法应答字节完全相同。心跳周期内会重切 SIT1145 Normal。

| cause  | 含义                 |
| ------ | -------------------- |
| `02` | App 无效，拷贝未失败 |
| `03` | 拷贝失败且 App 无效  |

### 失败码

镜像校验 `fail_step`（探测应答末字节、M3、心跳共用）：

| 值              | 含义                                     |
| --------------- | ---------------------------------------- |
| `01`          | magic 错误                               |
| `02`          | `image_length` 为 0 或超出槽范围       |
| `03`          | 镜像 CRC 失败                            |
| `04`          | 复位向量越出`[0x08004100, 0x08010000)` |
| `05` / `06` | 已废弃，不会出现                         |

拷贝级失败码（只出现在 M2.detail）：

| 值     | 含义                       |
| ------ | -------------------------- |
| `FF` | metadata 与镜像 CRC 不一致 |
| `FE` | 擦除失败                   |
| `FD` | 编程失败                   |

### last_boot_reason（DID `0x2115`）

| 值     | 含义         |
| ------ | ------------ |
| `00` | 上电         |
| `01` | 软件复位     |
| `02` | 看门狗       |
| `03` | OTA 搬运成功 |
| `04` | 拷贝失败     |

reason 未变时不写 metadata。读值仍稳定，擦写次数需调试器观察。

## 第一部分：Boot 层测试（TC-Bxxx）

- [X] **TC-B001** (P0) 正常启动（无 pending，App 完好）

  - 前置: 主 metadata 有效（MATO / v4 / CRC 通过，`backup_valid=0`），App 镜像完好
  - 步骤: 上电，监听 `0x18FF480D`、`0x18DA030D`、`0x18FF260D`
  - 预期:| 顺序 | 数据                        | 含义          |
    | ---- | --------------------------- | ------------- |
    | 1    | `A1 00 01 01 01 CC CC CC` | M1 主区完好   |
    | 2    | `A2 00 FF CC CC CC CC CC` | M2 无 pending |
    | 3    | `A4 00 41 00 08 CC CC CC` | M4 跳 App     |
  - 判定: 三帧顺序、字节一致；M4 后 `22 F1 95` 可读
- [X] **TC-B002** (P1) metadata 来源（M1 字节 2 = 0 / 1 / 2）

  - 前置: 可改写主 metadata `0x0801C000`、备 metadata `0x0801C800`
  - 步骤与预期:| 轮 | 操作                     | M1                                                                                                   |
    | -- | ------------------------ | ---------------------------------------------------------------------------------------------------- |
    | 1  | 主区完好，不写 Flash     | `A1 00 01 01 01 CC CC CC`（src=0）                                                                 |
    | 2  | 破坏主区 magic，备区完好 | `A1 01 01 01 01 CC CC CC`（src=1）；落盘先备后主，下次上电回到 src=0                               |
    | 3  | 双区都坏                 | `A1 02 01 01 01 CC CC CC`（src=2 默认重建，`backup_valid` 清 0；magic/ver/crc 由默认值重建为 1） |
  - 判定: 轮 3 默认值随即落盘。App 镜像完好时仍走 M2 / M4。双区重建会清 `backup_valid`，已有 pending 镜像本轮不再拷贝
- [X] **TC-B003** (P0) 进入 Safe mode（破坏 App 区）

  - 前置: 设备已正常运行，记录当前 App 版本
  - 步骤: 擦除 App 区首扇区 `0x08004000` → 上电 → 抓 `0x18FF480D` 与 `0x18FF260D`
  - 预期:| 顺序 | 数据                        | 含义                                           |
    | ---- | --------------------------- | ---------------------------------------------- |
    | 1    | `A1 00 01 01 01 CC CC CC` | M1 仍读 metadata                               |
    | 2    | `A2 00 FF CC CC CC CC CC` | 无 pending                                     |
    | 3    | 无 M4                       | 镜像 magic 失败，`fail_step=1`，cause=`02` |
    | 4    | `01 41 42 54 02 01 A5 00` | 心跳立刻发出                                   |
  - 判定: 设备停在 Safe mode；后续 B004 / B006 可接着测
- [X] **TC-B004** (P0) Safe mode 探测（双格式）

  - 前置: 承接 B003，`fail_step=1`
  - 步骤: 各发一次
    1. 裸帧 `22 21 13`（DLC=3）
    2. ISO-TP `03 22 21 13 CC CC CC CC`
  - 预期: 两次均回 `05 62 21 13 FE 01 CC CC`
  - 判定: 两种写法逐字节相同
- [X] **TC-B005** (P0) fail_step 判例

  - 前置: 每轮破坏 App 区后上电进 Safe mode，发 `03 22 21 13 CC CC CC CC`
  - 预期:| 轮    | 构造                                     | 探测应答                    |
    | ----- | ---------------------------------------- | --------------------------- |
    | 1     | 擦首扇区 / 改 magic                      | `05 62 21 13 FE 01 CC CC` |
    | 2     | `image_length=0` 或 `> 0xBF00`       | `05 62 21 13 FE 02 CC CC` |
    | 3     | payload 改 1 字节、头 CRC 不改           | `05 62 21 13 FE 03 CC CC` |
    | 4     | 复位向量改出`[0x08004100, 0x08010000)` | `05 62 21 13 FE 04 CC CC` |
    | 5 / 6 | —                                       | 不会出现                    |
  - 判定: 每轮应答末字节与上表一致。拷贝级失败码 `FF`/`FE`/`FD` 只出现在 M2.detail（例如 `A2 FF 03 CC CC CC CC CC`），探测应答读的是镜像 `fail_step`
- [X] **TC-B006** (P1) Safe mode 心跳（500ms）

  - 前置: 设备停在 Safe mode
  - 步骤: 监听 `0x18FF260D` ≥ 3 秒
  - 预期: 每 500ms 一帧 `01 41 42 54 <cause> <fail_step> A5 00`；cause 为 `02` 或 `03`，`fail_step` 与探测应答相同
  - 判定: 1 秒窗口 ≥ 2 帧，间隔 500ms ± 10ms；cause / step 与 B003 / B005 构造一致
- [ ] **TC-B007** (P0) 坏 Backup 预验拦截

  - 前置: App 区完好；Backup 区 magic、长度合法，payload CRC 损坏；`backup_valid=1`
  - 步骤: 上电，抓 `0x18FF480D`；起来后读 `0x2115` / `0x2112`
  - 预期:

    | 顺序 | 数据                        | 含义            |
    | ---- | --------------------------- | --------------- |
    | 1    | `A1 01 00 01 01 01 CC CC` | M1              |
    | 2    | `A2 00 00 CC CC CC CC CC` | 拷贝开始        |
    | 3    | `A3 00 FF 00 CC CC CC CC` | Backup 预验开始 |
    | 4    | `A3 00 03 00 CC CC CC CC` | 预验失败 CRC    |
    | 5    | `A2 FF 03 CC CC CC CC CC` | 拷贝失败        |
    | 6    | `A4 00 41 00 08 CC CC CC` | 跳回旧 App      |

    App 区保持原镜像（预验失败发生在擦除之前）。

    | DID        | 请求                        | 应答                                       |
    | ---------- | --------------------------- | ------------------------------------------ |
    | `0x2115` | `03 22 21 15 CC CC CC CC` | `04 62 21 15 04 CC CC CC`（COPY_FAIL）   |
    | `0x2112` | `03 22 21 12 CC CC CC CC` | `04 62 21 12 06 CC CC CC`（Rolled Back） |

    `backup_valid` 仍为 1，下次开机重跑整链。
  - 判定: 坏 Backup 拦在擦写之前；App 完好时跳回旧 App。App 同样无效时才进 Safe mode（cause=`03`）
- [ ] **TC-B008** (P0) 正常 OTA 拷贝链

  - 前置: 完整 UDS 下载，`0x37` 验签通过后置 `backup_valid=1` 并自复位
  - 步骤: 复位后抓 `0x18FF480D`；起来后读 `0x2115` / `0x2112` / `0x2114`
  - 预期:
    | 顺序 | 数据                                                       | 含义                                        |
    | ---- | ---------------------------------------------------------- | ------------------------------------------- |
    | 1    | `A1 01 00 01 01 01 CC CC`                                | M1                                          |
    | 2    | `A2 00 00 CC CC CC CC CC`                                | 拷贝开始                                    |
    | 3    | `A3 00 FF 00 CC CC CC CC` → `A3 01 00 00 CC CC CC CC` | Backup 预验通过                             |
    | 4    | （无标记）                                                 | 擦除 + 编程 + 读回                          |
    | 5    | `A3 00 FF 01 CC CC CC CC` → `A3 01 00 01 CC CC CC CC` | App 复验通过                                |
    | 6    | `A2 01 00 CC CC CC CC CC`                                | 提交：`backup_valid` 清 0，reason=OTA_ACT |
    | 7    | `A4 00 41 00 08 CC CC CC`                                | 跳新 App                                    |

    | DID        | 应答数据字节           |
    | ---------- | ---------------------- |
    | `0x2115` | `03` OTA_ACT         |
    | `0x2112` | `05` Confirmed       |
    | `0x2114` | `FE`（pending 已清） |
  - 判定: 上表逐帧一致；M2 提交帧是搬运完成的线上凭证
- [ ] **TC-B009** (P1) 拷贝中途断电

  - 前置: 可重复走 B008
  - 步骤: 在 M2(`00 00`) 之后、M2(`01 00`) 之前的擦除/编程窗口随机断电 ≥ 3 次；每次重新上电
  - 预期: `backup_valid` 只在复验通过后才清，重启后再次出现 M2 `A2 00 00 …`，最终至少一轮走到 `A2 01 00 …` + M4 + App。纯断电不增加 `copy_retry_count`（读 `0x2116` 辅证）
  - 判定: 任意断电点后能自恢复
- [ ] **TC-B010** (P1) last_boot_reason

  - 前置: 读 `03 22 21 15 CC CC CC CC` → `04 62 21 15 <reason> CC CC CC`（metadata 读失败回 `FF`）
  - 预期:| 轮 | 操作                     | `0x2115`     |
    | -- | ------------------------ | -------------- |
    | 1  | 冷上电                   | `00`         |
    | 2  | 软件复位                 | `01`         |
    | 3  | 看门狗复位               | `02`         |
    | 4  | OTA 搬运成功当次（B008） | `03`         |
    | 5  | 拷贝失败当次（B007）     | `04`         |
    | 6  | 连续两次冷起             | 两次都是`00` |
  - 判定: 五种 reason 都能读到；连续开机读值稳定

## 第二部分：CAN-UDS 驱动层测试（TC-Dxxx）

| 项        | 值                                                                           |
| --------- | ---------------------------------------------------------------------------- |
| 位时序    | 250 kbps，18MHz / (54+18) Tq，采样点 75%，位时间 4µs；classic CAN，FDF=0    |
| 空闲电平  | 隐性（TXD 高）                                                               |
| ISO-TP    | SF 载荷 ≤ 7B；FC 默认 CTS / BS=0 / STmin=1ms；N_As / N_Bs / N_Cr = 1s       |
| RX 软队列 | 深度 16，满则丢新帧                                                          |
| 填充      | UDS / 诊断 SF、FC、M1–M4 一律 DLC=8、余量`CC`；心跳与生命周期为满 8B 数据 |

- [X] **TC-D001** (P0) 物理层与总线空闲

  - 前置: 分析仪 / 示波器挂 CANH / CANL；Boot 与 App 各测一轮
  - 步骤: ① 测波特率；② 空闲电平；③ 抓包核 ID
  - 预期: ① 250kbps、SP=75%、classic CAN；② 空闲隐性；③ 29-bit 扩展帧，ID 集合见环境表
  - 判定: 示波器 + 抓包逐项比对
- [X] **TC-D002** (P1) CAN ID 路由

  - 前置: App 与 Safe mode 各测一轮
  - 步骤: 向下列 ID 发 `03 22 21 02 CC CC CC CC`：① `0x18DA030D`；② `0x18DB33F1`；③ `0x18FF260D`
  - 预期:
    1. App：① 无 UDS 应答；② 有应答，响应仍走 `0x18DA030D`；③ 无应答
    2. Safe mode：只收 `0x18DA0D03`。Boot 硬件滤波：Filter0 精确匹配 `0x18DA0D03`，Filter1 匹配 `0x18DB33xx`。② 能过硬件滤波，协议层丢弃；③ 被硬件滤波拦下
  - 判定: 响应 ID 恒为 `0x18DA030D`，无关 ID 不触发 UDS / NRC
- [ ] **TC-D003** (P1) SIT1145 引脚互逆与唤醒（App）

  - 前置: `CAN_LP_STANDBY_ENABLE=1`（当前源码为 0，本用例在 =1 下执行）
  - 步骤: ① 进 Standby，测 PA11 / PA12；② 唤醒，测恢复顺序；③ 确认无 bus-off
  - 预期:
    1. Standby：PA12 推挽输出高，PA11 输入上拉
    2. 恢复顺序：PA11 / PA12 回 CAN 复用 → SIT1145 Normal（≤ 3 次重试）→ 清 CW → 等 PA11 回隐性（≤ 5ms）→ 控制器上线。TXD 先回 CAN 复用再切 Normal
    3. 唤醒后首帧 `10 01` 在 30ms 内被 ACK 并回 `50 01`
  - 判定: 往返后通信立刻恢复，无 error passive / bus-off
- [ ] **TC-D005** (P0) ISO-TP 单帧与 `CC` 填充

  - 前置: App 运行
  - 步骤: ① `03 22 21 02 CC CC CC CC`；② `02 3E 00 CC CC CC CC`
  - 预期: ① `04 62 21 02 <state> CC CC CC`；② `02 7E 00 CC CC CC CC CC`。SF 恒 8B，余量 `CC`
  - 判定: SF 载荷 ≤ 7B，尾部均为 `CC`
- [ ] **TC-D006** (P0) ISO-TP 多帧（含 `0x36`）

  - 前置: 读识别 DID 任意会话；`0x36` 需编程会话 + 安全解锁
  - 步骤与预期:
    1. 上行：`03 22 F1 95 CC CC CC CC` → ECU FF `10 23 62 F1 95 …`（35B）→ 测试仪 FC `30 00 01 CC CC CC CC` → ECU CF，SN `1`→`F` 回绕，STmin=1ms、BS=0，末帧尾 `CC`
    2. 下行：测试仪 FF `10 <len_hi> 36 <bsc> …` → ECU FC `30 00 01 CC CC CC CC` → 测试仪 CF `21…`
    3. FF 长度 > 4095 → ECU FC `32 00 00 CC CC CC CC`（OVERFLOW）
  - 判定: 每个 FF 后 8ms 内见到 FC；整包重组后 UDS 应答正常
- [ ] **TC-D007** (P1) FC 送达

  - 前置: App；高频连续 `34`（走 FF 下行）
  - 步骤: 连续 ≥ 30 次 `34`，统计 FF 后 FC
  - 预期: FC 100% 在 FF 后 8ms 内出现（ECU：先等上一帧落地 ≤ 5ms，单帧确认 ≤ 8ms，失败 1ms 间隔重试 ≤ 3 次）
  - 判定: 30/30 命中
- [ ] **TC-D008** (P2) ISO-TP 超时

  - 前置: 支持停发 / 改包的测试仪
  - 步骤: ① ECU 发 FF 时不回 FC；② 测试仪发 FF 后停发 CF；③ 约 1s 后补发正常 SF
  - 预期: ① N_Bs=1000ms 后放弃本次发送，可接受新请求；② N_Cr=1000ms 后 RX 回 IDLE；③ 后续 SF 正常
  - 判定: ZCANPRO 时间戳为秒级，只判「约 1s 后状态复原」。毫秒精度需逻辑分析仪
- [ ] **TC-D009** (P1) Padding `0xCC`

  - 前置: App 与 Safe mode
  - 步骤: 抓全部 UDS / 诊断帧，查尾字节
  - 预期: App SF / FC、Boot FC、探测应答 / `3E` / NRC、M1–M4 均为 DLC=8、余量 `CC`。心跳与生命周期为满 8B 数据
  - 判定: 抓包中无 `00` 尾填充（满 8B 的 `0x18FF260D` / `0x18FF480D` 除外）
- [ ] **TC-D010** (P2) TX 缓冲满

  - 前置: 高负载或短时无 ACK（拔终端电阻 / 总线拥塞）
  - 步骤: ① 连续触发 ECU 长应答 / 多帧；② 总线恢复后观察
  - 预期: Boot 邮箱满则丢帧、不阻塞。App 先试一个邮箱，再试另一个，两拒才丢。总线恢复后发送正常
  - 判定: 可见个别 UDS 超时重发，系统不卡死
- [ ] **TC-D011** (P2) RX 软队列溢出

  - 前置: 可高速连发的测试仪；Safe mode 与 App 各测
  - 步骤: ECU 处理慢窗口突发 > 16 帧
  - 预期: 队列深 16，满时丢新到帧、不清队。排空后恢复收帧
  - 判定: 溢出期间部分请求无应答（host 按 P2=50ms 重发即可），恢复后首帧即应答
- [ ] **TC-D012** (P1) Boot 诊断发送有界

  - 前置: Boot 固件；TX 不利（高负载或短时无 ACK）
  - 步骤: 该条件下上电，观察启动链与 M 帧
  - 预期: M1–M4 发不出去或 3ms 内发不完就弃帧。个别 M 帧可缺失，M2 决策与跳转 / Safe mode 不受影响，metadata 无额外擦写
  - 判定: 最终启动结果（M4 或 Safe mode 心跳）与总线良好时一致
- [ ] **TC-D013** (P1) Standby 唤醒与延迟在线

  - 前置: `CAN_LP_STANDBY_ENABLE=1`（当前源码为 0，本用例在 =1 下执行）；可读 `03 22 21 19 CC CC CC CC`
  - 步骤与预期:
    1. Standby 下向总线发任意 250kbps 帧 → 收发器唤醒 → 30ms 内 ACK 主机重发并回 `50 01` → 100ms 后发 BOOTUP `0x18FF260D`
    2. 上电 init 只置位，首次 poll 才切 Normal（SysTick 就绪后再做 harvest / CTS）
    3. `0x2119`：`[0]` flags（bit0=进过 Standby，bit1=WUP 唤醒），`[1]` wup_count，`[2-3]` last_standby_sec 小端
  - 判定: 唤醒往返成功，BOOTUP 延迟 100ms ±，`0x2119` 三字段递进更新

## 附录：DID 合集

门禁：读（`0x22`）任意会话、无需安全访问。写（`0x2E`）先查会话再查安全（会话不对回 `7F 2E 22`，未解锁回 `7F 2E 33`）。未知 DID：读 `7F 22 31`，写 `7F 2E 31`。

Safe mode：只应答 `22 21 13` 探测和 `3E`；其他 `22` 回 `7F 22 11`；其余 SID 无应答。
