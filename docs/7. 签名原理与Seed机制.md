# 12. 签名原理与 Seed 机制

> **适用**：理解 ECDSA 非对称加密原理、UDS SecurityAccess Seed-Challenge 认证流程
> **涉及文件**：`boot_verify.c/h`、`can_protocol.c`、`uECC.c/h`、`sha256.c/h`（SecurityAccess 全在 APP 侧，Boot 无 UDS）

---

## 1. ECDSA 私钥/公钥配对原理

本项目使用 **ECDSA P-256 (secp256r1)** 椭圆曲线非对称加密算法。

### 1.1 核心数学关系

```
公钥 = 私钥 × 椭圆曲线基点 G
```

| 组件 | 长度    | 说明                                                                                |
| ---- | ------- | ----------------------------------------------------------------------------------- |
| 私钥 | 32 字节 | 随机整数，存储于`docs/keys/private.pem`                                           |
| 公钥 | 65 字节 | 椭圆曲线上的点 (X, Y)，格式`04 \|\| X \|\| Y`，存储于 Bootloader `.ecdsa_pubkey` 段（内置）+ Device Info `ecdsa_pubkey[65]`（支持密钥轮换） |

**不可逆性**：知道公钥无法反推私钥（椭圆曲线离散对数问题，计算上不可行）。

### 1.2 签名与验证流程

| 步骤 | 签名方（产线/PC）                                                        | 验证方（Bootloader）                                                               |
| ---- | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| 1    | 用 SHA-256 对数据取哈希`h`                                             | 同样对数据取 SHA-256 哈希`h`                                                     |
| 2    | 用**私钥** + 随机数 k 对 `h` 运算 → 产出 64 字节签名 `(R, S)` | —                                                                                 |
| 3    | —                                                                       | 用**公钥** + 哈希 `h` + 签名 `(R, S)` 运算 → 输出 1（有效）或 0（无效） |

**关键特性**：

- 私钥持有者能签名，公钥持有者能验证，**反过来不行**
- 同一份数据用不同随机数 k 签名，结果不同，但都有效
- 没有私钥就无法伪造签名（安全性的根基）

### 1.3 本项目中的两个用途

| 用途                                    | 签名对象                   | 存储位置                          | 验证时机            |
| --------------------------------------- | -------------------------- | --------------------------------- | ------------------- |
| 镜像签名校验 (`boot_verify.c`)        | 裸固件数据（不含 256B 头） | 镜像头 signature 字段 (偏移 0x0C) | 每次上电跳转 APP 前 |
| SecurityAccess 身份认证 (`0x27` 服务) | SHA-256(seed)              | 运行时通过 CAN 发送               | OTA 升级前解锁      |

两者使用**同一把密钥对**：私钥在 PC/产线侧，公钥烧在 Bootloader 的 `.ecdsa_pubkey` 段。

## 2. Seed 机制（UDS 0x27 SecurityAccess）

### 2.1 什么是 Seed

Seed 是 MCU 在 SecurityAccess 服务中生成的**随机挑战值**（Challenge），本质上是一个 **nonce（Number used ONCE）**。

- 长度：32 字节（由 8 次 `generate_random_seed()` 拼成）
- 生成时机：每次 Host 发送 `27 01` 时重新生成
- 用途：与签名绑定，防止重放攻击

### 2.2 完整交互流程

```
Host (PC/产线)                            MCU (APP, can_protocol.c)
    │                                          │
    │──── 27 01 (Request Seed) ───────────────>│
    │                                          │ 8× generate_random_seed()
    │                                          │ → g_seed[32]（32 字节随机数）
    │<─── 67 01 [seed: 32 bytes] ─────────────│
    │                                          │
    │  (本地计算)                               │
    │  hash = SHA-256(seed)                    │
    │  sig  = ECDSA_Sign(hash, private_key)    │
    │                                          │
    │──── 27 03 [block_seq][sig 分块] ×N ────>│  填 g_sa_sig_buf[64]
    │<─── 67 03 [block_seq] ─────────────────│
    │                                          │
    │──── 27 02 (触发验签) ─────────────────>│  hash = SHA-256(seed)
    │                                          │  uECC_verify(pubkey, hash, sig)
    │<─── 67 02 (解锁成功) ─────────────────│  if result==1 → security_unlocked=1
    │    或 7F 27 35 (Invalid Key)             │  else → fail_count++, 超 3 次锁 30s
```

### 2.3 Seed 生成算法

```c
// can_protocol.c（SecurityAccess 全在 APP 侧，Boot 无 UDS）
static uint32_t generate_random_seed(void)
{
    static uint32_t lfsr = 0xA5A5A5A5U;     // LFSR 初始值
    uint32_t tick = timer_get_tick();         // SysTick 计数（时间熵源）

    lfsr ^= tick;                            // XOR 混入时间熵

    // 32-bit 最大长度 LFSR（tap: bit 31, 21, 1, 0）
    bit = ((lfsr >> 0) ^ (lfsr >> 1) ^ (lfsr >> 21) ^ (lfsr >> 31)) & 1U;
    lfsr = (lfsr >> 1) | (bit << 31);

    lfsr ^= (tick << 7) ^ (tick >> 13);     // 再次混合

    return lfsr;
}

// 27 01 处理：循环 8 次拼出 32 字节 seed（大端写入）
for (idx = 0U; idx < 32U; idx += 4U)
{
    uint32_t seed_val = generate_random_seed();
    g_seed[idx]     = (uint8_t)((seed_val >> 24) & 0xFFU);
    g_seed[idx + 1] = (uint8_t)((seed_val >> 16) & 0xFFU);
    g_seed[idx + 2] = (uint8_t)((seed_val >>  8) & 0xFFU);
    g_seed[idx + 3] = (uint8_t)( seed_val         & 0xFFU);
}
```

**设计要点**：

- 使用 **LFSR（线性反馈移位寄存器）+ SysTick 时间戳** 生成伪随机数，循环 8 次拼出 32 字节 seed
- 每次 `27 01` 请求都重新生成（已解锁时按 ISO 14229 返回 32 字节全 0）
- 对于安全访问场景，LFSR 的随机性已足够（seed 的作用是保证新鲜性，而非密码学安全随机数）

### 2.4 Seed 验证（MCU 端）

```c
// 验证逻辑（can_protocol.c handle_security_access，APP 侧）
sha256_hash(g_seed, 32U, hash);                                  // 对 32 字节 seed 取 SHA-256
result = uECC_verify(g_app_ecdsa_pubkey, hash, g_sa_sig_buf);   // ECDSA 验签
```

Host 发回的 64 字节签名是**对 SHA-256(seed) 的 ECDSA 签名**，MCU 用预置公钥验证。

### 2.5 为什么公钥能验证随机 Seed 的签名

**公钥验证的是「签名能力」，不是「数据内容」。**

ECDSA 验证函数只关心三件事：

1. 公钥是什么
2. 数据哈希是什么
3. 签名是什么

**它不关心数据是什么**——可以是固件、可以是 seed、可以是任意字节。

#### 类比理解

| 角色 | 比喻                               |
| ---- | ---------------------------------- |
| 私钥 | 一把能刻签名的「刻章刀」           |
| 公钥 | 一个能识别这把刀刻痕的「验证模具」 |
| 签名 | 用刀在数据上刻出的印记             |

验证过程：Host 用「刻章刀」（私钥）在 `SHA-256(seed)` 上刻了一个印记，MCU 用「验证模具」（公钥）检查这个印记是否匹配。**模具不关心你刻的是什么内容，它只检查「这个印记是不是这把刀刻的」。**

#### Seed 随机不影响验证

```
Host 侧：
  seed = MCU 发来的 32 字节随机数
  hash = SHA-256(seed)           ← 固定的哈希算法
  sig  = ECDSA_Sign(hash, 私钥)  ← 私钥对这个哈希签名

MCU 侧：
  hash = SHA-256(seed)           ← 同样的 seed，同样的哈希
  result = uECC_verify(公钥, hash, sig)  ← 公钥验证签名
```

验证成功与否只取决于：

1. 私钥和公钥是否配对（是 → 签名有效）
2. 签名时的 hash 和验证时的 hash 是否相同（是 → 同一个 seed）

**seed 随机的作用不是让验证「更难」或「更容易」，而是让每次交互的签名内容不同，防止重放。**

#### 数学保证

```
已知：公钥 Q，数据哈希 h，签名 (r, s)
验证：检查 (r, s) 是否由持有私钥 d 的人对 h 生成的

椭圆曲线保证：
  只有知道 d 的人才能生成有效的 (r, s)
  知道 Q 的人可以验证 (r, s) 是否有效
  从 Q 无法推导出 d
```

所以：MCU 有公钥 Q → 能验证签名；Host 有私钥 d → 能生成签名；seed 随机 → 每次 h 不同 → 每次签名不同 → 无法重放。

#### 代码对应

```c
// MCU 端（验证方，can_protocol.c）
sha256_hash(g_seed, 32U, hash);                                  // 算哈希
result = uECC_verify(g_app_ecdsa_pubkey, hash, g_sa_sig_buf);   // 公钥验签

// Host 端（签名方）
hash = SHA256(seed)                                              // 算同样的哈希
sig  = ECDSA_Sign(hash, private_key)                             // 私钥签名
```

**公钥能验证，是因为椭圆曲线数学保证了「公钥-私钥-签名-哈希」四者的数学关系成立。和 seed 是否随机无关——seed 只是让哈希值每次不同，让签名无法重放。**

### 2.6 为什么需要 Seed

**核心目的：防止重放攻击（Replay Attack）。**

**假设没有 seed**：

```
攻击者抓到一次合法的 0x27 02 响应（64 字节签名）
→ 下次直接重放同一签名 → 解锁成功
```

**有 seed 后**：

```
每次 0x27 01 返回的 seed 不同
→ 同一个签名只对当次 seed 有效
→ 重放旧签名 → SHA-256(新seed) ≠ SHA-256(旧seed) → 验签失败
```

**Seed 保证了每次认证交互的唯一性和新鲜性。**

### 2.7 完整认证状态机

```
                        ┌─────────────────┐
                        │  Idle (锁定)     │
                        └────────┬────────┘
                                 │ 27 01
                                 ▼
                        ┌─────────────────┐
                        │  Seed Generated  │ ← 生成 32 字节随机 seed
                        └────────┬────────┘
                                 │ 27 03 分块送签名 + 27 02 验签
                                 ▼
                    ┌────────────┴────────────┐
                    │                         │
               验签通过                    验签失败
                    │                         │
                    ▼                         ▼
           ┌────────────────┐        ┌────────────────┐
           │  Unlocked       │        │  fail_count++   │
           │  (安全解锁)     │        └────────┬───────┘
           └────────────────┘                  │
                                     fail_count >= 3?
                                      ┌────┴────┐
                                     Yes        No
                                      │          │
                                      ▼          ▼
                             ┌──────────────┐  回到 Seed Generated
                             │  Lockout 30s  │  (等待下次 27 01)
                             └──────────────┘
```

## 3. 安全防护措施

| 措施             | 实现                                               | 代码位置                                                   |
| ---------------- | -------------------------------------------------- | ---------------------------------------------------------- |
| 失败次数限制     | 连续 3 次失败锁定 30 秒                            | `SECURITY_MAX_FAILURES=3`, `SECURITY_LOCKOUT_MS=30000` |
| 已解锁时 seed 全 0 | ISO 14229 规范，避免重复计算（返回 32 字节 0x00） | `memset(&unlock_resp[2], 0, 32U)`（can_protocol.c）  |
| 签名分帧传输     | 64 字节签名通过 `0x03` 子功能 + block_seq 分块发送，`0x02` 才触发验签 | `sub_func == 0x03` 填 `g_sa_sig_buf[64]`，序号错回 NRC |
| Response Pending | ECDSA 验证在 M4F 上约 30~50ms，先回 NRC 0x78       | `proto_send_nrc(0x78)`                                   |
| 请求顺序校验     | 必须先 27 01 再 27 02，否则 NRC 0x24               | `g_seed_generated` 状态检查                              |

## 4. 密钥管理

### 4.1 密钥对生成

```bash
# 生成 ECDSA P-256 私钥
openssl ecparam -genkey -name prime256v1 -noout -out docs/keys/private.pem

# 提取公钥
openssl ec -in docs/keys/private.pem -pubout -out docs/keys/public.pem

# 查看公钥坐标（写入 boot_verify.c 用）
openssl ec -in docs/keys/private.pem -text -noout
```

### 4.2 密钥对匹配验证

```bash
# 用私钥签名，再用公钥验证
echo "test" > /tmp/test.bin
openssl dgst -sha256 -sign docs/keys/private.pem -out /tmp/test.sig /tmp/test.bin
openssl dgst -sha256 -verify docs/keys/public.pem -signature /tmp/test.sig /tmp/test.bin
# 输出 "Verified OK" 表示密钥对匹配
```

### 4.3 安全约束

| 约束         | 说明                                               |
| ------------ | -------------------------------------------------- |
| 私钥不入 MCU | `docs/keys/private.pem` 仅存在于 PC/产线侧       |
| 公钥存储     | Bootloader 内置公钥（编译固化）+ Device Info `ecdsa_pubkey[65]`（支持运行时轮换） |
| 密钥轮换     | 通过 UDS DID `0x2120` 写入新公钥到 Device Info（需 Programming + SecurityAccess），Bootloader 优先读 Device Info；更换内置公钥需重烧 Bootloader |
| 量产密钥     | 开发密钥必须替换为正式密钥对                       |

## 5. 与镜像签名校验的关系

| 对比项   | 镜像签名校验                              | SecurityAccess Seed 认证      |
| -------- | ----------------------------------------- | ----------------------------- |
| 使用场景 | 上电跳转 APP 前                           | OTA 升级前解锁                |
| 签名对象 | 裸固件数据（整块数据）                    | SHA-256(seed)（32 字节随机数） |
| 签名存储 | 镜像头 signature 字段                     | 运行时通过 CAN 帧传输         |
| 验证频率 | 每次上电                                  | 每次安全访问会话              |
| 相同点   | 都用 ECDSA P-256 + SHA-256 + 同一把密钥对 | —                            |
