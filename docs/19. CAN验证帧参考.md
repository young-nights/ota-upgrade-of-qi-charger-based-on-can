# 19. CAN 验证帧参考

> 固件验证/排障用总线帧全集：Boot 诊断帧、生命周期标记、低功耗诊断帧、唤醒帧约定与判读方法。
> 适用 APP 固件 1.1.41+（生命周期四值词汇表自 1.1.41 起）。硬件前提见 §7。
> 关联文档：`10. CAN-UDS OTA 测试用例表`（用例）、`16. 功能需求文档`（DID 表）、`SIT1145_WUF_选择性唤醒异常测试报告`（WUF 早期异常）。

## 1. CAN ID 总表

| ID | 方向 | 用途 |
|----|------|------|
| `0x18DA0D03` | 主机→设备 | UDS 请求（ISO-TP）。**也是 SIT1145 WUF 唤醒匹配 ID** |
| `0x18DA030D` | 设备→主机 | UDS 应答（ISO-TP）+ UDS 侧识别帧 |
| `0x18FF480D` | 设备→主机 | Boot 诊断帧 M1–M4（A1/A2/A3/A4） |
| `0x18FF260D` | 设备→主机 | 生命周期标记帧（BOOTUP / WK / SB / ABT…） |
| `0x18FF270D` | 设备→主机 | 低功耗配置诊断帧（E0/E2/E3/E4）+ UDS 组包标记（AA 55） |

总线参数：250 kbps、Classical、29 位扩展帧、120Ω 终端。

## 2. Boot 诊断帧（ID `0x18FF480D`，Bootloader 发出）

开机/唤醒重新供电后出现。**看到 A1 = 整机冷启动**（不是复位故障）。

### M1 / A1 — metadata 来源与完整性

```
A1 [src] [magic_ok] [ver_ok] [crc_ok] CC CC CC
```

| 字节 | 含义 |
|------|------|
| [1] src | `00` 主区 `0x0801C000` / `01` 备区恢复 `0x0801C800` / `02` 默认重建 / `FF` 未记录 |
| [2] magic_ok | metadata `MATO` 魔数正确 = 1 |
| [3] ver_ok | metadata 版本正确 = 1 |
| [4] crc_ok | metadata CRC32 一致 = 1 |

正常开机：`A1 00 01 01 01`。出现 `A1 02 …` = 两个 metadata 区都失效走默认重建（查供电/写 Flash 历史）。

### M2 / A2 — 备区拷贝结果

```
A2 [ret] [info] CC CC CC CC CC
```

[1]=拷贝返回码（`FF`=无拷贝/未涉及），[2]=明细。

### M3 / A3 — APP 校验结果

```
A3 [pass] [fail_step] [target] CC CC CC CC
```

pass=1 通过；fail_step=0xFF 校验进行中；target=0 备区源 / 1 APP 区。

### M4 / A4 — 跳转地址

```
A4 [addr0] [addr1] [addr2] [addr3] CC CC CC
```

地址小端。实机：`A4 00 31 00 08` = 跳 `0x08003100`（APP 入口）。

## 3. 生命周期标记帧（ID `0x18FF260D`，CCU 词汇表 2026-10-28）

格式：`[0]=状态码 [1..7]=0x00`（全零）。**字节 0 仅允许 4 值**：

| byte0 | 名称 | 含义 | 发送方 |
|-------|------|------|--------|
| `0x01` | BOOTUP | 上电/复位，开始启动 | **Bootloader**（整机上电后 <100ms） |
| `0x02` | OPERATIONAL | 启动完成，可正常工作（**1s 周期广播**，SLEEP 后停） | APP |
| `0x03` | WAKEUP | **保留词汇位，固件不发送**（不区分冷启动/唤醒启动，2026-10-28 决策） | — |
| `0x04` | SLEEP | 即将进入休眠（确认送达后才睡，失败重试 1 次） | APP |

发送序列（**不区分冷启动/唤醒启动**）：

| 场景 | 序列 |
|------|------|
| 启动（插电 / CAN 唤醒） | `01` → `02` |
| 进入休眠 | 休眠前发 `04`，发送完成后再进休眠 |

要点：
- BOOTUP 在**整机上电后 100ms 内**（含 Bootloader 阶段）；
- 多帧 UDS 传输期间状态帧不丢弃，传输结束后补发（pending FIFO）；
- 0x37 OTA 复位前**不发预告帧**（静默复位）；Boot 安全模式 ABT 心跳已废弃（fail_step 经 `22 2113` 查）；
- wup_count/唤醒源/睡眠时长不再上线，改查 DID `0x2119`/`0x211A`。

### 同步的 UDS 侧识别帧（ID `0x18DA030D`，ISO-TP SF，不在词汇表约束内）

| 场景 | 载荷 |
|------|------|
| 冷启动 | `03 01 41 00 CC CC CC CC` |
| 唤醒启动 | `07 01 41 57 4B cnt src secL` |

### legacy 格式（1.1.40 及更早固件，读旧日志时对照）

`[1]=0x41('A')` + ASCII 标记：`01 41 00` BOOTUP / `01 41 57 4B cnt src secL secH` WK / `06 41 53 42` SB / `01 41 42 54` ABT。主机解码器保留双格式兼容分支。

## 4. 低功耗配置诊断帧（ID `0x18FF270D`）

入睡序列中、`sit1145_sleep_enter()` **之前**发出（配置前快照）。结束标记 `[7]=0xA5`。

### E0 — 模式/事件/CAN Control 快照

```
E0 MODE EVENT_EN TRANSCEIVER_EVENT CAN_CONTROL TRX_EVENT_STATUS flags A5
```

| 字节 | 寄存器 | 判读 |
|------|--------|------|
| [1] MODE | 0x01 | 快照在切 Sleep 前，恒 `07`（Normal）；**不是「没睡成」的证据** |
| [2] EVENT_EN | 0x23 | `03`=CWE\|CFE 已使能（bit0=CWE，bit1=CFE） |
| [3] TRANSCEIVER_EVENT | 0x24 | 残留事件位（CW=bit0，WUF=bit1） |
| [4] CAN_CONTROL | 0x20 | `41`=init 值（CFDC\|CMC=01）；`71`=CFDC\|PNCOK\|CPNC\|CMC=01（WUF 已锁） |
| [5] TRX_EVENT_STATUS | 0x63 | CW=bit0 等 |
| [6] flags | — | bit0=`g_lp_sleep_fail`，bit1=`g_lp_ever_sleep` |

### E2 — WUF 掩码/帧控

```
E2 wuf_ok frame_ctrl MASK0 MASK1 MASK2 MASK3 A5
```

`frame_ctrl` 期望 `C8`（IDE=1、PNDM=1、DLC=8）。MASK 全 `00`=精确 ID 匹配。
注意：`[1] wuf_ok` 是 E2 发送时点的预设值（0），不代表本轮配置结果。

### E3 — WUF ID / 数据掩码

```
E3 ID0 ID1 ID2 ID3 DM0 DM1 A5
```

ID 小端，期望 `03 0D DA 18`（= `0x18DA0D03`）。**DLC=8 的有效数据掩码在 DM0~DM7**（本帧读 DM0/DM1，DM2~7 见 E4），期望 DM0=0x02、DM1=0x3E。

### E4 — 数据掩码 DM2–DM7

```
E4 DM2 DM3 DM4 DM5 DM6 DM7 A5
```

期望全 `00`（byte2~7 不查，含 0xCC 填充段）。

### AA 55 — UDS 组包完成标记

```
AA 55 [PCI] 00 00 00 A5
```

UDS 请求重组完成时发出，`[2]`=该请求的 ISO-TP PCI。**不是故障**，仅证明请求已入协议栈。

## 5. 唤醒帧约定

- **WUF 过滤器（严格）**：ID=`0x18DA0D03`（精确）+ **DLC=8**（PNDM=1 时 DLC 不匹配整帧不唤醒）+ 数据 `02 3E 00` 前缀**近似命中**。
- **唤醒帧 = `02 3E 00 CC CC CC CC CC`（DLC=8，0xCC 填充）**——与普通 UDS SF 同线格式；**全链路统一 DLC=8**（其余 UDS 指令/应答同为 DLC=8+0xCC 填充）。DLC=3 裸 `02 3E 00` 不再唤醒。
- **数据近似限制（硬件约束）**：SIT1145 数据匹配是 `(rx & DM) ≠ 0` 任一命中（组位图，无期望值寄存器），DM0=0x02/DM1=0x3E——凡 DLC=8 且 byte0 bit1 或 byte1 bit1~5 任一为 1 的帧都会唤醒（如 `02 10 00 CC…`、`FE FF FF…`）。字节级严格匹配硬件做不到。
- 推荐 burst：`02 3E 00 CC…`（DLC=8）**≥6 帧（常用 8）、间隔 250ms**——burst 对抗工具链无 ACK 丢帧（见 §7 约束）。

## 6. 验证判读方法

### 6.1 休眠进入证据链

1. `06 41 53 42`（SB 标记）+ E0/E2/E3/E4 诊断帧出现（≈ 空闲 `CAN_LP_IDLE_TIMEOUT_MS`=10s 后）；
2. 之后总线**完全静默**；
3. **硬件电平（INH/电流）是唯一最终判据**——总线静默 ≠ 休眠（`can_driver_offline()` 后必然静默）。

时序注意：SB→E4 诊断约 3s，INH 断电 ≈ SB+3.5~4s。**SB 后 ≥5s 才可认定整板已断电**，过早发帧会打在未睡设备上。

### 6.2 唤醒证据链

WUF 匹配 → INH 恢复供电 → **整机冷启动**，总线依次出现：

```
A1 / A2 / A4（Boot 诊断帧） → 01 00…（BOOTUP，Bootloader） → 02 00…（OPERATIONAL） → 7E 00 等 UDS 应答
```

判读要点：
- 唤醒后出现 **A1/A2/A4 是正常签名**（=重新供电），不是复位故障；
- **不区分冷启动/唤醒启动**（2026-10-28）：两种启动序列一致（`01→02`），WAKEUP(0x03) 不发送。

### 6.3 非唤醒帧（负向验证）

错误 ID（如 `0x18DA0D04`、`0x18DA0D02`、`0x18FF0101`、`0x18DA0D01`）单帧/多帧均**不应**唤醒。
实测基线：单帧定点 14/14、轻量三帧/轮 10 轮 30/30 零误唤醒。
若错误 ID 复现唤醒（历史报告 `0x18DA0D04` 曾异常），查 WUF MASK/ID 配置（E2/E3 帧）。

### 6.4 测试脚本

原 `python_tools/wsl/tc_lp_sleep_wake.py`、`standby_wake_test.py` 等已于 2026-10-28
删除（脚本废弃）；证据抓取改用 QiChargerStationTool 日志 / 任意 ZQWL 收帧工具，
判读仍按本节证据链执行。

## 7. 硬件与工具链约束（判读前必读）

1. **供电拓扑**：SIT1145 进 Sleep → INH 断电 = **AT32 整板断电**（MCU 不轮询、RAM 清零）；CAN 唤醒 → 重新供电冷启动。
2. **休眠时收发器不 ACK**：任何无 ACK 流量（错误帧/唤醒帧）都可能把 ZQWL 等适配器打进 TX 错误/自动重发状态，导致后续唤醒 burst 丢失（不醒）或 UDS 洪泛（同帧连续应答数百次）。
   **约束：唤醒 burst 必须是设备入睡后的第一笔总线流量。**
3. **判休眠必须硬件电平**：E0/SB/静默/UDS 无响应只能证明「固件以为自己睡了」。
4. 充电门：`0x2101` 充电使能 + 霍尔在位时刷新空闲计时——**充电中永不进休眠**。

## 8. 常见误判对照

| 现象 | 常见误判 | 实际含义 |
|------|----------|----------|
| 唤醒后出现 A1/A2/A4 | 「设备复位了/不稳」 | 正常：CAN 唤醒=重新供电冷启动 |
| E0 中 MODE=0x07 | 「没睡成」 | 快照在切 Sleep **前**，恒为 Normal，不作判据 |
| SB 后总线静默 | 「已休眠」 | 只证明 MCU CAN 离线；以硬件电平为准 |
| UDS 应答数百条 | 「固件死循环」 | 多为适配器无 ACK 重发风暴下的连续应答（§7.2） |
| 唤醒后只看到 `01→02` | 「缺 WAKEUP」 | 正常：已不区分冷启动/唤醒启动（0x03 保留不发） |
| `AA 55 …` 帧 | 「协议异常」 | UDS 组包完成标记，正常 |
| A1 src=02 | 「启动异常」 | metadata 双区失效走默认重建，查供电/Flash 写史 |
