## 1. 项目概述

### 1.1 目标

在 **CAN 2.0B 扩展帧、250 kbps** 上，用 **ISO-TP + UDS** 升级 Qi 无线充主控固件：

- 双槽 A/B ping-pong：只擦写**非活跃槽**，失败可回退
- 镜像带 256 字节 **XATO** 头（magic / 长度 / CRC32 / ECDSA P-256 `R||S` / 版本）
- **Trial Boot**：新镜像必须在 `trial_timeout_sec`（默认 10 s）内由 APP 确认，否则复位回 Bootloader 回滚
- **Safe Mode**：双槽无效，或 APP 把 metadata 写成 `OTA_STATE_DOWNLOADING` 后复位，Bootloader 停留在 UDS 下载循环

### 1.2 硬件

引脚以 [1. AT32F426KBU7-4_引脚定义.md](<1.%20AT32F426KBU7-4_引脚定义.md>) 为准。

| 项           | 值                                                                                                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 主控         | AT32F426KBU7-4，Cortex-M4F                                                                                                                                         |
| 主频         | 180 MHz（HEXT + PLL，APB1 = 180 MHz）                                                                                                                              |
| Flash / SRAM | 128 KB / 20 KB                                                                                                                                                     |
| 外设库       | SPL（`at32f422_426_*`），非 HAL                                                                                                                                  |
| CAN          | CAN1，PA11=RX / PA12=TX，29-bit，250 kbps                                                                                                                          |
| CAN 收发器   | SIT1145：SPI1 PA4=CS（低有效）、PA5=SCK、PA6=MISO、PA7=MOSI；**先**配 Normal Mode 再开 CAN。PB3 输出低                                                       |
| USART2       | PA2/PA3，9600 8N1，接 Qi 芯片                                                                                                                                      |
| USART1       | PB6/PB7 Debug，预留                                                                                                                                                |
| 霍尔         | **仅 PA0 一路** `H_OUT`：低电平 = 有磁场 = 手机在位 → DID `0x2118=0x00`；高电平 = 无磁场 = 无手机 → DID `0x2118=0x01`。同时作为充电使能条件之一。无第二路 GPIO |
| 12V Buck     | PB1`12V_MCU_Control`，**低电平开启**                                                                                                                       |
| 无线充 5V    | PB2`5V_MCU_Control`，**高电平开启**；低功耗 / Programming / SHUTDOWN 必须拉低                                                                              |
| NC GPIO      | 软件输出低：PA1、PB0、PB10、PA8、PA9、PA10、PA15、PB4、PB5、PB8                                                                                                    |

### 1.3 两个工程

```
                    CAN 250 kbps, ISO-TP, ID 0x18DA0D03 / 0x18DA030D
                    ┌──────────────────────▲──────────────────────┐
                    │                      │                      │
          ┌─────────┴──────────┐  ┌────────┴─────────┐
          │ Bootloader 28 KB   │  │ APP 42 KB/槽     │
          │ 0x08000000         │  │ 槽基址+256 入口  │
          │ 引导 / 验签 / 跳转 │  │ 充电业务 + 触发  │
          │ Safe Mode UDS 下载 │  │ Trial 确认/超时  │
          └─────────┬──────────┘  └────────┬─────────┘
                    │   共享 metadata / XATO 头
                    ▼
          0x0801C000 Primary  +  0x0801C800 Backup  +  0x0801D000 Device Info  +  0x0801E000 NVM
```

| 工程       | 目录                          | 职责                                                                                 |
| ---------- | ----------------------------- | ------------------------------------------------------------------------------------ |
| Bootloader | `qi_wireless_bootloader/`   | 上电引导、槽选择、镜像校验、跳转；Safe Mode 完成全部下载 UDS                         |
| APP Slot A | `qi_wireless_code_slotA/`   | 充电业务、生命周期广播、UDS 查询；**只负责把 MCU 送进 Boot**，不实现 0x34/0x36 |
| APP Slot B | `qi_wireless_code_slotB/`   | 同 Slot A，IROM1 Start = `0x08011900`                                              |

产线只烧 **Bootloader + Slot A**。Slot B 出厂为空，第一次现场 OTA 写入 B。

## 2. Flash 布局

常量：Bootloader `boot_metadata.h`，APP `ota_trigger.h`（`OTA_` 前缀，数值相同）。

| 区域        | 起始           | 大小               | 说明                                                 |
| ----------- | -------------- | ------------------ | ---------------------------------------------------- |
| Bootloader  | `0x08000000` | `0x7000` (28 KB) | 引导 + Safe Mode                                     |
| Slot A      | `0x08007000` | `0xA800` (42 KB) | 头 256 B + 代码，入口`0x08007100`                  |
| Slot B      | `0x08011800` | `0xA800` (42 KB) | 同上，入口`0x08011900`                             |
| Metadata 主 | `0x0801C000` | `0x800`          | `ota_metadata_t` 272 B                             |
| Metadata 备 | `0x0801C800` | `0x800`          | 先写备、再写主                                       |
| Reserved    | `0x0801D000` | `0x1000`         | Device Info 保留区，存放 SN、ECDSA 公钥等设备标识，OTA 擦写跳过 |
| NVM         | `0x0801E000` | `0x2000`         | APP 配置                                             |

```
0x08000000  Bootloader
0x08007000  Slot A 头 (XATO)     ← 打包后的 .ota.bin 从这里烧
0x08007100  Slot A 向量表/代码   ← Keil Target IROM1 Start
0x08011800  Slot B 头
0x08011900  Slot B 向量表/代码
0x0801C000  Metadata
0x0801D000  Device Info (SN 等)
0x0801E000  NVM
0x08020000  Flash 末尾
```

Keil **只在 Target 配 IROM**，不用 scatter。Slot A：`IROM1 = 0x08007100 / 0xA700`；编 Slot B 镜像时改为 `0x08011900 / 0xA700`。裸 `.bin` 不含头，必须经 `pack_image.py` 加头后再烧槽起始地址。详见文档 9。

> **Flash 擦除粒度**：AT32F426 的 Flash 页大小为 **1 KB（0x400）**，`FLASH_SECTOR_SIZE` 定义为 `0x400U`。`erase_slot_flash()` 以 1 KB 步进擦除整个槽区域。

### 2.1 Metadata（272 B，`"MATO"` = `0x4F54414D`）

CRC32 覆盖除末尾 `crc32` 外的 268 字节（IEEE 802.3，`0xEDB88320`）。

| 字段                                                           | 含义                                                                                                                             |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `active_slot`                                                | 最近一次**已确认**的槽（0=A，1=B）                                                                                         |
| `pending_slot`                                               | 刚下完、待试运行的槽；`0xFE` = 无                                                                                              |
| `slot_*_valid` / `slot_*_crc32`                            | 该槽镜像是否通过校验                                                                                                             |
| `trial_state`                                                | 0 IDLE / 1 PENDING / 2 ACTIVE / 3 CONFIRMED                                                                                      |
| `trial_slot` / `trial_retry_count` / `trial_max_retries` | 试运行槽与重试（默认上限 3）                                                                                                     |
| `trial_timeout_sec`                                          | APP 确认窗口，默认 10                                                                                                            |
| `ota_state`                                                  | 0 IDLE / 1 DOWNLOADING。为 1 时 Bootloader**不跳 APP**，进 Safe Mode                                                       |
| `last_boot_reason`                                           | `0x00` 上电 / `0x01` 软件复位（`NVIC_SystemReset` / UDS `11`） / `0x02` WDG 遗留码 / `0x03` OTA 激活 / `0x04` 回滚 |

### 2.2 Image Header（槽起始 256 B，`"XATO"` = `0x4F544158`）

```
槽基址 + 0x000  magic / image_length / crc32 / signature[64] / version[16] / timestamp / pad
槽基址 + 0x100  应用镜像（向量表 + 代码），长度 = image_length ≤ 0xA700
```

跳转地址 = `槽基址 + 256`。CRC32 和 ECDSA 都只覆盖头后面的固件，不含头本身。

## 3. 职责划分：谁做什么

| 能力                          | APP                                                                                              | Bootloader Safe Mode                                 |
| ----------------------------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| `0x10` 会话                 | 支持 Default / Programming / Extended                                                            | 同左；切回 Default 会中止下载并清解锁                |
| `0x11` hardReset            | Programming 会话下先写`DOWNLOADING` 再复位；否则只复位                                         | 回`0x51` 后 `NVIC_SystemReset`                   |
| `0x27` SecurityAccess       | ECDSA 解锁（与 Boot 共用同一套公钥）                                                             | ECDSA 解锁，下载硬门禁                               |
| `0x22` 读 DID               | 版本、槽、OTA 状态等                                                                             | 同左；擦除后`0x2114` 为下载目标槽                  |
| `0x2E 2010`                 | Programming +`0x27` 解锁后可写 `01`（APP）；未解锁 NRC `0x33`，非 Programming NRC `0x22` | 只接受`01` = APP                                   |
| `0x2E F18C`                 | 产线写 SN：Programming + 解锁后写入 Device Info（`0x0801D000`）；默认会话只读                  | 同左（Safe Mode 也可写，便于空片工位）               |
| `0x31 FF00` 擦槽            | NRC`0x11`                                                                                      | 擦**非活跃槽**                                 |
| `0x34 / 0x36 / 0x37 / 0x38` | **一律 NRC `0x11`**                                                                      | 完整下载路径                                         |
| Trial 确认 / 超时             | `ota_trial_poll()`：健康 100 ms 后确认；超时 `NVIC_SystemReset`                              | `process_trial_state()`：PENDING→ACTIVE，超限回滚 |
| 看门狗                        | **不实现**（已确认：无 IWDG / WWDT）                                                       | **不实现**                                     |

识别当前固件：APP 和 Boot **都**实现 `0x27`、`0xF180`、`0x2113`，不能用这三项判断。主机发 `0x34`（或 `0x31 01 FF00`）：APP 回 NRC `0x11`（下载只在 Boot）；Boot 在未满足会话/解锁/擦除时回 `0x22` / `0x33` / `0x24`，**不会**是 `0x11`。`7F 34 11` = 还在 APP，先 `10 02` + `11`。

## 4. Bootloader 工作流

入口：`qi_wireless_bootloader/mdk_user/Src/main.c`。

**顺序与旧文档不同：先看 `ota_state`，再跑 Trial，再选槽。** `DOWNLOADING` 时不会处理 Trial，也不会跳 APP。

```
上电 / 复位
  │
  ├─ system_clock_config()  180 MHz
  ├─ nvic_priority_group_config(GROUP_4)
  ├─ timer_drv_init()
  ├─ boot_metadata_init(&g_meta)     主区 → 备份 → 默认值
  ├─ last_boot_reason = detect_boot_reason()
  │
  ├─ ota_state == DOWNLOADING ? ──是──▶ enter_safe_mode()  （不返回）
  │
  ├─ process_trial_state(&g_meta)
  ├─ select_boot_slot()              PENDING/ACTIVE → trial_slot，否则 active_slot
  ├─ try_boot_slot(选中槽)  只验签，通过后 main 再 jump
  │     失败 → try_boot_slot(另一槽)；若 Trial 失败而旧槽成功，先写回滚 metadata 再跳
  └─ 双槽失败 → enter_safe_mode()
```

`detect_boot_reason()` 一次读 CRM 复位标志再 `CRM_ALL_RESET_FLAG` 清掉：WDT/WWDT→`0x02`，`CRM_SW_RESET_FLAG`（`NVIC_SystemReset` / UDS `11 01`）→`0x01`，POR→`0x00`。当前工程已去掉 IWDG。OTA `0x37` 后 Trial PENDING 复位进 Boot 时，`process_trial_state()` 仍会把 `last_boot_reason` 改写成 `OTA_ACT`。

Trial 的 10 s 窗口在 **APP** 里数。Bootloader `main` **不**创建 trial 1 s 定时器。

### 4.1 进入 Safe Mode 的条件

1. metadata `ota_state == OTA_STATE_DOWNLOADING`（APP `0x10 0x02` + `0x11` 写入）
2. `select_boot_slot` 失败，或双槽 `try_boot_slot` 都失败（空片、头损坏、验签失败）

进入后 **不把 `ota_state` 清成 IDLE**。保持 DOWNLOADING，直到：

- `0x37` 成功（写成 IDLE + `TRIAL_STATE_PENDING`），或
- S3 超时 / 切回 Default Session，且至少有一个槽 `valid`（写成 IDLE，中止下载）

事件循环：`timer_poll` + `can_driver_poll` + `isotp_poll` + SIT1145 保活（每 500 ms 重发 `sit1145_normal_mode_set()`）。CAN 收包经 ISO-TP 重组后再进 `uds_process_message()`。

### 4.2 Trial 状态机（`boot_trial.c`）

`0x37` 成功时写入：`trial_state = PENDING`，`trial_slot = 刚写的槽`，`pending_slot` 同该槽，**不改 `active_slot`**（仍指向上一份已确认镜像）。

| 进入      | 动作                                                                                                                                                                                                             |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| IDLE      | 无                                                                                                                                                                                                               |
| PENDING   | → ACTIVE，`retry_count++`，`last_boot_reason = OTA_ACT`，保存                                                                                                                                               |
| ACTIVE    | 未确认又回到 Boot（含 APP`NVIC_SystemReset` / UDS `11`）则 `retry_count++`；`> max_retries` → 回滚：IDLE、`pending_slot=none`、切 `active_slot` 到另一 **valid** 槽、`BOOT_REASON_ROLLBACK` |
| CONFIRMED | → IDLE，清`retry_count`                                                                                                                                                                                       |
| 非法值    | 强制 IDLE                                                                                                                                                                                                        |

`select_boot_slot()`：`PENDING` 或 `ACTIVE` 选 `trial_slot`（`active_slot` 仍是上一份已确认镜像）；`IDLE`/`CONFIRMED` 走 `active_slot`。槽号不是 A/B 则失败进 Safe Mode。

- 产线 A 升 B：`active_slot` 仍为 A，ACTIVE 选 B 试跑
- 试跑失败且 A 仍可用：先把 Trial 清成 IDLE 并保存，再跳 A
- APP 确认后把 `active_slot` 写成 B

### 4.3 选非活跃槽（`select_inactive_slot`）

擦写永远对着**对面槽**，不覆盖正在跑的那份：

| 条件                           | 下载目标 |
| ------------------------------ | -------- |
| A valid 且`active_slot == A` | B        |
| B valid 且`active_slot == B` | A        |
| A 无效（含出厂空片）           | A        |
| 其余                           | B        |

产线只有 A：第一次 CAN OTA 擦 B。A、B 都无效（Safe Mode 空片）：擦 A。

### 4.4 Safe Mode UDS（硬门禁顺序）

Programming Session + 解锁之后：

```
10 02
  → 27 01 seed
  → 27 03 分片  或  一条 ISO-TP 27 02 带 64 B 签名
  → 27 02 验签（可先 7F 27 78）
  → 2E 2010 01
  → 31 01 FF00 擦非活跃槽     ← 不擦就 34 → NRC 0x24
  → 22 2114 读目标槽（脚本核 Reset Handler）
  → 34 申请下载（size = 打包文件总长，含 256 B 头）
  → 36 按块写（从槽基址写，第一包就是 XATO 头）
  → 38 可选（头里已有签名则可跳过）
  → 37 结束：flush、验镜像、置 PENDING
  → 11 01 复位进入试运行
```

逐步 CAN 数据见[第 7 节](#7-safe-mode-逐步-can-帧)。S3 = 5 s 无 UDS 掉回 Default。长步骤会先回 NRC `0x78`（ResponsePending）。

**0x27**

- `0x01`：4 字节 seed（已解锁则 seed 全 0）
- `0x03`：累积 64 字节 `R||S`（带 blockSeq）
- `0x02`：本条 ISO-TP 若 ≥ 66 字节则直接取 `data[2..65]`；否则用 `0x03` 缓冲。`SHA256(seed)` + `uECC_verify`
- 连续 3 次失败锁 30 s（NRC `0x36`）。切 Default **不清**失败计数

**0x31 01 FF00**

先 `7F 31 78`，擦目标槽全部 **1 KB** 扇区（`FLASH_SECTOR_SIZE = 0x400`），置 `g_dl_erased=1`、`pending_slot`、`ota_state=DOWNLOADING`，写指针从**槽基址**开始（含头）。

> **注意**: 擦槽操作 (`0x31 01 FF00`) 只擦除固件 Slot 区域，不会擦除 Device Info 保留区 (`0x0801D000` ~ `0x0801DFFF`)。Bootloader 在执行擦除时会校验目标地址，拒绝擦除 Device Info 区域，从而保护 SN 序列号等设备信息。

**0x34**

未擦 → NRC `0x24`。未解锁 → `0x33`。非 Programming → `0x22`。正响应 `[0x74, 0x20, 0x01, 0x00]`（maxBlockLength = 256，含 SID+序号+数据）。写入地址以擦除时绑定的槽为准，0x34 里的地址字段被解析但**不作为写指针**。

**0x36**

`blockSeq` 从 `01` 起，`FF` 下一帧 `01`（跳过 `00`）。内部 4 字节拼 word 再 `flash_word_program`，末尾不足 4 字节在 `0x37` 里 `program_image_flush()`。单帧 ISO-TP 最多约 5 字节数据；正式刷写走多帧，每包最多 254 字节数据。

**0x38**

可选。仅当头内 signature 仍全 `0xFF` 时，`0x37` 才把缓冲的 64 字节补进偏移 12。`pack_image.py` 已经签过头则不必发 0x38。

**0x37**

校验已写长度（含头）≥ 256，且等于 0x34 声明的 size（若声明过）；`boot_verify_image` 通过后：

- 对应槽 `valid=1`、写入 header 中的 crc32
- `ota_state = IDLE`
- `pending_slot = trial_slot = 下载槽`
- `trial_state = PENDING`，`trial_retry_count = 0`
- **不改 `active_slot`**

验签失败 → NRC `0x72`，该槽不会被标 valid。

### 4.5 镜像校验（`boot_verify_image`）

`g_verify_fail_step`：0 通过；1 magic；2 length；3 CRC；4 Reset Handler 不在本槽；5 公钥无效；6 ECDSA 失败。

1. `magic == XATO`
2. `0 < image_length ≤ 槽大小 − 256`
3. CRC32(槽基址+256, image_length) == header.crc32
4. 向量表 Reset Handler（清 Thumb 位）落在 `[入口, 槽末)` —— **拒绝把 Slot A 链接的 bin 写进 Slot B**
5. `SHA256(固件) + uECC_verify(Bootloader 内公钥, header.signature)`

公钥：`boot_verify.c` 中 `g_ecdsa_public_key`（SEC1 未压缩 `04||X||Y`），必须与 `docs/keys/private.pem` 成对。换密钥后必须重烧 Bootloader。

### 4.6 跳转 APP（`boot_jump_to_app`）

参数是**入口**（槽基址 + 256），不是槽基址。

关中断 → 复位 CAN1 并关时钟 → 关 SPI1 并关时钟 → **调用 `sit1145_standby_mode_set()` 将 SIT1145 切到 Standby** → 关 SysTick → 清 NVIC ICER/ICPR → `VTOR = app_addr` → 读 MSP / Reset_Handler → 校验 MSP 在 SRAM、Reset 在 APP Flash 范围 → `__set_MSP` → Thumb 跳转。

Bootloader **不开中断**；APP `main` 里 `__enable_irq()`，并用 `&__Vectors` 再设一次 VTOR（Slot A / B 链接都能对上）。

## 5. APP 工作流

入口：`qi_wireless_code_slotA/mdk_user/Src/main.c`（Slot B 同结构）。

```
SCB->VTOR = &__Vectors
system_clock_config / NVIC GROUP_4
timer_drv_init / board_gpio_init / nvm_drv_init
can_driver_init          SIT1145 初始化（先 Standby）
can_protocol_init        trial 状态 → 直接 Normal；否则 offline 等唤醒
qi_uart_init
__enable_irq()
lifecycle_init
ota_trial_init           若本镜像正在 trial，启动 10 s 窗口

while (1)
  timer_poll
  can_driver_poll
  can_protocol_poll        唤醒检测 + S3 + ISO-TP N_Cr + 6 min idle timeout
  qi_uart_poll
  lifecycle_poll           OPERATIONAL 时每 1000 ms 广播
  ota_trial_poll
```

**没有 IWDG，没有 `wdg_drv`。** 试运行超时靠 `NVIC_SystemReset()` 回到 Bootloader。

### 5.1 生命周期（`0x18FF260D`）

8 字节，byte0 = 状态，其余 0。`lifecycle_init` 发 BOOTUP；随后 `OPERATIONAL`（或 DEGRADED）每 1 s 一帧。`0x11` 复位前发 SHUTDOWN，并 `can_driver_wait_tx_idle(20)`。

### 5.2 低功耗（CAN 收发器）

> **当前策略**：`CAN_LP_IDLE_TIMEOUT_MS = 0`，CAN 常在线，SIT1145 保持 Normal 模式，不进入低功耗。通过 `#if` 条件编译禁用 Standby 分支。

| 状态       | SIT1145 模式 | MCU 功耗 | 唤醒方式              |
| ---------- | ------------ | -------- | --------------------- |
| 常规运行   | **Normal**   | 正常     | —                     |
| Safe Mode 保活 | Normal  | 正常     | 每 500ms 重发 `sit1145_normal_mode_set()` |

Bootloader 跳转 APP 前会调用 `sit1145_standby_mode_set()` 将 SIT1145 切到 Standby，APP 启动后由 `can_protocol_init()` 恢复 Normal。

Safe Mode 保活：每 500 ms 重发 `sit1145_normal_mode_set()`，防止 SIT1145 在 UDS 等待期间掉回 Standby。

### 5.3 APP 触发 OTA（唯一入口）

**不要对 APP 发 `0x34`。** 正确顺序：

```
主机 → APP : 02 10 02          Programming Session
APP  → 主机 : 02 50 02
主机 → APP : 02 11 01          hardReset
APP                ota_trigger_prepare()
                   回 02 51 01
                   SHUTDOWN + 等 TX
                   NVIC_SystemReset
Bootloader         ota_state==DOWNLOADING → Safe Mode
```

`ota_trigger_prepare()`：

- 读 metadata；两份都坏则填默认值，并把**当前运行槽**标 valid（避免误判"没有 APP"）
- **不擦槽、不改 active_slot**
- 只写 `ota_state = DOWNLOADING`，先 Backup 再 Primary

非 Programming 会话下的 `0x11 0x01`：**不**写 DOWNLOADING，只复位。此时若双槽仍有效，Bootloader 会再跳回 APP。

### 5.4 Trial 确认（`ota_trigger.c`）

`ota_trial_init`：仅当 `trial_state==ACTIVE` **且** `trial_slot == ota_running_slot()`（由 VTOR 判断）才打开窗口。

`ota_trial_poll`：

- 超过 `trial_timeout_sec`（默认 10 s）→ `NVIC_SystemReset()`，Bootloader 看到仍是 ACTIVE，累加 retry，超限回滚
- 启动满 100 ms 后 `ota_confirm_trial()`：把 `active_slot = trial_slot`，`pending = NONE`，`trial_state = CONFIRMED`，`retry=0`，`ota_state=IDLE`

下次上电 `process_trial_state` 把 CONFIRMED 收敛为 IDLE。

### 5.5 APP UDS 一览

| SID                                                  | 行为                                                                                     |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `0x10`                                             | Default / Programming / Extended；S3 = 5 s                                               |
| `0x11 01`                                          | 见 5.3                                                                                   |
| `0x22`                                             | DID 见下表                                                                               |
| `0x27`                                             | ECDSA 解锁（与 Boot 共用公钥）                                                           |
| `0x31` / `0x34` / `0x36` / `0x37` / `0x38` | NRC`0x11`                                                                              |
| `0x2E 2010`                                        | 需 Programming + 已解锁；写`01` 成功。未解锁 NRC `0x33`，非 Programming NRC `0x22` |
| `0x2E F18C`                                        | 产线写 SN，见下表与[文档 9 §6.1](<9.%20APP镜像打包与产线烧录.md>)                        |
| `0x3E`                                             | TesterPresent，任意 UDS 都会刷新 S3                                                      |

**DID（APP）** — 识别类为定长 32 字节、右补 ASCII 空格（与文档 3 / SRS 一致）。XATO 头 `version[16]` 只用于打包，不是 DID 长度。

| DID                     | 内容                                                                                                                                     |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `0xF180`              | Bootloader 版本，编译期字符串（如`"1.0.0"`），与 XATO 头无关                                                                           |
| `0xF18C`              | 序列号，Device Info（`0x0801D000`）。读：定长 32 字节空格填充；magic/CRC 无效则 NRC `0x31`。写：仅 Programming + Level 1，见产线扫码 |
| `0xF193`              | 硬件版本，优先 Device Info`hw_version`，否则编译期字符串                                                                               |
| `0xF195`              | APP 软件版本，来自本槽 XATO 头`version[]`；头无效则回编译期字符串                                                                      |
| `0x2010`              | 固件类型，读固定`0x01`；写见上表 `0x2E`                                                                                              |
| `0x2112`              | metadata`ota_state`                                                                                                                    |
| `0x2113`              | **正在运行的槽**（VTOR），不是尚未确认的 `active_slot`                                                                           |
| `0x2114`              | `pending_slot`                                                                                                                         |
| `0x2115` / `0x2116` | 上次启动原因 / 回滚次数低 8 位                                                                                                           |

**充电控制 DID**（详见文档 3 §8.5）：

| DID       | 内容 |
| --------- | ---- |
| `0x2100` | 充电器能力，4 字节，byte0=15（15W） |
| `0x2101` | 充电器使能，W，0x00=禁用/0x01=使能，复位后默认 0x00 |
| `0x2102` | 充电状态，R，PB2 电平：高=CHARGING, 低+使能=STANDBY, 低+未使能=DISABLED |
| `0x2103` | 设备在位，R，从 Qi 帧回调更新 |
| `0x2104` | 输出功率，R，uint16 mW，从 Qi 帧回调更新 |
| `0x2109` | FOD 状态，R，0x00=正常, 0x02=FOD 确认 |
| `0x210B` | 故障码，R，0x00=无, 0x04=过压, 0x05=欠压, 0x06=FOD, 0x07=过温, 0x0A=过流 |
| `0x210C` | 热降额等级，R，85 度保护/60 度恢复 |
| `0x210D` | 功率限值，W，三档 5W/10W/15W，NVM 持久化 |
| `0x2118` | 夹臂状态，R，PA0 低=0x00(有手机), 高=0x01(无手机) |

**Qi IAP DID**（详见文档 3 §8.5）：

| DID       | 内容 |
| --------- | ---- |
| `0x2130` | Qi IAP 控制，W，0x01=启动（+大小）/0x00 或 0x02=中止，UART `0xCC 0x01` |
| `0x2131` | Qi IAP 数据，W，地址+最多 22B，UART `0xCC 0x02` |
| `0x2132` | Qi IAP 状态，R，8B：state/progress/版本/已发/总长 |
| `0x2133` | Qi 芯片版本，R，2B LE，来自 UART `0x01` 上报 |

> **已移除 DID**（硬件不支持）：0x2106, 0x2107, 0x210A, 0x210E, 0x210F, 0x2111, 0x2117

Bootloader 侧 `0x2113` 读的是 metadata `active_slot`；`0x2114` 在已擦除时读 `g_dl_slot`。主机脚本以擦除后的 `0x2114` 为准核链接地址。

**产线 SN（`0x2E F18C`）**：扫码枪 → CCU → CAN-UDS 写入 Device Info，**不经 J-Link**。步骤见文档 9。MCU 组 `device_info_t`（`DEVI` + SN + CRC）写到 `0x0801D000`。OTA 擦槽不得碰该区。

### 5.6 充电控制逻辑

**接口**：`board_charge_set_enable(en)` — 控制 PB2（5V 无线充供电）。

**充电条件**：`g_charge_enabled && PA0 检测到手机` → PB2 拉高（使能 5V）。

- `g_charge_enabled`：由 DID `0x2101` 写入控制，复位后默认 `false`
- PA0 检测：低电平 = 有磁场 = 手机在位
- `board_charge_poll()` 在 main loop 中调用，实时轮询

**状态转换**：

```
上电 → g_charge_enabled=false → PB2=LOW
  │
  ├─ CCU 写 0x2101=0x01 → g_charge_enabled=true
  │     └─ PA0=LOW（手机在位）→ PB2=HIGH（充电中）
  │     └─ PA0=HIGH（无手机）→ PB2=LOW（待机）
  │
  ├─ CCU 写 0x2101=0x00 → g_charge_enabled=false → PB2=LOW
  │
  └─ Programming Session → PB2=LOW（强制失能）
```

### 5.7 Qi UART

USART2 9600 8N1，64 字节 RX FIFO，ISR 入队、主循环按字节回调。与 Qi 芯片的命令/状态机仍为驱动层，协议解析未做完。

## 6. 端到端 OTA（两种主机场景）

下载段（进 Safe Mode 之后）完全相同。差别只在**怎么进 Boot**。ZCANPRO 脚本开关：`RESET_APP_TO_BOOT`。

### 6.1 场景 A — 板子正在跑 APP（现场升级）

镜像必须按**非活跃槽**链接：跑 A 时编 Slot B（IROM `0x08011900`），跑 B 时编 Slot A。Reset Handler 必须落在目标槽，否则 `boot_verify` 第 4 步失败。

```
主机                         APP                         Bootloader
 │  10 02                     │                              │
 ├───────────────────────────▶│ 50 02                        │
 │  11 01                     │ prepare DOWNLOADING          │
 ├───────────────────────────▶│ 51 01 → reset ──────────────▶│
 │                            │                              │ DOWNLOADING → Safe Mode
 │  （等 ~2.5 s）              │                              │
 │  10 02 / 27 / 2E / 31 …    │                              │
 ├──────────────────────────────────────────────────────────▶│ 擦对面槽、写打包镜像
 │  11 01                     │                              │ 37 置 PENDING
 ├──────────────────────────────────────────────────────────▶│ reset
 │                            │◀──── 跳 trial 槽入口 ────────┤
 │  22 F195 读版本            │ 100 ms 后 CONFIRMED          │
 │  34 → 7F 34 11             │ 确认已在 APP（下载 SID 不支持）│
```

### 6.2 场景 B — 已在 Safe Mode（空片 / 双槽无效 / 上次下载未完成）

`RESET_APP_TO_BOOT = False`。不要对 Boot 再发一遍 APP 的 `10 02 + 11`（会直接复位，下载被打断）。从[第 7 节](#7-safe-mode-逐步-can-帧)的第 1 步 `10 02` 开始即可。

空片时 `select_inactive_slot` 选 A，镜像必须链到 `0x08007100`。

### 6.3 主机必须下发的文件

`pack_image.py` 或脚本现场打包后的 **256 B 头 + 裸 bin**。0x34 的 size = 该文件总长，且 ≤ `0xA800`。不要把 Keil 裸 `.bin` 当 0x36 载荷。

### 6.4 错误与回滚

| 现象                                      | 处理                                                                               |
| ----------------------------------------- | ---------------------------------------------------------------------------------- |
| APP 回`7F 34 11`                        | 还在 APP，先`10 02` + `11`；`0x27` 现在 APP 也支持，不再用 `7F 27 11` 判断 |
| `7F 34 24`                              | 没擦就 34                                                                          |
| `7F xx 33`                              | 没过 0x27                                                                          |
| `7F xx 22`                              | 不是 Programming Session，或 S3 掉线                                               |
| `7F 36 73`                              | blockSeq 错，需重新 34                                                             |
| `7F 37 72`                              | 长度/CRC/槽内 Reset/ECDSA 失败                                                     |
| 新 APP 10 s 内无确认（卡死、没跑到 poll） | APP 自己复位；retry 超限切回上一 valid 槽                                          |
| 双槽都验不过                              | Safe Mode，可再刷                                                                  |

回滚原则：未通过五项校验的镜像不会被跳转；Trial 未确认不会改写 `active_slot`；双槽无效永远能进 Safe Mode。

## 7. Safe Mode 逐步 CAN 帧

适用：`qi_wireless_bootloader` 已进入 `enter_safe_mode()`（空片、双槽无效，或 metadata 为 `DOWNLOADING`）。

请求 ID 一律 `0x18DA0D03`，响应 ID `0x18DA030D`，扩展帧，经典 CAN 250 kbps，DLC=8。**第 1 字节必须是 ISO-TP PCI**。

> **注意**: 擦槽操作 (`31 01 FF00`) 只擦除固件 Slot 区域，不会擦除 Device Info 保留区 (`0x0801D000` ~ `0x0801DFFF`)。Bootloader 在执行擦除时会校验目标地址，拒绝擦除 Device Info 区域，从而保护 SN 序列号等设备信息在 OTA 升级后仍然保留。

### 7.1 必做顺序（代码硬门禁）

```
10 02 编程会话
  → 27 01 要 seed
  → 27 03 分片送 64B 签名  （或一条 ISO-TP 多帧 27 02）
  → 27 02 验签
  → 2E 2010 01 选 APP
  → 31 01 FF00 擦槽          ← 不擦直接 34 会 NRC 0x24
  → 34 申请下载
  → 36 按块写镜像            ← 必须是 pack_image.py 打的包（256B 头 + 固件）
  → 37 结束传输并验签
  → 11 01 复位进试用
```

过程中超过 5 s 没有 UDS，会掉回 Default Session，下载中止。长步骤前后插 TesterPresent：

```
02 3E 00 00 00 00 00 00
```

擦 Flash / 验签会先回 `7F xx 78`（ResponsePending），再出最终正响应。超时放到 8～10 s。

### 7.2 逐步 CAN 数据（ZCANPRO 普通发送）

| 步 | 作用 | 发出（8 字节） | 期望 `18DA030D` |
|---|---|---|---|
| 1 | Programming Session | `02 10 02 00 00 00 00 00` | `02 50 02 ...` |
| 2 | RequestSeed | `02 27 01 00 00 00 00 00` | `06 67 01 s0 s1 s2 s3` |
| 3 | 签名分片 ×16 | `07 27 03 ss d0 d1 d2 d3` | `03 67 03 ss ...` |
| 4 | SendKey 验签 | `02 27 02 00 00 00 00 00` | 可能先 `7F 27 78`，再 `02 67 02` |
| 5 | 固件类型 APP | `04 2E 20 10 01 00 00 00` | `03 6E 20 10 ...`（必须 `01`） |
| 6 | 擦非活跃槽 | `04 31 01 FF 00 00 00 00` | 先 `7F 31 78`，再 `04 71 01 FF 00` |
| 7 | RequestDownload | 见下文 | `04 74 20 01 00`（maxBlock=256） |
| 8 | TransferData | `36` + blockSeq + 数据 | `02 76 ss ...` |
| 9 | TransferExit | `01 37 00 00 00 00 00 00` | 先 `7F 37 78`，再 `01 77` |
| 10 | 复位 | `02 11 01 00 00 00 00 00` | `02 51 01`，然后 MCU 复位 |

先发第 1、2 步。能拿到 4 字节 seed，说明 Safe Mode + CAN-UDS 已经通，再往下做验签和擦写。

> **说明**: 上表第 6 步（擦槽）只擦除固件 Slot 区域，不会擦除 Device Info 保留区 (`0x0801D000` ~ `0x0801DFFF`)。SN 序列号等设备信息在 OTA 升级后仍然保留。

### 7.3 签名

对 **4 字节 seed**（大端 `s0 s1 s2 s3`）做 `SHA256`，再用仓库 `docs/keys/private.pem` 做 ECDSA P-256，得到 64 字节 `R‖S`（IEEE P1363，不是 DER）。必须与烧进 Bootloader 的公钥成对。

`ss` 从 `01` 到 `10`，每帧 4 字节签名（16 帧凑满 64 字节）。连续 3 次验签失败锁 30 s（`7F 27 36`）。切 Default Session **不会**清失败计数。

也可以一条 `27 02` + 64 字节走 ISO-TP 多帧（FF / 等 FC / CF）。ZCANPRO 普通发送要自己拆，实验室优先用 `0x27 0x03` 分片。

OpenSSL 示例（把 seed 换成实际值）：

```bash
printf '\xAA\xBB\xCC\xDD' | openssl dgst -sha256 -binary -out seed.hash
openssl pkeyutl -sign -inkey docs/keys/private.pem \
  -in seed.hash -pkeyopt digest:sha256 -out sa.der
# 再把 DER 转成 64 字节 R||S（与 pack_image.py 相同方式）
```

### 7.4 0x34 RequestDownload

只想点通正响应（不校验总长）：

```
02 34 00 00 00 00 00 00
```

正式刷写要带 ALFID 和 size。size = 打包文件总长（含 256 字节头），且 ≤ 槽大小 `0xA800`。地址字段会被读，但写入仍从槽基址开始。

未先发第 6 步擦除（`g_dl_erased=0`）直接 0x34 → NRC `0x24`。

示例（size = `0x00001000`，UDS 11 字节，要多帧）：

```
UDS: 34 00 44  00 00 00 00  00 00 10 00
     SID fmt ALFID  4B 地址(忽略)   4B 长度

FF:  10 0B 34 00 44 00 00 00
     等 MCU FC: 30 00 01 ...
CF:  21 00 00 00 10 00 00 00
```

### 7.5 0x36 TransferData

`blockSeq` 从 `01` 起，`FF` 下一帧是 `01`（跳过 `00`）。

镜像必须带 XATO 头（magic + length + CRC32 + 64B 头内签名 + 固件）。裸 Keil `.bin` 用 `python_tools/pack_image.py` 打包，或交给 `zcanpro_ext_ota_slotA.py` / `zcanpro_ext_ota_slotB.py` 现场打包，不要直接当 0x36 载荷。

单帧最多塞 5 字节数据：

```
07 36 01 d0 d1 d2 d3 d4
```

完整刷写应走 ISO-TP 多帧，每包 UDS = `36 ss` + 最多 254 字节（0x34 宣告 maxBlockLength=256）。

`0x38` 可跳过：打包时头里已有签名即可。

## 8. CAN / ISO-TP / UDS

### 8.1 ID

| ID             | 方向          | 用途                                     |
| -------------- | ------------- | ---------------------------------------- |
| `0x18DA0D03` | Tester → ECU | UDS 物理寻址                             |
| `0x18DA030D` | ECU → Tester | UDS 响应                                 |
| `0x18DB33xx` | 功能寻址      | Safe Mode 也收，预留                     |
| `0x18FF260D` | ECU → 总线   | 生命周期（APP 1 Hz；Safe Mode 默认不发） |

帧格式：CAN 2.0B 数据帧，DLC=8。**UDS 的第 1 字节是 ISO-TP PCI**，不是 SID。单帧：`0x0N` + N 字节 UDS。多帧：`1x` FF / `30` FC / `2x` CF。详见文档 5。

### 8.2 位时序（Boot / APP `can_driver.c` 相同）

```
APB1 = 180 MHz
DIV = 10  → CAN 时钟 18 MHz
SJW = 4, BTS1 = 63, BTS2 = 9
标称 250 kbps，采样点约 87.5%
PA11 RX MUX4 上拉，PA12 TX MUX4 推挽
过滤器：掩码 0，收全部扩展数据帧
软件 RX FIFO 16 帧；TX 先 PTB 再 STB
```

### 8.3 NRC 常用

| NRC                            | 含义                   | 典型出处                            |
| ------------------------------ | ---------------------- | ----------------------------------- |
| `0x11`                       | 服务不支持             | APP 的下载类 SID；Boot 未实现的 SID |
| `0x12`                       | 子功能不支持           | 非法 session / resetType            |
| `0x13`                       | 长度/格式错            |                                     |
| `0x22`                       | 条件不满足             | 非 Programming 就擦/下              |
| `0x24`                       | 顺序错                 | 未擦就 34；未 34 就 36              |
| `0x31`                       | 超出范围               | 固件类型不是 APP；size 过大         |
| `0x33`                       | 未解锁                 |                                     |
| `0x35` / `0x36` / `0x37` | 验签失败 / 次数 / 锁定 | 0x27                                |
| `0x72`                       | 编程失败               | 擦写、0x37 校验                     |
| `0x73`                       | 块序号错               | 0x36                                |
| `0x78`                       | ResponsePending        | 擦、验签、0x37                      |

### 8.4 正响应摘要（UDS 层，不含 PCI）

```
10 xx     → 50 xx
11 01     → 51 01
27 01     → 67 01 s0 s1 s2 s3     （APP 和 Boot 均返回 seed）
27 02     → 67 02
31 01 FF00→ 71 01 FF 00
34 …      → 74 20 01 00
36 ss …   → 76 ss
37        → 77
38 ss …   → 78 ss
3E 00     → 7E 00
```

### 8.5 ISO-TP 填写规则

单帧（UDS 长度 1～7）：

```
Byte0     Byte1..N        其余
PCI 0x0N  N 字节 UDS      00 或 CC 填充
```

负响应：

```
7F [SID] [NRC]
7F [SID] 78     ← ResponsePending
```

## 9. 中断与时基

Bootloader 与 APP 各有一份 `at32f422_426_int.c`，结构相同。优先级分组 4 位抢占。

| 中断     | 优先级 | 处理                                |
| -------- | ------ | ----------------------------------- |
| SysTick  | 内核   | `timer_tick_inc()`，1 ms          |
| CAN1 RX  | (1,0)  | 硬件缓冲 → 软件 FIFO，协议在主循环 |
| CAN1 ERR | (2,0)  | 总线关闭恢复                        |
| USART2   | (3,0)  | 仅 APP：Qi RX FIFO                  |
| Fault    | —     | `while(1)`                        |

软件定时器最多 16 个。APP 生命周期用 `timer_get_tick()` 自己数 1000 ms，不是独立硬件定时器。

## 11. 实现约束

1. **下载只在 Bootloader。** APP 和 Boot 均实现 `0x27`，**不要**用 `7F 27 11` 或 `0xF180`+`0x2113` 判断当前固件。探测：`0x34`（或 `0x31 01 FF00`）回 `7F xx 11` → APP；Boot 对下载类 SID 不会回 `0x11`。
2. **镜像必须带 XATO 头**，且 Reset Handler 落在将要写入的槽。产线烧 Slot A 入口对应的打包文件到 `0x08007000`；OTA 到 B 必须用 B 链接的 bin。
3. **私钥与 Bootloader 公钥绑定。** 路径约定 `docs/keys/private.pem`。更换密钥后重烧 Bootloader，旧镜像全部验签失败。
4. **0x38 不是必选。** 打包时已经写入头签名；0x37 以 Flash 里的头为准做 `boot_verify_image`。
5. **不实现看门狗（已确认）。** 试运行失败靠 APP 10 s 后 `NVIC_SystemReset`，或镜像校验不过而选另一槽 / Safe Mode。SRS QI-WDG-001～004 对本板 N/A。
6. **metadata 掉电安全：** 先 Backup 再 Primary。APP 触发 OTA 时不把运行槽标成无效。
7. **S3 = 5 s。** 擦写、多帧传输过程中要插 `3E 00`（或任意 UDS）。
8. **Qi 充电协议解析未完成**，不影响 OTA 路径。

实验室一键升级用 `python_tools/zcanpro_ext_ota_slotA.py` / `zcanpro_ext_ota_slotB.py` / `zcanpro_ext_ota_auto.py`；产线打包用同目录 `pack_image.py`。不要在文档和脚本之外再发明第三套地址或会话顺序。
