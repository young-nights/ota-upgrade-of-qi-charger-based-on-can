# 宏定义切换方式

> 项目中所有可通过宏定义切换的行为模式汇总
> 更新：2026-11-04 整修——§4 ENTRY_MODE 塔碑化、§5 改工具侧自适应块长、§7 更名 CAN_LP_SLEEP_ENABLE（10s 真休眠语义）、删 2026-09 烧录台账旧注；此前：2026-09-02 初版

---

## 使用方法

在 Keil `.uvprojx` → **C/C++** → **Define** 中添加宏，多个用逗号分隔：

```
BOOT_JUMP_METHOD=1
```

或在源文件顶部 `#define`（仅对该文件生效）。

---

## 1. BOOT_JUMP_METHOD

| 项目 | 说明 |
|------|------|
| 文件 | `qi_wireless_bootloader/mdk_app/Src/boot_jump.c` |
| 默认值 | `0` |
| 取值 | `0` 或 `1` |

| 值 | 方式 | 说明 |
|----|------|------|
| `0` | 内联汇编 | `msr msp` + `bx`，编译器无关，当前默认方式 |
| `1` | 函数指针 | `__set_MSP` + `((app_entry_t)(reset_addr))()`，官方 IAP 风格 |

**代码位置**：
```c
#ifndef BOOT_JUMP_METHOD
#define BOOT_JUMP_METHOD  0
#endif
```

**切换方式**：Keil Define 中加 `BOOT_JUMP_METHOD=1`，或改默认值为 `1`。

**差异说明**：
- 方式 0：`msp` 和 `reset` 通过内联汇编寄存器传入，跳转后不依赖 C 栈，更安全
- 方式 1：先调 `__set_MSP` 再通过函数指针跳转，与官方例程一致，可读性更好

## 2. SAFE_MODE_PROBE_ENABLE（已移除，行为固化）

> **已移除**：该宏连同 SAFE_MODE_PROBE_PERIOD_MS / SAFE_MODE_PROBE_STATE
> 于 17bc8ab 从 boot_safe_mode.c 删除（HEAD 全树 grep 零引用）。心跳改为
> **无条件**发送，不再有编译开关。

**现行 HEAD 行为（boot_safe_mode.c enter_safe_mode / safe_heartbeat）**：
Safe Mode 无条件每 500ms 在 `0x18FF260D`（CAN_ID_LIFECYCLE_BROADCAST）发送
心跳帧 `01 41 42 54 cause fail_step A5 00`（'ABT' 标记 + cause/step 现场），
并同周期调用 `sit1145_normal_mode_set()` 重切收发器 Normal（见 §3）。
帧格式注释以 boot_safe_mode.c 头部为准（ABT 心跳**现行**：2026-10-28 revert 恢复 500ms `01 41 42 54`；原「与主机脚本两侧同步」要求作废——旧主机脚本已删除）。

| 文件 | `qi_wireless_bootloader/mdk_app/Src/boot_safe_mode.c` |

## 3. SAFE_MODE_SIT1145_KEEPALIVE_ENABLE（已移除，行为固化）

## 5. 传输块长（工具侧）

| 项目 | 说明 |
|------|------|
| 位置 | QiChargerStationTool `RunUpgradeAsync` / ProductionStationTool `OtaUpgradeAsync` 的 `transferBlock` 参数 |
| 取值 | `0`=自适应（默认）；`1`~`254` 为显式上限 |

- **自适应（0）**：按 `0x34` 正响应 `74 20 <maxBlockLen:2B>` 宣告取块长——MCU1=256（`OTA_DL_MAX_BLOCK_LEN`）、MCU2=22（`QI_IAP_MAX_CHUNK`），块长翻倍即 0x36 往返减半。
- 上限约束：块长 ≤ 254（SID+BSC 后 ISO-TP SF 数据上限；实际以 0x34 宣告为准）。

## 7. CAN_LP_SLEEP_ENABLE（APP 固件，低功耗进入总开关）

> **当前 =1（生产语义）**：空闲 `CAN_LP_IDLE_TIMEOUT_MS` 后进 Sleep（真休眠，SIT1145 INH 断电整板）。定义在 `app_config.h`（编译期开关集中管理，旧 `CAN_LP_STANDBY_ENABLE` 已更名并改 Sleep 语义）。

| 项目 | 说明 |
|------|------|
| 文件 | `qi_wireless_code_app/mdk_app/Inc/app_config.h` |
| 当前值 | `1`；空闲超时 `CAN_LP_IDLE_TIMEOUT_MS = 10000`（10s） |
| 取值 | `0` 或 `1` |

| 值 | 说明 |
|----|------|
| `1` | 生产语义：空闲 10s → `can_lp_go_sleep()` → SLEEP(0x04) 确认送达 → 诊断帧 E0~E3（0x18FF270D）→ SIT1145 Sleep（INH 断电整板）。唤醒仅 WUF 匹配（0x18DA0D03 + SID 0x3E 掩码）或重新上电 |
| `0` | 全部 Sleep 入口关闭（回归调试期常在线）；唤醒/恢复代码保留 |

**门禁**（与 doc 16 §2.6.1 一致）：
- 充电中（`g_qi_charger_enable!=0 && Hall 在位`）每轮刷新空闲计时——**永不进 Sleep**
- 周期帧不刷新空闲计时
- Programming 会话/IAP 期间不进 Sleep

**诊断**：DID `0x2119`（ever_sleep / wake_src / sleep_fail + wup_count + last_sleep_sec）、`0x211A`（wipe 诊断）；诊断帧 E0~E3 见 doc 19。

**MDK 验证（烧录后）**：

1. qi_wireless_code_app Rebuild 编译 0 error
2. 上电后立即用 QiChargerStationTool「读版本」读三 DID（0xF195/0xF180/0xF193）全部有应答
3. 空闲 10s 后抓 `0x18FF260D` 可见 `04` SLEEP；之后 WUF 唤醒/上电读 DID 仍有应答
4. 完整跑一轮 OTA 升级，流程正常

## 9. Keil 工程配置示例

在 `.uvprojx` 的 **C/C++** → **Define** 中：

```
BOOT_JUMP_METHOD=1
```

效果：
- Bootloader 跳 APP 使用函数指针方式（官方 IAP 风格）
- SAFE_MODE_PROBE_ENABLE 已于 17bc8ab 移除：Safe Mode 心跳与 SIT1145 keepalive为无条件行为，无需配置

生产环境建议：
```
BOOT_JUMP_METHOD=0
```

效果：
- 使用内联汇编跳转（更安全）
- Safe Mode 心跳与 SIT1145 keepalive 为无条件行为（非宏控制，见 §2/§3）
