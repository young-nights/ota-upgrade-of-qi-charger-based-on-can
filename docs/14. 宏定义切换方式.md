# 宏定义切换方式

> 项目中所有可通过宏定义切换的行为模式汇总
> 更新：2026-09-02；2026-09-18 增补 §7 CAN_LP_STANDBY_ENABLE（回归调试期临时开关）；2026-09-18 §2/§3 safe mode 两宏确认已移除（17bc8ab），行为固化描述同步 HEAD

---

## 使用方法

在 Keil `.uvprojx` → **C/C++** → **Define** 中添加宏，多个用逗号分隔：

```
BOOT_JUMP_METHOD=1
```

或在源文件顶部 `#define`（仅对该文件生效）。

---

## 1. BOOT_JUMP_METHOD

| 项目 | 说明 |
|------|------|
| 文件 | `qi_wireless_bootloader/mdk_app/Src/boot_jump.c` |
| 默认值 | `0` |
| 取值 | `0` 或 `1` |

| 值 | 方式 | 说明 |
|----|------|------|
| `0` | 内联汇编 | `msr msp` + `bx`，编译器无关，当前默认方式 |
| `1` | 函数指针 | `__set_MSP` + `((app_entry_t)(reset_addr))()`，官方 IAP 风格 |

**代码位置**：
```c
#ifndef BOOT_JUMP_METHOD
#define BOOT_JUMP_METHOD  0
#endif
```

**切换方式**：Keil Define 中加 `BOOT_JUMP_METHOD=1`，或改默认值为 `1`。

**差异说明**：
- 方式 0：`msp` 和 `reset` 通过内联汇编寄存器传入，跳转后不依赖 C 栈，更安全
- 方式 1：先调 `__set_MSP` 再通过函数指针跳转，与官方例程一致，可读性更好

> 现在 OTA 全程在 APP 内完成（0x31/0x34/0x36/0x37），Boot 无 UDS。

| 项目 | 说明 |
|------|------|
| 文件 | `python_tools/zcanpro_ext_ota_auto.py` |
| 默认值 | `"auto"` |
| 取值 | `"auto"` / `"app"` / `"boot"` |

| 值 | 说明 |
|----|------|
| `"auto"` | 【已废弃，行为描述仅存历史意义】旧实现发 `0x34` 按 NRC 值分叉定位（"NRC `0x11`=已在 APP"），该判据与现固件相反且不得回退：APP 默认会话对 `0x34` 回 NRC `0x22`（`ota_download.c` 会话门禁），对 `0x34` 的任何应答=APP，Boot 对 `0x34` 静默。现行判定只按正证据（见 `python_tools/zcanpro/non-qi/zcanpro_charge_start.py probe_location`）：`22 2113` 应答且 `62 21 13` 后字节为 `0xFE`=Boot safe mode；任何其他应答（含任意 NRC）=APP；无应答先 Standby 唤醒收敛+生命周期帧监听再判 |

## 5. TRANSFER_BLOCK_DATA（脚本侧）

| 项目 | 说明 |
|------|------|
| 文件 | `python_tools/zcanpro_ext_ota_auto.py` |
| 默认值 | `128` |
| 取值 | `1` ~ `254` |

| 值 | 说明 |
|----|------|
| `128` | 每帧传输 128 字节（默认，平衡速度与可靠性） |
| `254` | 最大值，每帧传最多数据（ISO-TP SF 上限） |
| `64` | 更保守，每帧更少数据 |

**代码位置**：
```python
TRANSFER_BLOCK_DATA = 128
```

**注意**：Bootloader 的 `UDS_MAX_BLOCK_LEN` = 256，`TRANSFER_BLOCK_DATA` 不应超过 `256 - 2`（SID + BSC）= 254。

## 7. CAN_LP_STANDBY_ENABLE（APP 固件，CAN Standby 进入总开关）

> **当前 =1（2026-09-27 起生产语义）：上电 Normal + 空闲 30s 进 Standby**；=0 为回归调试期临时禁用手段（2026-09-18 引入，2026-09-27 已恢复 1）

| 项目 | 说明 |
|------|------|
| 文件 | `qi_wireless_code_app/mdk_app/Inc/can_protocol.h`（:63） |
| 当前值 | `1`（上电 Normal、空闲 30s 进 Standby；2026-09-27 需求拍板） |
| 取值 | `0` 或 `1` |

| 值 | 说明 |
|----|------|
| `1` | 生产语义（2026-09-27 起）：上电/跳转即 Normal 立即可通信；空闲 **30s**（`CAN_LP_IDLE_TIMEOUT_MS`）进 Standby。`sit1145_init` 步骤10 停机块已删。原「上电即 Standby」历史行为废弃，不保留复现开关 |
| `0` | 所有进入 Standby 的入口关闭，上电/复位/空闲均保持 CAN 常在线；唤醒/恢复代码保留 |

**受控入口（开关=0 时全部关闭）**：

1. **上电/复位进 Normal（原「默认 Standby」已废弃）**：`can_protocol_init()` 统一置 `g_lp_need_online=1`，首次 `can_protocol_poll` 调 `can_lp_enter_normal()`（SysTick 就绪后，与 trial 同路径）
2. **空闲超时自动进 Standby**：`can_protocol_poll()` 30s 有符号差值判定（can_protocol.c）——`#if` 加开关条件，=0 时整段不编译
3. **`sit1145_init()` 步骤10 收发器进 Standby**——已整块删除（2026-09-27），收发器留步骤7 CMC 配置态
4. **函数定义**：`can_lp_enter_standby`/`can_lp_hold_standby`（can_protocol.c :351-377）随开关不编译，源码完整保留

**行为对照**：

| 场景 | 开关=1（当前/生产） | 开关=0（回归调试） |
|------|----------------|--------------------|
| 上电/复位 | 一律首次 poll 进 Normal（上电即 Normal） | 一律首次 poll 进 Normal，常在线 |
| 空闲 30s | 发 SB（StandBy，进待机标记）→收发器进 Standby | 不进，保持在线 |
| OTA 复位后 | trial/rollback 在线；其余 Standby | 一律在线 |
| trial 上电 | 在线（confirm 需要 CAN） | 在线（流程不变，只更可靠） |

**入口复核（grep 全量）**：`can_lp_enter_standby` 调用点仅空闲超时（已守卫）；`can_lp_hold_standby` 调用点仅 init 分支 + enter_standby 函数体（均已守卫）；`sit1145_standby_mode_set` APP 侧调用点仅 sit1145.c 步骤10 + hold_standby 函数体（均已守卫）；`pwc_standby_mode_enter`/`can_standby_mode_enable` 应用层无调用；bus-off 恢复兜底 `can_driver_offline→online`（can_protocol.c :469）立即回在线，非 Standby 入口。**Boot 侧无 standby 进入逻辑**（boot sit1145_init 以 normal_mode_set 结尾，Safe Mode keepalive 默认=1），无需改。

**诊断影响**：DID `0x2119` bit0=ever_standby bit1=last_wake_was_wup **bit2=standby_fail(sticky)**；正常运行会出现 SB（StandBy，进待机标记）`06 41 53 42` 与 WK（Wake-up，唤醒标记）`01 41 57 4B`。

**MDK 验证（烧录后）**：

1. qi_wireless_code_app Rebuild 编译 0 error（开关=1 下 standby 函数参与编译，应无 unused 警告）
2. 上电后立即用 `zcanpro_read_app_version.py` 读三 DID（0xF195/0xF180/0xF193）全部有应答
3. 空闲 30s 后抓 `0x18FF260D` 可见 SB（StandBy，进待机标记）`06 41 53 42`；之后再发帧唤醒读 DID 仍有应答
4. 完整跑一轮 OTA 升级，trial/confirm 流程正常

**待烧台账条目（2026-09-18）**：qi_wireless_code_app（原 slotA）需 MDK Rebuild + **烧录器直烧**（旧固件可能 180s 后休眠，无法 OTA 自举）；烧录基线 commit = `e28235c`（standby 开关代码随该提交入库）；新语义下 `CAN_LP_STANDBY_ENABLE=1`（上电 Normal + 空闲 30s Standby）；`SW_VERSION_STR` 未改，台账以 commit 号区分烧录物。

**归属说明**：standby 开关代码（can_protocol.h/c、sit1145.c）于 2026-09-18 11:40 被并行打包脚本改名会话的 `git add -A` 一并扫入 e28235c（其 message 仅描述脚本改名）；开关技术细节以本节与本日 docs/14 补录提交 Description 为准。

## 9. Keil 工程配置示例

在 `.uvprojx` 的 **C/C++** → **Define** 中：

```
BOOT_JUMP_METHOD=1
```

效果：
- Bootloader 跳 APP 使用函数指针方式（官方 IAP 风格）
- SAFE_MODE_PROBE_ENABLE 已于 17bc8ab 移除：Safe Mode 心跳与 SIT1145 keepalive为无条件行为，无需配置

生产环境建议：
```
BOOT_JUMP_METHOD=0
```

效果：
- 使用内联汇编跳转（更安全）
- Safe Mode 心跳与 SIT1145 keepalive 为无条件行为（非宏控制，见 §2/§3）
