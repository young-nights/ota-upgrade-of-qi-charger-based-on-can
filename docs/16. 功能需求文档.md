# CAN-UDS OTA 功能需求文档

- **版本**: v1.7
- **日期**: 2026-10-22
- **状态**: 正式文档
- **适用范围**: Qi 无线充电模块 CAN-UDS OTA / Qi IAP 升级与充电控制功能
- **代码基线**: `qi_wireless_code_app` + `qi_wireless_bootloader`（对照源码逐项核对）

---

## 1. 概述

### 1.1 功能目标

通过 CAN 2.0B 总线（250 kbps，29-bit 扩展帧），使用 ISO-TP + UDS 协议实现：

1. **MCU1（AT32F426）APP 固件 OTA 升级**：下载到备份区 → 验签 → 自复位 → BOOT 搬运切区
2. **MCU2（Qi 芯片）IAP 升级**：与 MCU1 OTA 共用 UDS 下载通路，数据经 UART 转发
3. **充电业务控制**：霍尔检测、5V 使能、功率档位、故障/状态查询
4. **低功耗**：SIT1145 Sleep + 选择性远程唤醒（WUF）

### 1.2 系统架构

```
CCU（主机）──CAN 250kbps──▶ Qi 充电模块（MCU1: AT32F426）
                                  │
                    ┌─────────────┴─────────────┐
                    │    Bootloader 12KB         │
                    │    0x08000000 ~ 0x08002FFF │
                    │  仅选区+验签+跳转（无 UDS）  │
                    └─────────────┬─────────────┘
                    ┌─────────────┴─────────────┐
                    │  App 区 52KB（含 XATO 头）  │
                    │  0x08003000 ~ 0x0800FFFF   │
                    │  头 @0x08003000            │
                    │  入口 @0x08003100          │
                    │  （充电业务 + UDS + OTA/IAP）│
                    └─────────────┬─────────────┘
                    ┌─────────────┴─────────────┐
                    │  备份区 52KB               │
                    │  0x08010000 ~ 0x0801CFFF   │
                    │  OTA 暂存（待搬运镜像）      │
                    └─────────────────────────────┘
                                  │ USART2 19200 8N1
                                  ▼
                           Qi 无线充电芯片（MCU2）
```

> **架构说明（OTA-ARCH-0920，单 App）**：无 A/B ping-pong 双运行区。运行中的固件不被覆盖——OTA 将新固件写入备份区，APP 验签并置 `backup_valid` 后自复位，BOOT 复验并搬运至 App 区。

### 1.3 术语定义

| 术语 | 说明 |
|------|------|
| CCU | Central Control Unit，主机控制器 |
| OTA | Over-The-Air，本项目指 CAN 总线远程固件升级 |
| IAP | In-Application Programming，Qi 芯片经 UART 的应用编程 |
| UDS | Unified Diagnostic Services (ISO 14229) |
| ISO-TP | ISO 15765-2，CAN 传输层协议 |
| XATO | 自定义镜像头格式（256 字节） |
| Safe Mode | Bootloader 挂起（空片/镜像无效），靠产线镜像救砖 |
| Device Info | 设备信息保留区（0x0801E000） |
| Metadata | OTA 状态元数据（0x0801D000 / 0x0801D800 双副本） |

### 1.4 版本字符串（编译期常量）

| 常量 | 示例 | 来源 | 对应 DID |
|------|------|------|----------|
| `SW_VERSION_STR` | `QC_JYF_MCU1_FW_x.y.z` | `can_protocol.c`（**唯一真相源**） | 0xF195 |
| `BOOTLOADER_VER_STR` | `QC_JYF_BL_1.0.0` | `can_protocol.c` | 0xF180 |
| `HW_VERSION_STR` | `QC_JYF_HW_1.1.5` | `can_protocol.c`（**唯一真相源**） | 0xF193 |
| MCU2 Qi 版本 | `QC_JYF_MCU2_FW_x.y.z` | Qi 芯片上报缓存 / `0x2013` 主动问询 | 0x2133 / 0x2013 |

**规则**：
- 版本号只改固件编译常量 + 文档；XATO 头 version 区（0x4C）固定填 `0x00`，不携带版本
- UDS `0xF195` 直接取 `SW_VERSION_STR`，不读 OTA metadata / 镜像头
- 每次代码变更须在同一提交内递增 `SW_VERSION_STR`（默认 patch +1）

## 2. 功能需求

### 2.1 单 App 升级机制（备份区暂存 + BOOT 搬运）

**需求编号**: OTA-REQ-001

**描述**: Boot + App + 备份区单 App 升级模式。OTA 写入备份区，BOOT 校验后搬运至 App 区；运行中固件不被直接覆盖。

**详细要求**:

| 项目 | 说明 |
|------|------|
| Boot 区 | `0x08000000` ~ `0x08002FFF`，12KB |
| App 区基址 | `0x08003000`（含 XATO 头） |
| App 代码入口 | `0x08003100`（= App 基址 + 256B 头；Keil IROM1） |
| 备份区 | `0x08010000` ~ `0x0801CFFF`，52KB |
| 镜像头 | 256 字节 XATO（magic / length / CRC32 / ECDSA / 保留区） |
| 0x4C 偏移 | 16B 保留占位，打包固定填 `0x00`，**不携带版本号** |
| 运行区标识 | `ota_running_slot()` 恒返回 0（App 区）；`0x2113` 读值为 0 |

**验证标准**:
- OTA 一律写入备份区（0x08010000）；BOOT 复位后校验并搬运至 App 区（0x08003000）
- 镜像须按 App 窗口链接（Reset Handler 落在 `[0x08003100, 0x08010000)`）
- 擦写备份区不影响正在运行的固件
- 产线整片烧录用 `merge_prod_bin.py` 从 `0x08000000` 烧 Boot+App

### 2.2 APP 下载 + 自复位切区（MCU1）/ UART 转发（MCU2）

**需求编号**: OTA-REQ-002

**描述**: 擦写与下载在运行中的 APP 完成。Bootloader 12KB 只做选区+验签+跳转，无 UDS。MCU1 与 MCU2 共用 UDS 下载 SID，由 `2E 20 10` 选择目标。

#### 2.2.1 MCU1（APP 固件）下载流程

```
10 02              进入编程会话（Programming）
27 01 / 27 03×16 / 27 02   安全访问（32B seed + ECDSA 签名）
2E 20 10 01        选择固件类型 = APP
31 01 FF 00        擦除备份区（无 addr/size 参数）
22 2114            读目标（擦除后 = 0x02 备份区）
34                 RequestDownload（ALFID，目标备份区）
36 × N             TransferData（XATO 镜像流）
37                 RequestTransferExit：验签 + commit_backup
                   → 回 0x77 → SHUTDOWN 广播 → NVIC_SystemReset()
（BOOT）           复验备份区 → 擦 App 区 → 搬运 → 跳 0x08003100
```

#### 2.2.2 MCU2（Qi 芯片）IAP 流程（统一 UDS 路径）

```
10 02              编程会话
27 …               安全访问
2E 20 10 04        选择固件类型 = MCU2
31 01 FF 00        「擦除」直通：不擦本机 Flash，标记就绪
                   → PB2 保持供电 → Qi IAP prepare（UART 0xCC 0x01+size）
34                 目标放宽至 0xFFFF（Qi 16-bit 地址空间）
36 × N             数据经 UART 0xCC 0x02 转发（每包 ≤22B）
                   延迟应答：等 Qi ACK 后回 76 BSC
37                 无本机验签/提交/复位
                   → 刷 Qi 版本缓存（短阻塞 ≤800ms）
                   → ota_state = 0x0A（MCU2 Confirmed）
```

**关键约束**:

| 项 | 值 |
|----|----|
| S3 会话超时 | **30 秒**（`SESSION_TIMEOUT_MS=30000`，多帧组包期间每帧刷新） |
| P2 / P2* | 50 ms / 5000 ms（会话应答中携带） |
| 擦除/验签长操作 | 返回 NRC 0x78（ResponsePending） |
| 未擦就 34 | NRC 0x24 |
| 未解锁就擦/写 | NRC 0x33 |
| Qi IAP 每包 | ≤22B（`QI_IAP_MAX_CHUNK`） |
| Qi IAP prepare ACK 超时 | 2500 ms |
| Qi IAP 数据 ACK 超时 | 2000 ms |
| MCU2 完成后版本刷新 | ≤800 ms 阻塞 / 3s 非阻塞轮询 |
| Programming 会话 | 强制 PB2 = 低（禁 5V），IAP 路径例外（`board_iap_hold_power`） |

**已删除的旧路径**：DID `0x2130`（Qi IAP 控制）/ `0x2131`（Qi IAP 数据）写服务**已移除**，不可再用。

### 2.3 镜像安全校验

**需求编号**: OTA-REQ-003

**描述**: 下载完成后对镜像做完整性、来源、地址合法性校验。

**校验顺序（APP `verify_backup_image` / BOOT `boot_verify_image`）**:

| 步骤 | 校验项 | 失败 |
|------|--------|------|
| 1 | magic == `0x4F544158`（"XATO"） | fail_step=1 |
| 2 | `0 < image_length ≤ 槽大小 - 256` | step=2 |
| 3 | CRC32(固件负载) == header.crc32 | step=3 |
| 4 | Reset Handler ∈ `[入口, 槽末)` | step=4 |
| 5 | ECDSA P-256 签名验证 | step=5/6 |

**ECDSA 签名方案**:
- 算法: ECDSA P-256（secp256r1）
- 签名格式: 64 字节 IEEE P1363（R‖S，各 32 字节）
- 摘要: SHA-256(固件负载) 或 seed（SecurityAccess）
- 公钥来源: 优先 Device Info（`ecdsa_pubkey[65]`，`pubkey_valid=0x01`），未配置则回退 APP/Boot 内置常量
- 私钥: `docs/keys/private.pem`（PC 端签名）

**公钥写入**:
- UDS `2E 2120 [65B]`（Programming + 解锁）
- 首字节必须 `0x04`（SEC1 未压缩），长度必须 65

**验签开关（`app_config.h`，测完必须恢复 =1）**:
- `SA_VERIFY_ENFORCE`：27 02 解锁验签
- `OTA_VERIFY_ENFORCE`：0x37 镜像验签

### 2.4 0x37 收尾自复位（Trial 交接）

**需求编号**: OTA-REQ-004

**描述**: MCU1 下载完成后，APP 验签 + `commit_backup()` 置 `backup_valid=1`，回 `0x77` 后**自动复位**，无需主机再发 `11 01`（该 SID 已删除）。

**交接流程**:

```
APP:  37 成功 → verify_backup_image()（CRC32 + ECDSA）
APP:  commit_backup() → backup_valid=1, backup_crc32=…
APP:  发 0x77 → 等 TX 空闲 → SHUTDOWN 广播 → NVIC_SystemReset()
BOOT: metadata backup_valid=1 → 复验备份区 → 擦 App 区 → 搬运
BOOT: 成功 → last_boot_reason=0x03(OTA_ACT) → 跳 0x08003100
      失败 → last_boot_reason=0x04(COPY_FAIL) → 回滚/保持旧镜像
```

**约束**:
- 验签失败不写 `backup_valid`，回 NRC 0x72，备份区/运行区保持原状
- `0x37` 重试幂等：已 commit 后重试直接回正响应
- metadata 写入顺序: **先 Backup（0x0801D800）再 Primary（0x0801D000）**（掉电安全）
- 空片/双副本无效: BOOT 进 Safe Mode，靠产线 `merge_prod_bin.py` 从 0x08000000 救砖

**Metadata v4（28B，crc32 @0x18，`META_VERSION=4`）**:

| 偏移 | 字段 | 说明 |
|------|------|------|
| 0x00 | magic | `0x4F54414D`（"MATO"） |
| 0x04 | version | 4 |
| 0x08 | backup_valid | APP 验签后置 1；BOOT 搬运成功后清 0 |
| 0x09 | copy_fail_step | 失败步骤 |
| 0x0A | last_boot_reason | 0x00 上电 / 0x01 软复位 / 0x02 WDG / **0x03 OTA 激活** / **0x04 搬运失败** |
| 0x0C | backup_crc32 | 暂存负载 CRC |
| 0x10 | copy_retry_count | 搬运重试次数（DID 0x2116） |
| 0x14 | ota_state | 见 §2.11 |
| 0x18 | crc32 | 上述字段 CRC32 |

> v2 及更早数据被拒绝并重建默认值。无 `app_valid` 字段。

### 2.5 安全访问（SecurityAccess）

**需求编号**: OTA-REQ-005

**描述**: ECDSA P-256 seed-signature 解锁，防止未授权擦写。

**流程**:

```
CCU:  27 01 → 请求 seed
MCU:  67 01 [32B seed]          ← 每次 27 01 刷新；已解锁时回 32×0x00
CCU:  SHA-256(seed) → 私钥 ECDSA 签名 → 64B
CCU:  27 03 [blockSeq] [4B] × 16 帧   （blockSeq 0x01..0x10，0x01 重置缓冲）
CCU:  27 02 → 触发验签
MCU:  uECC_verify(公钥, SHA256(seed), 签名) → 67 02 或 7F 27 35
```

**安全策略**:
- 连续 3 次验签失败 → 锁定约 30 秒（27 02 → NRC 0x36）
- 锁定期间 27 01 → NRC 0x37
- 切回 Default Session **不清除**失败计数
- `27 03` 重复 blockSeq 幂等（重试不撞 NRC 0x71）
- SecurityAccess 仅在 APP 实现；镜像验签与 SA 用同一密钥对

### 2.6 低功耗与 CAN 收发器管理（Sleep）

**需求编号**: OTA-REQ-006

**描述**: SIT1145 Sleep + 选择性远程唤醒（WUF）。**Standby 路径已于 2026-10-16 移除**，仅保留 Sleep（MCU 不进 Stop，主循环等唤醒）。

#### 2.6.1 状态转换

| 场景 | SIT1145 模式 | 触发条件 |
|------|-------------|----------|
| 上电默认 | Normal | 首次 `can_protocol_poll` → `can_lp_enter_normal()` |
| CAN 唤醒 | Normal | WUF 匹配（CW 标志 / PA11 拉低） |
| 30s 无 UDS 收发 | Sleep | `CAN_LP_IDLE_TIMEOUT_MS=30000` |
| 充电门禁有效 | Normal（不进 Sleep） | `g_qi_charger_enable!=0 && Hall 在位` 持续刷新计时 |
| IAP 进行中 | Normal | `board_iap_hold_power(1)` 强制 PB2 保持 |
| 编程会话 | 5V 强制关闭 | `10 02` → `board_5v_set(0)` |

**充电门禁 stale 机制（防误进 Sleep）**:
- 每次 UDS 交互（TesterPresent / 请求 / 应答）→ `can_lp_mark_uds()` **重置** `g_charge_gate_since=0`
- 60s stale 窗口仅在**真正无 UDS 通信**时到期（判定禁充写入丢失）并放行 Sleep
- 正常充电 + 周期 UDS 保活 → 计时器持续重置，不会误进 Sleep

#### 2.6.2 进入 Sleep 流程

```
can_protocol_poll() 空闲 30s 超时
  → can_lp_go_sleep()
    → SB 帧 (0x18FF260D)
    → can_lp_enter_sleep()
      → 诊断帧 E0/E2/E3/E4 (0x18FF270D)
      → can_driver_offline()
      → sit1145_sleep_enter()
         ① 清事件标志  ② WUF 过滤配置  ③ CPNC=1+PNCOK=1
         ④ CAN Control 回读×3  ⑤ Mode = Sleep
      → can_driver_pins_sleep()
```

#### 2.6.3 WUF（选择性唤醒）配置

匹配目标：CAN ID `0x18DA0D03`（UDS 请求）+ SID `0x3E`（TesterPresent）数据掩码。

| 寄存器 | 值 | 说明 |
|--------|----|------|
| ID0-3 | `03 0D DA 18` | CAN ID 小端 |
| MASK0-3 | 全 0 | 精确匹配 |
| Frame Control | `0xC8` | IDE=1, PNDM=1, DLC=8 |
| DM0 | `0x00` | 不检查 byte0 |
| DM1 | `0x0C` | byte1 bit2+bit3（SID 0x3E 特征） |
| CAN Control | `0x71` | CFDC=1, PNCOK=1, CPNC=1 |

**数据掩码**：至少一位同时为 1 则匹配（AND）。
- `0x3E` AND `0x0C` = `0x0C` ≠ 0 → 唤醒
- `0x10`/`0x22` AND `0x0C` = 0 → 不唤醒

**写入顺序（关键）**: ID → 掩码 → 数据掩码 → 帧控制 → CAN Control（PNCOK 最后写）

#### 2.6.4 唤醒判定（anti-phantom）

1. CW 标志 + RXD 已释放 → 立即唤醒（fast path）
2. RXD 低 + CW 有 → 清标志 + 5ms 重锁 → 0→1 = 真唤醒
3. 仅 PA11 低无 CW → phantom，不唤醒
4. Round-3 wipe 诊断经 DID `0x211A` 可读（ev24/ev63/stat/attempts）

#### 2.6.5 低功耗诊断 DID

| DID | 内容 |
|-----|------|
| 0x2119 | flags(bit0 曾 Sleep / bit1 唤醒源 / bit2 sleep_fail) + wup_count + last_sleep_sec |
| 0x211A | wipe 诊断 4B：ev24 / ev63 / stat / attempts |
| 0x21FF | SIT1145 当前模式：0x01=Sleep, 0x04=Standby, 0x07=Normal |

### 2.7 生命周期广播

**需求编号**: OTA-REQ-007

**描述**: APP 运行期间通过 CAN 广播状态。

| 项目 | 说明 |
|------|------|
| CAN ID | `0x18FF260D` |
| 周期 | **10000ms（0.1Hz）**，`LIFECYCLE_PERIODIC_ENABLE=1` 时生效；Sleep 期间停止 |
| byte0 | 状态码 |
| byte1 | `0x41`(APP) / `0x42`(Boot) |

**生命周期状态**:

| 值 | 名称 | 说明 |
|----|------|------|
| 0x01 | BOOTUP | 上电/复位 |
| 0x02 | INIT | 初始化中 |
| 0x03 | OPERATIONAL | 正常运行 |
| 0x04 | DEGRADED | 降级运行 |
| 0x05 | FAULT | 严重故障 |
| 0x06 | SHUTDOWN | 准备下电（0x37 自复位前） |

**触发时机**:
- 状态切换立即广播
- SIT1145 唤醒后: BOOTUP
- CAN bus-off 恢复后: BOOTUP
- `0x37` 自复位前: SHUTDOWN
- 多帧 UDS 组包/应答期间抑制 lifecycle TX（`uds_mf_busy()`），避免抢邮箱

### 2.8 Device Info 设备信息管理

**需求编号**: OTA-REQ-008

**描述**: Flash 保留区存储设备标识；OTA 擦除不涉及此区域。

**存储地址**: `0x0801E000`（4KB）  
**结构**: `device_info_t` v3，512 字节

| 字段 | 类型 | 偏移 | 说明 |
|------|------|------|------|
| magic | uint32 | 0x00 | `0x44455649`（DEVI） |
| version | uint32 | 0x04 | 3 |
| crc32 | uint32 | 0x08 | CRC32 |
| sn | char[32] | 0x0C | 序列号 |
| hw_version | char[8] | 0x2C | **已弃用**（F193 改读编译常量） |
| production_date | uint32 | 0x34 | 产线日期 |
| ecdsa_pubkey | uint8[65] | 0x38 | SEC1 未压缩公钥 |
| pubkey_valid | uint8 | 0x79 | 0x01=有效, 0xFF=未配置 |
| qi_fw_ver_major | uint8 | 0x7A | Qi 版本 major |
| qi_fw_ver_minor | uint8 | 0x7B | Qi 版本 minor |
| qi_fw_ver_patch | uint8 | 0x7C | Qi 版本 patch |
| qi_fw_version_valid | uint8 | 0x7D | 0x01=有效, 0xFF=未获取 |
| reserved | uint8[386] | 0x7E | 保留 |

**UDS 访问**:

| 操作 | DID | 条件 |
|------|-----|------|
| 读 SN | 22 F18C | 任意会话；未写入 → NRC 0x31 |
| 写 SN | 2E F18C [≤32B] | Programming + 解锁；右补 0x20 |
| 读公钥 | 22 2120 | `pubkey_valid=0x01` 否则 NRC |
| 写公钥 | 2E 2120 [65B] | Programming + 解锁；首字节 0x04 |

**Qi 版本探测**：上电 PB2 短暂供电 → 被动监听 Qi CMD 0x01 → 缓存 + Flash 持久化 → PB2 关闭。

### 2.9 UDS 服务支持

**需求编号**: OTA-REQ-009

**描述**: 全部 UDS 在 APP 实现；Bootloader 无 UDS（Safe Mode 仅少量诊断）。

#### 2.9.1 服务矩阵（APP）

| SID | 服务 | 支持 | 说明 |
|-----|------|------|------|
| 0x10 | DiagnosticSessionControl | ✅ | Default / Programming / Extended；suppressPosResp |
| 0x11 | ECUReset | ❌ | **已删除**，回 NRC 0x11 |
| 0x22 | ReadDataByIdentifier | ✅ | 见 §2.10 |
| 0x27 | SecurityAccess | ✅ | 27 01/03/02 |
| 0x2E | WriteDataByIdentifier | ✅ | 见 §2.10 写门禁 |
| 0x31 | RoutineControl | ✅ | FF00 擦除；2100 Clear Faults |

### 2.11 Flash 布局与保护

**需求编号**: OTA-REQ-011

| 区域 | 起始 | 结束 | 大小 | 说明 |
|------|------|------|------|------|
| Bootloader | 0x08000000 | 0x08002FFF | 12KB | 选区+验签+跳转 |
| App 区 | 0x08003000 | 0x0800FFFF | 52KB | XATO 头 @0x08003000，入口 @0x08003100 |
| 备份区 | 0x08010000 | 0x0801CFFF | 52KB | OTA 暂存 |
| Metadata 主 | 0x0801D000 | 0x0801D7FF | 2KB | OTA 状态 |
| Metadata 备 | 0x0801D800 | 0x0801DFFF | 2KB | 掉电安全副本 |
| Device Info | 0x0801E000 | 0x0801EFFF | 4KB | SN/公钥/Qi 版本缓存 |
| NVM | 0x0801F000 | 0x0801FFFF | 4KB | APP 配置（功率档位等） |

**保护机制**:
- Flash 页大小: 1KB（`FLASH_SECTOR_SIZE = 0x400`）
- OTA 擦除范围: 仅备份区；搬运时 BOOT 擦 App 区；**不涉及** Device Info / NVM
- 擦除期间 `__disable_irq()` + `flash_sector_erase_bounded()`（有界等待，超时 NRC 0x72）
- 擦除后 `can_driver_offline→online` 重初始化，避免 bus-off/错误态
- Metadata 先写 Backup 再写 Primary
- Device Info 整页擦除后重写（CRC32）

**Keil 链接**:
- APP: IROM1 = `0x08003100`，Size = `0xCF00`
- Boot: IROM = `0x08000000`，Size = `0x3000`
- VTOR = `0x08003100`

## 3. 控制层面功能需求

### 3.1 OTA-REQ-014 无线充电控制

**描述**: 霍尔（PA0）检测手机，控制 5V 无线充供电（PB2）。

**引脚**:

| 引脚 | 方向 | 功能 | 电平 |
|------|------|------|------|
| PA0 | 输入上拉 | 霍尔 H_OUT | 低=有磁场=手机在位；高=无手机 |
| PB1 | 输出 | 12V Buck 使能 | 低=使能 |
| PB2 | 输出 | 5V 无线充供电 | 高=使能 5V |
| PA2/PA3 | USART2 | Qi UART 19200 8N1 | MUX1 |
| PA11/PA12 | CAN1 | CAN RX/TX | MUX4 |
| PA5/6/7 | SPI1 | SIT1145 | MUX0 |

**控制逻辑**:

| 条件 | PB2 | 说明 |
|------|-----|------|
| 上电默认 | 低 | `g_charge_enabled=false` |
| 使能 + 手机在位 | 高 | `board_charge_poll()` 主循环轮询 |
| 使能 + 无手机 | 低 | 等待放置 |
| 禁用 | 低 | 写 0x2101=0 |
| Programming 会话 | 低 | `10 02` 强制失能 |
| Qi IAP 进行中 | **高（保持）** | `board_iap_hold_power(1)`，不受霍尔/使能影响 |
| 阻塞故障激活 | 拒绝使能 | 写 0x2101=1 → NRC 0x22 |

**验证标准**:
- 上电 PB2 为低
- 使能且手机在位 → PB2 高；移走手机 → PB2 低
- Programming 会话强制 PB2 低
- IAP 全程 PB2 保持高
- DID 0x2118 反映夹臂/手机状态

---

### 3.2 OTA-REQ-015 Qi 功率档位

**描述**: 三档功率经 UDS 配置，NVM 持久化，转发 Qi 芯片。

| 档位码 | 功率 | 兼容旧 2B mW 载荷 |
|--------|------|-------------------|
| 0x01 | 5W | 5000 |
| 0x02 | 10W | 10000 |
| 0x03 | 15W | 15000 |

- 读 `22 210D` → 1B 档位码
- 写 `2E 210D 01|02|03`（Extended + 解锁）
- 兼容旧 2 字节 LE mW 载荷，映射到档位码
- 值域外 → NRC 0x31
- NVM 偏移 `0x100`；上电加载，旧 NVM mW 值自动映射
- 默认 15W（0x03）

### 3.3 OTA-REQ-016 Qi UART 抓取 / 透传

**描述**: 旁路观察与调试 Qi UART 总线。

| 项 | 说明 |
|----|------|
| 抓取缓冲 | 256B 环形 + 溢出标志（`qi_uart_sniff`） |

## 4. 非功能需求

### 4.1 可靠性

- OTA 中断电：metadata 先 Backup 后 Primary，恢复后可继续或回滚
- 搬运失败：`last_boot_reason=0x04`，旧镜像保持 / 回滚
- 空片/双副本无效：BOOT Safe Mode；产线 `merge_prod_bin` 救砖
- 擦除有界等待：超时可观测（NRC 0x72），可重试
- 多帧 ISO-TP：重复 CF 忽略不 abort；FC 失败可重试；长操作刷 S3

### 4.2 安全性

- 固件签名: ECDSA P-256，防未授权固件
- 安全访问: 32B seed + 签名，3 次失败锁 30s
- 密钥轮换: 公钥存 Device Info，UDS 可更换
- 测试开关 `SA_VERIFY_ENFORCE` / `OTA_VERIFY_ENFORCE` 默认 =1，禁止提交 =0

### 4.3 兼容性

- Device Info v3（Qi 版本 3 字节 + valid）
- Metadata v4（v2 及更早拒绝并重建）
- 功率 DID 兼容旧 2B mW 载荷
- XATO 头布局字节冻结（256B，偏移不变）

## 5. 约束与限制

1. **下载在 APP**（0x31/0x34/0x36/0x37）；Boot 12KB 只搬运切区。空片用 `merge_prod_bin.py`
2. **镜像必须带 XATO 头**，裸 bin 经 `pack_image.py` 打包
3. **私钥与公钥绑定**，更换密钥需同步
4. **不实现看门狗**；0x37 后靠 APP 自复位
5. **S3 = 30 秒**，超长操作主机仍建议周期 `3E 80` 保活
6. **Flash 页 1KB**，擦除粒度必须匹配
7. **旧 DID 0x2130/0x2131 不可再用**；Qi IAP 统一 `2E 20 10 04` 路径
8. **0x11 ECUReset 已删除**；复位由 0x37 自复位或硬件复位完成
9. **版本号唯一真相源**为 `SW_VERSION_STR` / `HW_VERSION_STR` / `BOOTLOADER_VER_STR` 编译常量
