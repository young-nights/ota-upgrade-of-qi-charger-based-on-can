## 1. 目的

本文档定义由 CCU 控制的车载外设模块的通用 CAN 协议架构。

所有新外设均应（SHALL）使用本架构，除非获得项目特定的例外批准。外设专用 SRS 文档应（SHALL）引用本文档，并仅定义所分配的节点地址、设备专用 DID、状态载荷、例程和验收标准。

## 2. 范围

本规范涵盖：

- CAN 物理层和数据链路层配置
- 用于诊断通信的 29 位扩展寻址
- 基于 ISO-TP 的 UDS 诊断服务
- 用于受保护操作的 ECDSA P-256 安全访问
- 固件下载和复位流程
- 外设生命周期广播消息
- 通用 DID 和否定响应处理
- 通用供应商验证要求

本规范不定义外设业务逻辑，例如显示屏页面渲染、充电器功率调节、传感器采样或执行器控制。这些需求属于各外设 SRS。

## 3. 网络模型

CCU 为诊断主节点。每个外设为诊断目标节点，拥有一个已分配的源地址。

**节点表：**

| 节点              | 地址              | 角色                             |
| ----------------- | ----------------- | -------------------------------- |
| CCU               | 0x03              | 诊断主节点 (Diagnostic Master)   |
| 外设 (Peripheral) | 在外设 SRS 中分配 | 诊断目标节点 (Diagnostic Target) |

多个外设可共享同一 CAN 总线。每个外设应（SHALL）使用唯一的源地址和唯一的生命周期状态 PGN 分配。

## 4. CAN 物理与数据链路层

| 参数         | 要求                                                        |
| ------------ | ----------------------------------------------------------- |
| CAN 标准     | CAN 2.0B，Classical CAN                                     |
| 波特率       | 250 kbps                                                    |
| 诊断 ID 格式 | 29 位扩展帧                                                 |
| 最大 DLC     | 8 字节                                                      |
| 字节序       | 多字节载荷字段采用小端序（Little-endian），除非另有明确说明 |
| 终端电阻     | 按整车线束设计；端节点需 120 欧姆终端电阻                   |
| 采样点       | 87.5%（推荐）                                                |
| CAN 收发器   | 需外部收发器（如 SIT1145），须在 CAN 控制器初始化前完成 Normal Mode 配置 |

## 5. 诊断 CAN 标识符

UDS 诊断消息应（SHALL）使用 J1939 风格的 PDU1 寻址，PF 为 0xDA。

CAN ID 布局（按 ISO 15765-2 普通固定寻址）：

```
0x18DA{TA}{SA}
```

- **优先级 (Priority)**: 6
- **PF**: 0xDA
- **TA**: 目标地址 (N_TA — 目的地，占据 J1939 PDU1 中的 PS 字段)
- **SA**: 源地址 (N_SA — 发送方)

对于地址为 xx 的外设，诊断 ID 如下：

| 方向        | CAN ID     | 含义                       |
| ----------- | ---------- | -------------------------- |
| CCU → 外设 | 0x18DAxx03 | 诊断请求（TA=xx，SA=0x03） |
| 外设 → CCU | 0x18DA03xx | 诊断响应（TA=0x03，SA=xx） |

外设应（SHALL）仅接受寻址到自身地址的请求（N_TA 与其分配地址匹配）。

外设还应（SHALL）接受功能寻址请求（用于广播诊断）：

| 方向 | CAN ID | 含义 |
|------|--------|------|
| CCU → 所有外设（功能寻址） | `0x18DB33xx` | 功能广播（PF=0xDB，PS=0x33，SA 任意） |

功能寻址使用 PF=0xDB（PDU2 格式），目标地址字段（PS）为功能组地址 0x33。SA 无限制，接收端通过 PS=0x33 识别功能寻址。

### Qi 充电模块 CAN 帧汇总

本项目实际用到的所有 CAN ID 如下（29-bit 扩展帧，250 kbps）：

| CAN ID | 方向 | 用途 | 帧类型 | 说明 |
|--------|------|------|--------|------|
| `0x18DA0D03` | CCU → Qi 模块 | UDS 物理寻址请求 | 数据帧 | TA=0x0D（Qi），SA=0x03（CCU） |
| `0x18DA030D` | Qi 模块 → CCU | UDS 物理寻址响应 | 数据帧 | TA=0x03（CCU），SA=0x0D（Qi） |
| `0x18DB33xx` | CCU → 所有外设 | UDS 功能寻址广播 | 数据帧 | PF=0xDB，PS=0x33，Safe Mode 也接收 |
| `0x18FF260D` | Qi 模块 → 总线 | 生命周期状态广播 | 数据帧 | byte0=状态码，byte1=0x41(APP)/0x42(Boot)，1Hz |
| — | CCU → 总线 | **唤醒帧** | 数据帧 | 任意 250kbps 扩展帧即可唤醒 SIT1145（ISO 11898-2 WUP） |

**唤醒帧说明**：SIT1145 处于 Standby 模式时，CAN 收发器处于低功耗监听状态。CCU 发送任意一帧 250kbps 扩展帧（如 UDS `02 3E 00` TesterPresent 或 `02 10 02` 进入编程会话），SIT1145 检测到总线活动后自动切换到 Normal 模式，MCU 检测到唤醒标志（PA11 拉低或 TRANSCEIVER_EVENT CW 位）后启动 CAN 通信。

典型唤醒序列：
```
CCU: 发送 02 3E 00 00 00 00 00 00（CAN ID 0x18DA0D03）
SIT1145: 检测总线活动 → Standby → Normal
MCU: 检测 PA11 拉低 → can_lp_enter_normal() → 回复 7E 00
```

#### OTA 下载流程

| 指令（hex） | 含义 | 正响应 | 备注 |
|---|---|---|---|
| `04 31 01 FF 00` | 擦除非活跃槽 | 先 `7F 31 78`，再 `04 71 01 FF 00` | 超时 8~10s |
| `02 34 00` | 申请下载（简略） | `04 74 20 01 00` | maxBlock=256 |
| `0B 34 00 44 [4B addr] [4B size]` | 申请下载（完整） | `04 74 20 01 00` | 多帧传输 |
| `xx 36 ss [data...]` | 传输镜像数据 | `02 76 ss` | ss 从 01 起，FF 后→01 |
| `01 37` | 结束传输 | 先 `7F 37 78`，再 `01 77` | 验签+CRC |

#### 负响应码（NRC）

| NRC（hex） | 含义 | 典型场景 |
|---|---|---|
| `11` | 服务不支持 | APP 的下载类 SID |
| `22` | 条件不满足 | 非 Programming 就擦/下 |
| `24` | 顺序错 | 未擦就 34 |
| `31` | 超出范围 | size 过大或 DID 无效 |
| `33` | 未解锁 | SecurityAccess 未通过 |
| `35` | 签名无效 | ECDSA 验签失败 |
| `36` | 次数超限 | 3 次失败锁 30s |
| `37` | 延迟未到期 | 锁定期间 |
| `72` | 编程失败 | Flash 擦写/CRC/签名 |
| `73` | 块序号错 | blockSeq 不连续 |
| `78` | ResponsePending | 擦除/验签/0x37 长操作 |

## 6. ISO-TP 传输层

UDS 载荷应（SHALL）通过 ISO-TP 使用 29 位普通寻址进行传输。

| 参数                | 要求                                              |
| ------------------- | ------------------------------------------------- |
| 单帧载荷            | 0 至 7 字节                                       |
| 多帧载荷            | 8 至 4095 字节                                    |
| 流控制              | 接收方应（SHALL）在首帧 (First Frame) 之后发送 FC |
| 块大小 (Block Size) | 0x00（首选），无限制连续帧                        |
| STmin               | 1 ms（默认）                                      |
| N_As                | 1000 ms                                           |
| N_Ar                | 1000 ms                                           |
| N_Bs                | 1000 ms                                           |
| N_Cr                | 1000 ms                                           |

外设应（SHALL）拒绝畸形的 ISO-TP 传输，并应（SHALL）在不需重新上电的情况下恢复。

## 7. UDS 诊断服务

以下 UDS 服务为各外设通用。

| SID  | 服务                                     | 必需               | 安全要求              |
| ---- | ---------------------------------------- | ------------------ | --------------------- |
| 0x10 | DiagnosticSessionControl（诊断会话控制） | 是                 | 无                    |
| 0x11 | CCUReset（CCU 复位）                     | 是                 | 无                    |
| 0x22 | ReadDataByIdentifier（按标识符读数据）   | 是                 | 无                    |
| 0x27 | SecurityAccess（安全访问）               | 是                 | 无                    |
| 0x2E | WriteDataByIdentifier（按标识符写数据）  | 是                 | 受保护 DID 需 Level 1 |
| 0x31 | RoutineControl（例程控制）               | 是                 | 受保护例程需 Level 1  |
| 0x34 | RequestDownload（请求下载）              | 支持固件更新时必需 | Level 1               |
| 0x36 | TransferData（传输数据）                 | 支持固件更新时必需 | Level 1               |
| 0x37 | RequestTransferExit（退出传输）          | 支持固件更新时必需 | Level 1               |
| 0x3E | TesterPresent（测试仪在线）              | 是                 | 无                    |

外设 SRS 文档可（MAY）仅在需要时定义额外服务。

### 7.1 响应时序

| 参数                                    | 值         |
| --------------------------------------- | ---------- |
| P2（服务器响应时间）                    | <= 50 ms   |
| P2*（增强响应时间，发送 NRC 0x78 之后） | <= 5000 ms |

如果外设无法在 P2 时间内响应，应（SHALL）发送 NRC 0x78（requestCorrectlyReceivedResponsePending）将超时扩展至 P2*。此情况预期出现在 ECDSA P-256 签名验证、Flash 擦除或 CRC 计算等操作期间。

### 7.2 抑制肯定响应 (suppressPositiveResponse)

在 DiagnosticSessionControl（0x10）、CCUReset（0x11）和 TesterPresent（0x3E）的子功能参数中，第 7 位为抑制肯定响应位。当该位置位时，外设应（SHALL）执行请求但不应（SHALL NOT）发送肯定响应。否定响应仍应发送，不受此位影响。

### 7.3 会话管理

| 会话                    | 值   | 用途                  |
| ----------------------- | ---- | --------------------- |
| Default（默认会话）     | 0x01 | 正常运行和只读诊断    |
| Programming（编程会话） | 0x02 | 固件更新和 Flash 操作 |
| Extended（扩展会话）    | 0x03 | 受保护配置和扩展诊断  |

非默认会话在 5 秒内未收到 TesterPresent 时应（SHALL）超时。超时后，外设应（SHALL）返回默认会话并清除安全解锁状态。

**会话切换规则：**

- 从一个非默认会话切换到另一个非默认会话（例如从 Extended 切换到 Programming）应（SHALL）清除当前安全解锁状态。CCU 必须在会话切换后重新认证。
- 进入默认会话应（SHALL）中止任何正在进行的固件传输并清除安全解锁状态。
- 外设应（SHALL）在任何会话中响应 DiagnosticSessionControl。

### 7.4 安全访问 (SecurityAccess)

安全访问 Level 1 在量产中应（SHALL）使用 ECDSA P-256 挑战-响应机制。

**流程：**

1. CCU 发送 `[0x27, 0x01]`。
2. 外设响应 `[0x67, 0x01, seed...]`，附带 4 字节随机种子。
3. CCU 使用其私钥对种子进行签名。
4. CCU 发送 `[0x27, 0x02, signature...]`，附带 64 字节 ECDSA P-256 签名。
5. 外设使用已注入的公钥验证签名。
6. 如果验证成功，外设响应 `[0x67, 0x02]`。

**安全要求：**

- 种子应（SHALL）每次请求唯一。
- 量产种子源应（SHALL）为硬件 RNG 或经批准的密码学 RNG。
- 公钥应（SHALL）存储在只读或受保护的存储器中。
- 安全未解锁时，受保护操作应（SHALL）以 NRC 0x33 失败。
- 无效签名应（SHALL）以 NRC 0x35 失败。
- 连续三次失败应（SHALL）触发锁定，返回 NRC 0x36（exceededNumberOfAttempts）。锁定期间，后续 SecurityAccess 请求应（SHALL）以 NRC 0x37（requiredTimeDelayNotExpired）拒绝。
- 锁定延迟应（SHALL）为 **30 秒**。
- 成功会话复位（DiagnosticSessionControl 至 Default）时可（MAY）清除失败计数器。不要求跨掉电周期保持。

## 8. 通用 DID

### 标准标识 DID

| DID    | 名称                        | 访问 | 格式 |
| ------ | --------------------------- | ---- | ---- |
| 0xF180 | Bootloader 版本 (Bootloader Version) | 读   | 定长 32 字节 ASCII，右补空格 |
| 0xF18C | 序列号 (Serial Number)      | 读；产线可写 | 定长 32 字节 ASCII，右补空格 |
| 0xF193 | 硬件版本 (Hardware Version) | 读   | 定长 32 字节 ASCII，右补空格 |
| 0xF195 | ECU 软件版本 (ECU Software Version) | 读   | 定长 32 字节 ASCII，右补空格 |

四行识别 DID 为同一张表，不得拆开。字符串规则见 8.1；`0xF18C` 读写规则见 8.2.1。

### 固件管理 DID

| DID    | 名称                                  | 访问  | 格式               |
| ------ | ------------------------------------- | ----- | ------------------ |
| 0x2010 | 固件类型 (Firmware Type)              | 读/写 | uint8              |
| 0x2120 | ECDSA 公钥 (Public Key)              | 读/写 | 65 字节 SEC1 未压缩，写需解锁 |
| 0x2012 | 资源包版本 (Resource Package Version) | 读    | UTF-8 字符串，可选 |

### 默认固件类型值

| 值   | 含义                 |
| ---- | -------------------- |
| 0x01 | APP 固件             |
| 0x02 | 资源包（如支持）     |
| 0x03 | Bootloader（如支持） |

### 8.1 版本字符串格式

所有识别类 DID（0xF180、0xF193、0xF195、0xF18C）的读取响应应（SHALL）为 **定长 32 字节**，以 ASCII 空格（`0x20`）填充。版本号使用语义化版本格式 `MAJOR.MINOR.PATCH`（例如 `1.2.3`），右端补空格至 32 字节。序列号（0xF18C）为 ASCII 字符串，右端补空格至 32 字节。

> **注意**：XATO 镜像头中的 `version[16]` 字段保持 16 字节不变，那是 OTA 打包格式，与 UDS DID 响应格式无关。

### 8.2 DID 0x2010 访问控制

DID 0x2010（固件类型）的写访问应（SHALL）要求编程会话和 SecurityAccess Level 1。在默认会话和扩展会话中为只读。

### 8.2.1 DID 0xF18C 访问控制（序列号）

DID `0xF18C` 数据在 Device Info（`0x0801D000` ~ `0x0801DFFF`）。

- **读**：任意会话。响应定长 32 字节、右补 ASCII 空格。Device Info 无效（无 `DEVI` / CRC 失败）时应（SHALL）返回 NRC `0x31`。
- **写**：仅产线。应（SHALL）要求 Programming Session + SecurityAccess Level 1（`0x2E F18C`）。扫码枪 → CCU → CAN-UDS，MCU 将 SN 写入该区。默认会话或扩展会话写应（SHALL）以 NRC `0x22` 或 `0x33` 拒绝。
- OTA 擦写不得包含 Device Info。升级后 SN 仍在。

工位步骤见 [9. APP镜像打包与产线烧录.md](9.%20APP镜像打包与产线烧录.md) §6.2。

### 8.3 多 DID 读取

外设应（SHALL）支持在单次 ReadDataByIdentifier（0x22）请求中读取多个 DID，上限为 ISO-TP 载荷限制。如果任何请求的 DID 不受支持，外设应（SHALL）对整个请求返回 NRC 0x31。

### 8.4 外设专用 DID

外设专用 DID 应（SHALL）由各外设 SRS 定义。新外设 DID 宜（SHOULD）使用专用范围以避免冲突。

#### 充电控制 DID

| 0x2102 | 充电状态     | R   | uint8             | 读 PB2 电平：高=CHARGING, 低+使能=STANDBY, 低+未使能=DISABLED                                              |

| 0x2104 | 输出功率     | R   | uint16 (mW)       | 从 Qi 帧回调更新                                                                                            |
| 0x2105 | 输入电压/电流 | R  | 待定              | 保留定义，来源 CCU                                                                                          |

| 0x210C | 热降额等级   | R   | uint8             | 85 度保护，60 度恢复                                                                                        |

## 9. 固件升级

### 9.1 UDS 下载流程

支持固件更新的外设应（SHALL）实现通用 UDS 下载流程：

| 步骤 | 操作                             | UDS 服务                           |
| ---- | -------------------------------- | ---------------------------------- |
| 1    | 进入编程会话                     | 0x10 0x02                          |
| 2    | 解锁 SecurityAccess Level 1      | 0x27 0x01 / 0x27 0x02              |
| 3    | 通过写入 DID 0x2010 选择固件类型 | 0x2E                               |
| 4    | 擦除目标存储区域                 | 0x31 0x01 0xFF00（RoutineControl） |
| 5    | 请求下载（含地址和大小）         | 0x34（RequestDownload）            |
| 6    | 按序号块传输固件数据             | 0x36（TransferData）               |
| 7    | 结束传输并触发验证               | 0x37（RequestTransferExit）        |
| 8    | 外设验证 CRC32 和 ECDSA P-256 签名   | 内部操作                           |
| 9    | 复位以激活新镜像                 | 0x11（CCUReset）                   |

### 9.2 传输要求

- 块序号计数器应（SHALL）在首次 TransferData 时为 0x01（初始值为 0x00，首帧传输前递增）。
- 块序号计数器应（SHALL）递增至 0xFF 后回绕至 0x01。
- 0x00 不应（SHALL NOT）用作正常块序号计数器值。
- 最大 TransferData 块大小应（SHALL）通过 RequestDownload 响应协商（lengthFormatIdentifier 和 maxNumberOfBlockLength）。供应商应（SHALL）在文档中说明支持的最大块大小（建议最小值：256 字节）。
- 外设应（SHALL）要求 SecurityAccess Level 1 才能执行 RequestDownload、擦除例程和固件类型 DID 写入。未事先解锁的请求应（SHALL）以 NRC 0x33 拒绝。
- 如果 Flash 擦除或签名验证超过 P2 时间，外设应（SHALL）发送 NRC 0x78（ResponsePending）以保持会话活跃。

### 9.3 验证要求

- 外设应（SHALL）在将固件镜像标记为有效之前验证 CRC32。
- 外设应（SHALL）在启动下载镜像之前验证 ECDSA P-256 固件签名。
- 外设应（SHALL）拒绝具有无效长度、无效 CRC、无效签名、不支持格式或不支持固件类型的镜像。
- 如果验证失败，外设应（SHALL）保留之前的有效镜像或进入安全故障模式。

### 9.4 双槽固件布局（可选）

外设宜（SHOULD）实现双槽（A/B）固件布局以防止 OTA 过程中变砖。实现双槽时：

- 活跃应用槽在下载期间不应（SHALL NOT）被擦除或覆盖。新固件应（SHALL）仅写入非活跃槽。
- 每个槽应（SHALL）包含完整的独立可执行镜像和镜像元数据（至少包括：镜像长度、固件版本、CRC32、签名、槽有效性状态）。
- 启动元数据更新（槽激活、试用启动确认、回滚）应（SHALL）为原子操作或掉电安全的。任何时刻的掉电应（SHALL）导致确定性的有效状态，而非损坏的中间状态。
- 供应商应（SHALL）在发布包中提供最终 Flash 存储映射、槽大小、最大镜像大小和元数据布局。

未实现双槽的外设应（SHALL）在文档中说明其安全恢复机制（例如具有重新下载能力的安全 Bootloader）。

### 9.5 试用启动与回滚（可选，需双槽）

实现双槽时，外设宜（SHOULD）支持带自动回滚的试用启动：

- CCUReset 后，Bootloader 应（SHALL）以试用模式启动待定镜像。
- 应用应（SHALL）仅在完成核心初始化（CAN 通信、安全子系统、NVM 访问）后确认新镜像。
- 如果新镜像在供应商定义的超时时间内（默认 10 秒）未能确认，Bootloader 应（SHALL）回滚到之前的有效槽。
- 如果新镜像在确认前反复复位，Bootloader 应（SHALL）在供应商定义的重试次数（默认 3 次）后回滚。
- 之前的有效槽应（SHALL）保持可启动状态，直到新镜像被确认。
- 回滚后，外设应（SHALL）通过外设 SRS 中定义的设备专用 DID 报告回滚事件。

### 9.6 掉电与故障恢复

无论是否实现双槽，以下恢复行为应（SHALL）适用：

| 故障点                   | 要求恢复行为                     |
| ------------------------ | -------------------------------- |
| RequestDownload 之前掉电 | 启动之前的有效镜像               |
| TransferData 期间掉电    | 启动之前的有效镜像；下载目标无效 |
| 验证期间掉电             | 启动之前的有效镜像               |
| CRC 或签名无效           | 拒绝镜像，保留之前的有效镜像     |

实现双槽时，以下额外要求适用：

| 故障点                     | 要求恢复行为                                                |
| -------------------------- | ----------------------------------------------------------- |
| 写入待定激活后、复位前掉电 | Bootloader 基于原子元数据激活有效的待定槽或保持之前的活跃槽 |
| 试用启动期间掉电           | 重试试用启动直到重试次数上限，然后回滚                      |
| 新镜像确认前系统复位       | 按重试次数上限重试后回滚                                    |

镜像确认之前的任何 OTA 失败应（SHALL）保留之前已确认的镜像。外设不应（SHALL NOT）在任何 OTA 步骤被中断后进入不可启动状态。

外设 SRS 文档应（SHALL）定义最大固件大小、设备专用 OTA DID 和额外验收标准。

## 10. 生命周期状态广播

每个外设应（SHALL）使用 J1939 风格的 PDU2 广播消息发布生命周期状态。

CAN ID 布局：

```
0x18FF{GE}{SA}
```

- **优先级 (Priority)**: 6
- **PF**: 0xFF
- **GE**: 外设状态组扩展，在 SRS 中分配
- **SA**: 外设源地址

字节 0 应（SHALL）包含通用生命周期状态：

| 值   | 状态         | 含义                    |
| ---- | ------------ | ----------------------- |
| 0x01 | BOOTUP       | 外设已上电或复位        |
| 0x02 | INITIALIZING | 外设正在初始化硬件/软件 |
| 0x03 | OPERATIONAL  | 外设已就绪，可正常运行  |
| 0x04 | DEGRADED     | 外设以降级能力运行      |
| 0x05 | FAULT        | 外设存在严重故障        |
| 0x06 | SHUTDOWN     | 外设正在准备断电        |

字节 1-7 应（SHALL）为零，除非外设 SRS 定义了扩展状态载荷。

**广播要求：**

- BOOTUP 应（SHALL）在上电或复位后 100 ms 内发送。
- OPERATIONAL 应（SHALL）在初始化完成时发送。
- DEGRADED 或 FAULT 应（SHALL）在状态变化后 100 ms 内发送。
- SHUTDOWN 宜（SHOULD）在可能的情况下于正常断电前发送。
- 在 OPERATIONAL 或 DEGRADED 状态下，外设宜（SHOULD）以默认 1 Hz（1000 ms）的频率发送周期性状态广播。外设 SRS 可（MAY）定义可配置的周期或禁用周期性广播。

## 12. CAN Bus-Off 恢复

如果 CAN 控制器进入 bus-off 状态（发送错误计数器 >= 256，按 ISO 11898-1），外设应（SHALL）在检测到 128 次 11 个连续隐性位后尝试自动恢复。外设不应（SHALL NOT）需要重新上电来从 bus-off 恢复。

Bus-off 恢复后，外设应（SHALL）：

- 发送 BOOTUP 或 OPERATIONAL 生命周期广播以标识其恢复。
- 恢复正常 UDS 服务器操作。
- 不清除 bus-off 之前已存在的任何活跃故障状态。

供应商应（SHALL）在发布包中提供 bus-off 恢复时序文档。

## 13. 通用供应商验证

每个外设供应商应（SHALL）提供以下证据：

- CAN 波特率和 ID 过滤正确性。
- UDS 服务肯定和否定响应。
- ISO-TP 单帧和多帧行为。
- 会话超时和 TesterPresent 行为。
- SecurityAccess 有效和无效签名行为。
- 受保护 DID 和例程的访问控制。
- 固件下载、验证和复位行为。
- 生命周期广播时序和状态转换。
- 无需重新上电的 CAN bus-off 恢复。
- 24 小时 CAN 通信稳定性。

外设 SRS 文档应（SHALL）添加设备专用验证项。
