> **适用**：理解 Bootloader 镜像签名校验机制、掌握打包/签名脚本用法、验证签名正确性
> **涉及文件**：`boot_verify.c/h`、`sha256.c/h`、`uECC.c/h`、`pack_image.py`、`merge_prod_bin.py`

## 1. 签名校验原理

Bootloader 在每次上电跳转 APP 前，对镜像执行 6 级校验，全部通过才允许跳转。

### 1.1 校验流程

步骤编号与 `g_verify_fail_step` 取值一致：

```
boot_verify_image(base_addr, slot_size)
  │
  ├─ Step 1: Header Magic ─── "XATO" (0x4F544158)
  │     fail_step = 1
  │
  ├─ Step 2: Image Length ─── 不能为 0，不能超出 slot 容量
  │     fail_step = 2
  │
  ├─ Step 3: CRC32 ──────── IEEE 802.3 CRC 覆盖裸固件（不含头）
  │     fail_step = 3
  │
  ├─ Step 4: Reset Handler ─ Reset 向量必须落在当前 slot 内
  │     fail_step = 4
  │
  ├─ Step 5: 公钥完整性 ──── 符号 g_pubkey_magic == "KEYP" (0x4B594550)
  │     fail_step = 5
  │
  └─ Step 6: ECDSA P-256 ─── SHA-256(裸固件) → uECC_verify(pubkey, hash, sig)
        fail_step = 6
```

上电时 Boot 先查备份区搬运标志（backup_valid），再验 **App 区**镜像；搬运失败详情记 metadata copy_retry/fail_step。`g_verify_fail_step` 只保留**最后一次**校验结果：成功路径会把它清 0；空槽会在 Magic 处写成 1，覆盖前一槽的 3/4/6。板端读法见第 4.2 节。

### 1.2 失败诊断码

`g_verify_fail_step` 记录最后一次校验的失败步骤（不是第一槽的失败码）：

| 值 | 含义               | 常见原因                                  |
| -- | ------------------ | ----------------------------------------- |
| 0  | 校验通过           | —                                        |
| 1  | Magic 错误         | 镜像头损坏、烧录地址偏移、裸 bin 直接烧入 |
| 2  | 长度越界           | image_length 为 0 或超出 slot 容量        |
| 3  | CRC32 不匹配       | 固件数据被篡改或传输错误                  |
| 4  | Reset Handler 越界 | 镜像链接到错误 slot（A 链 B 或反之）      |
| 5  | 公钥损坏           | Flash 被意外擦写，公钥区 Magic 不匹配     |
| 6  | ECDSA 签名无效     | 私钥与公钥不匹配、签名被篡改、数据损坏    |

### 1.3 密钥体系

| 组件 | 算法                    | 说明                                                                            |
| ---- | ----------------------- | ------------------------------------------------------------------------------- |
| 公钥 | ECDSA P-256 (secp256r1) | 65 字节 SEC1 未压缩格式`04 \|\| X \|\| Y`，烧写在 Bootloader `.ecdsa_pubkey` 段 |
| 私钥 | ECDSA P-256             | 仅存在于`docs/keys/private.pem`，**不允许烧入 MCU**                     |
| 哈希 | SHA-256                 | 对裸固件（不含 256 字节头）计算，产出 32 字节摘要                               |
| 签名 | IEEE P1363              | `R \|\| S` 各 32 字节 = 64 字节，存放在镜像头 `signature` 字段                |

**关键约束**：

- 签名对象 = 裸固件数据，**不含** 256 字节 XATO 头
- 公钥存储：Bootloader 内置公钥（编译时固化）+ Device Info 区 `ecdsa_pubkey[65]`（支持运行时轮换）
- **密钥轮换**：可通过 UDS DID `0x2120` 将新公钥写入 Device Info（需 Programming + SecurityAccess），Bootloader 优先从 Device Info 读取公钥；若 Device Info 未配置则回退内置公钥
- 内置公钥编译进 Bootloader，更换需重烧 Bootloader
- 私钥必须严格保密，仅用于开发/产线打包

### 1.4 镜像头布局（256 字节）

与 `boot_verify.h` 中 `image_header_t` 定义一致：

| 偏移 | 长度 | 字段            | 说明                          |
| ---- | ---- | --------------- | ----------------------------- |
| 0x00 | 4    | magic           | `0x4F544158` ("XATO"，小端) |
| 0x04 | 4    | image_length    | 裸固件字节数（不含头）        |
| 0x08 | 4    | crc32           | 裸固件 CRC32 (IEEE 802.3)     |
| 0x0C | 64   | signature       | ECDSA P-256 R\|\|S            |
| 0x4C | 16   | hdr_reserved_ver | 保留占位（原 `version` 字段，声明已从结构定义删除），打包固定填 `0x00`，偏移锁定不可回收 |
| 0x5C | 4    | build_timestamp | 打包时的 Unix 时间戳          |
| 0x60 | 160  | reserved        | 填 0                          |

## 2. 密钥生成

### 2.1 生成新密钥对

```bash
# 生成 ECDSA P-256 私钥
openssl ecparam -genkey -name prime256v1 -noout -out docs/keys/private.pem

# 提取公钥（用于对比 / 验证）
openssl ec -in docs/keys/private.pem -pubout -out docs/keys/public.pem
```

### 2.2 从私钥提取公钥坐标（写入 Bootloader 用）

```bash
# 查看私钥详情（含公钥坐标）
openssl ec -in docs/keys/private.pem -text -noout
```

输出示例：

```
pub:
    04:79:0d:96:ca:91:2d:90:db:73:df:21:b0:6e:e7:
    ce:19:aa:7c:1f:75:30:55:0a:48:21:84:19:b4:4b:
    4c:37:cb:f5:7c:d3:fc:9e:26:be:1b:a6:94:dd:45:
    62:7e:aa:ca:71:38:f5:7a:8e:a8:d5:dd:20:70:33:
    26:f0:95:41:71
```

将 `04:` 后的 64 字节十六进制填入 `boot_verify.c` 的 `g_ecdsa_public_key[65]` 数组：

- 第 1 字节固定为 `0x04`（未压缩点标记）
- 第 2~33 字节 = X 坐标
- 第 34~65 字节 = Y 坐标

### 2.3 验证密钥对匹配

```bash
# 用私钥签名任意数据，再用公钥验证
echo "test" > /tmp/test.bin
openssl dgst -sha256 -sign docs/keys/private.pem -out /tmp/test.sig /tmp/test.bin
openssl dgst -sha256 -verify docs/keys/public.pem -signature /tmp/test.sig /tmp/test.bin
# 输出 "Verified OK" 表示密钥对匹配
```

### 2.4 当前仓库默认密钥

`docs/keys/` 下已包含默认开发密钥：

- `private.pem` — ECDSA P-256 私钥
- `public.pem` — 对应公钥

**量产时必须替换为正式密钥对。**

## 3. 打包脚本使用

### 3.1 `pack_image.py` — 裸 bin → 签名镜像

路径：`python_tools/1.packaging script/pack_image.py`

功能：读取 Keil 产出的裸 `.bin`，计算 CRC32 + ECDSA P-256 签名，写入 256 字节 XATO 头，输出 `app_slot_a.bin`（按链接槽自动命名）。

默认路径按脚本文件位置回推到**仓库根**，在任意当前目录执行都可以，但要指向脚本本身：

```bash
cd "python_tools/1.packaging script"
python pack_image.py
```

或在仓库根：

```bash
python "python_tools/1.packaging script/pack_image.py"
```

**显式指定参数**（已 `cd` 到 `python_tools/` 时）：

```bash
python pack_image.py \
  --bin ../../qi_wireless_code_app/mdk_project/Objects/qi_wireless_code_app.bin \
  --key ../../docs/keys/private.pem \
  --out "../app bin/app_slot_a.bin"
```

> **镜像头不携带版本号（2026-09-18 起）**：XATO 头 0x4C 区（16B）为保留占位（原 `version` 字段声明已从 `image_header_t` 删除），打包固定填 `0x00`，偏移锁定不可回收；版本号唯一定义在固件 `SW_VERSION_STR`（`can_protocol.c`），发版只改固件常量 + 文档，打包脚本无版本参数。

| 参数          | 默认值（相对仓库根）                                          | 说明                           |
| ------------- | ----------------------------------------------------------- | ------------------------------ |
| `--bin`     | `qi_wireless_code_app/mdk_project/Objects/qi_wireless_code_app.bin`    | Keil fromelf 产出的裸 APP .bin |
| `--key`     | `docs/keys/private.pem`                                   | ECDSA P-256 私钥 PEM           |
| `--out`     | `python_tools/app bin/app_slot_a.bin`（按链接槽自动命名）  | 输出镜像路径                   |
| ~~`--version`~~ | —                                                     | 不存在此参数；镜像头不携带版本号（0x4C 为保留占位，原 version 字段已删除） |

**成功输出示例**：

```
输出: /path/to/app_slot_a.bin
总长: 48128  (头 256 + 固件 47872)
链接: App 区  → 产线烧录地址 0x08004000
```

**常见错误 / 误用**：

| 提示或现象 | 原因 | 处理 |
| --- | --- | --- |
| `找不到固件` | 还没 fromelf 出 `.bin`，或路径不对 | 先在 Keil 中 Rebuild |
| `找不到私钥` | `docs/keys/private.pem` 不存在 | 按第 2 节生成密钥 |
| `超过槽大小` | 裸 bin > `0xBF00`（48896 字节）；脚本按打包后总长 > `0xC000` 报错 | 减小 APP 代码 |
| 打印 `链接: 历史B槽地址` | **失败**。单 App 架构要求 IROM1=`0x08004100`；0x08010100 属备份区，App 镜像不得链接该址 | 改 IROM1=`0x08004100` 重编后再打包 |

槽起始（烧含头 `.bin`）和代码入口（Keil IROM1）不是同一个地址：

| 槽 | 槽起始（含 256B 头，烧录地址） | 代码入口 / IROM1 Start | IROM1 Size |
| --- | --- | --- | --- |
| A | `0x08004000` | `0x08004100` | `0xBF00` |
| 备份区 | `0x08010000` | —（OTA 暂存区，非链接目标） | `0xC000` |

### 3.2 `merge_prod_bin.py` — Boot + APP 合并

路径：`python_tools/1.packaging script/merge_prod_bin.py`

功能：将 `bootloader.bin` + `app_slot_a.bin` 合并为一个 `prod_image.bin`，用于产线烧录。

```bash
cd "python_tools/1.packaging script"
python merge_prod_bin.py
```

| 参数       | 默认值                                                        | 说明               |
| ---------- | ------------------------------------------------------------- | ------------------ |
| `--boot` | `qi_wireless_bootloader/mdk_project/Objects/bootloader.bin` | Bootloader 二进制  |
| `--app`  | `python_tools/app bin/app_slot_a.bin`                     | 已签名的 APP 镜像  |
| `--out`  | `python_tools/burn bin/prod_image.bin`                    | 合并输出           |
| `--hex`  | —                                                            | 同时生成 Intel HEX |

**布局**：

```
0x0000  Bootloader  16KB (不足 16KB 补 0xFF)
0x4000  App 区     (含 256B XATO 头 + 固件，烧录 @0x08004000)
```

合并后的 `prod_image.bin` 从 **`0x08000000`** 整体烧录。

### 3.3 完整产线打包流程

```
Keil Rebuild → fromelf → qi_wireless_code_app.bin (裸 bin)
                            │
                  pack_image.py (--key private.pem)
                            │
                  app_slot_a.bin (XATO 头 + 签名 + 固件)
                            │
                  merge_prod_bin.py (--boot bootloader.bin)
                            │
                  prod_image.bin (Boot + App)
                            │
                  J-Link / AT32 ISP 从 0x08000000 烧录
```

## 4. 签名校验测试方法

### 4.1 离线验证（PC 端）

独立脚本：`python_tools/1.packaging script/verify_image.py`，一键完成全部 6 项检查。

```bash
# 基本用法（在仓库根）
python "python_tools/1.packaging script/verify_image.py" "python_tools/app bin/app_slot_a.bin"

# 指定公钥 / 目标槽（--slot A|B 决定 Reset Handler 校验基址）
python "python_tools/1.packaging script/verify_image.py" <image_path> --key docs/keys/public.pem --slot A
```

输出示例：

```
============================================================
XATO Image Verification: app_slot_a.bin
File size: 19312 bytes (header 256 + firmware 19056)
============================================================
  ✅ [PASS] Magic 正确: XATO
  ✅ [PASS] Image length 正确: 19056 bytes
  ✅ [PASS] CRC32 正确: 0xEA163241
  ✅ [PASS] Version: 1.0.0
  ✅ [PASS] Build timestamp: 2026-08-28 18:49:25 UTC
  ✅ [PASS] ECDSA 签名验证通过
============================================================
Result: 6 passed, 0 failed
============================================================
```

退出码：`0` = 全部通过，`1` = 有失败项，`2` = 文件错误。

以下为各检查项的实现细节（脚本内部已封装）：

### 4.2 板端测试（MCU 端）

Boot 工程没有 USART，`g_verify_fail_step` **只能 SWD/JTAG 读**，不能靠串口。

上电路径（`main.c`）：`try_boot_slot(选中槽)`，失败再 `try_boot_slot(另一槽)`。变量只保留最后一次：

| 现场 | 复位后读到的 `g_verify_fail_step` |
| --- | --- |
| 另一槽是空的（擦除或无 XATO 头） | 几乎总是 **1**（空槽 Magic 失败覆盖了前一槽的 3/4/6） |
| 另一槽镜像合法 | 跳到另一槽 APP，变量被成功路径清成 **0** |
| 要看「正在测的那一槽」失败码 | SWD 断在**第一次** `boot_verify_image()` 返回 `-1`，或先擦除另一槽 |

下面 4.2.2～4.2.4 默认：**擦除 Slot B**（`0x08010000` 起 48KB），坏镜像只烧 Slot A，并且用 SWD 停在第一次校验失败。若不上断点、只复位后读变量，空 B 会把结果改成 1。

#### 4.2.1 正常跳转测试

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 烧录合并后的 `prod_image.bin` | 烧录成功 |
| 2 | 复位上电 | 跳转 APP；SWD 见 `g_verify_fail_step == 0` |
| 3 | 在 APP 读 `0x22 F195` | 正响应 32 字节，ASCII `"QC_JYF_FW_1.1.16"` 右补空格（不是裸字符串） |

#### 4.2.2 签名无效测试

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 擦除 Slot B | 另一槽无效 |
| 2 | 用错误私钥重新签名打包 | 生成无效镜像 |
| 3 | 烧录到 Slot A（`0x08004000`） | 烧录成功 |
| 4 | SWD 在 `boot_verify_image()` 返回 `-1` 处下断，复位 | 第一次失败 `g_verify_fail_step == 6`（ECDSA） |
| 5 | 若放行再跑完 | 空 Slot B 再失败，变量变成 1，停在 Safe Mode |

#### 4.2.3 CRC 篡改测试

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 擦除 Slot B | 另一槽无效 |
| 2 | 改镜像中任意 1 字节固件数据，保持原 CRC32 和 signature | — |
| 3 | 烧录到 Slot A | 烧录成功 |
| 4 | SWD 停在第一次 `boot_verify_image()` 失败 | `g_verify_fail_step == 3`（CRC 在 ECDSA 之前，不会走到 6） |

#### 4.2.4 Magic 篡改测试

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 擦除 Slot B | 另一槽无效 |
| 2 | 改镜像头前 4 字节为非 `XATO` | — |
| 3 | 烧录到 Slot A | 烧录成功 |
| 4 | 复位上电（可不下断） | `g_verify_fail_step == 1`。A 与空 B 都是 Magic 失败，复位后读到 1 与第一次失败一致 |

#### 4.2.5 Reset Handler 越界测试

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 编 Slot A 固件（IROM1=`0x08004100`），`pack_image.py` 打包 | Reset Handler 落在 A 入口一带 |
| 2 | **擦除 Slot A**（否则仍会从合法 A 跳走，验不到 B） | Slot A 无效 |
| 3 | （历史机制，单 App 架构已废弃）A 链接 bin 烧到 0x08010100/0x08010000 的旧风险条目 | 现行：载荷固定 App 链接 0x08004100；OTA 写备份区 0x08010000，BOOT 搬运 |
| 4 | 复位上电 | 先验空 A → fail_step=1，再验 B → **`g_verify_fail_step == 4`**，停在 Safe Mode |

### 4.3 JTAG/SWD 调试验证

在调试器中按**符号**检查（Boot 无串口）。地址以 `.map` 为准，不要按「公钥后再加 4 字节」去 Flash 里扫：

```
# 变量名               | 位置                 | 含义
g_verify_fail_step     | 见 .map              | 最后一次校验：0=通过，1~6=失败步骤
g_ecdsa_public_key     | .ecdsa_pubkey 段     | 65 字节公钥
g_pubkey_magic         | 同段内独立符号（static） | 0x4B594550 ("KEYP")
```

`g_pubkey_magic` 与 `g_ecdsa_public_key[65]` 同属 `.ecdsa_pubkey`，但 `uint32_t` 按 4 字节对齐，中间可能有 3 字节填充，**不是** `key[65..68]`。代码用符号比较，不按偏移读。当前 Keil 用 Target IROM、无 scatter，该段只是命名 RO，不是单独隔离区；Boot 超 16KB 会链接失败，不会静默覆盖公钥。

**Watch 监视建议**：

- `g_verify_fail_step` — 核心诊断变量；要看某一槽的失败码，断在该次 `boot_verify_image()` 返回 `-1`
- `header->magic` / `header->image_length` / `header->crc32` — 镜像头字段
- 单步进入 `boot_verify_image()` 观察每步返回值

### 4.4 自动化测试脚本框架

```python
#!/usr/bin/env python3
"""离线签名校验自动化测试（不需要 MCU）。"""

import hashlib
import struct
import subprocess
import sys
import os

def test_header_magic(image_path):
    """测试 1: Magic 校验"""
    with open(image_path, "rb") as f:
        magic = struct.unpack("<I", f.read(4))[0]
    assert magic == 0x4F544158, f"Magic 错误: 0x{magic:08X}"
    print("[PASS] Header Magic 正确")

def test_image_length(image_path):
    """测试 2: 长度校验"""
    with open(image_path, "rb") as f:
        f.seek(4)
        img_len = struct.unpack("<I", f.read(4))[0]
    total = os.path.getsize(image_path)
    assert 0 < img_len <= total - 256, f"长度越界: {img_len}"
    print(f"[PASS] Image Length 正确: {img_len} bytes")

def test_crc32(image_path):
    """测试 3: CRC32 校验"""
    import binascii
    with open(image_path, "rb") as f:
        header = f.read(256)
        firmware = f.read()
    stored = struct.unpack("<I", header[8:12])[0]
    computed = binascii.crc32(firmware) & 0xFFFFFFFF
    assert stored == computed, f"CRC 不匹配: 0x{stored:08X} != 0x{computed:08X}"
    print(f"[PASS] CRC32 正确: 0x{stored:08X}")

def test_version(image_path):
    """测试 4: 0x4C 保留占位区应为 16 字节 0x00（原 version 字段已从
    image_header_t 定义删除，该区为保留占位，打包固定填 0x00）。
    注：改造前打包的旧镜像该区非零属正常，本检查仅针对新产物。"""
    with open(image_path, "rb") as f:
        f.seek(0x4C)   # 0x4C 偏移锁定不变
        ver = f.read(16)
    assert ver == b"\x00" * 16, f"0x4C 保留占位区非全 0x00: {ver.hex()}"
    print("[PASS] 0x4C 保留占位区全 0x00（版本号见固件 SW_VERSION_STR）")

if __name__ == "__main__":
    path = sys.argv[1] if len(sys.argv) > 1 else "app_slot_a.bin"
    test_header_magic(path)
    test_image_length(path)
    test_crc32(path)
    test_version(path)
    print("\n全部测试通过。")
```

## 5. 常见问题

| 问题 | 原因 | 解决方案 |
| --- | --- | --- |
| Bootloader 停在 Safe Mode | 两槽都校验失败 | SWD 看 `g_verify_fail_step`。复位后若另一槽为空，读到的多半是 1，不是第一槽的 3/4/6 |
| 签名后验证仍然失败 | 私钥与公钥不匹配 | 重新生成密钥对，确保 PEM 与 `boot_verify.c` 中公钥对应 |
| 签名验证耗时过长 | 纯软件 ECDSA P-256 在 M4F 上约 30~50ms | 属于正常范围，不影响启动（单次验证） |
| SHA-256 哈希不一致 | 签名时和验证时的数据范围不同 | 确保签名对象 = 裸固件（不含 256 字节头） |
| 公钥损坏 (fail_step=5) | `g_pubkey_magic` 不是 `KEYP` | 用符号读 magic，不要按公钥后 4 字节猜偏移 |
| 镜像链接地址错误 | IROM1 入口设错，或把含头 `.bin` 烧到入口而非区起始 | 链接=`0x08004100`（App 区）；产线烧录=`0x08004000`；OTA 载荷写备份区=`0x08010000`（BOOT 搬运） |

## 6. 安全注意事项

1. **私钥保护**：`docs/keys/private.pem` 不允许进入版本控制的公开分支，生产环境应使用离线签名工站
2. **公钥存储**：Bootloader 内置公钥（编译固化）+ Device Info `ecdsa_pubkey[65]`（支持运行时轮换）
3. **密钥轮换**：通过 UDS DID `0x2120` 写入新公钥到 Device Info（需 Programming + SecurityAccess），Bootloader 优先从 Device Info 读取；若未配置则回退内置公钥。更换内置公钥需重烧 Bootloader
4. **签名不可伪造**：没有正确私钥无法生成合法签名，恶意固件无法通过校验
