# Flash 空间分配 — QI Wireless Bootloader

> **MCU**: AT32F426 (Cortex-M4F, 128KB Flash, 20KB SRAM)
> **Flash 基地址**: `0x08000000`
> **Flash 总大小**: 128KB (`0x08000000` ~ `0x0801FFFF`)
> **Sector 大小**: 1KB (AT32F426)

---

## 一、整体 Flash 布局总览

| 区域               | 起始地址       | 结束地址       | 大小          | 说明                                                                     |
| ------------------ | -------------- | -------------- | ------------- | ------------------------------------------------------------------------ |
| Bootloader         | `0x08000000` | `0x08006FFF` | 28KB (0x7000) | 引导程序，含 OTA 逻辑                                                    |
| Application Slot A | `0x08007000` | `0x080117FF` | 42KB (0xA800) | 应用固件 A                                                               |
| Application Slot B | `0x08011800` | `0x0801BFFF` | 42KB (0xA800) | 应用固件 B                                                               |
| Metadata Primary   | `0x0801C000` | `0x0801C7FF` | 2KB (0x800)   | OTA 元数据主副本                                                         |
| Metadata Backup    | `0x0801C800` | `0x0801CFFF` | 2KB (0x800)   | OTA 元数据备份（先写备后写主）                                           |
| Device Info        | `0x0801D000` | `0x0801DFFF` | 4KB (0x1000)  | 设备信息保留区，存放 SN 序列号、ECDSA 公钥等设备标识，OTA 擦写跳过此区域 |
| NVM Config         | `0x0801E000` | `0x0801FFFF` | 8KB (0x2000)  | APP NVM 配置区                                                           |

```text
0x08000000 ┌─────────────────────────────┐
           │      Bootloader (28KB)      │  0x7000 bytes
0x08007000 ├─────────────────────────────┤
           │   Application Slot A (42KB) │  0xA800 bytes
           │  image_header (256B) + app  │  header @ 0x08007000, app @ 0x08007100
           │                             │
0x08011800 ├─────────────────────────────┤
           │   Application Slot B (42KB) │  0xA800 bytes
           │  image_header (256B) + app  │  header @ 0x08011800, app @ 0x08011900
           │                             │
0x0801C000 ├─────────────────────────────┤
           │  Metadata Primary (2KB)     │  ota_metadata_t (272B)
0x0801C800 ├─────────────────────────────┤
           │  Metadata Backup (2KB)      │  power-loss copy
0x0801D000 ├─────────────────────────────┤
           │  Device Info (4KB)           │
0x0801E000 ├─────────────────────────────┤
           │  NVM Config (8KB)           │
0x0801FFFF └─────────────────────────────┘
```

**地址对齐验证**: 所有区域起始地址均为 1KB (0x400) sector 对齐 ✅（Metadata/Device Info/NVM 区域按 2KB 间距排列，满足 1KB 对齐要求）

## 二、ota_metadata_t 数据结构详解

`primary = (const ota_metadata_t *)META_PRIMARY_ADDR;` 这行代码将 Flash 地址 `0x0801C000` 强制类型转换为 `ota_metadata_t *` 指针，直接从 Flash 内存映射读取 OTA 元数据。

**结构体定义** (来源: `boot_metadata.h`):

```text
Flash 地址 0x0801C000 开始:
┌──────────────────────────────────────────┐
│ magic (4字节)              │ ← 0x4F54414D "MATO"          偏移 0x00
│ version (4字节)            │ ← 1 (metadata format v1)     偏移 0x04
│ active_slot (1字节)        │ ← 0=A, 1=B                   偏移 0x08
│ pending_slot (1字节)       │ ← 0=A, 1=B, 0xFE=none        偏移 0x09
│ slot_a_valid (1字节)       │ ← 1=Slot A 镜像有效           偏移 0x0A
│ slot_b_valid (1字节)       │ ← 1=Slot B 镜像有效           偏移 0x0B
│ slot_a_crc32 (4字节)       │ ← Slot A 镜像 CRC32           偏移 0x0C
│ slot_b_crc32 (4字节)       │ ← Slot B 镜像 CRC32           偏移 0x10
│ trial_state (1字节)        │ ← 0=IDLE,1=PENDING,2=ACTIVE,3=CONFIRMED  偏移 0x14
│ trial_slot (1字节)         │ ← 正在试运行的 slot (0=A,1=B) 偏移 0x15
│ trial_retry_count (1字节)  │ ← 当前试运行重试次数           偏移 0x16
│ trial_max_retries (1字节)  │ ← 最大重试次数 (默认 3)        偏移 0x17
│ trial_timeout_sec (2字节)  │ ← 试运行超时秒数 (默认 10)     偏移 0x18
│ reserved1 (2字节)          │ ← 对齐保留                    偏移 0x1A
│ rollback_count (4字节)     │ ← 回滚次数计数器               偏移 0x1C
│ last_boot_reason (1字节)   │ ← 0x00=上电,0x01=软件复位,0x02=WDG,0x03=OTA,0x04=回滚  偏移 0x20
│ ota_state (1字节)          │ ← 0x00=空闲,0x01=下载中        偏移 0x21
│ reserved2[2] (2字节)       │ ← 保留                        偏移 0x22
│ padding[232] (232字节)     │ ← 填充至 272 字节              偏移 0x24
│ crc32 (4字节)              │ ← 上述所有字段的 CRC32 校验    偏移 0x10C
└──────────────────────────────────────────┘
共 272 字节 (0x110)
```

**字段说明**:

| 字段                  | 类型         | 字节偏移 | 说明                                                    |
| --------------------- | ------------ | -------- | ------------------------------------------------------- |
| `magic`             | uint32_t     | 0x00     | 魔数`0x4F54414D` ("MATO")，用于识别有效元数据         |
| `version`           | uint32_t     | 0x04     | 元数据格式版本号，当前 = 1                              |
| `active_slot`       | uint8_t      | 0x08     | 当前活跃 slot: 0=A, 1=B                                 |
| `pending_slot`      | uint8_t      | 0x09     | 待切换 slot: 0=A, 1=B, 0xFE=无                          |
| `slot_a_valid`      | uint8_t      | 0x0A     | Slot A 镜像校验通过标志                                 |
| `slot_b_valid`      | uint8_t      | 0x0B     | Slot B 镜像校验通过标志                                 |
| `slot_a_crc32`      | uint32_t     | 0x0C     | Slot A 固件镜像的 CRC32                                 |
| `slot_b_crc32`      | uint32_t     | 0x10     | Slot B 固件镜像的 CRC32                                 |
| `trial_state`       | uint8_t      | 0x14     | 试运行状态机: IDLE(0)/PENDING(1)/ACTIVE(2)/CONFIRMED(3) |
| `trial_slot`        | uint8_t      | 0x15     | 当前试运行的 slot 编号                                  |
| `trial_retry_count` | uint8_t      | 0x16     | 已重试次数                                              |
| `trial_max_retries` | uint8_t      | 0x17     | 最大重试次数，默认 3                                    |
| `trial_timeout_sec` | uint16_t     | 0x18     | 试运行超时，默认 10 秒                                  |
| `reserved1`         | uint16_t     | 0x1A     | 保留对齐                                                |
| `rollback_count`    | uint32_t     | 0x1C     | 累计回滚次数                                            |
| `last_boot_reason`  | uint8_t      | 0x20     | 最近一次启动原因码                                      |
| `ota_state`         | uint8_t      | 0x21     | OTA 状态: IDLE(0)/DOWNLOADING(1)                        |
| `reserved2[2]`      | uint8_t[2]   | 0x22     | 保留                                                    |
| `padding[232]`      | uint8_t[232] | 0x24     | 填充至 272 字节                                         |
| `crc32`             | uint32_t     | 0x10C    | CRC32 (覆盖除自身外的所有字段)                          |

**CRC32 计算范围**: 从 `magic` 到 `padding` 末尾，共 268 字节 (`META_CRC32_OFFSET = sizeof(ota_metadata_t) - 4`)。

**双副本冗余机制**:

- Primary: `0x0801C000` — 每次启动优先读取（2KB sector）
- Backup: `0x0801C800` — Primary 校验失败时回退读取（独立 2KB sector，不再与 NVM 重叠）
- NVM: `0x0801E000` — APP 配置区，与元数据分离
- 保存顺序: 先写 Backup，再写 Primary (确保写 Primary 失败时 Backup 仍有效)

## 三、Application Slot 内部结构

每个 Application Slot 的起始位置包含一个 256 字节的 `image_header_t`，实际应用代码紧随其后。

### Slot A (`0x08007000` ~ `0x080117FF`, 42KB)

```text
0x08007000 ┌─────────────────────────────┐
           │  image_header_t (256字节)    │ ← 镜像头
           │  ┌───────────────────────┐  │
           │  │ magic    (4字节)      │  │ ← 0x4F544158 "XATO"
           │  │ image_length (4字节)  │  │ ← 镜像数据长度 (不含头)
           │  │ crc32    (4字节)      │  │ ← 镜像数据 CRC32
           │  │ signature (64字节)    │  │ ← ECDSA P-256 签名 (预留)
           │  │ version  (16字节)     │  │ ← "MAJOR.MINOR.PATCH\0"
           │  │ build_timestamp(4字节)│  │ ← Unix 时间戳
           │  │ reserved (160字节)    │  │ ← 填充至 256 字节
           │  └───────────────────────┘  │
0x08007100 ├─────────────────────────────┤
           │  Application Code           │ ← boot_jump_to_app(0x08007100)
           │  (最大 42KB - 256B = 42752B) │
           │                             │
0x080117FF └─────────────────────────────┘
```

### Slot B (`0x08011800` ~ `0x0801BFFF`, 42KB)

```text
0x08011800 ┌─────────────────────────────┐
           │  image_header_t (256字节)    │ ← 同 Slot A 结构
0x08011900 ├─────────────────────────────┤
           │  Application Code           │ ← boot_jump_to_app(0x08011900)
           │  (最大 42752 字节)           │
           │                             │
0x0801BFFF └─────────────────────────────┘
```

**image_header_t 结构体定义** (来源: `boot_verify.h`):

| 字段                | 类型         | 大小 | 说明                             |
| ------------------- | ------------ | ---- | -------------------------------- |
| `magic`           | uint32_t     | 4B   | 魔数`0x4F544158` ("XATO")      |
| `image_length`    | uint32_t     | 4B   | 镜像数据长度 (不含 header)       |
| `crc32`           | uint32_t     | 4B   | 镜像数据的 CRC32 校验            |
| `signature`       | uint8_t[64]  | 64B  | ECDSA P-256 签名                 |
| `version`         | char[16]     | 16B  | 版本字符串 "MAJOR.MINOR.PATCH\0" |
| `build_timestamp` | uint32_t     | 4B   | 构建时间 Unix 时间戳             |
| `reserved`        | uint8_t[160] | 160B | 填充至 256 字节                  |

**验证流程** (`boot_verify_image`):

1. 检查 `magic == 0x4F544158`
2. 检查 `image_length` 在合法范围内 (0 < length ≤ slot_size - 256)
3. 对 header 之后的 `image_length` 字节计算 CRC32，与 `header->crc32` 比对
4. Reset Handler 必须落在本槽 `[base+256, base+slot_size)`（拒绝 Slot A 链接镜像写入 Slot B）
5. ECDSA P-256 签名验证（SHA256(image_data) + uECC_verify 公钥验签）

## 四、Metadata 区域细节

### Metadata Primary (`0x0801C000` ~ `0x0801C7FF`, 2KB)

```text
0x0801C000 ┌─────────────────────────────┐
           │  ota_metadata_t (272字节)    │ ← 元数据主副本
0x0801C110 ├─────────────────────────────┤
           │  未使用 (剩余 sector)        │
0x0801C7FF └─────────────────────────────┘
```

- 擦写粒度: 1KB sector (`flash_sector_erase`，`META_PAGE_SIZE = 0x400`)
- 写入方式: 按 uint32_t 逐字编程 (`flash_word_program`)

### Metadata Backup (`0x0801C800` ~ `0x0801CFFF`, 2KB)

与 Primary 相同结构。`boot_metadata_save()` / `ota_metadata_save()` 先写 Backup 再写 Primary。

### NVM Config (`0x0801E000` ~ `0x0801FFFF`, 8KB)

```text
0x0801E000 ┌─────────────────────────────┐
           │  NVM Config Area (8KB)       │ ← nvm_drv 读写 (sector 粒度)
           │  ┌───────────────────────┐  │
           │  │ NVM Validity Magic    │  │ ← offset 0x00, "NVM1" (0x4E564D31)
           │  │ User Config Data ...  │  │
           │  └───────────────────────┘  │
0x0801FFFF └─────────────────────────────┘
```

NVM 与元数据备份已分离，不再共用同一扇区。

**NVM 存储内容**：功率限值（DID `0x210D`，三档 5W/10W/15W）等 APP 配置数据，掉电后保持。

NVM 驱动参数:

- Sector 大小: 2KB (`NVM_SECTOR_SIZE = 0x800`，NVM 驱动按 2KB 块擦写)
- Flash 物理 Sector 大小: 1KB (`FLASH_SECTOR_SIZE = 0x400`)
- Sector 数量: 4 (`0x2000 / 0x800`)
- 总容量: 8KB

## 四-b、Device Info 保留区 (`0x0801D000` ~ `0x0801DFFF`, 4KB)

```text
0x0801D000 ┌─────────────────────────────┐
           │  Device Info (4KB)           │
           │  ┌───────────────────────┐  │
           │  │ magic    (4字节)      │  │ ← 0x44455649 ("DEVI")
           │  │ version  (4字节)      │  │ ← 设备信息格式版本，当前 = 2
           │  │ crc32    (4字节)      │  │ ← 以下所有字段的 CRC32
           │  │ sn[32]   (32字节)     │  │ ← 设备序列号 (ASCII, 末尾补 0x00)
           │  │ hw_version[8] (8字节) │  │ ← 硬件版本号 (如 "v1.2\0")
           │  │ production_date (4字节)│  │ ← 产线日期 (Unix 时间戳, 可选)
           │  │ ecdsa_pubkey[65] (65字节)│ ← SEC1 未压缩公钥 (0x04||X||Y)，用于密钥轮换
           │  │ pubkey_valid (1字节)  │  │ ← 0x01=有效，0xFF=未配置
           │  │ reserved[390]         │  │ ← 填充
           │  └───────────────────────┘  │
0x0801DFFF └─────────────────────────────┘
共 512 字节有效数据，剩余填充 0xFF
```

**device_info_t 结构体定义** (v2，新增 ECDSA 公钥存储):

| 字段                | 类型         | 大小 | 字节偏移 | 说明                                                         |
| ------------------- | ------------ | ---- | -------- | ------------------------------------------------------------ |
| `magic`           | uint32_t     | 4B   | 0x00     | 魔数`0x44455649` ("DEVI")，用于识别有效设备信息            |
| `version`         | uint32_t     | 4B   | 0x04     | 设备信息格式版本号，当前 = 2（v2 新增公钥字段）              |
| `crc32`           | uint32_t     | 4B   | 0x08     | CRC32 校验（覆盖 magic ~ reserved 末尾）                     |
| `sn`              | char[32]     | 32B  | 0x0C     | 设备序列号，ASCII 字符串，末尾补`\0`                       |
| `hw_version`      | char[8]      | 8B   | 0x2C     | 硬件版本号，ASCII 字符串                                     |
| `production_date` | uint32_t     | 4B   | 0x34     | 产线烧录日期（Unix 时间戳，可选）                            |
| `ecdsa_pubkey`    | uint8_t[65]  | 65B  | 0x38     | SEC1 未压缩 ECDSA P-256 公钥（`0x04\|\|X\|\|Y`），支持密钥轮换 |
| `pubkey_valid`    | uint8_t      | 1B   | 0x79     | 公钥有效标志：`0x01`=有效，`0xFF`=未配置                 |
| `reserved`        | uint8_t[390] | 390B | 0x7A     | 填充至 512 字节，剩余填 0xFF                                 |

**OTA 保护机制**:

- Bootloader 在执行擦除操作时，校验目标地址是否落在 Device Info 区域 (`0x0801D000` ~ `0x0801DFFF`)
- 如果目标地址在 Device Info 范围内，**拒绝擦除**，返回错误
- Device Info 区域在产线烧录时写入，之后只读不写（除产线二次烧录外）
- SN 可通过 UDS `0x22 F18C` 读取

**v2 新增 — ECDSA 公钥存储**:

- `ecdsa_pubkey[65]`（offset 56）存储 SEC1 未压缩公钥，用于 Bootloader 密钥轮换
- `pubkey_valid`（offset 121）标志位：`0x01` 表示公钥已配置且有效，`0xFF` 表示未配置
- Bootloader 启动时优先从 Device Info 读取公钥（`boot_verify_get_public_key()`），若未配置则回退到内置公钥
- 公钥可通过 UDS DID `0x2120` 读写（写入需 Programming Session + SecurityAccess Level 1）
- CRC 向后兼容：version=1 的旧 Device Info 仍可正常读取 SN，公钥字段视为未配置

## 五、Bootloader 区域 (`0x08000000` ~ `0x08006FFF`)

```text
0x08000000 ┌─────────────────────────────┐
           │  Vector Table               │ ← 中断向量表
           │  Bootloader Code            │ ← 含以下模块:
           │   - boot_metadata.c         │   元数据读写
           │   - boot_verify.c           │   镜像校验 (CRC32 + ECDSA P-256)
           │   - boot_jump.c             │   跳转应用
           │   - can_driver              │   CAN 通信
           │   - UDS safe mode handler   │   安全模式 OTA
           │   - trial boot state machine│   试运行状态机
           │   - nvm_drv.c               │   NVM 驱动
           │   - timer_drv.c             │   定时器驱动
           │   - isotp.c                 │   ISO-TP 分帧传输
           │   - uECC.c                  │   ECDSA P-256 验签库
           │   - sha256.c                │   SHA-256 哈希库
0x08006FFF └─────────────────────────────┘
```

## 六、启动流程与 Flash 交互

```text
上电 / 复位
    │
    ▼
[1] 读取 Primary Metadata (0x0801C000)
    │
    ├─ magic/version/CRC32 校验通过 → 使用 Primary
    │
    ├─ 校验失败 → 读取 Backup Metadata (0x0801C800)
    │   │
    │   ├─ Backup 有效 → 恢复 Primary，使用 Backup 数据
    │   │
    │   └─ Backup 也无效 → 填充默认值，写入双副本
    │
    ▼
[2] 检测 ota_state 是否为 DOWNLOADING
    │
    ├─ 是 → 直接进入 Safe Mode (CAN OTA)
    │
    ├─ 否 → 继续
    │
    ▼
[3] 检测启动原因 (WDG / Power-On)
    │
    ▼
[4] 处理试运行状态机 (trial_state)
    │
    ▼
[5] 选择 Boot Slot (active_slot 或 trial_slot)
    │
    ▼
[6] 校验 Slot 镜像 (image_header_t + CRC32)
    │
    ├─ 校验通过 → boot_jump_to_app(slot_base + 0x100)
    │
    └─ 校验失败 → 尝试另一个 Slot
        │
        ├─ 另一个 Slot 通过 → 更新 active_slot，跳转
        │
        └─ 两个 Slot 均失败 → 进入 Safe Mode (CAN OTA)
```

| `DEVICE_INFO_SIZE`  | `0x1000` (4KB)  | Device Info 大小                  |

## 八、链接配置（Keil Target IROM）

**Bootloader 和 Application 均在 Keil Target 对话框中配置 IROM/IRAM，不使用 Scatter File。**

### Bootloader 配置

| 项           | 值                                                        |
| ------------ | --------------------------------------------------------- |
| IROM1 Start  | `0x08000000`                                            |
| IROM1 Size   | `0x7000`（28 KB，不可超出）                             |
| IRAM1 Start  | `0x20000000`                                            |
| IRAM1 Size   | `0x5000`                                                |
| Scatter File | **不勾选**，Use Memory Layout from Target Dialog ✓ |

> ⚠️ Bootloader IROM 上限必须严格限制为 `0x7000`（28 KB）。若超出将覆盖 Slot A 起始地址 `0x08007000`，导致设备变砖。

### Application Slot A 配置

| 项           | 值                                                        |
| ------------ | --------------------------------------------------------- |
| IROM1 Start  | `0x08007100`（header 后 256B）                          |
| IROM1 Size   | `0xA700`（42 KB − 256B header）                        |
| IRAM1 Start  | `0x20000000`                                            |
| IRAM1 Size   | `0x5000`                                                |
| Scatter File | **不勾选**，Use Memory Layout from Target Dialog ✓ |

### Application Slot B 配置

| 项                 | 值             |
| ------------------ | -------------- |
| IROM1 Start        | `0x08011900` |
| IROM1 Size         | `0xA700`     |
| IRAM1 Start / Size | 同 Slot A      |

> 编 Slot B 镜像时只改 Target IROM1 Start 为 `0x08011900`，编完再改回 Slot A，避免下次误链到 B。详见文档 9。

## 九、空间利用率分析

| 区域                        | 大小            | 占比           |
| --------------------------- | --------------- | -------------- |
| Bootloader                  | 28KB            | 21.9%          |
| App Slot A                  | 42KB            | 32.8%          |
| App Slot B                  | 42KB            | 32.8%          |
| Metadata (Primary + Backup) | 4KB             | 3.1%           |
| Device Info                 | 4KB             | 3.1%           |
| NVM Config                  | 8KB             | 6.3%           |
| **合计**              | **128KB** | **100%** |

- 单个 App 最大可用代码空间: 42KB - 256B(image_header) = **42,752 字节**
- Metadata 区每副本 2KB，实际使用 272B，剩余空间可扩展
