# 17. 休眠与选择性唤醒（WUF）验证操作

> **面向客户侧 AI / 自动化调用**：本文给出可直接执行的命令、预期证据与 PASS/FAIL 判定规则。
> 环境接入（USB NCM / SSH / broodctl REPL 用法）见仓库根 `AGENTS.md`「CCU 联机升级通道」。
> 结论参考：2026-11-04 实测全链路通过（见 §5 实测时间线）。

---

## 0. 机制摘要

| 项 | 值 |
|----|----|
| 设备 | Qi 无线充电模块（AT32F426，单 App 架构，入口 `0x08003100`） |
| 休眠触发 | UDS 空闲 **10s**（`CAN_LP_IDLE_TIMEOUT_MS=10000`）→ 真休眠（SIT1145 INH **断电整板**） |
| 充电门禁 | 充电中（DID `0x2101`=1 且霍尔在位）**永不进 Sleep** |
| 唤醒方式① | **WUF 选择性唤醒**：CAN 帧 `ID=0x18DA0D03`、`DLC=8`、数据 `02 3E 00 CC CC CC CC CC`（PNDM 严格匹配：前两字节 `02 3E`） |
| 唤醒方式② | 重新上电 |
| 唤醒形态 | **冷启动**：Boot 决策链 → 跳 App → BOOTUP→OPERATIONAL |

## 1. 命令清单（bash over ssh，逐条可复制）

> 全部在管理机执行（WSL/终端能 `ssh root@192.168.7.1` 即可）。
> `broodctl` 是 REPL：命令写在 printf 的行里从 stdin 灌入；**命令行不能直接跟子命令**。

### 1.1 在线探测（liveness probe）

```bash
ssh root@192.168.7.1 'printf "qi_charger identity\nquit\n" | /data/local/bin/broodctl --target-imei=869620080567857 2>&1 | tail -n 7'
```

- **应答**（含 `mcu1-app:` 行）= 设备在线
- `timeout waiting for state.qicharger.identity` = 设备无应答（休眠/断电）

### 1.2 标准唤醒 burst（8 帧 × 250ms 节拍）

```bash
ssh root@192.168.7.1 '{ for i in 1 2 3 4 5 6 7 8; do echo "can send 0x18DA0D03 02 3E 00 CC CC CC CC CC --ext"; sleep 0.25; done; echo quit; } | /data/local/bin/broodctl --target-imei=869620080567857 2>&1 | grep -c "can send → OK"'
```

- 预期输出 `8`（8 帧全部发出）
- **注意**：`can send` 的 ID 必须带 `0x` 前缀；节拍不要压成连发（实测连发 10ms 间隔可能唤不醒，250ms 节拍稳定）

### 1.3 唤醒后验证（burst 后等 3s 再探测）

```bash
ssh root@192.168.7.1 '{ for i in 1 2 3 4 5 6 7 8; do echo "can send 0x18DA0D03 02 3E 00 CC CC CC CC CC --ext"; sleep 0.25; done; sleep 3; echo "qi_charger identity"; echo quit; } | /data/local/bin/broodctl --target-imei=869620080567857 2>&1 | tail -n 7'
```

- 预期：出现 `mcu1-app: …` 行 = **唤醒成功**

### 1.4 记录仪帧级取证（decodes candump）

```bash
ssh root@192.168.7.1 'cd /data/recorder && /data/local/bin/broodctl recorder candump rec-current.rec > /tmp/candump.txt 2>&1; grep -E "18FF260D|18FF480D|18FF270D" /tmp/candump.txt | tail -n 25'
```

补充：查唤醒帧是否上总线

```bash
ssh root@192.168.7.1 'grep "18DA0D03#023E00" /tmp/candump.txt | tail -n 10'
```

> candump 时间戳为 Unix 秒（UTC）；`rec-current.rec` 为滚动实时段，可反复导出。

## 2. 验证流程

### 2.1 进入休眠验证

1. 跑一次 §1.1 在线探测（刷新空闲计时），此后**停止一切 UDS 交互**
2. 等待 **≥15s**（10s 阈值 + 余量）
3. 再跑 §1.1：预期 **timeout 无应答**
4. §1.4 取证：窗口内应有（见 §3 表）：
   - `18FF260D` 载荷 `04 00…`（SLEEP 广播）
   - `18FF270D` E0~E3 四连帧（入睡配置，E2 含 WUF ID/掩码）
   - 其后该 ID 对安静默 ≥10s

### 2.2 唤醒验证（休眠状态下执行）

1. §1.3 唤醒+探测：预期 3s 内 identity 恢复应答
2. §1.4 取证：窗口内应有：
   - `18DA0D03#023E00CCCCCCCCCC` ×8（burst 帧，WUF 触发源）
   - `18FF480D` Boot M1/M2/M4 决策链帧（= **冷启动**证据）
   - `18FF260D` 载荷 `01`（BOOTUP）→ `02`（OPERATIONAL，1s 周期）

> **注意**：工具自带的前置唤醒（如 `mcu2_upgrade` 内置 3 次探测）对长睡设备可能不足
>（等不到开机完成即放弃，报 `wake not acknowledged: 3 probes`）。此时先跑 §1.2/§1.3
> 标准 burst 唤醒、再立即执行业务命令即可（业务流量会刷新空闲计时，不会中途再睡）。

## 3. 证据帧定义（帧级判定表）

| CAN ID | 载荷示例 | 含义 | 判定用途 |
|--------|----------|------|----------|
| `0x18FF260D` | `04 00 00 00 00 00 00 00` | 生命周期 **SLEEP**（即将休眠，送达后才睡） | **进入休眠** |
| `0x18FF260D` | `01 00 …` / `02 00 …` | **BOOTUP** / **OPERATIONAL**（1s 周期） | **唤醒后运行** |
| `0x18FF270D` | `E0 07 03 00 71 01 02 A5` | 入睡配置快照（MODE/EV_EN/EV/CCTL/TRX） | 休眠配置 |
| `0x18FF270D` | `E1 00 C8 00 00 00 00 A5` | WUF 过滤 fc=0xC8 | 休眠配置 |
| `0x18FF270D` | `E2 03 0D DA 18 02 3E A5` | **WUF ID=0x18DA0D03、掩码 02 3E**（DLC=8 严格） | **选择性唤醒配置** |
| `0x18FF480D` | `A1 00 01 01 01 CC CC CC` | Boot M1：metadata 来源=主区，magic/ver/crc 全 ok | **冷启动（唤醒=重新上电）** |
| `0x18FF480D` | `A2 00 FF CC CC CC CC CC` | Boot M2：拷贝决策 | 冷启动 |
| `0x18FF480D` | `A4 00 31 00 08 CC CC CC` | Boot M4：跳转 `0x08003100`（小端） | 冷启动 |
| `0x18DA0D03` | `02 3E 00 CC CC CC CC CC` | WUF 唤醒触发帧（TesterPresent 形态） | 唤醒源 |

## 4. PASS / FAIL 判定

**PASS**（两个都要）：
1. **进入休眠**：空闲 ≥15s 后 `identity` 无应答，且记录仪出现 `18FF260D#04…` + `18FF270D` E0~E3
2. **唤醒**：burst 后 ≤5s `identity` 恢复应答，且记录仪出现 `18FF480D` M1/M2/M4 + `18FF260D#01…→02…`

**FAIL 情形与排查**：

| 现象 | 可能原因 | 处置 |
|------|----------|------|
| **插拔/断电重启后** burst 唤不醒（未插拔时唤醒正常） | 冷上电 SPI 写丢失系列缺陷：①<1.1.59：init 步骤7/8 单次回读失败提前 return → `EVENT_EN` 停 0x00（E0 `[2]`=00）；②1.1.59~1.1.62：wuf_config 的 ID 中间字节（id1/id2）写丢失，wuf_ok 只查 id0/id3 照样通过 → WUF ID 错位永不匹配（E2 若为 `00 00 00 00`+`FF FF` 在 1.1.63+ 为真残缺，1.1.62- 的 E0~E3 是配置前快照仅供参考）。两者都因 CPNC=1 关标准唤醒而睡死 | 刷 **1.1.63+** 固件（init 重试 + ID 四字节全校验 + 逐写稳定延时 + 进睡前 CWE 门禁 + E0~E3 配置后快照自证）；未升级前插拔后请勿依赖选择性唤醒 |
| 空闲 15s 后仍应答 | 充电门禁生效（`2101`=1 且手机在位）；或周期 UDS 未停 | 确认关闭充电、移开手机、无 UDS 流量后重测 |
| burst 后仍无应答 | burst 节拍过密（连发无效）；或 ID 未加 `0x`；DLC≠8 | 用 §1.3 标准节拍命令 |
| burst 后 >5s 才应答 | 偶发（INH 上电慢），可接受为 PASS（记备注） | 重测观察稳定性 |
| 记录仪无 E0~E3 | 取证窗口不对 / recorder 未在录 | 按时间窗重取 `rec-current.rec` |
| `wake not acknowledged` | 业务命令内置探测太弱（见 §2.2 注） | 先标准 burst 唤醒再执行业务命令 |
| 读 `0x2119` 无应答 | 请求落在休眠窗口（设备断电中）；22 2119 甚至可能误唤醒设备但应答必丢 | 先标准 burst 唤醒、见 BOOTUP/OPERATIONAL 后再读 |

## 6. 可选补充证据：DID 0x2119（低功耗计数器）

> **0x2119 是固件真实存在的 DID**：`can_protocol.h:151` 定义
> `DID_SIT1145_LP_STATUS`，`can_protocol.c:1502` `fill_did_payload` 实现，任意会话可读。

`22 2119` → `62 2119` 4 字节应答：

| 字节 | 含义 |
|------|------|
| [0] | bit0=曾 Sleep；bit1=本次唤醒源为 WUF；bit2=sleep_fail(sticky)；bit3=CAN RX 丢帧(sticky)；bit[7:4]=唤醒源码 |
| [1] | `wup_count`（WUF 唤醒次数累计） |
| [2-3] | `last_sleep_sec` LE（上次睡眠时长，秒） |

用 raw CAN 读取（应答帧 `18DA030D#07622119…`）：

```bash
ssh root@192.168.7.1 '{ echo "can send 0x18DA0D03 03 22 21 19 CC CC CC CC --ext"; sleep 1; echo quit; } | /data/local/bin/broodctl --target-imei=869620080567857 > /dev/null 2>&1; sleep 1; cd /data/recorder && /data/local/bin/broodctl recorder candump rec-current.rec > /tmp/c.txt 2>&1; grep "18DA030D#07622119" /tmp/c.txt | tail -n 3'
```

- **应答时机**：设备醒着时 `22 2119` 到达后 ~6ms 内回 `62 2119`（同步路径，任意会话无门槛）；实测应答 `18DA030D#07622119 33 01 00 00`（flags=0x33：曾 Sleep + WUF 唤醒 + 源码 3）
- **⚠ 必须在设备醒着时读**：设备真休眠 = 整板断电（INH），请求虽上总线但无人应答。且 `22 2119` 载荷头 `03 22` 与 WUF 掩码 `02 3E` 是「与非零即命中」的硬件近似匹配——**休眠中发 22 2119 可能误唤醒设备（超集误唤醒 = 硬件限制），但该请求的应答必然丢失**（设备冷启动约 0.7s，请求早已过去）。正确姿势：先 §1.2 标准 burst 唤醒、待 BOOTUP 后再读
- **计数为易失值**：整板断电 RAM 清零；bit0/bit1 及唤醒源经 SIT1145 锁存寄存器（0x24/0x63）反推，`wup_count`/`last_sleep_sec` 仅反映最近一次上电以来，作参考佐证（**PASS/FAIL 以 §3 帧级证据为准**）
