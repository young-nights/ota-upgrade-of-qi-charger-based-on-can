# Qi 无线充电芯片 UART 通信协议 (MCU ↔ Qi)

**项目**: QI 无线充电模块
**芯片**: AT32F426KBU7-4 (MCU) ↔ Qi 无线充电芯片
**通信接口**: USART2 (PA2=TX, PA3=RX)
**版本**: v1.0
**日期**: 2026-08-12
**来源**: 数据通信协议表-IAP.xlsx

---

## 1. 通用帧格式

所有 MCU ↔ Qi 芯片之间的 UART 通信均采用以下统一帧格式:

| 字段     | 长度   | 说明                                                      |
| -------- | ------ | --------------------------------------------------------- |
| 帧起始头 | 2 字节 | 固定`0x55 0xAA`                                         |
| 帧长度   | 1 字节 | 普通帧：帧命令 + 帧数据 + 帧流水号；IAP 帧无流水号：帧命令 + 帧数据 |
| 帧命令   | 1 字节 | 见命令码表                                                |
| 帧数据   | n 字节 | 具体数据                                                  |
| 帧流水号 | 1 字节 | 1~255, 递增循环                                           |
| 帧校验   | 1 字节 | 帧起始头 + 帧长度 + 帧命令 + 帧数据 + 帧流水号, 取低 8 位 |

### 1.1 校验算法

```
CS = (0x55 + 0xAA + LEN + CMD + DATA[0..n-1] + SEQ) & 0xFF   // 含 SEQ 的帧
CS = (0x55 + 0xAA + LEN + CMD + DATA[0..n-1]) & 0xFF          // 无 SEQ 的帧 (IAP)
```

### 1.2 命令码表

| 命令码   | 方向      | 含义                  |
| -------- | --------- | --------------------- |
| `0x00` | Qi → MCU | 回复指令 (ACK)        |
| `0x01` | Qi → MCU | 无线充上报数据 (状态) |
| `0x02` | MCU → Qi | 设置功率              |
| `0xCC` | MCU → Qi | IAP 流程 (固件升级)   |

### 2.1 帧格式

| 偏移 | 长度 | 字段      | 值/说明         |
| ---- | ---- | --------- | --------------- |
| 0-1  | 2    | 帧起始头  | `0x55 0xAA`   |
| 2    | 1    | 帧长度    | `0x08`（CMD+6B 数据+SEQ） |
| 3    | 1    | 帧命令    | `0x01`        |
| 4    | 1    | 状态字节1 | 见位定义        |
| 5    | 1    | 状态字节2 | 见位定义        |

| b5  | 过流保护  | 1 = 触发过流保护     |
| b6  | 过温保护  | 1 = 触发过温保护     |
| b7  | FOD 保护  | 1 = 触发异物检测保护 |

### 2.3 状态字节2 位定义

| Bit   | 名称     | 说明    |
| ----- | -------- | ------- |
| b0    | 充电次数 | 低 8 位 |
| b1-b7 | 保留     | 保留    |

## 5. 无线充 IAP 协议 (Command 0xCC)

MCU 通过 UART 向 Qi 芯片推送固件升级。这是 CAN-OTA 的关键环节: Host → CAN → MCU → UART → Qi 芯片。

### 5.1 IAP 升级流程

```
Host (PC)                    MCU (AT32F426)               Qi 芯片
    |                              |                          |
    |--- CAN: START (size) ------->|                          |
    |                              |-- UART: IAP进入 -------->|
    |                              |   (0xCC 0x01 + size)     |
    |                              |<-- UART: 应答 OK --------|
    |                              |                          |
    |--- CAN: DATA[0] ----------->|                          |
    |                              |-- UART: 发送数据 -------->|
    |                              |   (0xCC 0x02 + addr+data)|
    |                              |<-- UART: 应答 OK --------|
    |                              |                          |
    |        ... (重复传输) ...     |                          |
    |                              |                          |
    |--- CAN: VERIFY (CRC) ------->|                          |
    |<-- CAN: VERIFY_OK ----------|                          |
```

### 5.2 Step 1: MCU 通知 Qi 芯片进入 IAP 模式

**示例帧**: `55 AA 04 CC 01 32 B9 BB`

| 偏移 | 长度 | 字段           | 值/说明             |
| ---- | ---- | -------------- | ------------------- |
| 0-1  | 2    | 帧起始头       | `0x55 0xAA`       |
| 2    | 1    | 帧长度         | `0x04`            |
| 3    | 1    | 帧命令         | `0xCC` (IAP 流程) |
| 4    | 1    | IAP 子命令     | `0x01` (准备升级) |
| 5    | 1    | APP 大小高字节 | 固件大小 Bit[15:8]  |
| 6    | 1    | APP 大小低字节 | 固件大小 Bit[7:0]   |
| 7    | 1    | 帧校验         | 低 8 位累加和       |

验证: `0x55+0xAA+0x04+0xCC+0x01+0x32 = 0x1B9` → CS = `0xB9` ✓

**Qi 芯片应答**: `55 AA 04 CC 01 00 00 CS`

| 偏移 | 字段       | 说明                         |
| ---- | ---------- | ---------------------------- |
| 4    | IAP 子命令 | `0x01` (回应准备升级)      |
| 5    | 状态       | `0x00` = 成功, 其他 = 失败 |
| 6    | 保留       | `0x00`                     |

### 5.3 Step 2: MCU 发送 APP 固件数据

**示例帧 (第1包)**: `55 AA 1A CC 02 00 00 02 32 42 75 86 C0 D2 AE D2 BE 22 02 08 18 C2 AF D2 AE D2 BE D2 AF 6E`

| 偏移 | 长度 | 字段           | 值/说明                    |
| ---- | ---- | -------------- | -------------------------- |
| 0-1  | 2    | 帧起始头       | `0x55 0xAA`              |
| 2    | 1    | 帧长度         | `0x1A` (= 26)            |
| 3    | 1    | 帧命令         | `0xCC` (IAP 流程)        |
| 4    | 1    | IAP 子命令     | `0x02` (发送数据)        |
| 5    | 1    | 当前地址高字节 | Flash 写入地址 Bit[15:8]   |
| 6    | 1    | 当前地址低字节 | Flash 写入地址 Bit[7:0]    |
| 7-28 | 22   | APP 数据       | 固件数据 (最多 22 字节/帧) |
| 29   | 1    | 帧校验         | 低 8 位累加和              |

帧长度计算: `0x1A` = 26 = 1(IAP子命令) + 2(地址) + 22(数据) + 1(帧水号)

> **说明**：IAP 帧(0xCC)不使用帧流水号(SEQ)字段，LEN 仅包含「帧命令 + 帧数据」。因此 LEN = 1(CMD) + 1(子命令) + 2(地址) + 22(数据) = 26 = 0x1A，与示例帧一致。

**Qi 芯片应答**: `55 AA 04 CC 02 00 00 CS`

| 偏移 | 字段       | 说明                    |
| ---- | ---------- | ----------------------- |
| 4    | IAP 子命令 | `0x02` (回应数据接收) |
| 5    | 状态       | `0x00` = 成功         |
| 6    | 保留       | `0x00`                |

### 5.4 IAP 子命令汇总

| 子命令   | 方向      | 含义                         |
| -------- | --------- | ---------------------------- |
| `0x01` | MCU → Qi | 准备升级 (含固件大小)        |
| `0x02` | MCU → Qi | 发送固件数据 (含地址 + 数据) |

## 6. UDS 0x38 TransferSignature 签名传输协议

### 6.1 概述

MCU OTA 流程中，0x37 TransferExit 写入 Image Header 时 `signature[64]` 字段需要填入
ECDSA P-256 签名。新增 0x38 TransferSignature 命令，让主机能够在 0x36 TransferData
之后、0x37 TransferExit 之前传输 64 字节签名数据。

### 6.2 命令参数

| 参数     | 值                                      |
| -------- | --------------------------------------- |
| 命令码   | `0x38`                                |
| 方向     | Host → MCU（Bootloader Safe Mode）     |
| 安全要求 | 需先通过 0x27 SecurityAccess            |
| 签名大小 | 64 字节（ECDSA P-256 R‖S，各 32 字节） |

### 6.3 帧格式

每帧 8 字节 CAN 数据：

| 偏移 | 长度   | 字段          | 说明                              |
| ---- | ------ | ------------- | --------------------------------- |
| 0    | 1      | SID           | `0x38`                          |
| 1    | 1      | blockSeq      | 帧序号，从`0x01` 开始递增       |
| 2~7  | 最多 6 | signatureData | 签名数据（最后一帧可不足 6 字节） |

### 6.4 传输流程

64 字节签名分 11 帧传输：

| 帧序号 (blockSeq) | 载荷长度 | 累计字节 |
| ----------------- | -------- | -------- |
| 0x01              | 6        | 6        |
| 0x02              | 6        | 12       |
| ...               | ...      | ...      |
| 0x0A              | 6        | 60       |
| 0x0B              | 4        | 64       |

### 6.5 响应格式

**正响应**（2 字节）：

| 偏移 | 长度 | 字段     | 值         |
| ---- | ---- | -------- | ---------- |
| 0    | 1    | SID+0x40 | `0x78`   |
| 1    | 1    | blockSeq | 回显帧序号 |

**负响应**（3 字节）：

| 偏移 | 长度 | 字段     | 值       |
| ---- | ---- | -------- | -------- |
| 0    | 1    | NRC 标识 | `0x7F` |
| 1    | 1    | SID      | `0x38` |
| 2    | 1    | NRC 码   | 见下表   |

| NRC      | 含义                   | 触发条件             |
| -------- | ---------------------- | -------------------- |
| `0x11` | serviceNotSupported    | APP 端收到此命令     |
| `0x13` | incorrectMessageLength | 帧长度 < 3 字节      |
| `0x14` | responseTooLong        | 累计数据超过 64 字节 |
| `0x33` | securityAccessDenied   | 未通过安全访问       |
| `0x71` | transferDataAborted    | 序号错误或未激活     |

### 6.6 OTA 升级流程中的位置

```
0x34 RequestDownload    -- 擦除 Flash，初始化下载
0x36 TransferData       -- 传输固件数据（多帧）
0x38 TransferSignature  -- 传输 ECDSA 签名（11 帧）   ← 新增
0x37 RequestTransferExit -- 写入 Image Header（含签名）
0x11 ECUReset           -- 复位，进入 Trial Boot
```

### 6.7 实现要点

- 签名缓冲区独立于固件下载缓冲区，互不影响
- blockSeq 从 0x01 开始，必须严格顺序递增
- 首帧（blockSeq=0x01）自动重置签名状态机
- 若未发送 0x38 或传输不完整，0x37 将使用全 0xFF 填充 signature 字段
- APP 端不处理 0x38，返回 NRC 0x11（serviceNotSupported）

## 7. CCU→MCU 指令集（Qi 芯片 IAP 升级）

> CCU 通过 CAN-UDS 指令控制 MCU，MCU 再转发 UART 帧给 Qi 芯片完成固件升级。
> CCU 侧不需要关心 UART 协议细节，只需按下面的指令顺序操作即可。

### 7.1 前置条件

| 步骤 | CCU 发送 | MCU 响应 | 说明 |
|------|---------|---------|------|
| 1 | `02 10 02` | `50 02` | 进入编程会话 |
| 2 | `02 27 01` | `06 67 01 [seed0-3]` | 请求种子 |
| 3 | `07 27 03 01 [sig0-3]` × 16帧 | 每帧 `03 67 03 01` | 分片发送 64B 签名 |
| 4 | `02 27 02` | `7F 27 78` → `02 67 02` | 验签（等待数秒） |

### 7.2 升级指令

| 步骤 | CCU 发送（UDS 载荷） | MCU 响应 | 说明 |
|------|---------------------|---------|------|
| **读版本** | `22 21 33` | `62 21 33 [ver_lo][ver_hi]` | 读 Qi 芯片固件版本 |
| **启动升级** | `2E 21 30 01 [size_hi][size_lo]` | `6E 21 30` | size = 固件字节数 |
| **发送数据** | `2E 21 31 [addr_hi][addr_lo][data…]` | `6E 21 31` | addr = Flash 地址，data 最多 22B |
| **查状态** | `22 21 32` | `62 21 32 [8字节]` | 见下方载荷 |
| **中止升级** | `2E 21 30 02 00` | `6E 21 30` | 子功能 0x02 = 中止 |

### 7.3 0x2132 状态载荷（8 字节）

| 偏移 | 字段 | 说明 |
|------|------|------|
| 0 | state | 0x00=空闲, 0x01=升级中, 0x02=成功, 0x03=失败 |
| 1 | progress | 0–100 百分比 |
| 2-3 | version | uint16 LE，Qi 芯片版本 |
| 4-5 | sent | uint16 LE，已发字节数 |
| 6-7 | total | uint16 LE，固件总长 |

### 7.4 完整流程

```
# 1. 前置（进会话 + 安全解锁）
CCU → MCU: 02 10 02          → 50 02
CCU → MCU: 02 27 01          → 06 67 01 [seed]
CCU → MCU: 07 27 03 01 …     → 03 67 03 01（×16帧）
CCU → MCU: 02 27 02          → 7F 27 78 → 02 67 02

# 2. 读版本
CCU → MCU: 22 21 33          → 62 21 33 [ver_lo][ver_hi]

# 3. 启动升级
CCU → MCU: 2E 21 30 01 [size_hi][size_lo]  → 6E 21 30

# 4. 循环发送数据（每包最多 22B）
CCU → MCU: 2E 21 31 [addr_hi][addr_lo][data…]  → 6E 21 31
...（重复直到发完）

# 5. 查状态，等 state 变为 0x02（成功）
CCU → MCU: 22 21 32  → 62 21 32 [state][progress][ver][sent][total]

# 6. 如果失败，中止
CCU → MCU: 2E 21 30 02 00  → 6E 21 30
```

### 7.5 前置指令详解

CAN 帧 ID：请求 `0x18DA0D03`，响应 `0x18DA030D`，扩展帧，250kbps。

**SecurityAccess 签名计算**（PC 侧用 Python）：

```python
import hashlib
seed = bytes([s0, s1, s2, s3])  # 从 27 01 响应取 4 字节
h = hashlib.sha256(seed).digest()
# 用 docs/keys/private.pem 做 ECDSA P-256，输出 64 字节 R‖S
sig = ecdsa_sign(private_key, h)
```

**签名分片发送**（27 03）：

```
帧1: 07 27 03 01 [sig0-3]    → 03 67 03 01
帧2: 07 27 03 02 [sig4-7]    → 03 67 03 02
...
帧16: 07 27 03 10 [sig60-63] → 03 67 03 10
```

**27 02 验签**：发送后先收到 `7F 27 78`（ResponsePending），MCU 内部做 ECDSA 验证（数秒），最终返回 `02 67 02`（成功）或 `7F 27 35`（失败）。

### 7.6 注意事项

- 发 `2E 21 31` 前必须先 `2E 21 30` 启动，否则 MCU 返回 NRC `0x24`
- `22 21 32` 返回的 state 如果是 `0x03`（失败），说明 Qi 芯片没有正确接收数据
- 每包 data 最多 22 字节（UART 帧限制），超过会被 MCU 截断
- 升级过程中每 5 秒发一次 `02 3E 00` 防止 S3 超时

## 9. MCU→Qi 发送指令速查表

> 基于当前代码（`qi_protocol.c` / `can_protocol.c`）整理，仅列出 MCU 主动发出的帧。

### 9.1 设置功率（Command 0x02）

```
55 AA 03 02 [power] [seq] [CS]
       │       │      │     └─ 累加和 & 0xFF
       │       │      └─────── 流水号 1~255
       │       └────────────── 01=5W / 02=10W / 03=15W
       └────────────────────── LEN = CMD(1) + DATA(1) = 0x03
```

### 9.2 IAP 准备升级（Command 0xCC, 子命令 0x01）

```
55 AA 04 CC 01 [size_hi] [size_lo] [CS]
       │       │    │       │        └─ 累加和（不含 SEQ）
       │       │    │       └────────── 固件大小低字节
       │       │    └────────────────── 固件大小高字节
       │       └────────────────────── 子命令 0x01
       └────────────────────────────── LEN = CMD(1) + DATA(3) = 0x04
```

### 9.3 IAP 发送数据（Command 0xCC, 子命令 0x02）

```
55 AA [len] CC 02 [addr_hi] [addr_lo] [data0..dataN] [CS]
       │           │    │       │           │           └─ 累加和（不含 SEQ）
       │           │    │       │           └───────────── 固件数据（最多 22 字节）
       │           │    │       └───────────────────────── 写入地址低字节
       │           │    └───────────────────────────────── 写入地址高字节
       │           └────────────────────────────────────── 子命令 0x02
       └────────────────────────────────────────────────── LEN = 1(CMD)+1(子命令)+2(地址)+N(数据)
```

### 9.4 Qi→MCU 应答格式（Command 0x00 / 0xCC ACK）

```
普通帧 ACK:  55 AA 03 00 [status] [seq] [CS]
IAP ACK:     55 AA 04 CC [sub] [status] 00 [CS]
```

- `status = 0x00`：成功
- `status != 0x00`：失败

### 9.5 注意事项

- IAP 帧（0xCC）**不含流水号**，校验计算不加 SEQ
- 普通帧（0x02/0x00/0x01）**含流水号**，校验计算加 SEQ
- IAP 每帧最大数据量 **22 字节**（`QI_IAP_MAX_CHUNK`）
- 地址为 16-bit（Qi 芯片 Flash 地址空间）
