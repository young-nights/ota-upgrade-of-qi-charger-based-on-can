# SIT1145 WUF 选择性唤醒异常测试报告

> **芯片型号**：SIT1145AQT_FD
> **测试日期**：2026-10-19
> **固件版本**：QC_JYF_MCU1_FW_1.1.13
> **测试环境**：AT32F426 + ZQWL-CANFD (250kbps, 29-bit 扩展帧)

---

## 1. 背景

使用 SIT1145 的 **WUF 选择性唤醒（Partial Networking）** 功能，配置为只响应 CAN ID `0x18DA0D03` + DLC=8 + 数据字节匹配 `3E xx`（TesterPresent）的帧唤醒。其他帧不应触发唤醒。

## 2. WUF 配置

按官方参考代码 `SIT1145.c` 的 `SleepMode_Set` + `WUF_Set` 序列配置：

### 2.1 寄存器配置值

| 寄存器 | 地址 | 写入值 | 说明 |
|--------|------|--------|------|
| ID0 | 0x27 | `0x03` | CAN ID[7:0] |
| ID1 | 0x28 | `0x0D` | CAN ID[15:8] |
| ID2 | 0x29 | `0xDA` | CAN ID[23:16] |
| ID3 | 0x2A | `0x18` | CAN ID[28:24] |
| MASK0 | 0x2B | `0x00` | 掩码（1=无关位） |
| MASK1 | 0x2C | `0x00` | |
| MASK2 | 0x2D | `0x00` | |
| MASK3 | 0x2E | `0x00` | 全 0 = 精确匹配 |
| Frame Control | 0x2F | `0xC8` | IDE=1, PNDM=1, DLC=8 |
| DM0 | 0x68 | `0x00` | 数据掩码 byte0 |
| DM1 | 0x69 | `0x0C` | 数据掩码 byte1 (bit2+bit3) |
| DM2-DM7 | 0x6A-0x6F | `0x00` | 数据掩码 byte2-7 |
| Transceiver_event_en | 0x23 | `0x03` | CWE=1, CFE=1 |
| CAN Control | 0x20 | `0x71` | CFDC=1, PNCOK=1, CPNC=1, CMC=01 |

### 2.2 写入顺序（对齐官方代码）

```
1. 清事件标志 (0x61 → 0x63 → 0x64)
2. 写 ID 寄存器 (0x27-0x2A)
3. 写 ID 掩码 (0x2B-0x2E)
4. 写数据掩码 (0x68-0x6F)
5. 写帧控制 (0x2F)          ← 最后写
6. 写 Transceiver_event_en (0x23)
7. 写 CAN Control (0x20)    ← PNCOK=1 最后写，锁定配置
8. 写 Mode_control (0x01) = Sleep
```

### 2.3 寄存器读回验证（E2/E3/E4 诊断帧）

进 Sleep 前通过 CAN 总线发出诊断帧，读回所有配置寄存器：

```
E2: MASK0-3 = 00 00 00 00  ✓ 全部清零（精确匹配）
E3: ID=03 0D DA 18  DM0=00  DM1=0C  ✓ 正确
E4: DM2-DM7 = 00 00 00 00 00 00  ✓ 全部清零
```

**所有寄存器写入正确，与预期完全一致。**

## 3. 测试方法

1. 设备空闲 30s 后进入 Sleep 模式
2. 确认静默（总线无帧）
3. 发送测试帧（不同 ID / 不同 SID）
4. 监听 1.5s 判断是否唤醒（有帧返回 = 唤醒）
5. 最后用 `3E 00 @ 0x18DA0D03` 唤醒设备

## 5. 异常分析

### 异常 1：ID `0x18DA0D04` 唤醒

- 与目标 ID 仅 byte0 不同（`0x04` vs `0x03`）
- 掩码=`0x00`（精确匹配），不应匹配
- 但 `0x18DA0D02`（byte0=`0x02`）被正确过滤
- **`0x02` 和 `0x04` 与 `0x03` 的差异类似，但行为相反**

### 异常 2：ID `0x18DA0000` 唤醒

- 与目标 ID 差异 5 个 bit（`0x0D03` vs `0x0000`）
- 掩码=`0x00`，不应匹配
- 但 `0x18DAFFFF`（差异 11 bit）被正确过滤
- **差异位数少反而唤醒，多反而过滤**

### 异常 3：SID `0x31` 唤醒

- `0x31 & 0x0C = 0x00`，数据掩码不应命中
- DM1=`0x0C`（检查 byte1 的 bit2+bit3）
- `0x31` = `0b00110001`，bit2/bit3 均为 0
- 但设备仍唤醒

### 异常 4：ID `0x12345678` 唤醒（不稳定）

- 与目标 ID 差异 19 个 bit
- 掩码=`0x00`，不应匹配
- 多次测试结果不稳定（有时唤醒、有时过滤）

## 6. 疑问

1. **ID 掩码=0（全精确匹配）的硬件行为**：是否有已知的边界条件或限制？为什么 `0x18DA0D04` 唤醒而 `0x18DA0D02` 不唤醒？

2. **数据掩码检查逻辑**：规格书描述"至少一位同时为 1"，但 `0x31 & 0x0C = 0x00` 仍唤醒。是否存在其他匹配条件？

3. **DLC=8 时 DM 寄存器映射**：DM0-DM7 是否确实映射到数据字节 0-7？还是有不同映射？

4. **PNCOK 锁定行为**：写入 `0x20` 设 PNCOK=1 后，后续写入 `0x23`/`0x24` 是否会清 PNCOK？（我们已调整写入顺序，PNCOK 最后写）

5. **是否有推荐的 WUF 配置示例**（针对扩展帧 + DLC=8 + 数据掩码）可以参考？
