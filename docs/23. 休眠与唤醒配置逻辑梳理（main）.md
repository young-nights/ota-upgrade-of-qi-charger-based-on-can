# 23. 休眠与唤醒配置逻辑梳理（main 分支 / QC_JYF_MCU1_FW_1.1.84）

> 依据 main 分支固件源码整理：`qi_wireless_code_app/mdk_app/Src/can_protocol.c`、
> `Src/sit1145.c`、`mdk_can/Src/can_driver.c`、`Inc/app_config.h`、`Inc/sit1145.h`。
> 本文只讲「怎么配、怎么睡、怎么醒、哪些地方有守卫」，供排查睡死/唤不醒问题时对照。

---

## 1. 总览：状态机与开关

```
上电 ──► Normal（收发器 Normal=0x07，CAN 在线）
          │  空闲 CAN_LP_IDLE_TIMEOUT_MS（默认 10s）无 UDS 收发
          ▼
        Sleep（收发器 Sleep=0x01，SPI 断开，CAN 唤醒 WUP 值班）
          │  总线出现唤醒图案（WUF 帧 / 标准 WUP）
          ▼
        Standby（芯片硬件自动中转态，SPI 复活）──► MCU 写 Normal ──► 回到 Normal
```

- **低功耗模式只有一种：Sleep（0x01）**。Standby（0x04）不是配置目标，只是芯片被唤醒时的硬件中转状态（SPI 在 Standby 才恢复，MCU 由此发现"醒了"）。
- **总开关** `CAN_LP_SLEEP_ENABLE`（app_config.h）：
  - `=1`（生产语义）：空闲超时进 Sleep；
  - `=0`：空闲停机整段编译掉，CAN 常在线、全程醒着（调试用）。
- **核心分工**：SIT1145（收发器）负责睡眠期的唤醒检测；AT32 的 CAN 控制器负责协议/收帧。正常通信不依赖收发器的任何速率配置（它是直通电平），DATA_RATE 只被睡眠期的唤醒检测器使用——所以"唤醒配置丢了但通信正常"是这类问题的典型指纹。

## 2. 关键参数一览（app_config.h / can_protocol.c 宏）

| 宏 | 值 | 含义 |
|---|---|---|
| `CAN_LP_SLEEP_ENABLE` | 1 | 空闲睡眠总开关 |
| `CAN_LP_IDLE_TIMEOUT_MS` | **10 000**（10s） | 无 UDS 收发多久进睡（注意：formal_LTS 1.2.x 是 30s） |
| `SESSION_TIMEOUT_MS` | 30 000 | 非默认会话 S3：无诊断请求回默认会话并清安全状态 |
| `CAN_LP_WAKE_INHIBIT_MS` | 100 | 入睡后抑制误唤醒的静默窗（窗内事件不算数） |
| `CAN_LP_WIPE_RETRY_MS` | 100 | RXD 卡低时清标志重试的节流间隔 |
| `CAN_LP_ANNOUNCE_DELAY_MS` | 100 | 唤醒后补播 BOOTUP/OPERATIONAL 的延迟 |
| `CAN_LP_RX_HARVEST_MS` | 30 | 唤醒/入睡前的短窗 RX 收割（赶主机重发） |
| IAP 放宽 | 30 000 | Qi IAP 进行中把空闲超时临时放宽到 30s（防升级中途睡着断电） |

## 3. 上电链路（进 Normal）

1. `can_driver_init`：时钟/GPIO（PA11=RX 上拉、PA12=TX）→ **`sit1145_init()`**（9 步：SPI 配置 → 读芯片 ID 验证 → CAN_CONTROL（CFDC=1/PNCOK=0/CPNC=0/CMC=Normal）回读 → **DATA_RATE=250k** 回读 → `wake_enable`（EVENT_EN 写 CWE+CFE，**写后回读+最多 5 次重试**）→ 清残留事件）。init 失败会**重试一次**，再失败仍继续启动（不能卡死），靠后续 `normal_mode_set` 兜底——注意 `normal_mode_set` 只写 MODE，**不补 DATA_RATE/EVENT_EN**。
2. 控制器进软件复位、配位时序/滤波，保持复位等收发器就绪。
3. `can_protocol_init` 置 `g_lp_need_online=1` → **首次 `can_protocol_poll`** 执行 `can_lp_enter_normal`：
   TXD 回 CAN AF → `sit1145_normal_mode_set`（MODE=Normal＋CTS 等待，×3 重试）→ `wakeup_clear`（清 0x61/0x63/0x64/0x24）→ 等 RXD 释放 → `can_driver_online`（**整外设硬复位**+重配位时序/滤波+清标志——软复位挂久了 RX 中断/滤波可能不恢复，故强制硬复位）→ `g_can_awake=1` → 刷空闲计时 → 补播生命周期帧（BOOTUP→OPERATIONAL）→ 30ms RX 收割（睡后第一帧只当 WUP，赶主机重传窗口内 ACK）。

## 4. 空闲判定与入睡触发（poll 尾部）

刷新空闲计时 `g_uds_last_ms` 的时机（`can_lp_mark_uds`）：上电拉起、**任何 UDS 请求帧**（含多帧逐帧）、**任何应答发送**、入睡被取消后。即：只要有诊断收发，入睡点就顺延。

入睡判定（`can_protocol_poll`）按顺序四道闸：

1. **充电闸门**：`g_qi_charger_enable(0x2101)=1` 且霍尔检出物体（PA0）→ 每轮刷新计时（充电中永不入睡）；
2. **空闲超时**：`(now - g_uds_last_ms) >= idle_limit`（有符号比较防计时器回绕误判）；IAP 进行中放宽到 30s；
3. **忙闸门（2026-11-10）**：ISO-TP 多帧组装中 / 挂起应答未清 / 多帧应答待发 / OTA 下载中 → **一律不入睡**（入睡的 session_reset 会清挂起应答、中止下载）；
4. **失败退避（fw 1.1.77）**：上次入睡失败后 1s 内不重试（防「E0~E3 连发十几组」刷屏风暴）。

## 5. 入睡流程（go_sleep → enter_sleep）

```
can_lp_go_sleep:
  [醒态] 清 g_lp_rx_seen → session_reset_to_default()
         → 有界等 MF UDS 清空（≤2.5s，主机哑巴不阻塞入睡）
         → 浅守卫：等待窗里收到帧 → can_lp_abort_sleep（取消入睡）
         → 丢弃未发状态帧 → 发 SLEEP(0x04) 生命周期帧（handle 确认，失败补发一次）
can_lp_enter_sleep:
  ① 浅守卫：g_lp_rx_seen → abort_sleep 返回
  ② can_driver_offline（关中断+软件复位：不 ACK、不发帧）
  ③ sit1145_sleep_config() —— 配置段（见 §6）；失败 → 恢复在线，下轮重试
  ④ E0~E3 配置后诊断快照（短暂上线发帧；10s 节流；见 §8）
  ⑤ 深守卫：短暂上线 30ms 收割 RX——配置/快照期间到达的请求被处理即
     abort_sleep（请求当场应答，主机无感）
  ⑥ sit1145_sleep_commit() —— 模式切换段（见 §7）；失败 → 恢复在线，下轮重试
  ⑦ can_driver_pins_sleep（TXD 预置高=隐性再切 GPIO，防显性毛刺误触发 WUP）
     → g_can_awake=0，记入睡时刻，arm 唤醒 pre-wipe 诊断
```

**abort_sleep（取消入睡的全链恢复）**：pins_active → NormalMode → 清唤醒事件 → CAN_CONTROL 复位为初始值（PNCOK=0/CPNC=0/CMC=Normal，因为配置段可能已锁 PNCOK|CPNC）→ CAN online → 刷空闲计时（让触发入睡的那条请求先被服务）→ 补播 OPERATIONAL（SLEEP 帧可能已上线，告知主机没睡成）。

## 6. 睡眠配置段：sit1145_sleep_config

顺序（对齐官方 SleepMode_Set）：

1. **清事件**：0x61/0x63/0x64 写 0xFF（W1C）+ 0x24 清 CW|WUF；
2. **DATA_RATE=250k 自愈重写**：该寄存器属 PN 配置区（0x20-0x2F），仅 init 写过一次——冷上电 init 失败或收发器单独复位即丢失，且**丢了一点不影响正常通信（直通），只影响睡眠期唤醒检测采样**，故每次入睡都重写（必须在 PNCOK 锁定前）；
3. **选择性唤醒（WUF）配置**：`wuf_config_uds` 配置 ID=0x18DA0D03 + DLC=8 + 数据 02 3E 近似匹配（PNDM=1，ID+DLC+数据评估），逐写加稳定延时；随后 **3 轮「解锁→全量重配→锁定→只读校验」循环**：
   - 解锁：CAN_CONTROL 清 PNCOK；
   - 全量重配：DATA_RATE + ID/MASK/DM/FrameCtrl（顺序 ID→Mask→DM→FrameCtrl）；
   - 锁定+使能：`wuf_enable`（CPNC=1 → PNCOK=1 锁定配置区 → EVENT_EN 写 CWE+CFE）；
   - 只读校验：PNCOK=1、frame_ctrl=0xC8、ID 四字节全等、MASK=0、DM0=0x02/DM1=0x3E、DATA_RATE=250k、**EVENT_EN.CWE=1**——任一不符判失败；
   - 锁定期不能单补寄存器（会失效/清 PNCOK），必须解锁→全量重配→再锁；
4. **退化保命**：3 轮都没配好 → 放弃选择性唤醒，退化**标准 WUP（任意帧唤醒）**——宁可多醒，不可睡死；
5. **WAKE_enable(0x4C)=双边沿**（官方必需步，带回读）；
6. **唤醒源最终门禁**：EVENT_EN.CWE 必须=1 才允许进睡；不是则 `wake_enable` 补救一次（自带回读重试），仍不生效 → 返回 0 不入睡。

## 7. 睡眠提交段：sit1145_sleep_commit

- 写 MODE_CONTROL=Sleep(0x01)，回读三态：
  - `0x01` 或 `0xFF`（SPI 已断=真睡）→ 成功；
  - 仍是 0x07/0x04 → 写入被忽略 → **CMC=00 兜底**：CAN_CONTROL 置离线再写 Sleep（实测 CMC=01 时写入可能被忽略）；
  - 兜底仍不匹配 → 返回 0（不睡，恢复在线重试）。
- 成功后 `can_driver_pins_sleep`，`g_can_awake=0`，arm 防误唤醒诊断。

## 8. 唤醒判定（睡眠期 poll 的 wake-watch）

入睡后 `g_can_awake=0`，主循环持续跑 wake-watch（`CAN_LP_WAKE_INHIBIT_MS=100ms` 静默期过后才受理）：

1. **pre-wipe（一次性无条件清事件）**：静默期后的首轮 poll 把 0x24/0x63/0x64/0x61 全清——入睡过程/稳定期锁存的**幽灵唤醒**（如 TXD 切换毛刺造成的 CW 假锁存）在此被抹掉，只有 wipe 之后的事件才可能授权唤醒（前后读数记录进 0x211A 诊断）；
2. **判定顺序：先读标志、再看 PA11/RXD 电平**：
   - SPI 死（读回 0xFF，芯片还在 Sleep）→ 走 PA11 电平兜底（`wakeup_pending`）；
   - **标志置位 + RXD 已释放** → 真唤醒，立即拉起（零延迟）；
   - **RXD 拉低** → 幽灵嫌疑：**清掉标志**后 ≤5ms 等 RXD 释放；清后 **0→1 重锁存**（= 主机后续帧/自动重传）才算真唤醒；RXD 卡低则本拍拦截、按 100ms 节流重试清标志（防主循环饿死）；
   - SPI 死 + PA11 低 → 兜底放行（死 SPI 不能吞掉总线唤醒）；
3. **放行后**：记录唤醒源（ev24 CW/WUF→2，ev63 CW→3，PA11→1）+ E1 唤醒决策快照 → `can_lp_enter_normal` 拉起（§3.3）。

> 设计权衡：防幽灵与保唤醒是对立的——擦标志窗口、RXD 低分支清标志都会"吃掉"真唤醒的首拍，靠**主机重发/突发帧**补 0→1 重锁存兜底。因此唤醒测试要打**多帧突发**（如 3E 连发），单发探测落在危险窗里可能被吞。

## 9. 诊断观测点（排障用）

| 观测 | 内容 | 用途 |
|---|---|---|
| **E0**（0x18FF270D，配置后快照） | [1]=MODE、[2]=EVENT_EN（期望 bit0=1）、[4]=CAN_CONTROL（wuf_ok=0x71 / 退化=0x41）、[6] bit0=sleep_fail | 睡前配置真值；EVENT_EN=0x00 = 唤醒开关丢=必睡死 |
| **E1** | wuf_ok、frame_ctrl（期望 0xC8）、MASK0-3 | WUF 帧控/掩码真值 |
| **E2** | ID0-3（期望 03 0D DA 18）、DM0-1（期望 02 3E） | WUF ID 是否写全（错位=永不匹配） |
| **E3** | DM2-7 | 数据掩码 |
| **WK/BOOTUP 帧**（01 41 57 4B / 01 41） | 唤醒/上电标识 | 唤醒失败时：**有 WK 但无 UDS 应答** = 醒了但接收链没起来；**什么都没有** = 没醒（查 E0） |
| **E1 唤醒决策快照** | src、ev24/ev63、wipe_stat、can_wake/rx_low、PA11 | 唤醒判定走了哪条分支、有没有被幽灵逻辑拦截 |
| DID **0x2119** flags | bit0 sleep_fail 粘滞、bit1 ever_sleep 等 | 入睡配置失败过没有 |
| DID **0x211A** | pre-wipe/wipe 统计（PREW_FLAG/POST_STICK/FLAG_IN_WAIT/BLOCKED…） | 幽灵误伤/擦除有效性取证 |

## 10. 与其他分支的差异提醒

- 本梳理基于 **main（QC_JYF_MCU1_FW_1.1.84）**：含 1.1.58~1.1.80 系列全部加固（init 重试、EVENT_EN 回读重试、wuf_ok 全量校验、逐写延时、sleep_config/commit 拆分、入睡取消守卫、忙禁睡、E0~E3 配置后快照+节流、入睡失败退避）。
- **空闲超时 main=10s、formal_LTS 1.2.x=30s**；1.2.1（v1.2.1 Tag）是该系列早期形态：无 sleep_config/commit 拆分、EVENT_EN 单次盲写、wuf 校验不全、无入睡取消守卫——排障时注意对照的固件版本。
- formal_LTS 当前 1.2.2 已按调试需求把 `CAN_LP_SLEEP_ENABLE=0`（全程醒着）。
