# 21. 工位1 多机并发 SN 联机分配方案（可行性）

> **问题**：工位1 安排多人（A/B/C）多机并测，各机独立生成 SN 会**撞号**——A、B 同一天都会产出 `LSCH42JY012606020001`，写进各自产品的 SN 重复，追溯失效。
> **目标**：联机方案保证 SN 唯一，**20 位 SN 格式不变**（`LS CH 42 JY 01 + YYMMDD + 4位序号`）。
> **服务器复用**：[18. 产线多工位数据同步与服务器配置](./18.%20产线多工位数据同步与服务器配置.md) 规划的 QI-SERVER（一台 Windows 工控机、:5000 HTTP、SQLite），SN 服务搭在同一服务上，不新增基础设施。

---

## 1. 问题定义

| 事实 | 说明 |
|------|------|
| SN 格式 | `LSCH42JY01` + `YYMMDD` + `SSSS`（20 位）；`SSSS`=当日流水号 **0001~9999** |
| 现状生成 | `SnGenerator.Generate(date, sequence)`；`sequence` 来自 `Station1Workflow._nextSequence`——**本机内存计数、从 1 起、重启归 1** |
| 撞号场景 | 同日 A/B/C 各自从 0001 起 → 三台产出相同 SN；即使错峰启动，计数独立仍会交叠 |
| 影响 | 设备内 SN 重复、测试记录无法一一对应、返修追溯混乱 |

**约束**：
- SN 20 位格式**不改**（4 位序号是唯一可分配空间，9999/日）
- 多机并发 ≥3 台同工位、同日独立测试
- 断网 / 服务器宕机**不得停线**，也**绝不可回退到本机计数撞号**
- 与测试记录同步服务（doc 18）协同，同一台服务器、同一套库

## 2. 现状代码位置（改造锚点）

| 文件 | 现状 | 改造点 |
|------|------|--------|
| `ProductionStationTool.Core/Sn/SnGenerator.cs` | 纯格式化/解析（`Generate(date, seq)` / `TryParse`） | **不动**（保持纯函数） |
| `ProductionStationTool.Core/Station/Station1Workflow.cs` | `Func<DateTime,int,string> _snGenerate` 可注入；`_nextSequence` 本机自增 | 注入点换成 **ISnSource**（序号来源） |
| `ProductionStationTool.Core/Data/SqliteTestRecordStore.cs` | 本机测试记录库 | 不动（记录仍本地，SN 唯一性由号源保证） |
| doc 18 Server 项目（规划中） | 测试记录汇总服务 | **扩展 3 个 SN 接口** + 1 张表 |

## 3. 方案对比

| | 方案A：中心取号 | 方案B：号段预分配 | 方案C：序号按机器分段 |
|---|---|---|---|
| 做法 | 每次生成前向服务器申请 1 个号（SQL 事务自增） | 每机一次领 50 个号，本地消耗，用尽再领 | 序号 = 机器ID×1000 + 本机计数（A=1001~1999，B=2001~…） |
| 唯一性 | ✅ 服务器强保证 | ✅ 区间不重叠即保证 | ✅ 分段天然不撞 |
| 断网 | ❌ 停线 | ✅ 号段内继续测 | ✅ 完全离线 |
| 联网需求 | 每次测试都在线 | 仅领号时在线 | 无 |
| SN 格式 | 不变 | 不变 | 不变（但序号含义绑定机器） |
| 容量 | 9999/日全局 | 9999/日全局（有号段浪费） | ≤9 台（9999 分段上限） |
| 追溯 | 服务器台账最全 | 台账 + 领号记录 | 需查机器编码表 |
| 复杂度 | 低（1 表 1 接口） | 中（区间管理） | 低但扩展性差 |

**推荐：A + B 混合**——默认在线**逐号申请**（绝对简单可靠）；服务器不可达时自动降级到**本机号段**（断网不断线）；方案C 仅作无网应急备案，不建议常态使用（机器数受限、序号语义与机器绑定）。

## 4. 推荐方案详设（A+B 混合）

### 4.1 服务器 API（挂在 doc 18 QI-SERVER 同一服务，:5000）

| 接口 | 方法 | 入参 | 出参 | 语义 |
|------|------|------|------|------|
| `/api/v1/sn/next` | POST | `{station, operator, count=1}` | `{date, items:[{sn, seq}]}` | 逐号申请（事务内取号+登记） |
| `/api/v1/sn/reserve` | POST | `{station, operator, count=50}` | `{date, startSeq, endSeq}` | 号段申请（离线兜底） |
| `/api/v1/sn/lookup` | GET | `?sn=` | `{station, operator, issuedAt, mode}` | 追溯查询 |

- 取号核心：`SELECT MAX(seq) WHERE date=今日` + `INSERT` 包在**同一事务**；`PRIMARY KEY(date, seq)` + `sn UNIQUE` 双保险
- 日期以**服务器时钟**为准（客户端时间偏差 >5min 拒绝并提示校时，防止跨日错位）

### 4.2 数据表（与 doc 18 的 `station.db` 同库）

```sql
CREATE TABLE sn_issued (
  date       TEXT    NOT NULL,          -- yymmdd
  seq        INTEGER NOT NULL,          -- 1..9999
  sn         TEXT    NOT NULL UNIQUE,   -- 完整 20 位
  station    TEXT, operator TEXT,
  mode       TEXT    NOT NULL,          -- next | reserve
  issued_at  TEXT    NOT NULL,
  PRIMARY KEY (date, seq)
);

CREATE TABLE sn_block (                   -- 号段发放台账
  id INTEGER PRIMARY KEY,
  date TEXT NOT NULL, station TEXT NOT NULL,
  start_seq INTEGER NOT NULL, end_seq INTEGER NOT NULL,
  handed_at TEXT NOT NULL
);
```

### 4.3 客户端改造点（ProductionStationTool.Core）

```csharp
public interface ISnSource
{
    /// <summary>申请 count 个当日序号；失败（离线/满）返回空。</summary>
    Task<IReadOnlyList<int>> TryReserveAsync(int count, CancellationToken ct);
}
```

| 实现 | 行为 |
|------|------|
| `ServerSnSource` | 调 `/sn/next`（超时 2s）；失败自动降级 `BlockSnSource` |
| `BlockSnSource` | 本地 SQLite 记住未用号段（`sn_block` 本地镜像）；用尽/跨日 → 尝试 `reserve` 一批 |
| `LocalCounterSource` | 现状本机自增（**仅限单机调试模式**，产线禁用） |

`Station1Workflow` 改动极小：`_snGenerate` 注入点换成 `ISnSource` + `SnGenerator.Generate` 组合（现有单测已按可注入设计，回归容易）。

### 4.4 一次测试的取号时序

```
① ISnSource.TryReserve(1)   → seq（在线 next 或 本地号段弹出）
② SnGenerator.Generate(today, seq)   → SN
③ 写入设备 + 回读校验（现行流程不变）
④ 写入失败 → SN 不入库、序号作废不回收（宁可空号不撞号）
⑤ 入库测试记录（现行流程不变）
```

## 5. 并发与失败语义

| 场景 | 行为 | 保证 |
|------|------|------|
| A/B/C 同时取号 | 服务器事务串行化 + (date,seq) 主键 | 必得不同 seq |
| 服务器宕机 / 断网 | 自动降级本地号段继续测 | 不撞号、不停线 |
| 号段用尽且离线 | **停止生成并提示联网补号**（禁止退回本机计数） | 不撞号 |
| 写 SN 失败 | SN 不入库（现行规则）；序号作废不回收 | 空号可接受 |
| 跨日 | 日期字段变化，seq 从 1 重新分配；本地旧号段作废 | 不跨日复用 |
| 客户端时钟漂移 | 日期以服务器为准；偏差 >5min 拒绝并提示校时 | 不产错日期 SN |
| 进程重启 | 号段从本地库恢复；逐号模式无状态 | 不撞号 |
| 换班/换机 | 号段随机器；服务器台账可查每段归属 | 可追溯 |

**唯一性底线**：任何情况下不得回退到「本机内存自增」作为产线号源（LocalCounterSource 仅限调试）。

## 6. 容量核算

| 项 | 值 |
|----|----|
| 序号空间 | 0001~9999 / 日（20 位格式硬约束） |
| 并发机器 | 3 台（A/B/C），预留 5 台 |
| 号段长度 | 50/机 → 最大预留 250/日 |
| 日产量 | 千级（doc 18 估计）→ 9999 上限充足，余量 >8 倍 |
| 服务器负载 | 每台每 40s 一次取号请求（按 40s/台测试节拍）→ 3 台 ≈ 0.075 QPS，SQLite 无压力 |

## 7. 联调与验收用例

| # | 用例 | 预期 |
|---|------|------|
| 1 | 3 台并发各生成 50 个 SN | 全部唯一；服务器台账 150 行 |
| 2 | 服务器停机 → 各机继续生成 | 走本地号段，产出仍唯一 |
| 3 | 号段耗尽 + 仍断网 | 工位机明确提示「请联网补号」，不生成 |
| 4 | 恢复联网 | 自动补领号段，台账与实际一致 |
| 5 | 跨零点连续测试 | seq 归 1 重开，日期字段翻日，无重复 |
| 6 | 写 SN 失败重测 | 序号不回收、无重复，失败 SN 不入库 |
| 7 | `sn/lookup` 追溯任一 SN | 返回发放工位/操作员/时间 |

验证命令示例：

```bash
curl -X POST http://QI-SERVER:5000/api/v1/sn/next -d '{"station":"ST-01","operator":"A","count":3}' -H 'Content-Type: application/json'
# → {"date":"261104","items":[{"sn":"LSCH42JY012611040001","seq":1}, …]}
```

## 8. 工作量与风险

| 项 | 工作量 |
|----|--------|
| Server：sn_issued/sn_block 两表 + 3 接口（可挂在 doc 18 Server 项目） | 0.5~1 天 |
| Client：ISnSource + ServerSnSource/BlockSnSource + 本地号段库 + 设置页 | 0.5~1 天 |
| 联调 + 验收用例 1~7 | 0.5 天 |

- **风险低**：不改 SN 格式、不改写设备/入库流程；核心是「序号来源」一个抽象点
- **回退**：任何异常可临时切 `LocalCounterSource`（单机调试），但产线验收标准要求联网/号段模式
