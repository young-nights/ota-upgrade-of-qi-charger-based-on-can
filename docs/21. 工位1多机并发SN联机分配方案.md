# 21. 工位1 多机并发 SN 联机分配方案（可行性）

> **问题**：工位1 安排多人（A/B/C）多机并测，各机独立生成 SN 会**撞号**——A、B 同一天都会产出 `LSCH42JY012606020001`，写进各自产品的 SN 重复，追溯失效。
> **目标**：联机方案保证 SN 唯一，**20 位 SN 格式不变**（`LS CH 42 JY 01 + YYMMDD + 4位序号`）。
> **服务器复用**：[18. 产线多工位数据同步与服务器配置](./18.%20产线多工位数据同步与服务器配置.md) 规划的 QI-SERVER（一台 Windows 工控机、:5000 HTTP、SQLite），SN 服务搭在同一服务上，不新增基础设施。

---

## 1. 问题定义

| 事实 | 说明 |
|------|------|
| SN 格式 | `LSCH42JY01` + `YYMMDD` + `SSSS`（20 位）；`SSSS`=当日流水号 **0001~9999** |
| 现状生成 | `SnGenerator.Generate(date, sequence)`；`sequence` 来自 `Station1Workflow._nextSequence`——**本机内存计数、从 1 起、重启归 1** |
| 撞号场景 | 同日 A/B/C 各自从 0001 起 → 三台产出相同 SN；即使错峰启动，计数独立仍会交叠 |
| 影响 | 设备内 SN 重复、测试记录无法一一对应、返修追溯混乱 |

**约束**：
- SN 20 位格式**不改**（4 位序号是唯一可分配空间，9999/日）
- 多机并发 ≥3 台同工位、同日独立测试
- 断网 / 服务器宕机**不得停线**，也**绝不可回退到本机计数撞号**
- 与测试记录同步服务（doc 18）协同，同一台服务器、同一套库

---

## 2. 网络拓扑（交换机与接线）

> 与 doc 18 共用同一条产线 LAN：SN 取号、测试记录上传走**以太网**；每台工位机的 CAN 是**独立点对点总线**，不经过交换机。

### 2.1 物理拓扑

> 工位构成按 `ProductionStationTool` 的工位页：工位1（SN + 电流电压）、工位2（老化测试）、工位3/4（预留）。
> **每工位机位数动态**：1~N 台，随产量增减（今天 1 台、明天 3 台均正常）；每个机位一台 Windows 电脑跑同一 `ProductionStationTool`（切到本工位页），本机身份由 `machine.json` 配置（编码 `ST-工位号-机位号`）。
> **ZQWL-CANFD 与机位一一对应：每个机位 1 个**；**工位2（老化）先不考虑 ZQWL-CANFD**。

```
① 以太网侧（星型汇入 SW1；机位数随产量动态增减 1~N 台/工位）

                ┌──────────────────────────────────────────────────────────┐
                │      交换机 SW1（24 口二层，非网管）                      │
                │      192.168.10.0/24 · 产线局域网 · 不联外网              │
                └──┬──────────────┬──────────────┬──────────────┬────────┬─┘
                   │              │              │              │        │
                   ▼              ▼              ▼              ▼        ▼
             ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌────────────┐
             │  工位1   │  │  工位2   │  │  工位3   │  │  工位4   │  │ QI-SERVER  │
             │ 机位×N₁ │  │ 机位×N₂ │  │ 机位×N₃ │  │ 机位×N₄ │  │    .10     │
             │ (1~N台) │  │ (1~N台) │  │ (1~N台) │  │ (1~N台) │  │   :5000    │
             └──────────┘  └──────────┘  └──────────┘  └──────────┘  │  SQLite    │
              N₁~N₄ 随产量动态增减（1 台/3 台均正常），机位编码         │ station.db │
              ST-工位号-机位号（如 ST-01-1、ST-01-2、ST-01-3）          └────────────┘
```

```
② 单机位接线（每个机位同构；工位1/3/4 的机位均如此，工位2 老化暂不考虑 ZQWL）

                    ┌──────────────────────────┐
                    │ 机位X（Windows 工位机）    │
                    │  ProductionStationTool   │─── ① 网线 ──► SW1 ──► QI-SERVER
                    │  machine.json 声明身份    │
                    └────────────┬─────────────┘
                                 │ ② USB（每机位 1 个 ZQWL-CANFD，一一对应）
                       ┌─────────┴─────────┐
                       │    ZQWL-CANFD     │
                       └─────────┬─────────┘
                                 │ ③ CAN 250 kbps · 29 位扩展帧 · 120Ω · 点对点
                       ┌─────────┴─────────┐
                       │   充电器 DUT       │
                       └───────────────────┘
```

- **机位分组**：工位k = 该工位当日启用的全部机位（如工位1 = 机位1..N₁）；每台电脑 `machine.json` 声明所属工位与机位号，界面标题栏显示本机编码
- **ZQWL-CANFD 归属**：一个机位一个盒子，USB 直连本机电脑、CAN 直连本机充电器——**不存在两台电脑共用一个盒子**；工位2 的机位暂不配 ZQWL-CANFD，但网线照接（测试记录仍走 ① 上传）

### 2.2 节点与端口规划

| 节点 | IP | 接入 | 说明 |
|------|----|------|------|
| 交换机 SW1 | —（二层透传） | — | **24 口**非网管（机位数会增长，按峰值预留）；无需 VLAN、不联外网 |
| QI-SERVER | `192.168.10.10`（静态） | SW1 | doc 18 同一台；:5000 HTTP + SQLite `station.db`（含 `sn_issued`/`sn_block`） |
| 工位机（机位） | **DHCP 保留**（MAC 绑定） | SW1 | 每工位 **1~N 台、随产量动态增减**；每台电脑跑 `ProductionStationTool`，`machine.json` 设 `stationNo`/`machineId`，编码 `ST-工位号-机位号`（如 ST-01-1、ST-01-2、ST-01-3） |
| ZQWL-CANFD 盒子 | — | USB（**每机位 1 个**） | 与电脑一一对应；工位2 老化暂不考虑 |
| 充电器（DUT） | — | CAN，**不接交换机** | 每机位一条独立 CAN（250 kbps 扩展帧），互不串扰 |

> IP 用 **DHCP 保留（MAC↔IP 绑定）** 而非手工静态表：机位数动态，静态表会漂；DHCP 保留既固定 IP 又免逐台改配置。无 DHCP 环境退而用静态池（网关侧登记）。QI-SERVER 保持静态 `.10`。

**机位增减操作清单（代码/服务器零改动）**：

| 动作 | 步骤 |
|------|------|
| 加机位 | 接网线 → 网关登记 MAC（DHCP 保留）→ 装 `ProductionStationTool` → 上位机「设置」页命名机位（写 `machine.json` 并留痕，也可手工编辑该文件）→ 重启 App（标题栏显示 `ST-xx-x` 即生效） |
| 减机位 | 直接撤电脑；测试记录/号段台账保留在服务器，DHCP 保留可释放 |
| 机位号约定 | 同工位内 `machineId` 不重复即可（推荐 1、2、3… 顺序启用，不必连续） |

### 2.3 取号链路与交换机故障语义

> SN 取号只发生在工位1（写 SN 的工位，其下**各机位均取号**）；工位2~4 走同一 LAN 上传测试记录，不取号。

```
     Station1Workflow ──► ISnSource.TryReserve(1) ──► SnGenerator.Generate(today, seq) ──► 写入设备
                                   │
              ┌────────────────────┴────────────────────┐
              │ 可达（默认，在线逐号）                    │ 不可达（2s 超时：断网/交换机故障/服务器宕机）
              ▼                                          ▼
       ServerSnSource                              BlockSnSource
       POST /api/v1/sn/next                        本地号段（sn_block 本地镜像）
              │                                          │
              ▼                                          ├─ 号段有余量 → 继续测，不撞号、不停线
       ① 网线 → SW1 → QI-SERVER                          └─ 号段用尽 → 停止生成，提示「请联网补号」
       （事务内取号，(date,seq) 主键）                       （禁止回退本机计数）
```

- **交换机断电 / 网线松动 / 服务器宕机**：`ServerSnSource` 2s 超时 → 自动降级 `BlockSnSource` 本地号段，**不停线、不撞号**
- **单机网线故障**：仅该机降级本地号段，其余电脑照常在线逐号取号 / 上传记录
- **恢复联网**：自动补领号段，台账与实际一致（验收用例 4）
- **号段用尽且仍离线**：停止生成并提示「请联网补号」——绝不回退本机内存计数

## 4. 方案对比

| | 方案A：中心取号 | 方案B：号段预分配 | 方案C：序号按机器分段 |
|---|---|---|---|
| 做法 | 每次生成前向服务器申请 1 个号（SQL 事务自增） | 每机一次领 50 个号，本地消耗，用尽再领 | 序号 = 机器ID×1000 + 本机计数（A=1001~1999，B=2001~…） |
| 唯一性 | ✅ 服务器强保证 | ✅ 区间不重叠即保证 | ✅ 分段天然不撞 |
| 断网 | ❌ 停线 | ✅ 号段内继续测 | ✅ 完全离线 |
| 联网需求 | 每次测试都在线 | 仅领号时在线 | 无 |
| SN 格式 | 不变 | 不变 | 不变（但序号含义绑定机器） |
| 容量 | 9999/日全局 | 9999/日全局（有号段浪费） | ≤9 台（9999 分段上限） |
| 追溯 | 服务器台账最全 | 台账 + 领号记录 | 需查机器编码表 |
| 复杂度 | 低（1 表 1 接口） | 中（区间管理） | 低但扩展性差 |

**推荐：A + B 混合**——默认在线**逐号申请**（绝对简单可靠）；服务器不可达时自动降级到**本机号段**（断网不断线）；方案C 仅作无网应急备案，不建议常态使用（机器数受限、序号语义与机器绑定）。

## 5. 推荐方案详设（A+B 混合）

### 5.1 服务器 API（挂在 doc 18 QI-SERVER 同一服务，:5000）

| 接口 | 方法 | 入参 | 出参 | 语义 |
|------|------|------|------|------|
| `/api/v1/sn/next` | POST | `{station, machine, operator, count=1}` | `{date, items:[{sn, seq}]}` | 逐号申请（事务内取号+登记） |
| `/api/v1/sn/reserve` | POST | `{station, machine, operator, count=50}` | `{date, startSeq, endSeq}` | 号段申请（离线兜底） |
| `/api/v1/sn/lookup` | GET | `?sn=` | `{station, machine, operator, issuedAt, mode}` | 追溯查询 |

> `machine` = 机位号（同工位多机位动态增减，取号并发数不限，服务器事务保证互不撞号）。

- 取号核心：`SELECT MAX(seq) WHERE date=今日` + `INSERT` 包在**同一事务**；`PRIMARY KEY(date, seq)` + `sn UNIQUE` 双保险
- 日期以**服务器时钟**为准（客户端时间偏差 >5min 拒绝并提示校时，防止跨日错位）

### 5.2 数据表（与 doc 18 的 `station.db` 同库）

```sql
CREATE TABLE sn_issued (
  date       TEXT    NOT NULL,          -- yymmdd
  seq        INTEGER NOT NULL,          -- 1..9999
  sn         TEXT    NOT NULL UNIQUE,   -- 完整 20 位
  station    TEXT, machine TEXT, operator TEXT,
  mode       TEXT    NOT NULL,          -- next | reserve
  issued_at  TEXT    NOT NULL,
  PRIMARY KEY (date, seq)
);

CREATE TABLE sn_block (                   -- 号段发放台账（归属到机位）
  id INTEGER PRIMARY KEY,
  date TEXT NOT NULL, station TEXT NOT NULL, machine TEXT,
  start_seq INTEGER NOT NULL, end_seq INTEGER NOT NULL,
  handed_at TEXT NOT NULL
);
```

### 5.3 客户端改造点（ProductionStationTool.Core）

```csharp
public interface ISnSource
{
    /// <summary>申请 count 个当日序号；失败（离线/满）返回空。</summary>
    Task<IReadOnlyList<int>> TryReserveAsync(int count, CancellationToken ct);
}
```

| 实现 | 行为 |
|------|------|
| `ServerSnSource` | 调 `/sn/next`（超时 2s）；失败自动降级 `BlockSnSource` |
| `BlockSnSource` | 本地 SQLite 记住未用号段（`sn_block` 本地镜像）；用尽/跨日 → 尝试 `reserve` 一批 |
| `LocalCounterSource` | 现状本机自增（**仅限单机调试模式**，产线禁用） |

`Station1Workflow` 改动极小：`_snGenerate` 注入点换成 `ISnSource` + `SnGenerator.Generate` 组合（现有单测已按可注入设计，回归容易）。

### 5.4 一次测试的取号时序

```
① ISnSource.TryReserve(1)   → seq（在线 next 或 本地号段弹出）
② SnGenerator.Generate(today, seq)   → SN
③ 写入设备 + 回读校验（现行流程不变）
④ 写入失败 → SN 不入库、序号作废不回收（宁可空号不撞号）
⑤ 入库测试记录（现行流程不变）
```

## 6. 并发与失败语义

| 场景 | 行为 | 保证 |
|------|------|------|
| A/B/C 同时取号 | 服务器事务串行化 + (date,seq) 主键 | 必得不同 seq |
| 服务器宕机 / 断网 | 自动降级本地号段继续测 | 不撞号、不停线 |
| 号段用尽且离线 | **停止生成并提示联网补号**（禁止退回本机计数） | 不撞号 |
| 写 SN 失败 | SN 不入库（现行规则）；序号作废不回收 | 空号可接受 |
| 跨日 | 日期字段变化，seq 从 1 重新分配；本地旧号段作废 | 不跨日复用 |
| 客户端时钟漂移 | 日期以服务器为准；偏差 >5min 拒绝并提示校时 | 不产错日期 SN |
| 进程重启 | 号段从本地库恢复；逐号模式无状态 | 不撞号 |
| 换班/换机 | 号段随机器；服务器台账可查每段归属 | 可追溯 |

**唯一性底线**：任何情况下不得回退到「本机内存自增」作为产线号源（LocalCounterSource 仅限调试）。

## 7. 容量核算

| 项 | 值 |
|----|----|
| 序号空间 | 0001~9999 / 日（20 位格式硬约束） |
| 并发机位 | **动态**：每工位 1~N 台随产量增减，合计按 3~20 台核算 |
| 号段长度 | 50/机位 → 20 机位全离线最大预留 1000/日 |
| 日产量 | 千级（doc 18 估计）→ 9999 上限充足，余量 >8 倍 |
| 服务器负载 | 每机位每 40s 一次取号请求（按 40s/机位测试节拍）→ 20 机位 ≈ 0.5 QPS，SQLite 无压力 |

> 机位数动态**不影响方案本身**：逐号模式并发数不限（服务器事务串行化）；号段按机位发放，增减机位只是增减 `sn_block` 归属行。

## 8. 联调与验收用例

| # | 用例 | 预期 |
|---|------|------|
| 1 | 3 台并发各生成 50 个 SN | 全部唯一；服务器台账 150 行 |
| 2 | 服务器停机 → 各机继续生成 | 走本地号段，产出仍唯一 |
| 3 | 号段耗尽 + 仍断网 | 工位机明确提示「请联网补号」，不生成 |
| 4 | 恢复联网 | 自动补领号段，台账与实际一致 |
| 5 | 跨零点连续测试 | seq 归 1 重开，日期字段翻日，无重复 |
| 6 | 写 SN 失败重测 | 序号不回收、无重复，失败 SN 不入库 |
| 7 | `sn/lookup` 追溯任一 SN | 返回发放工位/操作员/时间 |

```bash
curl -X POST http://QI-SERVER:5000/api/v1/sn/next -d '{"station":"ST-01","operator":"A","count":3}' -H 'Content-Type: application/json'
# → {"date":"261104","items":[{"sn":"LSCH42JY012611040001","seq":1}, …]}
```

## 9. 工作量与风险

| 项 | 工作量 |
|----|--------|
| Server：sn_issued/sn_block 两表 + 3 接口（可挂在 doc 18 Server 项目） | 0.5~1 天 |
| Client：ISnSource + ServerSnSource/BlockSnSource + 本地号段库 + 设置页 | 0.5~1 天 |
| 联调 + 验收用例 1~7 | 0.5 天 |

- **风险低**：不改 SN 格式、不改写设备/入库流程；核心是「序号来源」一个抽象点
- **回退**：任何异常可临时切 `LocalCounterSource`（单机调试），但产线验收标准要求联网/号段模式
